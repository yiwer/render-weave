# 03: 审核固定资源预览，相关资源变化后重新核准

**What to build:** 将候选检查、预览缓存、审核结论与应用绑定到同一份内容身份，使版本仓库和旧资源目录都能稳定预览，并在相关资源变化时明确拒绝旧批准。

**Blocked by:** 无

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；D02、D03、D16；US09–12、US14–15、US63（本票内容身份与资源兼容）；A04；A06（旧资源目录、相关/无关变化、资源损坏和历史资源身份缺失子项）；A20（本票合同、资料及兼容子项）。遵守 ADR-0023，保留 ADR-0022 的阶段 5 策略。

本票完成顺序操作下的审核一致性；并发提交由 04 承担，应用中断由 05 承担。

- [ ] 每次检查记录候选集合、依赖文档、请求、可信参考/内容事实、实际使用资源的版本与字节身份、构建和判据版本；预览、报告和核准结论可追溯到该身份。相同文件名但内容不同不能复用旧预览或批准，模型配置不混入已有候选的内容身份。
- [ ] 版本仓库使用固定资源完成本轮检查和审核预览，覆盖图片、直接字体、后备字体与 SVG 字体。审核后分别替换这些相关资源，旧预览仍能按原依据复查；新依据产生可区分的预览，不能将旧图作为新资源的检查证据。
- [ ] 旧清单目录保持现有输入方式；本轮以可验证的私有副本和哈希固定资源，不修改原目录、不强制迁移。应用核对清单映射、资源种类和实际依赖文件字节；相关图片或字体内容变化能够被检出。
- [ ] 相关资源变化使旧批准失效，应用返回逐项差异和重新检查、预览、核准的可行路径；完成重新核准后可以应用。工作区覆盖选项不能绕过资源身份核对。
- [ ] 对照修改未使用的资源或旧目录中的无关文件，已有核准仍可应用；不能通过把整个资源目录的任意变化都视为冲突来满足相关资源检查。
- [ ] 固定资源及当前应用依据中的相关字节损坏、缺失或不符记录时明确失败，不静默换用当前资源版本、不回退到不对应的缓存；错误能够定位到相关资源。
- [ ] 缺少完整资源身份的历史轮次保留原事实，不补造当时版本；应用前以当前内容重新检查并取得当前流程所需核准。原完整记录保持可读，历史轮次接续的状态处理归 08、09。
- [ ] 应用成功后，再经合法资源替换入口更新资源，未来出图继续按既有资源引用规则生效；本轮固定不变成永久锁定。当前本地审核要求保留，阶段 5 仍是内容变化后重查、仅在租户策略要求时重批。
- [ ] 同步本票涉及的工具/记录合同、资料和样例，明确新旧身份的读取与重新核准规则；跑相关既有回归并记录版本。工具行为变化按既有约定升版，不把旧报告改写为新规则通过。

**测试接缝：** 通过公开 Agent 运行、审核和应用入口创建并核准候选，配合公开资源替换与渲染入口观察批准状态、差异清单、预览内容和正式图片；以假执行器提供确定候选，分别覆盖版本仓库、旧清单和四类资源依赖。机制验收不以全部真实模型门槛为关闭条件，真实模型最终证据归统一验收活动。若必须先作小范围预重构，先保持现有测试通过，再在本票内完成闭环，不另建通用内容身份框架。
