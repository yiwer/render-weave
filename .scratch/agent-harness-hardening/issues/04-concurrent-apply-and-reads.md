# 04: 资源替换与应用并发时，核准内容和公开读取保持一致

**What to build:** 让资源替换、候选应用及公开读取协调同一短时提交边界，消除最后核对与实际提交之间的竞态。

**Blocked by:** 03

**Status:** resolved

**Trace:** [父规格](../spec.md)；D03；US13、US63（本票并发行为兼容）；A05（正常运行中的并发替换、核对与提交先后、一致读取及整体拒绝子项）；A20（本票合同、资料及兼容子项）。遵守 ADR-0023。

本票完成进程正常运行时的并发保证；强退后的提交意图、恢复阻断和幂等重试归 05，不在本票宣称已覆盖崩溃恢复。

- [x] 从公开入口并发替换相关资源与应用已批准候选，结果具有一致先后：先应用则提交依据与批准一致；替换先完成则旧依据被拒绝。不存在旧资源核对通过后用新资源悄悄提交的成功结果。
- [x] 产品入口中参与同一工作区与资源仓库写入的操作遵守同一协调约束，取得多个约束时顺序稳定；重复并发执行能够结束，不因相反获取顺序相互等待。工作区覆盖选项不能绕开该边界。
- [x] 应用修改多个关联文档时，并发公开渲染、审核和应用读取取得完整旧集合或完整新集合，不能消费部分新旧文件；未能取得一致输入时明确等待或返回可辨认的冲突结果。
- [x] 读取取得一致输入副本后再做耗时计算；计算期间发生合法写入，该次结果仍对应其已取得的完整内容身份，后续新读取能够看到新内容，不把两次依据混为同一份报告。
- [x] 模型等待和耗时渲染不长期占用写入边界；以受控长调用配合合法资源操作，验证后者不必等待整个模型或渲染任务结束。最后核对发现输入已变时整体拒绝，不能用旧计算结果绕过核对。
- [x] 两次冲突应用或工作区更新并发时，失败方不留下部分候选或半套关联文档；成功结果与实际工作区一致，已有工作区漂移检查仍然生效。
- [x] 无关资源变化及不冲突操作的合法对照仍可成功，不以拒绝全部并发操作满足一致性。人工直接改盘不纳入事务保证，但已有内容漂移和损坏检查不能因引入并发协调而失效。
- [x] 更新本票涉及的冲突结果合同、操作资料与兼容说明，明确正常并发与中断恢复的责任边界；相关既有审核、应用、资源替换和读取回归通过，涉及行为变化时按既有规则升版。

**测试接缝：** 同时调用公开资源替换、Agent 审核/应用和渲染入口，观察实际文件集合、预览/图片、内容身份、退出结果和问题清单；使用受控的整个资源或执行器边界制造等待，不增加私有计算步骤测试接口。真实模型最终证据归统一验收活动，不要求本票重复跑完整真实门槛。必要的小范围预重构先保持现有测试通过，并随本票完整行为交付，不另建锁服务或通用事务框架。
