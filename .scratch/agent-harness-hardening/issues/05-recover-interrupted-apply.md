# 05: 应用中断后恢复完整工作区，重试不重复发布

**What to build:** 为本地应用保存可恢复的提交依据，让提交中强退后得到完整旧状态或新状态，并对成功提交提供幂等重试。

**Blocked by:** 04

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；D03、D09；US16、US13（中断后的读取一致性）、US63（本票应用记录兼容）；A05（提交中断、恢复前读取、完整恢复、重复应用及外部新改动子项）；A20（本票合同、资料及兼容子项）。遵守 ADR-0023。

本票处理应用提交，轮次执行和候选检查点的恢复归 08、09；不以 Agent 运行状态推断应用成功，不新增服务端事务实现。

- [ ] 应用提交前保存足以辨认提交意图、旧/新内容身份和最终结果的可恢复依据；涉及数据定义发布、数据集/模板写入及应用结果时，恢复覆盖整次应用，不能只恢复其中的模板文件。
- [ ] 在提交尚未开始时强退，工作区保持原样；在多文件提交过程中强退，恢复后是完整旧状态或完整新状态，并明确显示未提交或已提交，不能留下部分成功。
- [ ] 强退后尚未完成恢复时，公开渲染、审核与应用必须先恢复、等待或明确返回需要恢复；它们不能取得混合输入，也不能把“存在部分新文件”解释为成功。
- [ ] 对同一已经成功的提交标识重复应用或在成功回应前中断后重试，返回可核对的已有结果；不重复发布数据定义版本、不重复保存候选、不产生第二次业务提交。
- [ ] 恢复发现工作区已有不属于本次提交的外部新修改时，停止并列出冲突；保留新内容和诊断，不用旧备份覆盖，未经冲突处理不宣称恢复完成。
- [ ] 同一未完成提交遭遇两个恢复者或恢复与重试并发时，操作协调同一提交边界，最终结果唯一；反复恢复能够收敛，正常合法提交与恢复后的公开读取仍能完成。
- [ ] 提交记录和审核依据保持可追溯，恢复不补造历史批准；未批准候选及宿主恢复草稿仍不能直接应用。新记录明确辨认未完成提交，旧成功记录按已有可证事实读取，不误识别为待重做提交。
- [ ] 中断验收覆盖宿主强退和可控提交中断，并记录恢复前后工作区与正式出图结果；不将逐文件替换或进程内异常撤回宣称为已覆盖强退，也不声称可保证任意存储断电持久性。
- [ ] 更新应用/恢复结果合同、操作资料和新旧记录兼容说明；相关既有应用回归及 04 的并发行为通过，涉及行为变化时按既有约定升版。

**测试接缝：** 从公开 Agent 应用 CLI 启动提交并终止受测宿主，随后经公开渲染、审核、应用入口观察阻断与恢复；核对工作区内容、数据定义发布版本、正式图片、退出码和结果记录。中断接缝只放在整个提交/资源边界，不检查私有写入调用顺序。真实模型最终证据归统一验收活动，本票以确定性故障验收关闭。必要预重构先保持现有测试通过，不另建通用工作流或数据库框架。
