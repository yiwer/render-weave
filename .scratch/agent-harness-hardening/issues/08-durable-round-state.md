# 08: 任务启动即可查看持久状态，强退后保留可读诊断

**What to build:** 在执行器启动前持久保存轮次输入与拥有者，运行中更新可查看状态，使宿主强退不再导致整轮无记录或伪造完成。

**Blocked by:** 03

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；D08、D16；US17、US18（强退状态与诊断子项）、US22（历史完整轮次读取）、US23、US24（不伪造来源和批准）、US63；A07（初始化后、终检后强退的状态子项）；A08（拥有者与无完整候选诊断子项）；A06（历史轮次读取与身份缺失子项）；A20（本票合同、资料及兼容子项）。遵守 ADR-0024。

本票交付运行中及中断后的可查看状态；完整候选检查点、接续和恢复竞争归 09，时间预算归 10。

- [ ] 启动执行器之前，宿主已提交轮次记录、固定输入和本轮内容身份；模型持续等待时，经现有 Agent 读取流程可确认轮次存在、运行阶段及输入依据，不能等模型结束才出现唯一记录。
- [ ] 正常任务能够辨认准备、执行、收尾和完成，现有失败/停止路径有对应原因；状态更新后始终可读，关键事件追加保留。没有完成成果检查和最终记录提交时，不能标记为完成。
- [ ] 执行状态、技术质量、内容/视觉结论和审核状态分别呈现；以执行结束但业务受阻、技术合格但待审核等对照验证，不能由一个完成或成功标记自动批准、自动应用。
- [ ] 初始化后、执行期间、终检后但最终记录提交前强退宿主，重新读取仍能获得已有输入、状态和诊断，不补造完成、批准或应用成功；没有完整候选时明确说明，不能拿残留文件冒充正式成果。
- [ ] 一个轮次至多一个有效可写拥有者，重复持有同轮次不能相互覆盖状态；拥有者陈旧不能仅凭经过时间便被接管，原执行器仍可写或身份不能确认时明确拒绝或保留待恢复状态。
- [ ] 旧版完整轮次仍可读取，展示其已有可证事实；格式损坏、记录不完整或身份不全时返回可定位诊断，不猜造缺失字段或历史资源版本。旧完整轮次的既有正常接续保持回归，新检查点接续由 09 验收。
- [ ] 轮次记录及状态显示保留作者交回与宿主恢复的区别；对已有恢复草稿继续拒绝直接批准和应用。原成果、已有来源留存与审核事实不因状态升级而被覆盖。
- [ ] 同步状态与记录合同、读取资料及旧格式兼容规则；既有 Agent 任务、审核和接续回归通过，新增格式/行为按现有约定升版。输出只含必要诊断，不包含凭据。

**测试接缝：** 通过公开 Agent CLI 启动假执行器的等待、正常完成和失败任务，从既有读取/审核入口及公开轮次记录观察状态；强退受测宿主后再次读取，核对退出结果与诊断。拥有者检查从整个执行器/轮次边界验证，不单测内部状态机。真实模型最终证据归统一验收活动，本票不重复完整模型门槛。必要预重构先保持现有测试通过，并以本票可查看行为收口，不另建纯状态框架。
