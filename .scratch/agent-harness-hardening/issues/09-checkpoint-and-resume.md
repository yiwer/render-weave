# 09: 已检查的完整候选在强退后可从检查点接续

**What to build:** 由宿主保存每次完整成果检查实际消费的不可变候选集合，并通过现有接续入口从该集合开启新轮次。

**Blocked by:** 08

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；D08、D09、D11（最后完整候选基础）；US18–24、US63；A07（检查点发布、集合恢复及原轮次事实子项）；A08（恢复竞争、旧执行器仍活和无候选子项）；A06（旧轮次接续与新轮次固定资源子项）；A11（完整候选集合与来源子项，较好候选比较归 11）；A20（本票合同、资料及兼容子项）。遵守 ADR-0024。

沿用当前执行器与只读 MCP；不恢复供应商内部会话，不把接续伪装成原执行连续运行。

- [ ] 完整候选集合的 `check_outcome` 每次成功完成检查后，宿主发布对应检查实际消费字节的检查点，并给出可观察的保存完成状态；先固定字节并检查保存副本，再原子发布记录。MCP 检查与比较仍只读，保存由宿主承担。
- [ ] 检查点包含主模板、全部必要被调模板及相关候选清单、不可变字节、哈希、核准依据和检查结果；后续工作副本变化不改变已保存集合，重新读取能够核对本次检查的完整内容身份。
- [ ] 结构完整但语义受阻的候选能够留存并接续；业务不合格不等于检查未完成。缺少依赖、候选半写或读取期间变化则不发布新完整检查点，返回明确诊断。
- [ ] 两份相互依赖模板只改完一份、未显式检查的新写入、损坏文件及单文件均可解析但未完成整组检查时，都不能顶替上一完整检查点；再次完成整组检查后才更新最后完整候选。
- [ ] 在保存完成信号后、检查点发布中及终检后强退宿主，恢复只选择已完整提交且可验证的检查点；发布中断不得损坏上一检查点，不能恢复检查未实际消费的新旧混合内容。
- [ ] 现有 `--from` 接续入口引用旧轮次、检查点及新反馈，开新轮次并固定其输入和资源；恢复内容与被引用检查点一致，旧轮次保持原中断/完成事实，不补造正式交回、批准或发布。
- [ ] 两个恢复者针对同一轮次的恢复状态并发操作时，至多一个有效可写拥有者；旧执行器仍可写或无法确认已失去写入能力时不能接管。没有完整候选时保留诊断并明确不能从残片接续。
- [ ] 旧版完整轮次继续按原入口接续；缺失检查身份或资源历史时保留可证事实，在新轮次重新固定和检查，不伪造旧版本。宿主恢复候选明确标记来源，只可查看或接续，直接批准/应用仍被拒绝。
- [ ] 同步检查点保存完成信号、接续与记录兼容合同、Agent 资料和样例，保持既有正常成果接续回归；行为变化按约定升版，原轮次和旧报告保持原样。

**测试接缝：** 从公开 Agent CLI 运行假执行器，经真实 MCP 协议完成成果检查，等待公开保存完成状态后终止宿主，再用现有读取与 `--from` 接续入口核对候选字节、来源、问题及新轮次结果。用完整执行器边界安排半写和等待，不开放私有检查点方法作为验收入口。真实模型接续效果的最终证据归统一验收活动，不作为本机制票的完整真实门槛。必要预重构先保持现有测试通过，不另建通用快照或会话恢复框架。
