# 11: 保留有证据更好的候选，正式交回退步时显示差异

**What to build:** 分开保留最后完整候选和可证明更好的候选，在正式交回退步时展示证据而不替换作者提交。

**Blocked by:** 09

**Status:** resolved

**Trace:** [父规格](../spec.md)；D11；US21、US24、US31–32、US63；A11（较好候选选择、不可排序、正式提交差异及恢复来源子项；完整集合保存基础由 09 验收）；A20（本票合同、资料及兼容子项）。遵守 ADR-0024。

本票使用已有可核准的检查维度；缺少依据时保持不可排序，不等待全部新视觉测量或以未经校准总分代替判断。

- [x] 最后完整候选与有证据更好的候选分别可查看并指向可验证的完整集合；新完整检查可以更新前者，但不因此自动覆盖后者，候选依赖和检查依据可追溯。
- [x] 仅在请求、数据、资源、参考、修改政策与判据相同的情况下比较；任一依据改变或无法确认时明确不可排序，不把不同基准下的分数当成进步。
- [x] 新候选保持技术硬约束和授权修改范围，不增加关键缺失、已知异常或未知范围，并至少改善一项核准指标时，才替代有证据更好的候选；用真实检查结果构造改善对照，验证记录更新。
- [x] 新增关键缺项、引入技术/范围违例、未知范围增加、维度互有得失及没有可信基准时，不更新较好候选；逐项解释退步或不可排序原因，不用总分抵消关键退步，不把全部任务一概判为不可排序。
- [x] 完全相同或没有可证明改善的候选不制造“更好”结论；较好候选即使仍有受阻问题也明确显示未核查/未通过范围，不将相对改善解释为业务全部合格。
- [x] Agent 正式交回保持其显式提交；若相对保留候选退步，审核入口显示两份内容及差异，最终提交标识和实际字节不被静默替换。
- [x] 中断或停止后可以从所选保留候选开新轮次，来源和检查身份明确；宿主恢复草稿仍只可查看/接续，不能直接批准或应用，旧候选与原轮次事实保持不变。
- [x] 同步候选比较/选择结果合同、审核和接续资料、新旧记录兼容规则；旧轮次没有较好候选证据时如实显示缺失，既有正式交回与恢复草稿回归通过，行为变化按约定升版。

**测试接缝：** 经公开 Agent CLI 与真实 MCP 成果检查形成多份完整候选，使用核准内容/视觉事实驱动改善、退步和冲突；从审核、公开记录与接续入口核对选择结果、差异和实际候选。假执行器仅提供候选序列，不以手填私有比较结果代替产品检查。真实模型最终证据归统一验收活动，不把完整真实门槛列为本机制票关闭条件。必要预重构先保持现有测试通过，不引入通用评分或自动选稿框架。
