# 14: 可信基准随评估任务进入产品路径并形成完整纠偏计划

**What to build:** 维护者可以从评估入口创建中英文四类任务的可信反馈计划，把核准事实或区域交给真实产品路径，并从假执行器结果核对基准、候选、反馈与终检的关联，为之后一次性真实模型验收准备可冻结输入。

**Blocked by:** 07、13

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md) H5、D06–D07、D12–D13；US40–43、US49–50；A15 的评估输入、8 类校准场景及 16 个有效观测计划、分页与内容身份机制子项。本票不承担 A15 的真实模型效果结论。

- [ ] 准备中文、英文各数据定义提取、数据集提取、模板辅助设计、模板辅助修改，共 8 类校准场景；每类预登记 2 次有效观测及相同预算，计划完整列出 16 个单元，真实模型尚未运行的保持未运行。
- [ ] 提取任务实际传入本次核准内容事实，模板任务实际传入核准参考区域；输入包括素材、任务前提、已知可修缺陷、预期修正与允许改动范围，不能只给出一个基准名称。缺材料或核准事实时列出缺失项，不用旧答案、模型自述或另一场景补足。
- [ ] 校准场景从已知可修缺陷出发，区分首次结果与反馈修正结果；分别判断目标修正、非目标保留和未知范围，不将工具调用发生或零 severe 当作纠偏成功。
- [ ] 至少一个模板场景有超过 20 个核准区域，后续页包含必须修正的问题；经评估入口和假执行器驱动 MCP 的续取流程，能取得该问题并在结果中核对其处置，不能只检查第一页或仅记一次调用。
- [ ] 评估输入指定的核准基准由宿主固定，候选、备注或工具传参中的替代文件不能让编排改用另一份真值；无基准、无效基准和有效基准分别得到诚实状态。运行时越权改写可信文件及凭据隔离由 16 验收，本票不以假执行器服从规则证明权限安全。
- [ ] 每次派发保存实际提示词、输入、基准及上游成果身份；合法任务串联与反馈接续不因动态提示词不同被误拒。最后有效比较与宿主终检必须对应同一候选、请求、数据、相关资源、参考和判据身份，改动后旧报告失效。
- [ ] 通过假执行器完整驱动 8 类场景及受控 pass、fail、invalid、not-run 结果，报告保留计划和不可覆盖的尝试；假结果显式标为机制验证，不能被计入真实模型有效观测或关闭 A15 的模型验收。
- [ ] 计划能引用身份和标准均相容的既有真实证据，并明确尚缺单元；不在本票调用真实模型。原票据 33、34 的业务核查以及 38 的既有真实业务验收仍保留唯一责任，后续统一冻结后只补未覆盖单元，不为本票另跑四场景。
- [ ] 本票同步评估配置、报告合同、操作说明、基准格式指引及涉及的 Agent/MCP 资料；公开入口回归验证任务前提、基准实际载入和输出关联，不把合同维护留到最终收口票。

**测试接缝：** 现有评估 CLI 经假执行器进入公开 Agent/CLI 全流程，结合真实 MCP 和宿主成果校验；读取实际轮次文件、工具结果与报告验证基准传递、分页和身份绑定，不调用真实模型，不把合成纠偏当成模型效果。
