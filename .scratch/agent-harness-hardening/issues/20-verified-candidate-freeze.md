# 20: 兼容检查通过后冻结同一份待验候选

**What to build:** 维护者获得经过离线回归与两平台检查的不可变候选包，后续真实模型活动明确使用同一构建、资料、工具合同和判据。

**Blocked by:** 01、11、18

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；US01、US33、US48、US63–64；A20 的兼容及自动验证部分；D06、D16。

- [ ] 核对所有前置实现已经各自完成合同、资料、记录格式和样例同步；本票不承担补做这些实现。发现缺口退回责任票，不能仅改报告使其通过。
- [ ] 从公开入口执行全量回归及共享样例一致性检查；涉及渲染的变更在 Windows、Linux 复核图片和摘要，保存命令、环境与结果，不用单平台结果替代。
- [ ] 旧完整轮次可读和接续，缺身份记录要求重新检查；旧报告不被改写，新判据另存结果。公开合同的兼容处理与版本声明一致。
- [ ] 候选包保存构建、合同、判据、运行策略、默认资料、运行时请求配置及资源依据的可验证身份；实际服务模型未知修订继续明确不可固定。包内内容不可随工作目录后续构建变化。
- [ ] 为原四场景和新增可信反馈计划提供确切候选身份，并提供后续计划绑定所需清单；19 的材料准备可并行，22–25 在其完成后、派发前将留出计划绑定该候选，本票不等待留出材料。不同计划的结论不互相替代，候选冻结不等于模型门槛通过。
- [ ] 实测修改工作目录的资料或构建不会改变已冻结包；使用不匹配内容发起验收在模型派发前失败并列差异。
- [ ] 冻结后若修代码、工具、资料、预算策略或评分规则，生成新候选身份并列出需重验的单元；不将旧、新构建结果拼接为最终通过。
- [ ] 保留阶段 5 默认直发与可选审批决定；本地兼容通过不宣称租户写入、托管隔离或客户自助已验收。

**测试接缝：** 公开 Agent/评估 CLI、公开渲染与 MCP 合同；沿现有全量回归和双平台验收入口。冻结行为以文件身份及派发前错误验证。

**责任边界：** 本票只做兼容检查、打包与冻结。A14 真实四场景仍归[原票 38](../../agent-template-authoring/issues/38-retest-after-quota-recovery.md)；新增可信反馈实跑归 21；真人走查归 26。
