# 24: 整站牌留出案例完成九次独立观测

**What to build:** 维护者获得整站牌这一分层的原始 Agent 能力、人工返工和正式交付证据，所有成功与失败都可追溯到冻结计划。

**Blocked by:** 19、21；[原票 38：固定候选的既有真实模型验收](../../agent-template-authoring/issues/38-retest-after-quota-recovery.md)

**Status:** ready-for-agent

**Trace:** [父规格](../spec.md)；US44–48、US55–57；A17 的整站牌执行及独立审核部分；D13、D14。

- [ ] 只运行 19 中类型为整站牌的 3 个登记案例（按真实模板家族统计独立性），每例 3 次，共 9 个计划观测；保持案例身份、真值、预算、全流程/修改任务分配和候选身份不变。
- [ ] 开始前确认 21 与原 38 使用相同候选并完成所需有效验收；如它们促成任何调参或修复，先由 20 冻结新候选并重新核对前置证据，不能边调优边运行留出。
- [ ] 每次从计划指定的独立初始输入开始，不继承同案例上一遍答案或人工修正版；全流程案例从素材走至所需正式出图，修改案例核对目标完成及非目标保留。
- [ ] 逐次保留所有尝试、原始成果、技术/内容/视觉结论、未知维度、人工修正、应用及正式出图结果；模型失败照实记录，基础设施无效单元只按预定重试规则补齐，缺少计划有效观测不得关闭本票。
- [ ] 独立审核人员在不知道生成过程自评的情况下对照核准真值和实际图片；记录关键错误误通过、分项差异和意见分歧，分歧解决后才形成案例结论。不能让生成者自评代替独立审核。
- [ ] 本分层 9 次有效观测及独立审核齐全，关键错误误通过为 0；模型业务失败本身不靠放宽标准变成成功，也不因存在模型失败否认已完整获得能力边界。
- [ ] 报告原始成功、人工补救后的交付、审核/修正分钟及全部尝试用量；unknown 不按 0，invalid 不从交付成本中消失，未成功订单不虚构单位成功成本。
- [ ] 保留首次冻结结果与全部后续事后分析。发现评分缺陷时停止宣称该集合通过，修复并另存重评分；已看结果且用于调优的案例转为校准/回归用途，不继续称独立泛化证据。
- [ ] 本票不修 runner、评分器、审核记录能力或资料策略；实现问题回到责任票。所有结果链接到同一总计划，最终总体分布由 26 汇总，不从 9 次观测推生产 SLA。

**测试接缝：** 固定候选的公开评估及 Agent CLI、审核/应用与正式出图入口；独立审核观察实际成果，不访问私有中间结构。
