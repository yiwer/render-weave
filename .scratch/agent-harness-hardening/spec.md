## Problem Statement

代建工程师已经能够从示例图提取数据定义与数据集、设计和修改模板、审核后正式出图，但还不能稳定回答三个问题：这份成果是否真的满足业务要求，应用的是否就是核准的内容，中断之后能否保留已有工作并可靠接续。

- **评分通过可能遗漏关键业务错误。** 已复现 366 停靠站点整表反序、多报站点仍通过现有评分判据；模板压测主要证明没有严重渲染问题，尚不足以证明换数据后的内容、顺序和状态正确。
- **审核依据可能在应用前变化。** 已复现相同图片资源追加新内容版本后，审核页仍显示旧预览并保留批准状态，应用却使用新资源，且不报告冲突。
- **中断保存尚未覆盖宿主崩溃。** 当前能在执行器结束后抢救候选，但宿主被强制结束时可能没有完整轮次记录；作者无法沿现有入口辨认和接续已完成工作。
- **长任务缺少宿主控制的完整边界。** 有轮数上限和硬额度停止，但缺整轮时间限制、可信检查点和无进展处置；最终结果也可能比中间候选退步。
- **评估尚不能充分说明新增能力与泛化。** 当前四场景来自两张中文线路牌；两版最新门槛都因额度原因未收齐。评估发起器未传可信参考或内容基准，因此四场景通过也不代表新版反馈闭环已验收。
- **维护者不能完整比较变更收益。** 续跑未严格核对实验身份，重试覆盖旧轮次影响成本核算；人工审核时间、全部尝试成本与交付率没有统一口径。

这些问题的代价是返工、审核失信、模型额度浪费，以及将未经证明的能力提前用于客户自助。当前技术校验、只读工具、可信参考、受阻草稿和来源留存都已有实现，本期是在这些能力上补缺口。

## Solution

让代建工程师获得一条可解释、可接续、可核验的工作流：固定本轮输入和资源 → 生成或修改工作副本 → 分项检查并保存完整候选 → 对照核准依据审核 → 在提交边界重新核对 → 应用并正式出图。任何停止都留下真实状态；任何质量结论都能指回被检查的内容。

### 交付分组与顺序

| 分组 | 交付结果 | 依赖与边界 |
|---|---|---|
| H1：可信判断 | 修正转录判据，加入模板反事实语义验证；明确未知与误通过 | 可以首先实施；不改变 DSL 语法 |
| H2：审核与应用一致 | 本轮资源固定、预览缓存与核准依据绑定、并发变化检查、应用中断可辨认 | 可以与 H1 并行；沿用已有资源版本能力 |
| H3：可复核实验 | 不可变实验身份、全部尝试留存、重新评分另存、完整成本口径 | 可以与 H1/H2 并行；是新版真实模型验收的前置 |
| H4：可靠执行 | 启动即落盘、不可变检查点、强退接续、整轮时间限制、取消和保守候选比较 | 使用 H2 的内容身份；复用已有硬额度停止 |
| H5：反馈与独立验收 | 带基准的真实纠偏、有限可见性检查、独立样式审核、冻结留出集 | 使用 H1/H2/H3；已有业务验收仍由原票据负责 |
| H6：效率与安全 | 全部尝试和人工成本报告、按需资料对照、素材注入回归、阶段 5 接入清单 | 使用 H3/H4/H5 的证据；扩展技术按收益试验决定 |

H1、H2 是最先交付的缺陷修补；H3 在后续真实模型验收前固定。不同分组可独立验收，但不能把部分完成描述为整个方案通过。

### 完成标准

1. 已复现的顺序/多报反例被准确拒绝；资源更新反例不能再用旧批准应用新检查内容，合法对照仍可完成。
2. 强退、取消、超时、硬额度停止后，可辨认最后完整候选并从新轮次接续；不伪造完成、批准或应用成功。
3. 评估可重复运行且不会混版，失败尝试和未知用量如实保留，原报告不被重新评分覆盖。
4. 原有四场景回归、带可信基准的真实纠偏、独立人工审核和留出集分别留证；相应证据不互相替代。
5. 下面 A01–A20 全部有结果；必需真实模型单元缺失时为未完成。留出集用于测能力边界，其运行完整不等于客户自助已获准上线。

## Implementation Decisions

### D01. 架构与范围

保留一个负责生成/修改的业务 Agent，宿主承担固定输入、最终校验、持久状态、预算与应用边界；模型调用循环继续复用现有执行器。当前本地应用仍经人工审核；未来共享写入按既有角色和租户策略控制，不增加永久强制审批。新增能力集中在任务宿主、审核应用、资源适配、比较器、评估编排与报告模块。阶段 5 的生产写入接口和托管工作台不在本期实现。

### D02. 同一份检查内容贯穿候选、预览、审核与应用

为每次检查记录不可变的内容身份：候选集合、依赖文档、请求、可信参考/内容事实、资源版本与实际字节、构建和判据版本。缓存与核准结论绑定该身份，不能只按文件名或工作区路径复用。固定范围涵盖图片、字体、后备字体和 SVG 字体；未使用资源不进入提交冲突集合。内容身份与模型运行配置分开：改变模型不会改变一份已有候选的字节，但会改变评估实验身份。

优先使用现有资源版本固定机制。旧清单目录在轮次内部保存可验证的私有资源副本及哈希，保持当前输入方式；不得借此修改原资源目录。资源字节损坏或缺失时明确失败，不静默读取当前版本替代。

### D03. 资源漂移和并发提交

审核期间以固定内容预览。应用前检查本次实际使用资源：版本仓库比较内容版本与字节身份，旧目录比较清单映射、资源种类和相关文件内容哈希；变化时返回逐项差异，使旧批准失效，并提供基于新资源重新检查、预览和审核的路径。工作区覆盖选项不能绕过这项检查。无关资源变化继续允许应用。

最后一次版本核对和提交必须在同一个短时并发控制边界内完成，参与资源替换和工作区应用的写入方遵守同一约束；按固定顺序取得所需锁或使用等价事务，长时间模型运行和渲染不占写锁。公开渲染、审核与应用读取工作区时协调同一提交边界，取得完整一致的输入副本后再做耗时计算；遇未完成提交须等待、先恢复或明确返回需要恢复，不能使用混合状态。并发冲突整体拒绝，不做部分候选提交。人工绕过接口直接改写磁盘不属于可保证事务的写入方，但应用前发现内容漂移仍须拒绝，后续读取须核查字节并拒绝损坏。

固定的是本次检查和提交依据；提交之后合法资源替换仍按原规则影响未来出图。在未来默认直发路径中，漂移要求重新检查；仅当租户策略要求批准时才重新批准。

### D04. 转录评分补齐顺序、数量与误报

按真值中的每次出现进行有序一对一匹配，记录替换、漏项、插入、错误重复、顺序违例、地标/设施漏报及误报；同名站点不是重复错误。匹配规则和歧义处理由评分器版本固定，报告对齐证据；不能任选有利对齐来隐藏歧义。

366 首期保留站名至少 57/59、地标至少 14/15、设施至少 17/18 的既有命中门槛，并增加已对齐站点顺序违例为 0、真实插入和超额重复为 0、地标与设施误报为 0。错别字按对应位置的替换计入站名容错，单个漏项不连带造成后续全部错位；无法区分替换与插入的匹配记歧义、不得自动通过。规则按案例真值和核准容错配置，不在通用领域资料中写入 366 答案。

### D05. 模板规则通过输出行为验收

对字段换值、列表增删/同名、模板参数、可选信息、长文本/尺寸和图片资源六类变化建立独立事实。通过实际文字、实例数、顺序、目标状态、可见性和允许变化范围判定。严重问题为零、图片哈希变化或内部变量值改变均不足以独立证明业务正确。修改任务同时检查目标完成和非目标保留；合法布局联动必须在案例政策中预先说明。

### D06. 评估实验身份固定

实验开始前固定执行器版本、请求模型、推理配置、端点身份、时间/轮数预算、构建、工具合同、提示词生成规则、静态资料与原始输入、评分器、配置、真值、参考和资源摘要。每次派发前另存实际提示词、读取资料及上游成果/检查点身份；响应后追加可获得的实际服务模型标识。这些是不可覆盖的尝试证据，不倒填为事先已知的实验条件。合法串联或反馈接续产生不同动态提示词，不单凭该差异拒绝续跑。端点身份不含凭据；提供方没有可固定模型修订时明确写不可固定，实际服务模型变化须标注，不能冒称条件完全相同或跨时间完全可复现。

相同实验标识续跑先比对当前条件，差异在派发模型前拒绝并列出；需要改变条件就新建实验。已完成的有效失败也保留为该次观测，不覆盖它直到得到成功；只补计划内无效或未运行单元。重新评分产生关联原尝试的新报告，原始报告和身份保持不变。并行数、开始/结束时间单列为调度条件；质量/成本对照同时固定调度条件，普通续跑允许调整并行数并记录，不隐藏这一差异。

### D07. 每次尝试不可覆盖

每次启动有唯一尝试标识，保存输入、日志、候选、停止原因、已知用量及结果，重试另建目录/记录。重启后先核对完成记录，避免重复派发与重复计量。已知上游瞬时错误沿用现有有限重试；硬额度停止派发，不自动等待、换模型或绕过限制。实验计划、尝试和最终评分分别表达；报告完整列出 pass、fail、invalid、not-run。对要求达线的门槛：任一计划内有效失败则整体 fail；无有效失败但缺少计划有效次数则 incomplete；全部计划有效观测达线才为 pass。执行完整性另列，已有失败不能被缺失观测掩盖；留出集另按 D13 报告能力分布。

### D08. 持久轮次状态与接续

在启动执行器前提交宿主记录和固定输入，区分准备、执行、收尾、完成、停止与失败。状态变化原子更新，关键事件追加留存；完成以成果检查与记录提交为准。执行状态、技术质量、内容/视觉结论、审核状态分别保存，不由一个布尔值互相推导。

通过现有接续入口开新轮次，引用旧轮次和完整检查点；不恢复供应商内部会话，不改写旧轮次事实。单轮次有独占执行拥有者；陈旧拥有者只能在确认原执行器不可继续写入后接管，不能仅因时间过去便并发恢复。历史完整轮次继续可读；记录不完整或身份无法确认时只展示诊断，进入显式恢复流程，不补造正式成果。

### D09. 检查点与应用中断

检查点保存一次显式检查所消费的完整候选集合、不可变字节、哈希、核准基准与结果，由宿主生成。完整候选集合的 `check_outcome` 每次成功完成检查后，宿主须发布与该检查实际消费字节一致的检查点，并提供可观察的保存完成状态；“检查执行完成”不要求业务合格，结构完整但语义受阻的草稿也可留存。必须先固定字节并检查保存副本，再原子发布记录；后续修改不改变它。半写、缺少依赖或读期间变化不发布新检查点，也不因目录中文件均可解析就推断整组修改已完成。未经显式集合检查的零散新写入不能顶替上一检查点。MCP 检查/比较工具继续只读，持久化由宿主承担。

本地应用另保存提交意图和可恢复记录。提交前中断不能改变工作区；提交中中断须能恢复为完整旧状态或完整新状态，并明确最终结果；不能宣称多个文件系统操作天然是一个原子事务。同一已成功提交标识再次执行返回已有结果，不重复发布或保存。恢复遇到外部新改动时停止并报告，不能用旧备份覆盖新内容。托管时复用服务事务，不将本地文件恢复机制当作多人生产数据库。

### D10. 时间、取消与停滞

保留各任务现有默认轮数；首版整轮墙钟时限默认 60 分钟，可显式配置正值。计时从启动执行器前开始，覆盖模型、工具、正常最终检查；输入校验与准备在启动前完成。耗时终检和渲染必须处于可强制终止的子进程或等价受限边界，不能只靠可能被同步计算阻塞的宿主定时器。触发时停止本轮新请求并终止执行器及该轮耗时检查，单独给予最多 30 秒本地保存宽限；宽限结束仍不能提交完整记录时保留可恢复状态。默认值是工程保护值，不是业务时延承诺。

超时、用户取消、硬额度、执行器失败和宿主恢复分别记原因，复用统一保存/清理路径；普通 429/5xx 不归为硬额度。首版只硬限制时间和现有轮数；token、费用统计所有已知尝试，缺失为未知。缺少实时可控计量的适配器不接受硬 token/费用上限配置，不把结束后的统计伪装成运行时限额。

停滞只处理尚未正式交回、仍有非空核准必修问题的机械重复：获得完整修复机会后，同一基准和候选连续两次完成检查仍无变化，或连续两次完整修改/复测周期中必修问题均无改善且无其他已核准进展。宿主终检、交回自检、分页、诊断复读和合法重复确认不计；任务完成条件已满足时进入交回流程。文件正在变化、基准改变或证据不足时不计。无可信比较依据的任务只依赖时间和轮数边界；不凭模型自评停掉任务。阈值可配置且计入实验身份。

### D11. 保守保留候选

分别保存最后完整候选与有证据更好的候选，仅在相同请求、数据、资源、参考、修改政策与判据下比较。新候选必须保持技术硬约束和修改范围，不增加关键缺失、已知异常或未知范围，并至少改善一项核准指标，才可替代“有证据更好”候选。维度互有得失或没有可信基准时标为不可排序，不输出总分选胜。

最终正式交回仍以 Agent 显式提交为准；如它相对保留候选退步，宿主显示两者与差异，不暗中替换提交。停止后可从保留候选开新轮次；宿主恢复草稿继续不可直接批准/应用。较好候选含义不等于业务已全部合格。

### D12. 反馈范围与最终可见性

复用现有可信区域、真实内容图、实例/源模板定位、分页与分项偏差。模型末次反馈和宿主终检必须针对同一候选及检查身份；变化后重新比较，旧报告不能作当前证据。真值由操作者核准，模型只可提出建议，不能改核准基准或通过规则。

首版新增可见性测量限于无复杂变换的轴对齐对象：已知画板裁切、累计透明度为零，以及由后绘制、累计不透明且实心的矩形实际覆盖区域造成的完全遮挡。覆盖判定核对绘制顺序、父级透明度和实际裁切，不以元素包围框代替绘制区域；空心/仅描边形状、图片透明孔洞和文字不凭包围框认定完全遮挡。在承诺范围内必须实际识别反例，不能全部退回未知。部分遮挡、其他遮挡形状、复杂裁切/变换、混合透明度、低对比和感知可读性保持按维度未知，交由独立审核；不设未经校准的通用对比度或相似度通过线。图片内容是否正确由核准资源/参考和独立图片反例检查，不能仅凭资源名称判断。

技术合格、可信内容、已测视觉维度分别给结论；未知不进入已通过分子，所需范围有未知就不能判整体通过。原先无条件保留的未知只能在对应测量有证据后局部消除。

### D13. 三套验收与留出集

离线行为反例验证判据与系统边界；原有四场景验证产品回归；新增可信反馈集显式传入参考/内容基准。原有场景按新评分器在固定构建下预先登记每场景两次有效观测，任一有效失败不能靠覆盖重跑消失。

可信反馈首批为中文/英文各四类任务：数据定义提取、数据集提取、模板辅助设计、模板辅助修改；每类预先登记两次有效观测和相同预算。模板任务带可信区域，提取任务带可信内容事实；至少一个模板任务超过 20 区域且后续页有必须处理的问题。任务须从已知可修缺陷出发核查修正、范围与未核实部分，工具调用发生本身不是成功条件。已有真实场景证据满足同一身份与标准时直接引用，不重复消耗额度。

另冻结 12 个公交业务案例，横版线路牌、竖版线路牌、整站牌、双语站名牌四个分层，各 3 例、各运行 3 次；至少 8 例走素材到正式出图全流程，其余覆盖模板修改。来源与哈希见 [候选登记](holdout-candidates.md)。同一家族的多例可以测同类业务差异，但不算多个独立家族；原图、裁切、退化图在同一分组。按实际家族与校准/资料策略试验隔离，已用于调优或独立性无法证明的家族只作回归，报告其数量和边界，不用 12 张图片声称 12 个新家族。固定案例、真值、预算和计划之后才运行，所有结果均保留；不自动以其他图替换用户素材。英文只核对素材中的英文站名、标题及明确核准的字段，不由双语站名推论英文线路全流程能力；本留出集不提供价签或跨业务泛化证据。查看结果并用于调整资料、策略、模型或规则后，该集降为校准/回归用途；下一次独立泛化验证须使用未参与调整的新家族。评分器缺陷修复允许另存事后重评分，保留首次结果并标明事后分析，不作为新增独立样本。

留出集要求 36 次计划及独立审核证据齐全、没有关键错误被系统宣称通过后漏放；模型失败如实列出并分析，不因集跑完宣称客户成功率达标。本期不设未经基线校准的生产成功率承诺。独立审核人员在不知道生成过程自评的情况下看真实成果，分别记录原始质量、人工修正、应用与正式出图结果；意见冲突保留并解决后才能标明该案例结论。

### D14. 成本、观测与证据保留

沿用已有提示词、资料原文、构建和工具日志，补全任务/轮次/尝试/候选/报告的关联标识及各阶段时间。分别记录总墙钟、各轮耗时求和、输入/输出、缓存读/写、输出内 thinking、工具调用和大小、停止原因、审核/修正分钟。thinking 不重复计入 output；未知用量不按 0 相加，给出已知小计与未知尝试数。

报告分别给模型质量和交付可用性：invalid 可从模型有效观测分母剔除，但保留在交付/成本口径中。按成功应用并完成所需正式出图的订单统计所有尝试和人工投入；无成功订单时单位成本未定义。金额只有提供方计价版本与完整用量可获得时才估算，否则显示原始用量。来源留存不含凭据；可分享摘要去除原图敏感内容和不必要的本机路径，完整业务材料保留在访问受控的轮次目录。

### D15. 上下文与扩展技术的对照

保留强制约束与资料目录，试验按阶段读取 DSL 参考、局部问题聚类、按需区域证据；与现有全量资料在同一模型、预算、样本和调度条件下配对比较。实验开始前登记主收益指标、最低有用改善及质量守卫；没有净收益或关键质量退步则保留当前默认。已有 effort 决定不改，不因本期成本治理自动改为 low。

独立视觉评审、OCR 草拟区域、结构约束输出与模型路由属于后续有条件试验，记录失败占比和收益后再决策；不成为当前默认运行依赖。OCR 与 DSL 展示能力继续由已有票据承担。新 DSL 写法不是本期目标。

### D16. 信任边界、兼容与发布

以正常任务和对抗素材成对验证：示例图、数据字段、资源名称、旧轮次内容中的指令不能扩大路径访问、读取凭据、修改可信参考、篡改检查记录或绕过应用。限制通过宿主和工具执行，不只靠提示词或 MCP 注解；评价正常任务效用，不能拒绝所有内容来通过安全检查。

工具行为变化按现有合同升版，合同、资料、样例同步；明确新记录格式和旧记录读取规则。缺少完整身份的旧轮次只按已有可证事实显示，应用前用当前内容重新检查并重新取得所需核准，不补造历史资源版本。旧报告保持原样，新判据另存结果；新旧构建不混合验收。阶段 5 开放写工具和托管时仍须按原决定补租户权限、审计、回退、容器、网络和凭据隔离，本期本地通过不能替代该验收。

## Testing Decisions

### 接缝与方法

以用户确认的现有公开 Agent/CLI 路径为主接缝，观察文件成果、退出码、问题清单、审核状态和正式图片。资源提交/替换、公开渲染/比较与真实 MCP 协议是同一业务路径所需的既有次接缝；不为每个内部模块新开测试接口，不以函数调用次数或私有数据结构证明完成。

先复用现有假执行器驱动产品入口验证失败、半写、用量和恢复，再用真实模型验收任务能力；假执行器不证明模型会使用新反馈。进程故障从 CLI 启动并终止受测宿主，资源竞态从公开替换与应用入口制造。时间测试设置短预算，使用足够的操作系统调度余量，验证有界结束而非精确毫秒。只测可观察结果；需要方便注入的环境接缝时应位于整个执行器/资源边界，不暴露私有计算步骤。

已有先例包括 Agent 轮次与审核应用测试、MCP 合同/路径逃逸测试、视觉比较与终检一致性测试、资源版本/替换测试、评估 CLI 重新评分测试，以及中英文受控视觉验收。测试准则继续遵守仓库编码约定；具体参考入口见 Further Notes。

“关键错误误通过”指系统在其声明已核查的必要范围内判通过，而独立真值确认存在关键内容错误、错误顺序、未授权改动或不可见关键内容。未知不等于误通过，但阻止对应范围宣称全过。对已承诺支持的能力，全部回答未知也不能通过验收。

资料、工具合同或模型相关行为改变后，必须完成与实际版本对应的模型评估；先合并离线能力不表示已完成模型验收。新规则评分失败是需要处理的结果，不通过放宽阈值维持旧绿灯。留出集失败应留作能力边界，若发现评分误通过则先修评分体系并另存重评分结果。

## Out of Scope

- 重新实现 Claude Code 的通用工具调用循环，或引入常驻 planner/generator/evaluator 多 Agent 框架。
- 阶段 5 人类页面、共享写入端点、在线工作台与托管调度；本期只保持兼容约束并列出前置验收，不代替其规格。
- 新 DSL 运算/语法、文本塑形或双向排版、阿拉伯文还原；语言范围遵守中文/英文决定。
- OCR 正式接入、自动批准模型生成的真值、训练感知评分模型、SSIM/LPIPS 等整体相似度放行阈值。
- 默认启用新的模型路由、独立视觉评审或约束解码服务；这些需要各自收益证据。
- 当前适配器无法执行的精确硬 token/费用上限，以及远端已开始生成的即时停止计费保证。
- 跨任意手工磁盘写入或恶意宿主操作的分布式事务保证；面向真实客户托管的端到端安全认证。
- 用本期工程评分或有限样本推出生产成功率承诺；自动修改平台额度或无授权反复消耗模型额度。
