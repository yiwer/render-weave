# Agent harness 实施票拆分方案（已确认）

2026-10-23。依据[已定 PRD](spec.md)拆成 **26 张新票**，每张均有独立文件、完整验收条目及公开测试接缝。用户已确认按本方案发布，正式票据见[实施索引](README.md)；进度与状态以各票据为准。父 PRD 保持原文，既有票据保留原勾选与历史结果。

采用这个粒度：完整审核资源闭环一票，并发与崩溃恢复另拆；运行状态、检查点、预算、候选比较各自可演示；资料准备与配对实跑分开；留出执行按四个公交类型分层拆开，单票 9 次观测。每票先做必要的小范围预重构并保持旧行为可用，再交付新行为；没有证据需要先开一个横跨仓库的大重构票。

## 依赖与真实模型安排

- 初始可并行的前沿是 **01、02、03、06**。按仓库领取规则，优先取 01；03 可并行修审核资源一致性，06 尽早建立评估身份。编号只表示依赖顺序，不表示所有票必须串行。
- 03 → 04 → 05 是审核应用线；03 → 08 → 09 → 10 → 12 是运行恢复线，11 从 09 分支；06 → 07 是评估记录线。
- 18 使用校准集完成资料策略对照；19 可独立准备留出材料，不向 18 暴露答案。同族案例不增加独立家族数；已知校准家族只作回归，独立泛化未知，不用同图裁切冒充新家族。
- 20 只在影响行为的实现与资料策略决定完成后冻结候选。21 与原 38 随后使用该候选做真实验收；22–25 等二者完成后并行，避免验收中调参污染留出。26 只做真人走查和证据收口。
- 机制票使用公开入口和假执行器验证自己交付的行为；真实模型条目只归对应运行票。每张实现票自行同步涉及的合同、资料和兼容处理，不拖到 20/26 再补。
- 计划内有效失败不能覆盖重跑到成功，硬额度停止，不自动轮询或切模型。相同条件和标准的历史证据可引用；条件不匹配不能为了省额度拼接。

- 原 18、20、33、34 的业务责任不复制；原 31、32、35 作为已有基线回归。原 36、37 不是本期依赖。
- 原 20 的遗留参考指向由原票修，17 的自动检查应明确报告它；按需资料候选使用公开工具已可达的资料。原 20 的整票关闭不阻塞 17，否则其真实模型验收与新候选冻结容易形成循环；本拆分不代替它修改或关闭原验收条目。
- 未把“原 33/34 已关闭”当成测量/编排机制的前置；所需实际业务审核由原 38 留证。历史阿文专属项不恢复为本期门槛。
