## Answer

2026-10-14 已完成。

**成果**

- **人读参考** [docs/dsl/template.md](../../../docs/dsl/template.md)：
  - 文件结构；变量（运算数、参数、派生变量、检查项）；可绑定与不可绑定属性表；状态样式；
  - 画板；三种布局与位置；13 种元素；
  - 文字（片段、展示格式、对齐、适配与缩字组）；循环与合并；调用；
  - Schema 之外的检查、已知限制、S1–S31 对应表。

  另有 [docs/dsl/requests.md](../../../docs/dsl/requests.md)：渲染请求、批次请求、示例、检查与限制。
- **示例**：会议胸牌四个模板（标准胸牌、场次行、标签格、会场格），用到 13 种元素、三种布局、状态样式、合并循环与调用。先在临时工作区实际出图核对，90 × 130 mm、120 DPI 下 0 问题，再原样嵌入参考。
- **JSON Schema 2020-12**：
  - `schemas/template.schema.json`：元素按父布局分三种变体约束 `place`，并按 type 分别约束属性与可覆盖的键；
  - `render-request.schema.json`、`batch-request.schema.json`：两者各自内嵌数据集文档结构。
- **Agent 参考** `agent/reference/template.md`：
  - 示例换成精简胸牌（标签格、简易胸牌）；
  - 去掉了线路牌词汇（`terminal`、`hasLandmark`），以及"码元素一般用不到"的说法；
  - 验证脚本改为读取它，旧的 `scripts/m190/template-reference.md` 已删除。
- **公开入口**：`checkDslDocument` 与新导出的 `dslDocumentKind` 识别全部五种文档；批次请求的逐项问题改写到 `items[n]` 位置。

**一致性测试**（`test/dsl-template-schema.test.ts`，22 项；语料收集抽到 `test/support/dsl-corpus.ts`）

- **语料**：模板 21 份（全部有效，6 份来自文档）、渲染请求 14 份（11 份有效）、批次请求 6 份（5 份有效）。
  - 引擎接受的都通过 Schema；Schema 接受而引擎拒绝的，只落在列明的语义类别里。
  - `m402-mixed-batch-request.json` 故意含一个像素超限项。
- **变异**：模板 108 种、渲染请求 13 种、批次请求 9 种结构错误。每种都至少用到一份语料，全部被 Schema 与引擎同时拒绝。
- **语义检查清单**（只看一份文档）：元素名称重复、网格行列越界、尺寸上下限颠倒、参数约束或缺省值不合规、展示格式不合法、状态样式覆盖后不合规、出图像素超限、渲染项标识重复，各有用例。
  - 状态样式这一类按"去掉所有 states 后问题消失"精确判定，不按问题代码粗放归类。
  - 需要其他文档的类别（变量未声明、类型对不上、调用基准不符、参数缺失等）在参考中列出代码，由现有静态检查与渲染测试覆盖。
- **参考示例**：
  - 人读参考的标准胸牌按正式模式出图 0 问题，`requests.md` 的渲染请求示例照样出图；
  - Agent 参考的简易胸牌 0 问题；
  - 两份模板参考都覆盖 Schema 中全部元素类型与属性关键字。
- **能否变红已验证**：临时撤回 `base` 多余键的收紧，测试立即报"base 上未知键：Schema 拒绝，引擎接受"，已还原。

**验证**：`npm test` 33 个文件 / 659 项通过（本票新增 22 项）；`npm run typecheck`、`npm run build` 通过。共享 M402 样例、码图样例与出图记录重放的测试全部通过，样例文件未改动。

**偏差与说明**

- 解析器按 M224 收紧了一批写法：把 `null` 当作"没写"的、静默忽略多余键的，都改为报错。仓库语料中都没有这些写法。
- 批次请求没有格式标识。此前规格、本票与 ADR-0016 把 `renderweave-batch/1` 写成批次请求的标识，实际上它是交付后批次清单的标识，已改正。
- 模板 Schema 是用一次性脚本生成的（脚本未入库），之后以 JSON 文件为事实源手工维护。
