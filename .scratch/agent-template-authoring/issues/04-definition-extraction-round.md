# 04: 一条命令发起数据定义提取，拿到可校验的成果

**What to build:** 代建工程师用 `renderweave agent run --task 数据定义提取 --sample … --brief … [--domain …]` 发起一轮，在独占的轮次目录里得到 `outcome.json`、候选文件，以及 RenderWeave 重新校验的结果。

**Blocked by:** 03

**Status:** ready-for-agent

**Trace:** 第三阶段 PRD；用户故事 1–6、16–18；验收 A05、A06。

- [ ] 按 ADR-0015 启动 Claude Code：
  - 受限模式，空白环境，独立配置目录，只连 `renderweave mcp`；
  - key 只从环境变量读取；
  - 模型与端点可配置，缺省为千问 token plan 的 qwen3.8-max。
- [ ] 轮次目录组装三层资料（通用指南、领域约定、项目说明）、DSL 参考与示例图；提示词不含具体业务。
- [ ] `outcome.json` 合同包括：
  - 任务类型与轮次；
  - 基于的输入：示例图哈希、工作区指纹；
  - 候选文件；
  - 待确认项：位置、候选值（可空）、原因（M44 四类）；
  - 说明与用量：用时、轮数、token。
- [ ] 先做结构校验，再用引擎校验候选；不合格时给问题清单，用退出码区分，不自动重试。
- [ ] 隔离测试：子进程环境中没有宿主的 `CLAUDE_*`、`ANTHROPIC_*` 变量；在全部产物中搜索 key，0 命中。
- [ ] 只给图片、没有指定数据定义时，命令提示先做数据定义提取。
- [ ] 不依赖模型的测试：用构造的 `outcome.json` 与候选覆盖合格、不合格两条路径。另在本机用真实 key 跑一次 M402，并记录结果。

**测试接缝：** 公开 CLI 与成果校验入口。模型调用可以替换为读取预置成果的假执行器，用来测试流程。
