# 07: 带反馈的下一轮与模板辅助修改

**What to build:** 代建工程师可以带着反馈发起下一轮，也可以对已保存的模板提出修改要求，拿到工作副本、结构化差异与修改前后的预览，审核后应用。

**Blocked by:** 06

**Status:** resolved

**Trace:** 第三阶段 PRD；用户故事 14、15；验收 A09。

- [x] `--from <上一轮> --feedback <文件>`：下一轮拿到素材、上一轮成果（含审核时的修改）与反馈（M58）。每轮一个独立目录，轮次链可查。
- [x] 模板辅助修改：输入为已保存的模板与修改要求，要求可以带元素路径；成果为工作副本（M49）与结构化差异。
- [x] 审核页显示修改前后的预览，两者都由 RenderWeave 渲染（M50、M52），同时显示差异。
- [x] 应用前比对工作副本所基于的保存内容。模板已被他人保存时显示差异，由人选择覆盖或重做（M51）。
- [x] 以用户在 M215 验收时指出的两类问题（地标位置、道路名分布）作为修改要求，一轮内修正，并通过对应检查。

**测试接缝：** 同 05；差异与预览以接口输出断言。

## Answer

2026-10-15 已完成。

**成果**（说明见 [docs/agent-tasks.md](../../../docs/agent-tasks.md#模板辅助修改)，决定见 M229）

- **带反馈的下一轮**：`agent run --from <上一轮> --feedback <反馈.md> --out <新轮次目录>`。
  - **输入**：任务、素材、基准、出图请求与修改要求都沿用上一轮，命令行不能再给；工作区重新取快照。
  - **上一轮成果**：按上一轮的 `review.json` 作用审核时的修改，放进 `candidates/` 作为起点；原样记录放进 `previous/`，反馈放进 `docs/feedback.md`。提示词另接 `agent/tasks/next-round.md`。
  - **可作为上一轮的**：审核通过、不通过、还没审核的轮次都可以；结构不合格的轮次给当时交回的文件与问题清单。
  - **轮次链**：`round.json` 的 `previous` 记录上一轮的目录、轮次、成果与审核结果的哈希。审核视图与公开入口 `readRoundChain` 列出整条链，某轮目录不见时链在那里断开。
- **模板辅助修改**：`agent run --task 模板辅助修改 --request <出图请求> --requirement <修改要求.md> --workspace <工作区>`。
  - **工作副本**：出图请求的主模板及它调用的已保存模板，原样复制进 `candidates/` 作为工作副本，并记录各自所基于的文件名与内容哈希（M51）。
  - **修改要求**：反引号里以模板名开头的元素路径必须找得到，只在第 1 轮核对。
  - **成果**：只列改过的与新建的模板；调用树以外的已保存模板不能改；与已保存相同的工作副本只记提示。
- **结构化差异**（`src/agent/diff.ts`，公开入口 `diffTemplate`）：
  - 由 RenderWeave 比对得出，不靠 Agent 自述；
  - 元素按元素路径配对，子元素换序单独列出；
  - 参数、派生变量与检查项按名称比对；
  - 写进 `check.json`，审核视图按审核后的工作副本重新计算。
- **审核**：
  - 修改前（已保存模板）与修改后（工作副本代替同名的已保存模板）两张预览，都由 RenderWeave 渲染，与示例图三图联动；修改后的严重问题阻止通过；
  - 模板卡片有改动表；
  - 轮次区列出轮次链、修改要求与反馈。
- **应用**（`src/agent/write-files.ts`）：
  - 工作副本整份替换当前保存这份模板的文件；
  - 先排他创建新文件，再逐个替换，任一步失败都删去新文件、恢复被替换的文件；
  - 要改的模板已被他人保存时，列出他人自基准以来的改动并拒绝。由人选择 `--overwrite` 覆盖，或 `--from` 重做；重做时候选从最新保存的内容开始。
- **预重构**：`AgentUsageError` 与工作区指纹移到 `src/agent/round-files.ts`，避免发起与审核两个模块相互引用。

**不依赖模型的测试**（`test/agent-rounds.test.ts` 13 项）

- **下一轮**：
  - 拿到素材、上一轮成果（含审核时的修改）、原样记录与反馈；
  - 工作区重新取快照；
  - 第 3 轮的链追到第 1 轮，目录不见时断开；
  - 上一轮结构不合格时，拿到当时的文件与问题清单；
  - 拒绝的情形：再给沿用的输入、没带反馈、上一轮的审核结果不合格。
- **模板辅助修改的发起**：
  - 9 种输入错误；
  - 调用树中的模板预置为工作副本，并记录基准；
  - 提示词、工具与轮数上限。
- **成果**：
  - 结构化差异；没改的只记提示；
  - 新建模板可以，调用树以外的模板不能改；
  - `diffTemplate` 的配对、换序与按名称比对。
- **审核**：
  - 修改前后的预览与直接渲染的结果逐字节一致；
  - 改动工作副本后，差异与修改后的预览随之更新。
- **应用**：
  - 替换已保存的模板，没改的不写，之后正式出图；
  - 应用后的下一轮从最新内容开始；
  - 上一轮把元素改名并应用后，修改要求照样沿用；
  - 模板已被他人保存时列出他人的改动并拒绝，重做与覆盖各自生效；
  - 只有无关文件变化时，不列模板冲突；
  - 新文件名被占用时撤回；Windows 上第二个替换失败时，恢复第一个。
- **能否变红已验证**：临时让以下 7 处失效，相应用例都失败，之后已恢复：
  - 审核时的修改带给下一轮；
  - 修改前的预览只用已保存的模板；
  - 检查模板是否被他人保存；
  - 替换失败时恢复；
  - 判断基准是否已变；
  - 没改的工作副本不写；
  - 调用树以外的模板不能改。

**偏差与说明**

- **第 1 轮多改了一处**：Agent 把道路段的宽度上限从 400 改为 1500，修改要求里没有这一条。它修复的是首测模板已有的 2 站严重问题，改动表里看得到，审核时接受。
- **实跑中发现并修复的问题**：
  - 审核页的改动表被渲染成 "[object …]"；
  - 宽幅图查看区留白过多、窄窗口横向溢出；
  - 下一轮沿用修改要求时，又按应用后的模板核对其中的元素路径，导致第 2 轮第一次发起被拒。

  三处都已修复，第三处先补了回归测试。
- **1500 mm 宽的顶栏**：顶栏元素仍按 740 mm 的位置排列。没有宽画板的设计稿可依据，反馈要求其余保持不变，Agent 在说明中写明，留给有设计稿时再改。
- **实跑用的资料暂放位置**：修改要求与反馈暂放在 `scripts/m190/scenarios/m402/product/`，票据 08 与项目说明一起归入 `agent/briefs/`。
