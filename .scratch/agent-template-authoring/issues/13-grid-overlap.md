# 13: 网格的比例列、跨行列元素与超出单元格不再静默重叠

**What to build:** 网格里的元素不再悄悄画进别的单元格。随内容测量的网格保持比例列的比例且放得下内容；跨多条随内容轨道的元素能撑开这些轨道；元素仍比所在单元格大时报问题，与堆叠布局放不下时一样。

**Blocked by:** 无

**Status:** resolved

**Trace:** 与 design-layout-draw 网格的对照（2026-10-18，见下「背景」）；ADR-0016（1.x 的兼容承诺）；`CODING_STANDARDS.md`「测试」；验收 A01、A02、A03。

背景：网格的三种轨道（固定、比例、随内容）与 design-layout-draw 的 `"100"`、`"n*"`、`"auto"` 对应，种类不缺。对照时实测出三处元素重叠、问题清单为空的情形：

- **随内容测量的比例列**：网格所在的框是随内容时，测量把比例列按随内容算，排列时又按比例重分（`src/layout/index.ts` 的 `resolveTracks`）。1:3 两列各放一个 5 mm 宽的字，测得总宽 10 mm，排成 2.5、7.5 mm，两个字重叠。
- **跨列元素不参与随内容轨道**：随内容轨道只看只占这一条的元素。两条随内容列加一个跨两列的六字标题，单元格 6 mm，标题画了 30 mm，伸进第三列。
- **元素比单元格大不报问题**：10 mm 的列里放 18 mm 的固定宽块，盖住右边的单元格。堆叠布局里同样的情形报 `layout.contentOverflow`。

影响面（2026-10-18 用临时日志统计后已移除）：全量测试 763 项、Agent 评估六次的轮次重新评分、价签与 366 的批次、M162 的两版模板，三种情形都没有出现。Agent 写的 51 个不同模板里只有 6 个用了网格，没有随内容轨道，也没有跨行跨列的元素。

- [x] 随内容测量时，比例轨道按比例放大到都能放下内容：每份的尺寸取各比例轨道"内容 ÷ 份数"的最大值，轨道尺寸 = 每份 × 份数。实际排列得到同样的尺寸，比例不变，元素不重叠。参照 CSS Grid 的 `fr` 在不定尺寸容器中的做法。
- [x] 跨多条轨道的元素：
  - 只跨固定与随内容轨道时，放不下的部分平均分给它跨到的随内容轨道；先处理跨度小的元素；
  - 随内容测量时还跨了比例轨道，按上一条把它计入"每份的尺寸"（扣去所跨非比例轨道与间距后，除以所跨份数之和）；
  - 只跨固定轨道，或在确定尺寸下跨比例轨道时不撑开，放不下的按下一条报问题。
- [x] 元素连同 `margin` 比所在单元格（含跨行跨列）宽或高时，报 `layout.contentOverflow`。位置是网格容器，与堆叠一致；说明里写元素名称、需要的尺寸和单元格尺寸。网格中没写宽高的元素缺省填满单元格，不受影响。
- [x] 兼容：
  - 已有的 golden、布局快照、M402 共享样例与已有出图记录的重放结果不变（A01）；
  - 这次修的是原本就会重叠的出图，写法不变。需求记录用 M 编号写明它与 ADR-0016"出图结果不变"的关系，在 ADR-0016 补一段修订，DSL README 的「1.0 之后的加法」改名为「1.0 之后的变化」并记一行。
- [x] 测试：
  - 背景里的三种情形先写成失败的测试，看着变红，修好后变绿；
  - 另覆盖跨行（纵向）的同类情形、跨度不同的元素先后处理、`margin` 计入超出判断；
  - 测试从 `src/index.ts` 的 `render` 进入，断言元素坐标与问题清单。
- [x] 参考：人读参考「布局与位置」的网格条目写明比例轨道在随内容时的取值、跨行列元素怎样撑开随内容轨道、超出单元格报问题；Agent 参考的网格行同步一句。改了 Agent 参考就按 M230 跑 Haiku 评估门槛，连续两次达线。

**成果**

- `src/layout/index.ts`：
  - `resolveTracks` 按 CSS Grid 的做法重写：随内容轨道先取只占一条的元素；跨多条、不跨比例轨道的元素按跨度从小到大，把差额平均分给所跨的随内容轨道；比例轨道在确定尺寸下分剩余空间，随内容测量时每份取"扣去所跨非比例轨道与间距后 ÷ 所跨份数"的最大值。只在影响轨道尺寸时才测量元素内容，没有多出的测量。
  - `gridBoxes`：元素连同 `margin` 比所在单元格大时报 `layout.contentOverflow`，位置是网格容器，说明里写元素名称、需要的尺寸与单元格尺寸。
