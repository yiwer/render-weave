# 19: `view_image` 缺省不再把小区域放大到 1400 像素

**What to build:** `view_image` 缺省最多放大 2 倍，另加可选 `scale`（1–4）让 Agent 需要时再放大；366 这类分段读图的图片 token 明显下降，转录成绩不降。不做多区域拼图。

**Blocked by:** 无

**Status:** resolved

**Trace:** M217（局部放大）、M234（`res:资源ID`）；2026-10-19 [外围工具复核](../../../docs/agent-tooling-review.md) P2-4，[二次复核](../../../docs/agent-tooling-evaluation.md#票据-19) 推翻原方案并改写；验收 A11。

背景：

- 现在每次查看都放大到最长边约 1400 像素、最多 4 倍（`src/mcp/tools.ts:40-41`、`src/mcp/tools.ts:317`）。366 评估里 Agent 用 460×520 的竖带，输出 1238×1400，放大 2.69 倍。
- Haiku 5.5 按输出像素计费，不降采样：8 张 1238×1400 的图约 18.9k tokens，约等于像素数 / 750（[实测](../../../docs/agent-tooling-evaluation.md#实测-1看图的倍数与拼图)）。
- 原方案（`regions` 拼成一张 contact sheet）的两条依据都不成立：
  - "61–63 张图片报 400"是 Step 5 Preview 经代理时的现象（`docs/stage3-acceptance.md:244`），这个模型已停测、OpenAI 格式不再支持（M232）；Haiku 5.5 单轮最多 34 张图没有报错，Gemini 4 Argon 的两次门槛评估也没有这类错误（`docs/agent-eval.md:131`、`docs/agent-eval.md:141`）。
  - Agent 本来就一次并行发 4–6 个 `view_image`：366 数据定义轮 18 次模型请求里 12 次带多个工具调用，拼图省不了几次请求。
- 同一批 8 条竖带的转录实测（经产品同一路径：无头 Claude Code + MCP + OpenCode Go 上的 Haiku 5.5，各 2 次）：

  | 方式 | 每张输出 | 8 段的图片 tokens | 站名正确（/59） |
  |---|---|---|---|
  | 原分辨率，8 张 | 460×520 | 约 3.5k | 59、59 |
  | 放大 2 倍，8 张 | 920×1040 | 约 10.9k | 59、59 |
  | 现行 2.69 倍，8 张 | 1238×1400 | 约 18.9k | 59、59（试跑 58） |
  | 原分辨率拼成 1 张 | 1876×1052 | 约 2.7k | 53、54 |
  | 1.5 倍拼成 1 张 | 2796×1572 | 约 3.1k（服务端已降采样） | 52、56 |

  放大没有提高准确率；拼图同样像素却掉到通过线（57）以下，错法正是评估里见过的漏字、多字（"坪山区委区政府"写成"坪山区委政府"）。

**决定**：

- 缺省倍数上限由 4 改为 2：`scale = min(2, 1400 / 最长边)`。只看 2 倍而不直接改 1 倍，是因为实测只覆盖站名，设施图标与地标这类小标记没有单独测。
- 新增可选 `scale`（1–4，数值）：写了就按它放大，仍受最长边 1400 像素约束；工具说明写明"缺省最多 2 倍；小字看不清时再用 `scale` 放大"。
- 不做 `regions` 拼图：上表的实测说明它会降低转录准确率。
- 合同：新增可选参数、改变缺省输出尺寸，按 `docs/mcp.md:109` 升版本，与票据 17、18、22 同批发 0.6.0，只跑一次评估。
- 评估要看：366 站名、地标、设施三项都不低于近三份报告的最低值；记录 366 两轮的 `cacheReadTokens` 与 `view_image` 平均输出像素。要是设施或地标掉了，缺省改回 3 倍再跑。

- [x] 省略 `scale` 时最多放大 2 倍；写 `scale` 时按它放大，最长边仍不超过 1400 像素。
- [x] 原 `region` 与省略参数的整图行为、`res:资源ID` 与越界裁切不变。
- [x] `scale` 越界（小于 1 或大于 4）是工具错误。
- [x] 合同测试与 `docs/mcp.md` 更新；全量 `npm test` 通过。
- [x] 同批评估：366 三项不低于近三份报告的最低值，记录图片 token 的变化。

**测试接缝：** `test/mcp.test.ts` 经 JSON-RPC 调 `view_image`，用 `fixtures/resources/images/` 的样图，断言返回的 `scale` 与 `output` 尺寸。

**不在本票：** `list_resources` 的资源缩略图；资源图标一般只有 96×96，现在放大 4 倍到 384×384，约 200 tokens 一张，不是成本来源。

## Answer

2026-10-20 完成，与票据 22、29 同批发合同 0.6.0（M272）。

- **代码**（`src/mcp/tools.ts`）：缺省 `scale = min(2, 1400 / 最长边)`；新增可选 `scale`（输入 Schema `minimum: 1, maximum: 4`，越界是参数不合规），仍受最长边 1,400 像素约束。工具说明写明"缺省最多 2 倍；小字仍看不清时用 scale"。
- **用例**（`test/mcp.test.ts`）：
  - 50×50 区域缺省输出 100×100；整图 200×100 输出 400×200；
  - `scale: 4` 输出 200×200，`scale: 1` 输出原尺寸；`scale` 为 0.5 与 5 都是工具错误；
  - `res:` 资源与 SVG 同样按 2 倍；工具清单快照更新。
- **同批评估** [2026-10-20-contract-060](../../../docs/agent-eval/reports/2026-10-20-contract-060.json)，门槛通过：
  - 366 站名 58、59，地标 15/15、15/15，设施 18/18、18/18，三项都不低于近三份报告的最低值（站名 58、地标 15、设施 17）；
  - 366 四轮读缓存合计 209 万 tokens，上一份（2026-10-20-ticket21）335 万，降 37%；
  - `view_image` 平均输出像素：数据集轮 0.87、1.13 → 0.43、0.83 百万像素，数据定义轮 0.70、0.78 → 0.64、0.40。
- **验证**：全量 `npm test` 951 项通过（交付前再跑一次见票据 27）。
- **偏差**：票据写的同批是 17、18、19、22；17、18、20 这次没做（用户 2026-10-20 只点了 19、22、23 与 26–29），合同 0.6.0 不含它们，以后做时另升版本、另跑评估。M402 数据定义轮的平均输出像素反而略升（0.28、0.35 → 0.49、0.49），是 Agent 看的区域变大了，不是倍数变大。
