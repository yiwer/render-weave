# 26: 需要塑形或从右往左的文字，出图时报问题而不是静默画错

**What to build:** 文字元素里出现阿拉伯文、希伯来文这类从右往左的文字，或天城文、泰文这类需要字形组合的文字时，渲染报一条严重问题 `text.unshapedScript`，指出元素路径与文字种类。草稿、出图、交付、审核页预览都能看到，不再以"0 个问题"交出不可读的文字。

**Blocked by:** 无

**Status:** resolved

**Trace:** ADR-0011、M106（逐字排版）；`docs/stage1-acceptance.md:74`（不做复杂文字塑形与双向排版）；2026-10-20 阿拉伯文站牌试跑。

背景（2026-10-20，`out/arabic-board/`，不进版本库）：

- 引擎按码点取字形、从左往右逐字排（`src/text/shape.ts:55`）。最小探针与交付图里，"حديقة النخيل"都成了从左往右排列的孤立字母，阿拉伯文读者认不出。
- 这时渲染报 0 个问题：Agent 的三张草图、引擎检查与正式交付都没有提示，是审核人放大看图才发现的。
- 阿拉伯文属于特殊需求，本票不做塑形与双向排版，只让这个限制可见。

**决定**：

- 新问题代码 `text.unshapedScript`，等级严重：出来的字与写的字不一致，与 `text.glyphMissing` 同级。
- 判定按码点区段：
  - 从右往左：希伯来文（U+0590–05FF、U+FB1D–FB4F）、阿拉伯文及其补充与扩展（U+0600–06FF、U+0750–077F、U+0870–08FF）、表现形式（U+FB50–FDFF、U+FE70–FEFF）、叙利亚文、它拿那文、N'Ko、撒马利亚文、曼达文（U+0700–07BF、U+07C0–07FF、U+0800–085F）；
  - 需要字形组合：天城文到僧伽罗文（U+0900–0DFF）、泰文、老挝文、藏文（U+0E00–0FFF）、缅甸文（U+1000–109F）、高棉文（U+1780–17FF）、蒙古文（U+1800–18AF）。
  - 东阿拉伯数字（U+0660–0669、U+06F0–06F9）不算：它们不连写、从左往右，现在就画得对。
- 每个文字元素最多报一条，消息写文字种类与最多 8 个不同的字，例如"阿拉伯文：ح د ي ق…"。与缺字检查在同一处（`src/text/fallback.ts`），条码的可读文字同样检查。
- 记 M 编号。

- [x] 含阿拉伯文的文字元素出图时有一条 `text.unshapedScript` 严重问题，位置是元素路径，消息列出文字种类与字。
- [x] 东阿拉伯数字、中文、拉丁文不报；同一元素混有多种这类文字时只报一条，列出各种类。
- [x] `render_draft` 的问题清单与 `renderweave render` 的 `problems.json` 都有这条。
- [x] 问题代码登记在 `src/problems.ts` 与 `docs/` 的问题代码表（如有）；全量 `npm test` 通过。

**测试接缝：** 从 `src/index.ts` 的渲染入口，用资源仓库里能显示阿拉伯字形的测试字体；没有这样的夹具字体时，用内联数据集与现有字体测"报问题"（缺字问题会同时出现，断言两条都在）。

**不在本票：** 阿拉伯文塑形、双向排版、东阿拉伯数字的展示格式（特殊需求，用户 2026-10-20 决定暂不做）。

## Answer

2026-10-20 完成。

- **代码**：
  - `src/text/scripts.ts` 列出要塑形或从右往左的文字区段，按文字种类分组返回；东阿拉伯数字除外；
  - `src/text/fallback.ts` 在缺字检查之后，对每个文字元素（含条码的可读文字）报一条 `text.unshapedScript`，等级严重；
  - `src/problems.ts` 登记问题代码。
- **用例**：`test/glyph-fallback.test.ts`「需要塑形或从右往左的文字（票据 26）」两项：
  - 阿拉伯文报一条，列出"阿拉伯文（ح د ي ق ة ا ل ن …）"，不含东阿拉伯数字，正式出图无图；
  - 希伯来文加阿拉伯文混排只报一条、两种都列出；中文、拉丁文与东阿拉伯数字不报。
- **文档**：M271；`docs/render-fonts.md`「结果」。
- **验证**：全量 `npm test` 47 个文件、951 项通过，`npm run typecheck` 通过。
