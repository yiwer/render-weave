# 27: Agent 资料补齐必填判断、领域约定的适用条件与模板的分段写法

**What to build:** 改 `agent/` 下的通用做法、任务提示词、线路牌约定与模板参考，让 Agent 在数据定义提取时按业务判断必填、只为示例图上出现的元素建字段；在模板辅助设计时先写骨架、分段加内容、每段检查，不按数据取值写分支，第一次合格就交回成果并随修改更新。评估门槛通过，模板轮的首次检查问题数与轮数下降。

**Blocked by:** 26、29

**Status:** resolved

**Trace:** M216（三层资料）、M222（示例不用评估场景的答案）、M233（交回前核对）；2026-10-20 阿拉伯文站牌试跑；用户 2026-10-20：更关心数据定义的理解与提取、模板的细节设计。

背景（2026-10-20，`out/arabic-board/`，不进版本库）：

- **必填判断**：Haiku 把站码、距始发站累计分钟、时刻表更新日期都设为必填。示例图只给了本站的站码，已过站的分钟数显示为"—"，更新日期是占位，数据集提取必然缺值。审核时三项都改成可选。
- **领域约定的适用条件**：线路牌约定第 3、4 条写的是带圈数字地标、站名上方设施图标，这张阿拉伯文站牌上没有。Agent 照约定建了 `landmark`、`facilities` 两个字段（自己列为待确认），审核时删掉。
- **一次写出大模板**：Gemini 4 Argon 第 5 轮先写出 113KB 的主模板才第一次检查，714 个问题（198 个缺 `displayName`，76+76 个尺寸写法，55 个条件写法，38 个 `horizontalAlign` 写成 `left`/`right`）。看到问题清单后用 Write 重写、再用 Edit 迭代，176 → 23 → 3 → 0，每步几分钟。
- **按数据取值写分支**：主模板里"站码等于 2048 时显示 ٢٠٤٨"、线路号只列 1–12、15、20。检查与 `check_outcome` 都抓不到，审核人换本站序号出图才发现。
- **用满轮数丢成果**：第 5 轮 80 轮用完时三个模板都已 0 问题，但没有 `outcome.json`，82.5 分钟、316k 输出 tokens 的这一轮没有成果，靠下一轮补交（7 分钟）。
- **文字能力边界**：资料没写引擎不做塑形与双向排版，Agent 出了 3 次草图都没提阿拉伯文的问题。

**决定**：

- **不加 MCP 写工具**（"增加元素""修改元素"一类）。MCP 保持只读（ADR-0015），模板仍由 Agent 用文件写入与 Edit 修改：上面的记录说明 Edit 迭代本身有效，浪费在一次写太多、检查太晚与轮数用满。切换条件：本票之后的评估里，模板轮首次 `check_templates` 仍过百个问题，或仍有用满轮数的，再评估只读的"元素片段预检"工具（校验 Agent 打算写入的片段，不写文件）。
- **`agent/guide.md`**（不改原有条目编号，新内容作为不编号段落或子条目，避免历史记录里的"第 N 条"对不上）：
  - 开头优先级之后：领域约定描述某类元素出现时怎么处理；示例图上没有这类元素，不为它建字段或元素。
  - 第 7 条子条目：必填按业务判断——示例图上只有部分项有值、显示为"—"或只是占位的字段，建可选并列入待确认；必填只给每个对象一定有、缺了图就不成立的字段。
  - 模板一节开头：先写骨架（画板与几大区块）并检查、出草稿，再一段一段加内容，每段检查；内容多的区块拆成被调模板，各一个文件；不要一次写完整份大模板再检查。
  - 模板一节：派生变量与状态样式只按参数、列表位置与数据之间的关系判断，不比较数据集里的具体取值；类别枚举按数据定义里的枚举值切换不在此列。
  - 模板一节：文字能力边界——按字逐个从左往右排，不做塑形与双向排版；示例图用到这类文字时如实列入待确认，不倒序存字、不改用表现形式字符；数字按数据原样显示。选字体前用 `list_resources` 看字体覆盖的文字（票据 29）。
  - 交付说明：第一次没有严重问题时就写 `outcome.json` 并 `check_outcome`，之后每轮修改都更新它。
- **`agent/tasks/template-design.md` 与 `template-revision.md`**：步骤改为骨架 → 分段加内容并检查 → 第一次合格即写成果 → 继续改并更新 → 最终核对。`definition-extraction.md` 与 `dataset-extraction.md` 加"第一次合格即写成果"。
- **`agent/domains/route-sign.md`**：开头加一句"以下条目说明线路牌上常见元素的含义与做法；示例图上没有的元素，不为它建字段或元素"。
- **`agent/reference/template.md`**：开头加"常见错误"一小节，列首次检查最多的几类：元素与派生变量都要 `displayName`；`width`/`height` 的四种写法；条件的写法；`horizontalAlign` 的取值（没有 `left`/`right`）。示例用会议胸牌（M222）。
- 资料改动按 `agent/README.md` 跑评估门槛。
