# 候选6中文实际成果：用户发现视觉偏差

用户反馈：

> 其实做得都不错，但还是有很多地方是不符合的，比如票价票制的样式大小。底部服务时间、班时的文字大小和文字粗细等等

原话、问题来源、候选与四份材料身份保存在 [review-01.json](review-01.json)。负责人判断：视觉验收尚未通过，需要纠偏；这不是用户逐包拒绝，也不推断四包的每个实例都有同一问题。审核分钟、是否预看诊断及用户实际查看的页面版本仍未知。问题链接指旧索引；后续交付了新版，14张图片字节相同的证明见既有 final-v2 独审。

## 已确认的问题与证据

| 检查项 | 用户指出的偏差 | 本次记录边界 |
| --- | --- | --- |
| Z04 票价/票制 | 样式、大小不符合 | 包含标签与内容的独立字体、字号、颜色、倾斜及胶囊内比例；尚未提供逐包位置和完整问题列表 |
| Z15 服务时间 | 字号、字重不符合 | 服务时间主行与运营说明分别核对，不能只检查文字存在 |
| Z16 班时 | 字号、字重不符合 | 时刻文字及分隔、与主行的层级需要核对；用户的“等等”不视为问题已穷举 |

只读提取了四包已经生成的公开 render 布局库存，见 [实际排版记录](typography-observation-01.json)。例如第一遍设计：票价为 `font-hei-bold` / 8 mm，所有片段均为橙色、slant 0；服务时间主行为 bold / 7 mm，运营说明与班时为 medium / 3.5 mm。这些是实际候选值，不是参考图的正确值。原图与第一遍设计图已目视对照，票价标签/内容的颜色分层及底栏文字比例存在可见差别；未从缩放截图虚构准确字号或字重真值。

自动评分覆盖已核实：`scripts/agent-eval/eval.ts:441` 的模板/修改通过条件检查压测、地标底线、道路名分布及修改范围；`scripts/agent-eval/score.ts:400` 的版面两项正是地标和道路。`score.ts:381` 计算的整体相似度没有成为上述通过条件，且不能单独替代小区域字体检查。因此原四8/8达线只证明原自动门槛通过，不能证明本次字体、字号和视觉层级合格。已有样式库存也明确保留参考字体名称、字号毫米值和外观容差未知。

本次没有建立“渲染器有bug”或“模型必然选错字体”的根因结论。局部修改原任务只授权地标与道路两处，其余要求保持；必须对照修改前基准区分已有样式偏差与本轮新增错误，不能反过来要求原修改轮擅自重做票价和底栏。

## 下一步修正方案

1. 优先建立 Z04/Z15/Z16 的区域对照：标签/内容分开，逐项列出文字框相对大小、字体资源与字重、倾斜、颜色、行距、留白。参考图无法确定的精确数值标未知或待核准，不能把任一旧DSL的值直接当真值。
2. 对照实际输入、可用字体资源和有效候选，定位偏差在参考理解、样式表达还是渲染执行；以公开渲染同区域对比验证，不把相似度高或无溢出当视觉通过。其他Z项继续保留审核，三个例子不是完整缺陷清单。
3. 把已确认的区域规则放入后续可信基准与反馈，明确目标修正和非目标保持。若修改评分器、通用资料或运行器，按既有规则冻结新候选并重新登记受影响验收；只修交付候选也另留纠偏轮次，保留原始失败/人审意见。
4. 新纠偏成果仍须逐区域人审，通过前不关闭原38、不提前派发依赖它的留出验收。原四自动报告、四份原成果、归档及64项原空表保持不变；本反馈单独追加。
