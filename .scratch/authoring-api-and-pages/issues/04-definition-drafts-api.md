# 04: 经开放 API 新建、保存、校验与删除数据定义草案

**What to build:** 服务端的数据定义草案：每个名称至多一份，可从空白或某个静态版本新建，带预期哈希整份保存，校验并预览编译产物。

**Blocked by:** 03

**Status:** ready-for-agent

**Trace:** [P1 PRD](../spec.md)「角色、权限与寻址」「数据定义草案」；用户故事 2、3、4、5、6、7、29；验收 A02、A10；M297、M298。

- [ ] 权限矩阵加 `definitions.write`、`templates.write`、`authoring.publish`、`authoring.approve`、`authoring.policy`，按 PRD 分给客户管理员与代建工程师；客户操作员与 API 密钥只读。
- [ ] 列出本租户的数据定义：每个名称的静态版本、有没有草案、草案基于哪一版，以及各版本被多少数据集与模板使用。
- [ ] 新建草案：空白（名称、显示名称），或从某个静态版本另起；名称已有草案时拒绝。
- [ ] 保存：整份替换，按原始字节存，带预期 SHA-256，不符答 409 并给当前哈希。
- [ ] 校验回答问题清单，定位到字段；编译预览回答 `compileStaticSchema` 的产物。
- [ ] 与基于的版本相比，删除与改名的字段列为"会影响绑定"，并列出用到它们的模板。
- [ ] 删除草案。
- [ ] 客户端点与代建端点（路径带目标租户）共用一份实现；全部进权限矩阵与跨租户端点清单；每次写入记审计，带前后内容哈希。
- [ ] 迁移的新表启用行级安全；OpenAPI 快照只有加法。

**测试接缝：** 开放 API，内存后端进 `npm test`，行级安全在 Docker 后端测；五种身份逐项覆盖。
