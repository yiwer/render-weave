# 05: 发布数据定义草案前看到字段级差异与数据集影响，发布后可以用旧版另发回退

**What to build:** 草案的发布预检与发布：差异、失配的数据集份数、仍绑定旧版的模板；发布成对写入原文与编译产物；回退是从旧版另起草案再发布。

**Blocked by:** 02、04

**Status:** resolved

**Trace:** [P1 PRD](../spec.md)「发布静态数据定义」；用户故事 8、9、10、11、29；验收 A04、A10；ADR-0008、ADR-0022、M278。

- [x] 发布预检（只读）：与基于版本的字段级差异（`diffDefinition`）；绑定基于版本的数据集逐份按新编译产物校验，回答失配份数与前 20 份的问题摘要；超过 1,000 份只校验前 1,000 份并标为"未全部核对"；仍绑定旧版本的模板列表。
- [x] 发布带草案的预期 SHA-256；用 `publishStaticSchema` 得到下一版本，在一个事务里写入原文与编译产物，然后删除草案。
- [x] 发布产物与本地 `renderweave publish` 对同一份数据定义的结果逐字节相同。
- [x] 严重问题拒绝发布，问题码与本地发布相同；版本号已被并发的发布占用时答 409。
- [x] 回退：从旧版本另起草案再发布，得到内容与旧版相同的新版本；旧版本保持不变。
- [x] 发布与预检进权限矩阵（`authoring.publish`）；审计记前后内容哈希与差异摘要。

**测试接缝：** 开放 API；发布产物与本地 `publish` 输出比字节；预检用 M402 样例与构造的失配数据集。

## Answer

完成于 2026-11-01，提交 efcba8b。接口写法见[开放 API · 数据定义草案](../../../docs/api.md#数据定义草案)，判断记在 M353。

**成果**

- **预检** `POST …/draft/publish-check`（`authoring.publish`，只读）：与基于版本的字段级差异；绑定基于版本的数据集按新编译产物逐份校验，给失配份数与前 20 份的问题摘要（每份至多 5 条），超过 1,000 份只校验前面的并标 `complete: false`；基准是这个名称的模板。
- **发布** `POST …/draft/publish`：`publishStaticSchema` 得到下一版本，按本地发布的写法存（缩进两格、末尾换行），在一个事务里锁住租户行，核对草案哈希与版本没被占用，成对登记，删除草案。严重问题答 400，问题码与本地相同；版本被占答 409 `draft.versionTaken`，什么也不写。
- **回退**：从旧版本另起草案再发布，没有单独的端点。
- **审计** `definition.publish`：对象是 `名称@版本`，前哈希是基于版本的原文，后哈希是新版本的原文，差异摘要逐字段。OpenAPI 升 1.4.0，只做加法。

**验证**

- 新用例 `service/test/definition-publish-suite.ts` 7 项（两种后端）：发布产物与 `runCli(['publish', …])` 的输出比字节；严重问题的问题码与本地发布比对；回退；新名称；抢先写入两种情况（包一层存储，在登记之前插入推送或保存）；前 20 份与上限。
- 变异核对：去掉版本占用检查，抢先那条失败；原文换成不带缩进的写法，比字节那条失败。

- Docker 后端 `node service/scripts/test-docker.mjs`：20 个文件 172 项全过，三个服务的结构化日志没有不合格的行。这也是合入 M350 之后第一次跑通整组。

**偏差**

- 上限 1,000 做成 `ServiceLimits.publishCheckDatasets`，用例用小值走超限路径，不必造一千份。
- 预检读全部模板时不限基于的版本：发布不改动它们，页面要知道的是谁还在用这个名称。
