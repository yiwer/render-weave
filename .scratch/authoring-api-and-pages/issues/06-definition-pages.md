# 06: 客户管理员在数据定义列表、详情与发布记录三页上改结构并发布

**What to build:** 数据定义的三张页面：列表、详情（字段表原地展开编辑、手动添加字段、校验、编译预览）与发布记录（差异、影响、发布与回退）。

**Blocked by:** 01、05

**Status:** resolved

**Trace:** [P1 PRD](../spec.md)「数据定义草案」「发布静态数据定义」；用户故事 1–12、27；验收 A11；M299；原型画板 06、07、08。

- [x] 列表：每个名称的当前版本、草案状态、引用数；新建数据定义；右键一行有打开、在新标签页打开、查看发布记录、导出编译产物 JSON Schema、复制引用、从这一版另起草案。
- [x] 详情：字段表列显示名称、字段名称、类型、约束、必填与"谁在用"；选中一行原地展开编辑；手动添加字段覆盖全部九种字段类型；随时校验，问题定位到字段；预览编译产物。
- [x] 改字段名称或删字段时提示会影响的绑定与模板。
- [x] 发布：先显示字段级差异与预检结果，再发布为下一版本；失配数据集与未全部核对的情况写清楚。
- [x] 发布记录：谁在何时发布了哪一版、改动摘要、内容哈希；以某一版另发新版本。
- [x] 客户操作员只读；"从示例图提取""从数据集提取"两个入口在 P2 接入前不显示。
- [x] 浏览器用例走通"另起草案 → 加必填字段 → 看差异与影响 → 发布 → 以旧版另发"。

**测试接缝：** 控制台浏览器用例（Docker 后端那组）；页面只调开放 API。

**对验收的偏差**

- **加了两个只读端点**：票据写"页面只调开放 API"，这一点没变；但接口原先没有操作员能读的发布记录，也没有"每个字段谁在用"，用加法补上（M355）。
- **"未全部核对"的浏览器用例用改过的回答**：真造 1,000 份数据集太慢；真实的上限行为在接口用例里覆盖（`definition-publish-suite.ts`，`complete: false`）。
- **与画板 07 的差别**：引用字段的子字段不在字段表里缩进展开，类型一列写被引用的版本；那些字段属于另一份静态数据定义，这里改不了。"来源"一列按票据换成"谁在用"。画板 06 的搜索框与"导入 JSON Schema"不做，前者票据没列，后者 PRD 排在后续。
- **发布记录的"待处理"现在只有草案**：发布申请在票据 11 接入。

**已知限制**

- 展开的一行有没保存的改动时，选另一行或点发布会先保存；但点模块下拉或别的链接离开这一页，改动直接丢，没有提示。
- 普通 http 地址上浏览器没有剪贴板接口，"复制引用"改为把引用写在页面上让人手动复制。
- 一次推送写入太多文档、差异摘要没留到某一版时，那一版的发布记录没有主体与时间，页面写"没有记录"（M355）。
