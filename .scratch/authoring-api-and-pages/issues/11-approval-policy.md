# 11: 租户打开"发布前需管理员批准"后，代建工程师的发布与推送变成申请，客户管理员批准后生效

**What to build:** 两个范围（数据定义发布、模板修订）的审批策略；发布申请的发起、批准、退回与过期；推送改到受约束的范围时整份变成申请；管理页的策略开关与两个发布页上的待处理区。

**Blocked by:** 06、09、10

**Status:** resolved

**Trace:** [P1 PRD](../spec.md)「审批策略与发布申请」；用户故事 24、25、32；验收 A07、A08；ADR-0021、ADR-0022。

- [x] 策略：两个范围各一个开关，缺省关（直发）；只有客户管理员（`authoring.policy`）能改，改动记审计。
- [x] 打开后，客户管理员以外的主体发布数据定义、保存模板或指回旧修订，得到一份发布申请；申请固定内容哈希与基准。客户管理员自己的发布直接生效。
- [x] 推送改到受约束的范围时，整份推送成为一份申请，内容已上传；批准时按推送规则重算冲突，再一次提交。
- [x] 批准（`authoring.approve`）时重核内容哈希、基准与严重问题；任何一项不符就把申请标为"已过期"，不能批准。退回必须留言。
- [x] 同一份草案、工作副本或同一位代建工程师的推送，同时最多一份待处理申请；申请之后内容被修改，申请随之过期。
- [x] 申请、批准、退回、过期各记一条审计，带主体与内容哈希。
- [x] 页面：管理页有两个开关并说明"缺省直发；有严重问题的成果任何人都不能批准"；数据定义发布记录页与发布模板修订页显示待处理申请，可批准、退回并留言。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API（代建令牌与客户管理员两种身份）；命令行 `push` 对进程内服务验证推送申请；页面经浏览器用例走通一次批准。

## Answer

完成于 2026-11-02，分支 `p1-11-approval`。接口写法见[开放 API](../../../docs/api.md#审批策略与发布申请)，实现见[出图服务](../../../docs/service.md#审批策略与发布申请)，判断记在 M357。

**对验收的偏差**

- **加了详情端点的重核结果与 `changes`**：票据只写批准时重核；不让客户管理员看到改了什么、现在能不能批，就是盲批。
- **申请时也查严重问题**：票据只写批准时重核。有严重问题的成果任何人都不能批准，早答 400 省得白看。代价是推送申请比直接推送多一道服务端检查（M357）。
- **新内容让旧申请过期，不拒绝**：票据写"最多一份待处理"。一律拒绝的话代建工程师的推送会卡住，所以重发相同内容答同一份，内容变了旧的过期。也因此不做"撤回申请"（M357）。

**已知限制**

- 列表不重核：基准变了不会主动标过期，打开详情才看得到，批准时才标（M357）。
- 页面只列待处理的申请，处理过的看审计与接口。
- 推送申请在页面上只显示差异摘要（路径与增删改），不显示模板的结构化差异；摘要只留前 50 项。
- 页面不会自动刷新：别人刚处理掉的申请要刷新后才消失，点下去会照实显示服务端的回答。
- 真人走查没有做，归票据 13。
