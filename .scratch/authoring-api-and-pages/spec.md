# 阶段 5.0 P1 PRD：代建接口与人类页面

2026-10-27。阶段 5 分六段（[路线图](../../docs/roadmap.md#阶段-5-的分段2026-10-27)），本期是第一段 P1。按 ADR-0022 与 M297–M299，数据定义与模板要有人能直接操作的页面，人和 Agent 走同一套代建接口；本期先把这套接口与页面做出来，Agent 的写工具在 P2 建在它上面。本期不依赖 Tool Runner 门槛，可以与正在进行的 Agent 验收并行。

## Problem Statement

出图这条线已经能卖（阶段 4），做模板却仍只能由代建工程师在本机完成：

- **客户改不了自己的数据定义与模板。** 服务端只存推送进来的静态数据定义与模板修订（M264、M278），出图控制台里模板只读。给线路牌加一个"运营方"字段、把线路号调大一点，都要找我们的代建工程师在本机改完再推送。
- **服务端没有"还没发布的那份"。** 数据定义只有不可变的静态版本，模板只有修订；网页上要改，必须先有可以反复保存、校验、预览的草案与工作副本。
- **发布看不到后果。** 发布新版本前看不到字段级差异，不知道多少份数据集会按新版失配；模板保存前没有结构化差异与前后对比。
- **审计不够回退与追责。** 审计只记主体、动作与对象（`service/migrations/0002_auth_and_isolation.sql:66`），ADR-0022 要求的前后内容哈希、差异摘要都没有；租户也没法要求"发布前需管理员批准"。
- **推送会覆盖网页上的改动。** 推送时模板与当前修订字节不同就记新修订（M265）。一旦网页能保存模板，代建工程师从旧内容推送就会悄悄盖掉客户刚发布的修订。
- **界面与原型不是一套。** 控制台是顶部导航的出图页面（`service/console/src/app.tsx` 的 `Shell`），原型是标题栏模块下拉加左栏 Agent 的新框架；平台管理员也没有页面，只能调接口。

## Solution

1. **代建接口**：数据定义草案与模板工作副本存进服务端，可保存、校验、预览；数据定义发布为静态数据定义，模板保存为新修订，都在服务端完成。客户端点与代建端点挂同一套处理逻辑（M261 的两种寻址）。
2. **发布前看后果**：数据定义给字段级差异与数据集影响；模板给结构化差异与前后对比图；回退沿用不可变版本与修订（ADR-0008、M265）。
3. **审计与审批**：每次代建写入记主体、前后内容哈希与差异摘要；租户可按范围打开"发布前需客户管理员批准"，缺省直发（ADR-0022）。
4. **推送与网页共存**：推送声明本地模板基于哪个修订，服务端发现网页上的改动就整体拒绝；新增 `renderweave pull` 把服务端当前内容取回本地。
5. **人类页面**：数据定义列表、详情与发布记录，模板设计（点选元素、属性面板、参数、结构、规则），发布模板修订，平台管理；控制台整体换成原型的新框架。

### 完成标准

在本机用 Docker Compose 从空环境起完整服务，走完以下流程：

平台管理员在控制台开通租户、设套餐、建客户管理员 → 代建工程师推送 M402 的数据定义、模板与资源 → 客户管理员在控制台从"线路牌 v1"另起草案、加一个必填字段，看字段级差异与数据集影响后发布为 v2 → 打开模板设计页，在图上点选线路号，在属性面板改字号，暂存工作副本、看草稿预览，看结构化差异与前后对比后保存为新修订 → 指回上一个修订 → 代建工程师从旧内容推送被挡住，`renderweave pull` 之后再推送成功 → 客户管理员打开模板修订的审批策略，代建工程师的推送变成发布申请，客户管理员批准后生效 → 审计里每一步都有主体、前后内容哈希与差异摘要。

全程不手工改数据库、不手工复制文件。现有测试与样例没有回归，开放 API 相对 1.0.0 只做加法。

## Implementation Decisions

### 角色、权限与寻址

- **新增权限名**（M261 的矩阵加法）：
  - `definitions.write`：新建、保存、删除数据定义草案；
  - `templates.write`：暂存与丢弃工作副本、复制模板；
  - `authoring.publish`：发布静态数据定义、保存模板修订、指回旧修订；
  - `authoring.approve`：批准与退回发布申请；
  - `authoring.policy`：修改审批策略。
- **分给谁**：客户管理员拿全部五项；代建工程师加前三项，`authoring.publish` 受审批策略约束；客户操作员与 API 密钥不加，只能经 `tenant.read` 只读查看草案、工作副本与修订历史；平台管理员不变。切换条件：客户要操作员做小改，或要用程序维护模板时，再给操作员或 API 密钥开放写入。
- **一套处理逻辑，两种寻址**：客户端点的租户由身份决定（`/v1/...`），代建端点在路径里写目标租户（`/v1/authoring/tenants/{tenantId}/...`，M261）。同一操作两处共用一份实现、一份请求与回答结构。

### 数据定义草案

- 每个数据定义名称至多一份草案，记"基于哪个静态版本"（新名称没有）。
- 新建：空白（名称、显示名称），或从某个静态版本另起（复制原文，去掉版本号）。
- 保存：整份替换，按原始字节存（同数据集，M270），带预期 SHA-256；首次保存不带。预期不符答 409，带当前内容哈希。
- 校验用引擎 `checkDslDocument`；编译预览用 `compileStaticSchema`。问题清单定位到字段。
- 草案可以删除。
- 与基于的版本相比，被删除或改了字段名称的字段列为"会影响绑定"：字段名称是身份（ADR-0005），改名等于删一个、加一个。

### 数据定义差异（引擎）

- 新增公开入口 `diffDefinition(before, after)`：按字段路径列出增、删、改；改动细到属性键：显示名称、类型、约束、必填、引用的版本。
- 列表与数据定义引用的子字段带父路径；比较用规范化 JSON，与 `diffTemplate` 一致（`src/agent/diff.ts:88`）。
- 纯函数，不读存储。

### 发布静态数据定义

- **发布草案**：带草案的预期 SHA-256。服务端用引擎的 `publishStaticSchema`（`src/schema/publish.ts:22`）得到下一版本的原文与编译产物，在一个事务里写入两份（同推送成对写入，M278），然后删除草案。产物与本地 `renderweave publish` 对同一份数据定义的结果逐字节相同。
- **严重问题拒绝发布**，与本地发布同一入口、同一问题码。
- **发布预检**（只读，同一请求结构）：
  - 与基于版本的字段级差异；
  - 绑定基于版本的数据集逐份按新编译产物校验，回答会失配的份数与前 20 份的问题摘要；超过 1,000 份时只校验前 1,000 份并给总数，标为"未全部核对"；
  - 仍绑定旧版本的模板列出，不改动（ADR-0008）。
- **回退**：从旧版本另起草案，再发布为新版本。页面上一键完成，接口上是两步。

### 模板工作副本

- 每个模板至多一份工作副本，记基准修订号；复制出来的新模板没有基准修订。子模板各有自己的工作副本。
- **暂存**：整份替换，带预期 SHA-256。暂存不影响当前修订，出图照旧读当前修订。术语上，这里叫"暂存工作副本"，把工作副本写成模板叫"保存模板"（页面上叫"发布修订"），与 `GLOSSARY.md`「工作副本」的"保存即应用"一致。
- **校验与草稿预览**：预览请求可以指定"用工作副本"，与已保存模板走同一套检查与限制（`measureRender`、按租户的并发与频率，M267）；回答图片、问题清单与布局摘要。
- **元素定位**：预览回答带每个元素实例的源模板与在模板文档里的位置。引擎的渲染证据里已有这项信息（`src/agent/style-verification.ts:156` 用的 `trace.source`），本期把它作为渲染入口的可选输出公开；布局摘要已有元素路径与框（`src/layout/types.ts:19`）。页面靠这两样从图上点选到属性面板。
- **复制为新模板**：取当前修订的内容与基准数据定义，换新名称，成为没有基准修订的工作副本；保存时记修订 1。
- **保存模板**：
  - 工作副本的基准修订等于当前修订才能保存；否则答 409，带 `revisionDiff` 两边的差异。显式 `overwrite` 才覆盖，口径同 `agent apply --overwrite`。
  - 模板静态检查有严重问题时拒绝。
  - 按 M265 记新修订（字节相同记为不变），当前修订指向它，删除工作副本。
- **指回旧修订**：已有（`service/src/api/authoring.ts:119`），开放给有 `authoring.publish` 的客户管理员，并进审批策略与审计。

### 属性面板、参数、结构与规则

- 属性面板按 `schemas/template.schema.json` 里所选元素类型的属性生成，改动写回工作副本里该元素的位置。保存前在页面里可以撤销与重做。不做自由拖拽（M205），位置与尺寸只能填数。
- 参数页编辑对外参数与内部参数的显示名称、类型、约束与缺省值；对外参数的列法同 `describeTemplate`。
- 结构页显示模板文档的元素树：容器、循环容器、子模板调用。与预览的选中双向同步，子模板调用可以打开子模板的设计页。
- 规则页列出所选元素相关的检查项与适配规则：缩字组、字形压缩下限、缩字下限（M238）。
- 页面上"让 Agent 修改""留评论"的入口在 P2、P4 接入前不显示。

### 发布模板修订页

- 显示结构化差异（`revisionDiff`）、改前改后用同一份样例数据集各渲染一张的对比图、修订历史（谁在何时、来自推送还是网页）与指回。
- 多份数据集的改动影响检查是 P3，本期不显示那一段。

### 审批策略与发布申请

- **两个范围**：数据定义发布、模板修订（含指回旧修订）。缺省都关，即直发（ADR-0022）。只有客户管理员能改。
- **打开后**：客户管理员以外的主体发起的发布变成发布申请，主体是本期的代建工程师、P2 起的 Agent。申请固定内容哈希与基准，等客户管理员批准，或退回并留言。客户管理员自己的发布直接生效。
- **推送也受约束**：推送改到打开了策略的范围时，整份推送变成一份发布申请，其中的内容已经上传；批准时按推送的同一套规则重算冲突，再一次提交。
- **批准时重核**：内容哈希与基准都没变（数据定义的下一版本号没被占用，模板的当前修订仍是基准），没有严重问题（ADR-0021）。任何一项不符就把申请标为"已过期"，需要重新发起。
- 同一份草案、工作副本或同一位代建工程师的推送，同时最多一份待处理申请。申请之后草案或工作副本又被修改，申请随之过期。
- 申请、批准、退回、过期各记一条审计。

### 审计

- `audit_events` 加可空列：前内容哈希、后内容哈希、差异摘要（增删改计数，加至多 50 个路径）、轮次与理由。轮次与理由给 P2 的 Agent 用，本期留空。
- 新的代建写入一律填写：保存或删除草案、发布、暂存或丢弃工作副本、保存模板、指回、复制、策略修改与申请处理。旧行保持空。
- 审计接口与管理页按主体种类筛选，可以把筛选结果导出为 CSV。

### 推送与网页改动共存

- 推送清单给每个模板加可选的 `baseRevision`，即本地这份内容基于的修订。服务端判定冲突：
  - 带了 `baseRevision`：当前修订不等于它，且推送内容与当前修订字节不同，算冲突；
  - 没带：当前修订不是推送产生的（来自网页保存、指回或批准），且字节不同，算冲突。只用推送的租户行为不变（兼容 M265）。
- 冲突照 M264 整体拒绝（409 `push.conflict`），说明当前修订由谁在何时产生。
- `renderweave pull --server --tenant --workspace`：把租户当前的模板、静态数据定义与编译产物写进本地工作区。每次推送或拉取后在本地记下各模板的修订号，下次推送带上；这份记录不能让本地读工作区报问题。令牌规则同推送（M264）。
- 服务端的草案与工作副本不受推送影响。静态数据定义的冲突规则不变（ADR-0008）。

### 控制台新框架

- **标题栏**：品牌、模块下拉（数据定义、模板、数据集、出图、资源、用量、管理；平台管理员只有平台），`Ctrl+1`… 切换模块，`Ctrl+K` 打开模块与常用动作（不搜对象）。
- **状态栏**：连接状态、当前租户、本月剩余额度、进行中的批次。
- **左栏**：留给 Agent，P2 接入前不显示。
- **视觉**：原型第 29 版的色板与做法（M208 的暖色中性；咖啡红 `#8E3B24` 是强调与主按钮，调和橙 `#F17D13` 只用在不承载文字的位置），一页一事、细分隔线、状态用圆点加文字。原型源文件存档在分支 `prototype/desktop-workbench`，原型只作讨论，不作实现基础。
- **画板 13–18 迁入新框架**，行为不变；浏览器用例只改选择器，不改断言。

### 平台管理页

- 平台管理员登录后只看到平台管理：
  - 服务健康一行：就绪、worker 报到、队列积压；
  - 租户列表：套餐、本月出图、Agent token、成员数、状态；展开后可改套餐、建成员账号（初始密码只显示一次）；
  - 开通租户；
  - 代建令牌的签发与吊销。
- 全部用已有的 `/v1/platform/*` 端点；缺的只读汇总（例如本月出图）用加法补。

### 开放 API 与迁移

- 1.x 只做加法（M276）：新端点、新可选字段，推送清单的 `baseRevision` 也是可选字段；OpenAPI 快照显式更新。
- 迁移从 `0010` 起按版本号执行；新表全部启用行级安全，进跨租户端点清单。

## Testing Decisions

### 接缝与既有实践

本期四个接缝，前三个沿用：

1. **开放 API**（主接缝）：服务测试只经 HTTP 驱动，断言回答、问题清单与经 API 可见的结果（版本、修订、申请、审计）。内存后端进 `npm test`；PostgreSQL 加 S3 后端在 `node service/scripts/test-docker.mjs` 里跑，行级安全只在这里测。
2. **引擎公开入口**：`diffDefinition` 与渲染入口新公开的元素定位。用 `docs/examples/m402-dsl/` 与 fixtures 做输入，断言差异条目与定位结果。
3. **命令行**：`renderweave push` 与 `pull` 对进程内服务跑，断言冲突、取回的文件与本地记录。
4. **出图控制台浏览器用例**（Docker 后端那组）：走完成标准的主路径，外加一次真人走查。

其余约定：

- **好的测试**给业务输入，断言能否发布、发布了什么、哪里被拒绝、审计记了什么、别的租户能否看到；不断言私有模块、表结构与调用次数。
- **逐字节对照**：服务端发布的静态数据定义与编译产物，与本地 `renderweave publish` 的产物比字节。
- **既有实践**：权限矩阵逐身份覆盖的用例、跨租户端点清单、OpenAPI 快照、推送的差异与冲突用例、控制台的浏览器用例。

### 实施顺序

1. 地基可以同时开工：控制台新框架、数据定义差异（引擎）、审计补字段。
