# 02：按静态数据定义创建数据集

**What to build:** 用户直接选择静态数据定义的确切版本创建数据集，模板只在预览和出图时按需选择。

**Blocked by:** 01

**Status:** resolved

**Trace:** M374；[接入方案](../../../docs/excel-agent-app-integration.md)第 1 项。

- [x] 数据集页可以选静态数据定义新建；不存在任何模板时仍可完成填写与保存。
- [x] 静态数据定义详情提供创建数据集入口，带入当前查看的确切版本；历史版本不会被替换成最新版。
- [x] 模板带入的新建入口仍可用，模板与定义不匹配时明确拒绝，不默默换定义。
- [x] 已有数据集无兼容模板时仍可编辑、保存；有兼容模板时预览/出图保持原行为。
- [x] 原有 Excel 导入行为和 `/v1/excel-imports` 合同不变；名称能与后续智能导入区分。
- [x] 不提前展示不能执行的“智能导入”按钮；功能完成后再由 P2 接入。

**测试接缝：** 控制台浏览器流程覆盖无模板非公交定义、新建/保存/重开、历史版本与模板入口；既有数据集和标准表导入 API 回归。无需模型调用。

## Answer

2026-11-03。已实现 `DatasetNew` 与无模板 `DatasetEditor`，静态数据定义详情带确切版本，旧模板入口与标准表批量出图保持兼容。截图在 `out/dataset-module/new.png`、`editor.png`、`list.png`。

验证：`npm run build`、`npm run typecheck`、`npm run typecheck:service`、`npm run build --prefix service` 通过；设置本机 Chrome 的 `RW_BROWSER` 后 `npm test -- --project service --maxWorkers=4`，26 文件通过、253 项通过、2 项按既有内存 worker 限制跳过。新增浏览器用例使用新建的空租户验证无定义提示、无模板新建/保存/重开/修改、历史版本带入、非法版本和模板不匹配拒绝；旧标准表与模板流程一起回归。

偏差：用户本轮进一步要求完整模块（M375），因此智能导入入口由票据 03 同批接入；未配置时明确显示未启用并禁用开始提取，没有展示可执行的假按钮。共享多行字段改用 textarea，保留批注中的换行；浏览器验证保存后与原始字符串完全一致。
