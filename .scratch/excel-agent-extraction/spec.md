## 目标与技术选择

把 rid-rs `quick_print` 的 Excel 制作表处理能力接入 RenderWeave：用户上传原始制作表，Agent 理解表格、处理数据、根据校验反馈修正，得到可审核的数据集，最终使用已有模板批量出图。

用户指定“使用 claude + opencodego，和识别模板一样”。复用当前模板识别的 Claude Code 执行器、Claude 模型与 OpenCode Go 渠道，不另起 Agent 框架、不另选模型供应商。当前默认值在 `src/agent/run.ts:54`：OpenCode Go Anthropic 兼容入口、`claude-haiku-5-5`、`OPEN_CODE_API_KEY`；执行器选择在 `src/agent/run.ts:491`。实际模型、预算和执行器版本随轮次记录，不把型号写死到 Excel 业务逻辑里。

本次接入目标是 RenderWeave，旧仓库只作业务参照，不复制实现。先完成本地闭环，再接服务端工作台。现有 P0 验收与 P1 收尾的顺序不因此自动改变。

## 用户流程与责任划分

1. **指定目标**：上传工作簿，选择已发布的静态数据定义，给出业务说明；模板用于可选预览和随后的出图，不是单独提取数据集的前提。没有合适数据定义时，先走数据定义提取与发布，再开始数据集提取，不让一次转换静默改定义。
2. **查看原表**：Agent 先取得 Sheet、尺寸、合并范围与区域摘要，按需读取表头、方向区块和数据行。原文件保持不变；较大结果分页，不再把所有工作表一次塞进上下文。
3. **转换与修正**：受控读取器从原始文件建立完整单元格视图；Claude Code 编写 Python 转换脚本，在隔离环境处理固定视图，输出候选数据集、来源映射与处理统计。工具返回异常、校验问题和遗漏；Agent 修改脚本后重跑。行遍历、列表展开、类型转换由程序执行，模型负责判断表的含义。
4. **独立检查**：宿主按选定的编译产物 JSON Schema 校验；另外核对顺序、数量、来源及未处理区域。脚本自己生成的“全部覆盖”不能算独立验证；解释有歧义时保留待确认项。
5. **审核与修订**：展示方向、站序、班时列表、尺寸单位、待确认项、未映射列以及与指定既有数据集的差异。人可以纠正字段或补说明后续跑；处理完待确认项才应用。
6. **预览与交付**：以现有模板生成草稿预览，按每个停靠位置组织渲染项。应用与正式交付仍走现有能力，记录输入、数据集、模板修订和资源版本。

脚本只是候选数据的生成方法，不是校验权威，也不能直接写生产数据库或调用正式交付。业务 Agent 继续沿用已有轮次、预算、停止、检查点、审核和应用机制。代码执行边界见 [ADR-0028 草案](../../docs/adr/0028-excel-agent-script-execution.md)。

## 业务数据映射

- 用数据定义表达线路信息、方向、有序停靠列表和扩展字段。优先按“一条线路的一个方向”形成数据集；一份工作簿可以产生多份数据集。逐站出图以停靠位置定位，不能用站名去重。
- 原来 `line` / `stop` / `route_stop` 的字段归属是需要保留的业务语义；旧数据库中的共享站点实体不搬进 RenderWeave。数据集仍自成一体（ADR-0010）。字段名称用英文，中文表头映射到显示名称（M89）。
- 当前站、下一站、已过/未过状态与尺寸、模板选择属于出图准备。能由既有模板参数或派生变量表达的沿用；缺少的逐站请求组织放在业务层，不把公交专用逻辑塞进通用引擎。
- 首个闭环固定使用已选模板与明确的尺寸规则。随后补旧模块的预设、历史配置继承、额外牌和变更比较；本地提取跑通不等于完整替代 `quick_print`。

## 实施顺序与验收

### 1. 真实制作表基准与最小本地闭环

取得一份实际失败制作表及预期线路、方向、站序、全部班时、尺寸单位，固定原件与人工核准值。先支持 `.xlsx`；旧 `.xls` 的需要和读法以真实文件评估，不能宣称已完全兼容旧上传入口。沿用 Claude Code + OpenCode Go，用已发布数据定义和现有模板，从原表到候选数据集、审核、预览、正式图跑通一次。

### 2. 多份候选、来源与修复

扩展工作簿输入和区域读取；补脚本执行、反馈和来源核对；检查多份候选在审核、覆盖、应用、检查点及恢复中的完整性。用人工标注夹具注入漏站、截断列表、错方向、错层级、重复站误合并，验证检查能够拒绝，且模型能按反馈修正。

### 3. 业务完整性

补逐站出图组织、前后差异、显式选用预设与历史配置、额外牌。历史匹配必须说明身份与歧义；不能让 Agent 自行猜测后覆盖既有数据。模板设计和修改仍是已有独立任务。

### 4. 工作台与托管

在本地能力和 P0/P2 条件满足后接服务端上传、轮次展示、修订与交付。沿用用户指定组合；如托管任务仍用 Claude Code，需要明确修订 ADR-0027 的产品执行器决定，不能自行改成 Tool Runner，也不能在共享服务进程里直接执行模型生成代码。
