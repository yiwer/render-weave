# 10: 停止长批次并辨认中断后的完整成果

**What to build:** 操作者取消批次时保留已完成项、停止下一项；进程意外结束后也能从完整记录辨认已交付成果，而不会把残留文件当作成功。

**Blocked by:** 08：35 个本站逐项正式交付，错误项不拖累整批

**Status:** ready-for-agent

**Trace:** 第二阶段 PRD；用户故事 21、25、26、27、28、43；验收 A07、A11。

- [ ] 公开批量入口与 CLI 均能请求取消；当前项完成并提交后停止，下一项不启动，其余项标记未执行，退出码 130。
- [ ] 开始前取消、两项之间取消以及当前项执行时取消均有可观察结果；不声称能中断同步 WASM 绘制。
- [ ] 进程在图片写入、记录内容写入、完成清单发布前后终止，已完整提交的项仍可读取和重放，未完成项不可读为成功。
- [ ] 整批最终清单尚未写出时，既有完整单项记录仍能辨认；API/CLI 对不完整运行作明确说明，不虚报整批完成。
- [ ] 已有目标、同目标并发和磁盘写入故障不会改变其他成功成果；存储不可用时停止后续调度。
- [ ] 根据失败/未执行清单显式生成新请求可重新运行，原批次不覆盖；不增加自动重试、自动续跑或新的后台服务。

**测试接缝：** 优先通过本票涉及的公开渲染、资源管理、交付或重放入口观察外部行为，CLI 验证参数、退出码与文件成果；不测试私有中间结构。需要的小范围预重构先做并保持已有测试通过，再完成本票行为。
