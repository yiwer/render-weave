# 11: 千项交付节省重复素材且内存不随图片累积

**What to build:** 同一批次内重复的字体和图片只占一份磁盘空间，任取一条记录单独复制后仍可重放；在此基础上完成 1,000 项正式交付，内存不随张数累积。

**Blocked by:** 08：35 个本站逐项正式交付，错误项不拖累整批

**Status:** ready-for-agent

**Trace:** 第二阶段 PRD；用户故事 41、43、45；验收 A09、A12。2026-10-13 按 M188 收窄。

- [ ] 去重范围限定为同一批次：同一内容（按 SHA-256）第一次完整写入并核对后，本批后续各项用硬链接为自己建立文件入口；不跨批次，不链接到资源仓库，不建共享目录，禁止符号链接。
- [ ] 硬链接失败（文件系统不支持、跨卷）时该文件回退为独立复制，交付照常成功；去重与复制两条路径都有测试。
- [ ] 删除同批其他项目录及原资源仓库后，本记录仍可读取和重放；单条记录复制到独立位置后重放一致。读取仍逐文件核对哈希，不把内容哈希当资源版本。
- [ ] 按 PRD A12：预热 50 次后交付 1,000 项，最后 50 项 RSS 中位数较预热后 50 项中位数增长不超过 256 MiB；图片与摘要一致，源输入不变。失败须定位并修复，不放宽阈值。
- [ ] 验收脚本记录 RSS 全程采样、峰值、耗时、平台、磁盘用量与实际去重方式；限定为受控本地串行批次能力。

不做：跨批次或资源仓库级去重、空间耗尽模拟（存储不可用已由 08 的探测覆盖）。理由见 M188：接入服务后记录会进对象存储，按哈希去重由存储层承担。

**测试接缝：** 通过公开批量入口与重放入口观察外部行为，CLI 验证文件成果；长批次以验收脚本执行，不把所有结果图片存入测试数组。
