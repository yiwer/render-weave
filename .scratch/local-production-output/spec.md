# 第二阶段 PRD：本地生产出图与可复现交付

2026-10-12。首期已按本地渲染引擎、CLI 与 M402 结构及行为验收；本期把它推进到可批量交付、可追溯和可重放的本地出图工具。本文是第二阶段规格，不扩大首期合格声明。

## Problem Statement

模板设计者已经能用数据定义、模板与数据集出一张线路牌，但交付工作仍需自己写脚本：逐次更换本站序号，管理输出目录，识别失败项，再确认图片有没有被上一张覆盖。正式图片也缺少完整出图记录；模板、数据集或资源文件一旦修改，仅凭原请求不能重现当时的图片。

此外，已确定的模板元素中，二维码与条形码仍未实现。查询链接和资产编号只能先在外部生成图片，无法直接由模板绑定文本生成，也无法在出图时统一检查内容是否合法、尺寸是否足够。

本期解决三个可独立核对、最终串成闭环的问题：模板直接生成码图；一个模板显式列出多个渲染项并逐项交付；交付后能脱离当前工作区，使用出图记录重放。资源内容版本是第三项的必要依赖。

## Solution

保留框架无关的渲染引擎与本地 CLI，新增二维码、条形码，提供有资源内容版本的本地资源仓库，以及批量出图、出图记录读取和重放能力。批量出图先串行执行，每项独立校验、独立落盘；正式成功项必须同时完成图片与出图记录的交付，失败项保留问题清单，继续处理其他可执行项。

首个交付场景为：以 M402 的 35 个停靠站点显式列出 35 个本站渲染项，得到可核对的清单与图片；另用独立的扩展模板验证查询二维码和资产条形码。之后修改当前模板、数据集和资源，再从原出图记录重放，图片、问题清单及布局摘要仍与原交付一致。既有 M402 样例继续作为兼容基线。

### 范围选择与依据

| 能力 | 本期判断 | 依据及边界 |
|---|---|---|

| 批量出图与逐项结果 | 必做 | M63；显式列出各项，不做“每站一张”的自动展开语法 |

| 动态模板、循环过滤/反序/附加项 | 后续候选 | M13、M22 与元素模型已明确为扩展；本期交付场景不依赖它们 |

### 完成标准

本期范围全部为必交付项，不以“支持批量但不能重放”代替闭环。完成必须同时满足：码图能从最终 PNG/JPEG 独立解码；混合成功/失败批次正确交付；旧资源替换后历史可重放；已有首期测试及 M402 基准无回归；长批次和文件故障验收通过；新使用者能按文档完成一次出图、定位失败并重放记录。

## Implementation Decisions

以下为本轮规划决定；M10、M59、M63、M67 等既有规则继续有效。没有实施的能力不得写入“当前支持”清单。

### 渲染能力与 DSL

1. 保持 TypeScript、框架无关引擎、CanvasKit 合成和显式资源字体；编码器只负责生成二维码或条形码的符号结构，最终图片仍走现有渲染流水线。编码依赖的版本、许可证、跨平台输出和独立解码可行性在首个实施单元中验证，不在 PRD 中预选库名。
2. 二维码内容为固定文本或文本变量绑定，支持 L/M/Q/H 纠错等级，缺省 M；条形码明确指定 CODE128、EAN-13、EAN-8 或 UPC-A，格式不绑定变量。CODE128 本期接受可打印 ASCII；其他三种接受包含校验位的完整数字文本，保留前导零，错误时拒绝，不自动猜补或改写编号。二维码支持中文、数字和 URL 文本，URL 只编码为内容，不访问网络。
3. 两类元素沿用名称、位置与尺寸、显隐和状态样式；内容与颜色可绑定，元素种类不可绑定。二维码不得非等比拉伸；条形码不得靠压缩字形一类策略放入过小空间。码区与必要留白必须共同落在元素内容区内；为避免无约束的自然尺寸，本期码元素要求能解析出确定的宽高，不支持自身随内容尺寸。
4. 缺省黑码白底，前景和背景必须不透明且不同色。码区按最终 DPI 决定整数像素模块尺寸；本期可交付配置要求最窄模块至少 2 px，这是产品验收下限，不宣称为通用印刷标准。必要留白按所选编码格式保留且不可关闭；不足时返回严重问题。条形码下方文字在码区之外预留空间，使用指定资源字体并沿用文字缺字规则。
5. 空内容、非法内容、编码容量不足、尺寸不足等问题使用稳定问题码和元素路径；草稿不绘制看似有效的错误码，只显示可定位的问题框，正式出图阻断。隐藏元素沿用现有静态检查与运行时不求值规则。草稿和正式的问题清单一致。最终布局摘要增加码种、码区尺寸、留白及模块像素尺寸，保留现有摘要字段的含义。
6. 新增语法按现有英文结构关键字和变量命名约定记录；旧模板省略新字段时行为不变。实际 DSL 字段名在实施前随可执行样例一并定稿，不能仅在解析器中暗增写法。共享样例同步补充文档和独立扩展样例，不覆盖已发布静态数据定义或为增加码图擅改原 M402 数据集。

### 资源内容版本

7. 扩展现有资源仓库抽象，提供按资源 ID 与内容版本读取的能力；增加本地导入、查询版本、替换前检查和应用替换的公开接口及 CLI。资源种类创建后不可改变，内容版本为该资源内自增的正整数，每次成功替换增加版本，即使字节相同也保留这次替换。内容哈希用于完整性检查与去重，不代替内容版本号。
8. 旧的无内容版本资源清单仍可供现有单次渲染使用。进入本期正式交付前，显式导入到新资源仓库，保留资源 ID、种类和字节，首个内容版本为 1；不原地改写旧夹具或静默把变化后的文件当成同一版本。
9. 替换前列出调用方指定的当前工作区中直接引用资源的模板与数据集，包括模板固定引用、状态样式、图片参数默认值及数据集图片字段；后备字体和 SVG 字体配置单独列为影响来源。影响检查不能声称覆盖尚未提供的其他工作区。应用替换需明确提交已检查的预期内容版本及工作区内容指纹，任一已改变则拒绝并要求重新检查；没有引用方的替换也走同一版本检查。
10. 历史内容不可覆盖。本期不提供资源删除、历史清理或完整资源管理界面；替换写入失败或同一资源并发替换时，旧当前版本仍可读取，只有一个基于预期版本的替换成功。外部直接改写仓库文件导致哈希不一致时报告损坏，不默默登记新版本。

### 批量出图与交付

11. 批量请求包含一个根模板、批次模式与非空渲染项列表；每项有批次内唯一标识、数据集、对外参数和出图参数。模式在批次内统一，草稿与正式分开运行。先校验批次外层结构、标识唯一性和项数上限，再逐项沿用现有渲染规则；默认上限 1,000 项，超出时拒绝并提示拆批。这是本地产品边界，不改变静态数据定义中的列表约束。
12. 外层结构错误、重复标识、根模板无法准备或交付目标不可建立，整批拒绝且不产生成功项；渲染项的数据、参数、尺寸或编码内容错误仅使本项失败。工作区本身的严重读取问题沿用首期拒绝规则。每项结果按输入顺序保留标识、状态、问题清单和可用的布局摘要；正式有严重问题时没有交付图片，草稿允许有严重问题但必须标明模式。
13. 默认只运行一个渲染项。公开批量入口逐项提供完成结果、进度和交付引用，并最终给出汇总；不把所有图片字节积累到最终返回值。每项仍调用同一渲染引擎，不复制检查、求值或布局逻辑。既有单次渲染与发布入口保持兼容；本期新增正式交付入口支持只有一个渲染项的请求，单次纯渲染接口仍不承担文件持久化。
14. 开始执行前固定工作区文档、各项数据与参数、渲染选项及资源当前版本映射；执行中使用固定的内容版本，不能每项重新读取“当前版本”。准备阶段发现输入变化或无法形成自洽集合时拒绝启动；不承诺对任意外部文件编辑器提供多文件事务。
15. 输出使用本次运行独占的新目录和受控生成的子目录名称，用户提供的项标识只作为数据保存，不能直接成为文件路径。已有目标拒绝覆盖，包括并发竞争；不复用单次 CLI 清理固定成果的策略。每项独立提交，成功图片、问题清单、摘要及正式出图记录均完整后才标记成功。单项可捕获写入失败不破坏其他成功项；存储整体不可用时停止调度，后续项标记未执行并给出原因。
16. 取消在项与项之间生效；当前正在渲染的一项完成并交付后停止，不宣称能中断同步 WASM 绘制。已完成成果保留，其余标记未执行。进程意外退出时已完整提交的项仍有效，未完成内容不能被读取为成功记录；不提供自动续跑或自动重试，可把失败和未执行项显式组成新批次。
17. CLI 约定：全部项按所选模式产出完整成果返回 0；业务失败、部分失败、目标冲突或 I/O 失败返回 1；命令用法或请求文件读取/解析错误返回 2；主动取消返回 130。草稿返回 0 只表示预览成果完整，汇总仍必须列出严重问题数量，不表示可正式交付。

### 出图记录与重放

18. 本期新增正式交付入口的每个成功项都有不可变出图记录；草稿和正式失败项保留运行结果，但不标记为正式出图记录。记录包括根模板及可达被调模板内容、实际数据集、相关静态数据定义及编译产物、实际请求与参数、渲染选项、资源 ID/种类/内容版本及字节、渲染器构建标识、问题清单、布局摘要和原图片摘要。各层被调模板基准及被引用定义的闭包必须完整。
19. 记录固定能影响结果的字体集合，包括后备字体与 SVG 字体配置；实际可用字体的字节随记录保存，缺失候选的状态也需固定，重放不得从本机补入后来安装的字体。资源先按固定版本供渲染读取，记录保存同一份字节，不能渲染后另读一次当前文件。
20. 本地出图记录使用独立格式版本，记录目录可整体复制并脱离原工作区读取；所有引用均限于记录内部，文件内容有哈希。同一卷上的不可变内容可用硬链接去重，但每份记录必须持有自己的文件入口，复制后仍自足，删除其他记录不能破坏它；不支持时回退独立复制，不能用依赖外部路径的符号链接代替。先完成内容文件，再发布完整性清单；损坏、缺失和不支持的记录版本必须明确拒绝。此取舍见 ADR-0013。
21. 重放是独立公开入口，只接收记录及输出目标，重新执行渲染并比较图片、问题清单与布局摘要，不是简单返回归档图片。使用兼容的确切渲染器构建和记录内容；构建标识涵盖实际引擎与依赖，不能仅依赖可能重复的包版本或 Git 提交号。构建不匹配则拒绝，不自动下载或执行记录携带的程序。时间、记录标识和存储位置不参与图片与布局的确定性比较。
22. 记录使输入可保存，不承诺任意未来版本都能像素一致；本期保证相同构建及锁定依赖在已验收平台上重放一致，所需旧构建不可取得时明确说明不能重放。记录包含业务数据与字体/图片原文件，使用指南须说明其内容及交接范围。

## Testing Decisions

### 接缝与既有实践

- 元素能力主要通过现有公开渲染入口验证问题清单、布局摘要和最终图片；批量交付及记录主要通过新增公开批量入口与重放入口验证。资源导入/替换通过其公开接口验证，因为版本冲突与替换影响无法只靠渲染观察。CLI 只补参数、退出码、文件冲突、取消及交付完整性测试。
- 测试接缝已按 to-spec 第 2 步向用户发起偏好核对；未收到不同偏好时采用上述入口作为本规划默认，不将未回复记作用户确认。
- 好的测试给出业务输入，断言能交付什么、哪里失败、已有内容是否保持以及能否重放。不断言内部编码器函数、临时元素树、数据库形状或私有模块调用次数；不为镜像实现的辅助函数单独造测试。
- 复用现有公开渲染测试、M402 端到端测试、草稿/正式诊断一致性测试、CLI 故障测试、golden 对比与跨平台脚本。编码器输出须由独立解码实现从最终图片读回，避免用同一个编码器证明自身正确。少量 golden 用于画面布局，不能代替可解码性。

### 验收矩阵

| 编号 | 场景与观察点 | 通过条件 |
|---|---|---|
| A01 | 首期兼容性 | 现有 364 个测试作为基线继续通过；共享 M402 11 份 JSON、基准图片及摘要无非预期变化；不以更新 golden 掩盖回归 |
| A02 | 二维码 | 数字、中文、URL 文本，四种纠错等级，固定值/字段/参数来源；最终 PNG/JPEG 在 120/300 DPI 的合格尺寸下独立解码为完整原文 |
| A03 | 四种条形码 | 合法完整编号（含前导零）、显示/隐藏文字、资源字体；120/300 DPI × PNG/JPEG 均能独立读回原编号，不能只比较编码器返回值 |
| A04 | 码图失败与样式 | 空值、错误类型、长度/字符/校验位不合法、容量与模块尺寸不足；同色或透明颜色拒绝；草稿定位、正式阻断，两个模式诊断一致；旋转 90°和循环实例定位有回归 |
| A05 | 35 张真实批次 | 显式列出 M402 本站 1–35，每项高亮及末站行为正确；清单恰好 35 项，标识与顺序一致，逐项对照单次渲染结果相同 |
| A06 | 混合失败与外层拒绝 | 在合法项之间放入本站 36、错误数据版本和非法码；仅错误项失败；重复项标识、空项列表和超项数则执行前整批拒绝 |
| A07 | 草稿与取消 | 草稿含严重问题仍保留问题清单；取消后已有成果完整，下一项不再启动，剩余项为未执行；CLI 退出码及汇总符合约定 |
| A08 | 资源版本与冲突 | 原资源导入为 v1，替换为 v2，引用不变而新图片变化；v1 字节仍可读；种类改变拒绝；两个基于 v1 的并发替换恰好一个成功；陈旧影响报告被拒绝 |
| A09 | 自足重放 | 正式出图后修改根模板、子模板、数据集、资源和字体配置；将记录复制到独立位置并令原工作区及其他记录不可用；重放与原图片、问题清单和布局摘要一致；去重与独立复制两种存储路径均验证 |
| A10 | 拒绝不完整记录 | 分别删除/改写资源、模板、编译产物，修改清单引用、记录版本或构建标识；均明确失败，不回退当前工作区，不把旧图片作为重放成功结果 |
| A11 | 写入与进程故障 | 目标已存在、并发目标冲突、资源替换失败、图片或记录写入失败、中途进程退出；原有成果不变，完整项可读，半成品不标记成功，最终状态不虚报 |
| A12 | 长批次与输入不变 | 同一固定 M402 请求预热 50 次后顺序交付 1,000 项，图片/摘要一致、源输入不变；采样全过程 RSS，最后 50 项 RSS 中位数较预热后 50 项中位数增长不超过 256 MiB；记录峰值、耗时、磁盘用量及环境，失败必须解释并修复，不能直接放宽阈值 |
| A13 | 运行中编辑 | 批次中修改当前模板或替换资源；本批仍全部使用启动时固定内容，下批使用新内容；不存在同批混用 |
| A14 | Windows/Linux | 锁定依赖和字体，两个平台全新安装、构建及测试；M402、码图和出图记录重放的图片及布局哈希一致，记录时间与路径不参与比较 |
| A15 | 使用指南 | 在临时工作区照文档完成导入资源、35 项批次、一次失败定位、一次版本替换和独立重放；记录实际命令、退出码及成果，代码内知识不能作为隐含前提 |

码图可解码的验收采用不被遮挡、未裁剪、不透明的黑白基准及明确列出的彩色样例；任意叠放遮挡、打印设备和实物扫码环境不属于保证范围。整数模块和 2 px 下限不能单独证明可扫码，独立解码失败仍视为验收失败。

A12 是本地批次回归门槛，不是服务容量认证；默认串行和项间取消也不构成超时或恶意输入隔离。阶段收尾仍执行全量测试、类型检查、构建、两轴代码审查，并产出第二阶段验收文档。

存储预算也需验证：当前四份思源黑体文件合计约 32.6 MiB，若每条记录独立复制，1,000 项仅字体就约 31.9 GiB。A12 优先在支持不可变文件去重的本地卷执行并记录实际磁盘增量，另用小批次验证无去重的复制与移交路径；不能为了省空间省略历史字体。

## Out of Scope

- HTTP 服务、数据库和对象存储选型、多用户、鉴权、任务队列、多进程并行、强制执行超时、自动重试与断点续跑。受控本地输入是本期运行前提；接入服务前另做最大展开规模、CPU/内存预算和进程隔离。
- MCP、CloudKiln、OCR 与业务 Agent 任务；它们仍遵守只读工具、每轮凭据及人工应用边界。
- 数据定义编辑界面、数据集表单与迁移、模板升级及协同工作副本、可视化编辑器、资源删除和历史回收。已有静态定义不可变规则不变。
- URL 图片抓取、网络安全校验器及远程字体。二维码内容是 URL 文本不意味着支持网络图片。
- 动态模板、循环过滤/反序/前后附加项、自动两排站点、纵向循环、自动网格扩展、文本表达式或脚本。
- 段落换行、复杂文字塑形、双向排版、额外码种、码内 logo、艺术二维码、GS1 业务语义、实物打印质量认证。
- M402 像素级复刻、替换商业素材或字体；原结构与行为验收约定不变。
- 分发历史渲染器运行包、跨渲染器版本迁移旧记录、把任意不受信任记录作为可执行程序运行。

### 实施顺序

1. 码图能力验证与 DSL 样例：先确认编码、独立解码、尺寸失败及跨平台行为，再接入模板静态检查、布局与绘制。
2. 资源内容版本：完成旧资源导入、按版本读取、替换影响与并发保护。
3. 单个渲染项的正式交付与重放：先把只有一项的批量请求闭环做完整，再扩展列表调度。
4. 批量调度与 CLI：逐项结果、混合失败、取消、清单和成果保护。
5. 全阶段验收：35 项场景、1,000 项稳定性、跨平台重放、首次使用文档和两轴审查。

以上是依赖顺序，不是已经创建或实施的票据。本规格发布在本地 Markdown issue tracker，状态为 `ready-for-agent`；后续拆票从本目录的 01 开始，不续接首期的票据 15。接口内部组织和库选型交给实施，外部行为及验收条件以本文为准。
