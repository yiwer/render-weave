# 01: 渲染骨架：一个文本字段从数据集到 PNG

**What to build:** 搭建 TypeScript 工程与测试，打通渲染入口与命令行的最小链路：一份只有一个文本字段的静态数据定义、一个"画板加一个文本元素"的模板（文本元素在画板上按固定位置与尺寸摆放，内容是绑定该字段的变量插槽）、一份数据集，依次经过数据集校验、求值、排版、栅格化，输出 PNG 或 JPEG，同时返回问题清单与布局摘要。这张票确立后续所有票共用的工作区形状、渲染请求形状、资源仓库、元素路径、问题清单结构与"测量、决定、记录、绘制"的排版分步。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 工程为 TypeScript、Node 22；引擎模块不依赖任何框架；一条命令运行全部测试。
- [x] 渲染入口接收工作区（静态数据定义、模板、数据集、资源仓库目录）与渲染请求（模板名、数据集、对外参数、出图参数、模式），返回图片、问题清单与布局摘要；命令行把三者写到指定的输出目录。
- [x] 渲染请求的数据集既可以引用工作区中的数据集，也可以直接附带数据集 JSON，两种方式各有测试。
- [x] 命令行退出码：出图成功为 0；正式出图因严重问题未出图、或输入无法读取时为非 0。
- [x] 工作区中的静态数据定义附带编译产物 JSON Schema；渲染入口只读取编译产物，出图时不编译（M103）。本票的编译产物是手写夹具，发布与编译由 03 提供。
- [x] 文件形式的资源仓库：按资源 ID 定位文件并区分图片资源与字体资源，资源引用写成 `res:资源ID`；后续各票沿用（图片元素见 05）。
- [x] 栅格化使用 CanvasKit；字体全部从资源仓库显式加载，不使用系统字体（M99）。
- [x] 准备脚本获取固定版本的思源黑体（SIL OFL）并核对 SHA-256，字体文件不进版本库。至少包含 M402 用到的 Medium 与 Heavy 两个字重，并注册为 M402 模板引用的 `res:font-hei-medium` 与 `res:font-hei-heavy`；11 的按字重替代所需的字重也在此列出。
- [x] 排版分为测量、决定、记录、绘制四步：布局摘要在绘制前生成，至少包含画板与每个元素的元素路径、实际位置与尺寸（毫米）、是否显示，文本的最终字号。
- [x] 元素路径由模板调用链上的元素名称逐层组成，循环容器处带循环序号（从 1 开始），例如 `标准线路单边/站点面板/站点列[12]/名称区/站名`；问题清单、布局摘要与草稿预览的标注共用同一种元素路径（M101）。本票只有一层，但结构按多层与循环序号设计；模板内元素名称重复时返回严重问题。
- [x] 毫米换算像素：像素数 = 毫米 ÷ 25.4 × DPI，四舍五入为整数（M100）；PNG 写入 DPI 元数据（pHYs），JPEG 写入 DPI 元数据。测试覆盖 740 × 165 mm、120 DPI 得到 3496 × 780 像素。
- [x] 数据集按编译产物 JSON Schema 用 ajv 校验；必填字段缺失时返回严重问题。
- [x] 实际尺寸超出画板适用尺寸范围时返回严重问题。
- [x] 问题清单每项包含稳定的问题代码、等级（提示或严重）、位置（字段路径、参数名、元素路径或检查项名）与中文说明；后续各票沿用这一结构。
- [x] 正式出图存在严重问题时不输出图片（草稿预览与检查顺序见 12）。
- [x] 同一平台上同样的输入两次渲染，布局摘要与图片字节都相同。
- [x] golden 图片对比工具：按像素差阈值比较，失败时生成"预期、实际、差异"三联图（参照 busbox-render-engine 的做法）。
- [x] 渲染入口的测试覆盖：正常出图、必填缺失、尺寸超出适用范围。

## Comments

**2026-10-09 实施完成。** `npm test` 24 个用例全过，`npm run typecheck` 无错误，`npm run build` 后 `node dist/bin.js` 出图正常。

实现要点：

- 渲染入口 `render(workspace, request)`（`src/render.ts`）；工作区读取 `loadWorkspace`（`src/workspace.ts`）按文件内容归类，`docs/examples/m402-dsl` 可以直接作为工作区；命令行 `src/cli.ts`，退出码 0 已出图、1 未出图、2 用法错误或请求无法读取。
- 排版四步：`src/layout.ts` 测量、决定、记录（布局摘要与绘制指令），`src/draw.ts` 只按指令绘制。
- 文字逐字排列（字形 ID 加前进宽度），行框取 OS/2 typo 上下高度，思源黑体随内容高度等于字号（M106）。缺字时字形 ID 为 0，票据 11 可直接在这一层判断。
- CanvasKit 必须用 full 构建：默认构建 `encodeToBytes(JPEG)` 返回 null（已实测）。
- 准备脚本 `scripts/fetch-fonts.mjs` 下载思源黑体 2.005R CN 子集的 Regular、Medium、Bold、Heavy 四个字重并核对 SHA-256；资源仓库 `fixtures/resources/resources.json` 注册为 `font-hei-regular/medium/bold/heavy`。
- 补充的 DSL 写法 S14–S17 见 `docs/examples/m402-dsl/README.md`（M105）；字段路径列表序号从 1 开始（M107）。
- golden 工具 `test/support/golden.ts`：通道差 ≤ 2、差异像素比例 ≤ 0.1%；人为替换 golden 后确认会失败并生成三联图。

未验证：本机是 Node 24.12，`engines` 声明 `>=22`，未在 Node 22 上实际运行；所用 API（`parseArgs`、`fetch`、`structuredClone`）在 Node 22 均可用。Node 22 下载字体若需代理，要设置 `NODE_USE_ENV_PROXY=1`。
