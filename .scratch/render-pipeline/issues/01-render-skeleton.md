# 01: 渲染骨架：一个文本字段从数据集到 PNG

**What to build:** 搭建 TypeScript 工程与测试，打通渲染入口与命令行的最小链路：一份只有一个文本字段的静态数据定义、一个"画板加一个文本元素"的模板（文本内容是绑定该字段的变量插槽）、一份数据集，依次经过数据集校验、求值、排版、栅格化，输出 PNG 或 JPEG，同时返回问题清单与布局摘要。这张票确立后续所有票共用的工作区形状、渲染请求形状、问题清单结构与"测量、决定、记录、绘制"的排版分步。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 工程为 TypeScript、Node 22；引擎模块不依赖任何框架；一条命令运行全部测试。
- [ ] 渲染入口接收工作区（静态数据定义、模板、数据集、资源仓库目录）与渲染请求（模板名、数据集、对外参数、出图参数、模式），返回图片、问题清单与布局摘要；命令行把三者写到指定的输出目录。
- [ ] 栅格化使用 CanvasKit；字体全部从资源仓库显式加载，不使用系统字体（M99）。
- [ ] 准备脚本获取固定版本的思源黑体并核对 SHA-256；字体文件不进版本库。
- [ ] 排版分为测量、决定、记录、绘制四步：布局摘要在绘制前生成，至少包含画板与每个元素的名称、实际位置与尺寸（毫米）、是否显示，文本的最终字号。
- [ ] 毫米按 DPI 换算像素；PNG 写入 DPI 元数据（pHYs），JPEG 写入 DPI 元数据。
- [ ] 数据集按编译产物 JSON Schema 用 ajv 校验；必填字段缺失时返回严重问题。
- [ ] 实际尺寸超出画板适用尺寸范围时返回严重问题。
- [ ] 问题清单每项包含稳定的问题代码、等级（提示或严重）、位置（字段路径、参数名、模板名加元素名称或检查项名）与中文说明；后续各票沿用这一结构。
- [ ] 正式出图存在严重问题时不输出图片（草稿预览的行为见 11）。
- [ ] 同一平台上同样的输入两次渲染，布局摘要与图片字节都相同。
- [ ] golden 图片对比工具：按像素差阈值比较，失败时生成"预期、实际、差异"三联图（参照 busbox-render-engine 的做法）。
- [ ] 渲染入口的测试覆盖：正常出图、必填缺失、尺寸超出适用范围。
