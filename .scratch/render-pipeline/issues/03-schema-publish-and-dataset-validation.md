# 03: 数据把关：发布静态数据定义与完整的数据集校验

**What to build:** 提供"发布静态数据定义"入口（规格中的次接缝）：把数据定义 DSL 发布为静态数据定义，并编译出 JSON Schema 2020-12，工作区中的编译产物从此由发布生成，取代 01 的手写夹具。渲染入口的数据集校验扩展到全部字段类型与约束，并检查数据集选定的版本与模板基准是否一致。

**Blocked by:** 01

**Status:** resolved

- [x] 支持全部字段类型：文本、数值、日期、时刻、时间、布尔、图片、列表、数据定义引用；各类型可用的约束（必填、长度、范围、整数、枚举、正则、项数、图片允许来源）按类型校验。
- [x] 发布时检测约束冲突（如最小长度大于最大长度、下界大于上界、枚举值违反其他约束），并拒绝引用成环、列表嵌套列表、引用不存在的静态数据定义版本，均返回问题。
- [x] 编译产物内联展开引用，不允许未定义的键，`title` 取显示名称，时刻与时间使用 `rw-time`、`rw-datetime` 自定义格式并附等价正则；M402 两份数据定义的编译产物与 DSL 草稿中的编译产物一致（快照测试）。
- [x] 数据集校验能定位到字段路径：必填缺失、值为 null、出现未定义的键、日期/时刻/时间格式错误、数值越界（数值按十进制精确解析与比较）。
- [x] 图片字段中的资源引用不存在、或指向字体资源时返回定位到字段路径的问题（使用 01 的资源仓库，不依赖 05）。
- [x] 数据集选定的静态数据定义版本与模板基准不一致时返回严重问题，属于阻止展开的问题（M102）。
- [x] M402 数据集校验得到 0 个问题。

## Comments

**2026-10-10 实施完成。** `npm test` 6 个文件 108 个用例全过（新增 50 个；CI 模式下 golden 只比对不改写），`npm run typecheck` 无错误。

实现要点：

- 数据定义模块 `src/schema/`：`parse.ts` 解析 DSL 并做约束检查与冲突检测，`compile.ts` 编译为 JSON Schema 2020-12（内联展开引用、发现成环与缺失），`publish.ts` 提供发布与重新编译两个入口；命令行新增 `renderweave publish`。
- 发布 M402 的"停靠站点""线路牌"两份定义，编译产物与草稿 `compiled-route-sign-v1.schema.json` 的内容与键顺序完全一致；停靠站点的编译产物与其中内联的部分一致，已作为 `compiled-stop-v1.schema.json` 补进草稿。
- 四个工作区（M402 草稿与三个夹具）中的编译产物都与发布结果一致，由测试持续核对；01 的手写夹具因此不再是手写的特例。
- 数据集校验新增：日期格式（标准 `date`，校验真实日期）、图片资源存在且是图片（`dataset.resourceNotFound`、`dataset.resourceKindMismatch`）、数值有效数字（`dataset.tooManyDigits`）；数据集版本与模板基准不一致时报 `dataset.staticSchemaMismatch` 并停止，两种模式都不出图。
- "十进制精确"按 M112 落实：数值限 15 位有效数字，此时双精度比较与十进制比较等价；工作区文件中超过 15 位的数字字面量借助 JSON.parse 的原文访问发现。ADR-0006 已补实现说明。
- M402 数据集校验 0 个问题：测试用内存资源仓库提供 7 个图片资源 ID，校验只看存在与种类，不依赖 05 的图片夹具。

未覆盖：直接以 JS 对象传入渲染入口的数据集，若数值在调用方解析时已失真（原文超过 15 位却读成短的双精度数），无法发现；命令行读取的请求文件可以发现。
