# 12: 检查顺序、草稿预览与正式出图

**What to build:** 确定渲染入口的检查顺序，以及两种模式在各类问题下是否出图：模板无法展开时两种模式都不出图；其余情况下，正式出图遇到严重问题就失败，草稿预览照常出图，在图上标出有问题的元素，缺值处显示占位，方便边改边看。

**Blocked by:** 01

**Status:** resolved

- [x] 检查顺序（M102）：先解析工作区与渲染请求；再执行模板静态检查、数据集校验、版本一致性与对外参数检查，这几项互不依赖，全部执行并汇总问题；存在阻止展开的问题时到此停止；否则依次求值（派生变量、检查项、条件显示、状态样式、循环与子模板调用）、排版、绘制。
- [x] 阻止展开的问题：模板或数据集无法解析、数据集的静态数据定义版本与模板基准不一致、模板调用成环、循环模板基准与列表元素不一致。出现时两种模式都不输出图片，只返回问题清单；问题代码能区分出这一类。本票用"模板无法解析"测试，其余几种在 03、08 中归入这一类。
- [x] 正式出图：存在严重问题时不输出图片，只返回问题清单与布局摘要。
- [x] 草稿预览：除阻止展开的问题外，即使存在严重问题也输出图片；有问题的元素按元素路径在图上以醒目边框标出；问题清单与正式出图得到的一致。
- [x] 草稿预览的占位（M104，落实 M16）：因问题而缺值的变量插槽显示该变量的显示名称作为占位（如"〔站名〕"），缺值的图片不画内容、只画问题边框；可选字段正常缺值时不显示占位。正式出图从不显示占位。
- [x] 无法定位到元素的问题（如数据集字段、参数）不画边框，只出现在问题清单中。
- [x] 渲染入口测试覆盖：同一份有严重问题的输入在两种模式下的输出差异；必填字段缺失时草稿显示占位；模板无法解析时两种模式都不出图。
