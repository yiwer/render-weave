# 渲染流水线首版：M402 线路牌从数据定义到 PNG

## Problem Statement

RenderWeave 已经完成需求探索与业务实体建模（M1–M97、ADR-0001–0010），并用真实设计稿 M402 写出了 DSL 草稿：静态数据定义、编译产物 JSON Schema、数据集、五个模板与渲染请求。但这些规则目前只存在于文档和 JSON 样例中，没有任何程序能校验它们、把模板和数据集变成图片。

模板设计者无法验证"站名按站数分档、长站名纵向压缩、相邻同名道路合并、本站高亮"这些规则在真实画面上是否成立；后续的 MCP 服务、业务 Agent 任务和在线编辑器也都缺少一个可以调用的渲染能力。按 ADR-0003，应先在不接入 agent 的情况下跑通首个场景的最小闭环。

## Solution

用 TypeScript 实现一套不依赖任何框架的渲染引擎和一个命令行入口：给定一个工作区（静态数据定义、模板与资源）和一次渲染请求（模板、数据集、对外参数、出图参数、草稿预览或正式出图），引擎依次完成数据集校验、模板静态检查、求值、排版与栅格化，输出图片、问题清单与布局摘要。

首版以 M402 DSL 草稿为主要样例：正式出图得到一张 740 × 165 mm、120 DPI 的 PNG，画面结构与设计稿一致；数据或模板有错时，问题清单能准确指出字段、参数或元素；2 站、50 站、长站名、1500 mm 宽度等变化下的排版结果可以通过布局摘要核对。另提供"发布静态数据定义"能力，把数据定义 DSL 编译为 JSON Schema。

## User Stories

1. 作为模板设计者，我想用一条命令把 M402 的模板、数据集与本站序号渲染成 PNG，以便确认模板规则在真实画面上成立。
2. 作为模板设计者，我想在草稿预览中即使存在问题也能得到图片，并看到出问题的元素被标出，以便边改边看。
3. 作为模板设计者，我想在正式出图遇到严重问题时得不到图片、只得到问题清单，以便不会交付错误的站牌。
4. 作为模板设计者，我想让每条问题都指出它来自哪个字段、参数、元素或检查项，并带有提示或严重等级，以便快速定位。
5. 作为模板设计者，我想在本站序号为 0 时所有站点显示为普通状态，以便同一模板也能出不标本站的线路牌。
6. 作为模板设计者，我想让序号小于本站序号的站点显示为已过站样式、等于本站序号的站点显示高亮底框与红字，以便呈现本站。
7. 作为模板设计者，我想在本站序号超过站点数时得到"本站序号超过了停靠站点数"的严重问题，以便不会静默输出全部已过站的错误图。
8. 作为模板设计者，我想让"开往"后显示站点列表末项的站名，以便不必在数据中重复填写终点站。
9. 作为模板设计者，我想让"下一站"显示本站后一站的站名与地标，本站是末站或未标本站时整行隐藏，以便底栏信息正确。
10. 作为模板设计者，我想让地标缺失的站点由站名占满整列，以便隐藏元素不留空位。
11. 作为模板设计者，我想让站名按站数分档得到统一字号，并把字号经对外参数传入站点模板，以便同一块牌上字号一致。
12. 作为模板设计者，我想让放不下的竖排站名先收紧字距、再纵向压缩字形（最多到原高 60%），以便长站名不缩小字号也能放下。
13. 作为模板设计者，我想在压缩到下限仍放不下时得到定位到该站名的严重问题，以便调整版式或数据。
14. 作为模板设计者，我想在站数多到列宽放不下时让同一缩字组的全部站名统一缩小字号，且不低于最小可读字号 5 mm，以便既能放下又保持一致。
15. 作为模板设计者，我想让横排短文本先横向压缩字形（最多到原宽 60%）再缩小字号，跨度大时拉开字距铺满，以便道路名在一列或多列中都排得好看。
16. 作为模板设计者，我想让道路带按"所在道路"合并相邻同值站点，每段横跨对应的站点列并与站点列对齐，以便还原设计稿的道路带。
17. 作为模板设计者，我想让每个合并段的左侧画分隔线、首段不画，以便段与段之间清楚分开。
18. 作为模板设计者，我想让班次时刻按内容宽度排成一行、项之间以"/"分隔、末项后不加"/"，以便呈现时刻表。
19. 作为模板设计者，我想让标识列表中的"地铁""医院"分别显示对应图标，以便站名上方的标识正确。
20. 作为模板设计者，我想在有线路号图片时显示图片、没有时显示倾斜描边的线路号文字，以便兼容两种素材。
21. 作为模板设计者，我想让站牌宽度在 740–1500 mm 内变化时重新排布、站点列随之变宽、字号不变，以便同一模板适配不同尺寸的站牌。
22. 作为模板设计者，我想在实际尺寸超出模板适用尺寸范围时得到严重问题，以便不会用错模板。
23. 作为模板设计者，我想让被调模板以调用框尺寸重新排布，调用框随内容时取其内容的自然尺寸，并检查是否落在其适用尺寸范围内，以便子模板与循环模板的尺寸行为可预期。
24. 作为模板设计者，我想用堆叠、网格与自由三种布局方式组织元素，其中自由布局可以距右或距下定位，以便适配可变尺寸的容器。
25. 作为模板设计者，我想用固定、随内容、填满三种方式设定元素的宽和高，以便表达设计稿中的比例关系。
26. 作为模板设计者，我想绘制矩形、椭圆、线条、多边形与 SVG 语法的路径，坐标以毫米计且不随框拉伸，以便画出箭头、底带收尾等异形外框。
27. 作为模板设计者，我想用状态样式按某个变量的取值覆盖元素属性（颜色、填充、透明度、是否显示、图片来源等），未列出的取值沿用元素自身属性，以便表达多种站点状态。
28. 作为模板设计者，我想让文本由文字片段与变量插槽组成，每个片段可单独设字体、字号、颜色、字重与倾斜，插槽带展示格式（如 HH:mm、0.##），以便写出"票价：一票制2元"这类文本。
29. 作为模板设计者，我想让字体缺字时按字重用思源黑体逐字替代，替代成功记为提示、仍缺字记为严重问题，以便生僻站名不会印成方框。
30. 作为模板设计者，我想让绑定在缺值时得到空值而不是设计时的占位内容，以便成品不会印出占位文字。
31. 作为模板设计者，我想在模板引用了不存在的变量、路径穿过非单引用、名称重复时得到定位到元素的问题，以便在出图前发现写错的地方。
32. 作为模板设计者，我想在循环模板的基准与列表元素的静态数据定义不一致、或循环参数填写了不存在或内部参数时得到问题，以便模板组合正确。
33. 作为模板设计者，我想在模板之间的调用关系成环时得到严重问题，以便不会无限展开。
34. 作为模板设计者，我想在绑定或状态样式的取值类型与属性类型不一致时得到问题，以便颜色、数值、图片不会混用。
35. 作为模板设计者，我想让必须提供而未提供的对外参数、超出约束的参数值都报问题，以便调用方传参正确。
36. 作为数据维护者，我想让数据集按其选定的静态数据定义的编译产物 JSON Schema 校验，以便数据结构错误在出图前被拦下。
37. 作为数据维护者，我想让数据集出现未定义的键时报错，以便字段改名后旧键不会被静默忽略。
38. 作为数据维护者，我想让必填字段缺失或写成 null 时报错、可选字段只能缺省，以便缺失与空值语义清楚。
39. 作为数据维护者，我想让时刻接受 `HH:mm` 或 `HH:mm:ss`、时间接受 `2025-01-02 09:08:12`、日期接受 `2026-01-02`，以便时间类数据格式统一。
40. 作为数据维护者，我想让数值按十进制精确解析与比较，以便票价等数值不受浮点误差影响。
41. 作为数据维护者，我想让图片字段中的资源引用必须存在于资源仓库且为图片资源，以便不会引用到字体或不存在的资源。
42. 作为数据维护者，我想在渲染时数据集选定的静态数据定义与模板基准版本不一致时得到严重问题，以便不会用错版本的数据。
43. 作为数据定义设计者，我想把数据定义 DSL 发布为静态数据定义并得到编译产物 JSON Schema，以便数据集有权威的校验依据。
44. 作为数据定义设计者，我想在约束彼此冲突（如最小长度大于最大长度、枚举值违反其他约束）、引用成环、列表嵌套列表时，发布被拒绝并得到问题，以便静态数据定义本身是自洽的。
45. 作为数据定义设计者，我想让编译产物内联展开被引用的静态数据定义，并为每个属性带上显示名称作为标题，以便外部工具也能理解。
46. 作为集成方开发者，我想通过一个与框架无关的函数调用渲染入口，以便日后在 MCP 服务、HTTP 服务与在线编辑器中复用同一套引擎。
47. 作为集成方开发者，我想在每次渲染的输出中得到布局摘要，包括每个元素的实际位置与尺寸、文本的最终字号、压缩比与缩字组结果，以便自动化测试和看不了图的 agent 也能核对排版。
48. 作为集成方开发者，我想让同样的工作区与渲染请求得到同样的布局摘要，以便结果可复现、可做快照测试。
49. 作为集成方开发者，我想让命令行把图片、问题清单与布局摘要写到指定目录，以便人和脚本都能使用。
50. 作为审核者，我想把 M402 正式出图结果与设计稿并排比较，以便确认首版达到设计稿的画面结构。

## Implementation Decisions

- 语言与运行时：TypeScript，Node 22。引擎是一组不依赖任何框架的模块；本期不使用 NestJS。服务外壳（HTTP API、持久化、鉴权、MCP 服务）在后续一期再选型，NestJS 是合理默认，但只承担外壳，不进入引擎。
- 工作区：本期的输入是一个本地文件集合，包含静态数据定义、模板、数据集与资源仓库目录。资源仓库首版为文件形式，以资源 ID 定位图片资源（PNG、JPEG、WebP、SVG）与字体资源（TTF、OTF），资源引用写成 `res:资源ID`。不做资源的上传、替换与版本记录。
- 模块划分：
  - 数据定义模块：解析数据定义 DSL，做结构检查与约束冲突检测，检查引用无环、列表不嵌套；发布为静态数据定义并编译出 JSON Schema 2020-12（内联展开引用，`additionalProperties: false`，`title` 取显示名称，时刻与时间使用 `rw-time`、`rw-datetime` 自定义格式并附带等价的正则）。这是次接缝。
  - 数据集校验模块：以 ajv 按编译产物校验，注册自定义格式；数值以保留原始数字文本的方式解析，数值约束与比较按十进制进行；再做图片资源引用的存在性与种类检查（类型自带检查，不属于可配置约束）。
  - 模板模块：解析模板 DSL，做静态检查：名称在模板内唯一（数据字段、参数、派生变量共用命名空间）；`{"var": …}` 与插槽路径可解析，只能经过单引用；派生变量声明了类型且运算数类型匹配；绑定与状态样式的取值类型匹配属性类型；循环模板基准与列表元素一致（基本类型对应单值数据定义）；参数填写只针对对外参数，未提供的必须有默认值；模板调用关系无环。
  - 求值模块：把模板、数据集与参数求值为一棵静态元素树。支持数据字段、对外参数与内部参数（默认值）、派生变量（条件分支、取项、长度、加减；取项超出范围得空值）、检查项、条件显示、状态样式、变量插槽与展示格式、循环容器（序号、是否首项、是否末项、总数、组内项数；按字段合并相邻同值项）、子模板调用（单引用字段、当前数据或无数据），作用域不继承。缺值绑定得空值，不回退到占位内容。
  - 排版模块：单位为毫米；校验实际尺寸落在画板适用尺寸范围内；实现自由（距左或距右、距上或距下）、堆叠、网格三种布局方式与固定、随内容、填满三种尺寸方式；循环项可等分宽度并按组内项数跨列；被调模板以调用框尺寸重新排布，随内容时取其内容的自然尺寸。文本排版支持横排与竖排、文字片段与插槽、两端分布、收紧与拉开字距、字形压缩（最多 60%）、缩小字号、缩字组、最小可读字号 5 mm、倾斜与描边，以及按字重的思源黑体逐字替代。输出布局摘要。
  - 栅格化模块：基于 Skia 把排版结果绘制为 PNG 或 JPEG，按 DPI 换算像素并写入 DPI 元数据。竖排与字形压缩若无法用 Skia 段落排版实现，则改为按字形逐个排版（如 HarfBuzz），仍在 TypeScript 中完成。
  - 渲染入口（主接缝）：接收工作区与渲染请求，依次执行数据集校验、参数校验、检查项、模板静态检查、求值、排版与栅格化，汇总问题清单。正式出图遇到严重问题时不输出图片；草稿预览总是输出图片，并在图上标出有问题的元素。
  - 命令行：对一个工作区执行渲染请求，把图片、问题清单与布局摘要写到输出目录。
- 问题清单：每项包含稳定的问题代码、等级（提示或严重）、位置（字段路径、参数名、模板名加元素名称、检查项名）与中文说明。
- 布局摘要：按模板调用层级列出每个元素的名称、实际位置与尺寸（毫米）、是否显示；文本另含最终字号、字距、压缩比、所属缩字组与是否发生字体替代。同样输入必须得到同样的摘要。
- 渲染请求沿用 M402 草稿的形状：模板名、数据集（引用工作区中的数据集或附带 JSON）、对外参数、出图参数（宽、高、DPI、格式）与模式（草稿预览或正式出图）。
- 字体：测试与样例使用思源黑体（SIL OFL）的固定版本，按 SHA-256 校验后放入资源仓库目录；字体文件不进版本库，由准备脚本获取。
- 样例：M402 DSL 草稿是首要样例；其语法若在实现中需要调整，同步修改草稿并重新做一致性检查（见 AGENTS.md）。

## Testing Decisions

- 好的测试只观察外部行为：通过渲染入口给出工作区与渲染请求，断言问题清单、布局摘要与少量图片；通过发布入口给出数据定义 DSL，断言编译产物或拒绝原因。不测试内部函数、中间数据结构或私有模块。
- 主接缝：渲染入口。场景至少包括：
  - M402 正式出图（本站序号 5）：无严重问题，布局摘要快照与预期一致，输出 740 × 165 mm、120 DPI 的 PNG。
  - 本站序号 0、本站为末站、本站序号超过站点数。
  - 2 站、20 站、35 站、50 站：站名字号分档与统一缩字。
  - 11 字长站名：字距收紧、纵向压缩比、超过下限时的严重问题。
  - 画板宽度 740 mm 与 1500 mm：列宽变化、字号不变；超出适用尺寸范围。
  - 道路带合并：分段数、跨列数与站点列对齐。
  - 数据集错误：缺必填、写 null、未定义的键、时刻格式错误、资源引用不存在或种类不对、静态数据定义版本与模板基准不一致。
  - 模板错误：未知变量、路径穿过列表、重名、循环模板基准不符、调用成环、类型不匹配、缺少必须的对外参数。
  - 缺字：替代成功为提示，仍缺字为严重。
  - 草稿预览在有严重问题时仍输出图片并标出问题元素。
- 次接缝：发布静态数据定义。断言 M402 两份数据定义的编译产物快照，以及约束冲突、引用成环、列表嵌套被拒绝。
- 断言以问题清单和布局摘要为主，它们是确定的结构化数据，适合快照测试；图片比对只保留少数几张，并允许像素级容差。M402 正式出图另做一次与设计稿并排的人工核对，作为首版验收。
- 仓库目前没有代码和测试，无既有测试可参照；M402 DSL 草稿及其已做过的一致性检查（JSON 合法、数据集按编译产物校验 0 错误、模板引用全部对上）是首批测试样例的来源。

## Out of Scope

- 业务 Agent 任务、MCP 服务、CloudKiln 接入与 OCR（ADR-0009）。
- 在线编辑器与任何 Web 界面。
- HTTP API、持久化、鉴权与多用户；数据定义的编辑与版本管理流程（本期只提供"发布"这一纯函数）、数据集迁移、模板升级。
- 批量出图、出图记录与历史复现。
- URL 图片及其安全校验；资源上传、替换与内容版本。
- 二维码、条形码元素与动态模板。
- 未在 M402 中出现的扩展能力：循环项过滤、反序、前后附加固定项等。

## Further Notes

- 依据：建模决定 M1–M97 与 ADR-0001–0010，术语见 GLOSSARY.md，样例为 M402 DSL 草稿与 M402 设计稿解读。
