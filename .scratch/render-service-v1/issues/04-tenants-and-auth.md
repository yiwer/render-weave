# 04: 平台管理员开通租户与成员，成员登录并管理 API 密钥，租户之间互相看不到

**What to build:** 租户、成员账号、角色、会话登录、API 密钥、代建工程师令牌、行级安全与审计日志。

**Blocked by:** 03

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「租户、账号与鉴权」；用户故事 1、19、20、21、39、40、42；验收 A03、A04；ADR-0018、M247。

- [x] 平台管理员能创建租户和成员账号，能重置密码。不做自助注册、第三方登录与邮件找回。
- [x] 成员用邮箱加密码登录，密码用慢哈希保存。
- [x] 客户管理员能管理本租户的成员与角色。
- [x] 客户管理员能创建和吊销 API 密钥：服务端只存哈希，创建时显示一次，吊销后立即失效。
- [x] 代建工程师令牌只能访问被指定的租户。
- [x] 按 M247 的权限矩阵逐项覆盖五种身份：客户管理员、客户操作员、API 密钥、代建工程师、平台管理员。
- [x] 隔离：
  - 鉴权后只拿到本租户的存储句柄，客户端不能提交对象键或路径；
  - 每张租户表开启行级安全，每个事务都设置当前租户；
  - 测试里故意漏写租户条件的查询，也查不到别的租户的行。
- [x] 维护一张跨租户端点清单：对其中每个端点，用另一租户的会话和密钥访问都被拒绝，也不泄露对象是否存在。后续票据新增端点时加进这张清单。
- [x] 写操作和跨租户操作追加写入审计日志，不记业务数据内容和密钥。客户管理员能查本租户的审计。
- [x] 仓库与日志中扫描 key 与密钥，命中 0。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API。内存后端覆盖权限矩阵，Docker 后端覆盖行级安全。

## Answer

2026-10-19 完成。决定见 M261（账号与鉴权）、M262（应用账号与行级安全，修订 M259 的迁移时机）、M263（服务的快速测试进 `npm test`），说明见[出图服务](../../../docs/service.md#账号与鉴权)。

**成果**

- **身份与令牌**：五种身份一律用 `Authorization: Bearer <令牌>`。
  - 会话、API 密钥与代建令牌是带前缀的随机串，服务端只存 SHA-256；
  - 密码用 scrypt 慢哈希保存，参数随哈希保存；
  - 初始密码与重置后的密码由服务随机生成，只显示一次。
- **端点**（`service/src/api/routes.ts`）：
  - 登录、登出与 `/v1/me`；
  - 平台管理员：租户、成员账号、重置密码、代建令牌；
  - 客户管理员：成员与角色、API 密钥、审计；
  - 代建工程师：读取被指定的租户。
- **权限**：路由只声明权限，权限按 M247 的矩阵分给五种身份（`service/src/api/permissions.ts`），后续端点沿用矩阵里的权限名。
- **后端抽象**：`service/src/backend.ts` 定义平台级操作与租户句柄，有两种实现：
  - 内存后端 `service/src/memory.ts`；
  - PostgreSQL 加 S3 后端 `service/src/postgres/backend.ts`。
- **隔离**：
  - 迁移 0002 建账号、会话、API 密钥、代建令牌与审计表，并给每张带 `tenant_id` 的表开行级安全；
  - 接口进程与 worker 改用应用账号 `renderweave_app` 连库，每个事务设置当前租户；
  - 迁移挪到部署步骤 `setup`，用属主账号执行；
  - 按邮箱登录与按令牌解析身份，由属主身份执行的两个函数完成。
- **跨租户端点清单**在 `service/test/cross-tenant-endpoints.ts`，后续票据新增端点时要加进去；漏列的端点会让测试失败。
- **测试**：开放 API 用例写一遍（`service/test/api-suite.ts`），两种后端共用。
  - 内存后端进根目录的 `npm test`：vitest 分引擎与服务两个项目，`pretest` 自动装服务依赖；
  - PostgreSQL 加 S3 后端在 Docker 后端测试里跑。
- **其他**：
  - 命令行 `platform-admin <邮箱>` 建第一个平台管理员；
  - `GLOSSARY.md` 加了成员、平台管理员、API 密钥、代建令牌四个术语。

**没做**：登录限频与锁定、成员自己改密码。没有出现在票据里，等控制台（票据 12）时再看。

**验证**

- **内存后端**（`npm test` 中的 11 项 API 用例）：
  - 平台管理员开通租户与成员；邮箱不区分大小写；密码哈希不含原文；
  - 登录失败两种情形的回答逐字相同；登出、过期（第 11 小时有效、第 13 小时失效）与格式不对的令牌都答 401；
  - 重置密码后旧密码与旧会话失效；
  - 成员与角色：停用即吊销会话，重新启用后旧会话仍无效；最后一个管理员不能降级或停用；
  - API 密钥只显示一次，列表里没有密钥本身，吊销后立即 401；
  - 代建令牌只认被指定的租户：访问别的租户与访问随机 ID 的回答逐字相同；过期与吊销后 401；
  - 权限矩阵：
    - 与 M247 的表逐项相等；
    - 18 个需要鉴权的端点 × 5 种身份加匿名，逐一断言；
    - 路由表里需要鉴权的端点必须都在矩阵里；
  - 跨租户端点清单：8 个端点 × 另一租户的管理员、操作员、密钥与代建令牌；
  - 审计：
    - 分页、跨租户标记；
    - 不含密码与令牌，也看不到别的租户；
    - 操作员与密钥读审计答 403；
  - 请求校验的问题码与位置；
  - 日志每行是 JSON，不含任何密码与令牌。
- **变异检查**：
  - 依次改坏：租户句柄不按租户过滤、操作员多给一项权限、停用不吊销会话、重置密码不吊销会话、代建令牌不查指定租户、新增端点不进清单、日志里写出令牌。7 处都让对应用例失败。
  - 对照的无害改动全过。
  - 起初漏掉"停用不吊销会话"：身份解析本来就拒绝停用账号。补了"重新启用后旧会话仍无效"之后才抓到。
- **Docker 后端**：`node service/scripts/test-docker.mjs` 从空环境构建并起服务，5 个文件、39 项通过，服务日志 10 行都是合格的 JSON。其中：
  - 同一组 11 项 API 用例跑 PostgreSQL 加 S3 后端。第一次跑时审计分页失败：`SELECT id::text … ORDER BY id` 按文本排序，与按数值翻页对不上。改为直接选 bigint 列后通过。内存后端测不到这一点。
  - 行级安全 6 项：
    - 每张带 `tenant_id` 的表都开了行级安全，测试覆盖全部 12 张；
    - 故意漏写租户条件，11 张租户表只返回当前租户的行；
    - 没设置租户时 12 张表都查不到；平台模式只看得到账号、会话、审计与代建令牌的租户表；
    - 越权插入被拒，漏写条件的更新只改到本租户；
    - 审计不能改不能删，应用账号不能删表、建表；
    - 应用账号直接查账号表查不到，只能经登录函数。
  - 健康检查确认服务用的是应用账号：不是超级用户，不能绕过行级安全，不拥有任何表。
- **Windows**：`npm run typecheck`、`npm run typecheck:service`、`npm run build` 通过；`npm test` 43 个文件、837 项通过（引擎 824 项不变，服务 13 项）。
- **Linux**（`node:22-alpine`，从 tar 在空目录安装）：构建、`typecheck`、`typecheck:service` 通过；`npm test` 自动安装服务依赖后，833 项通过，4 项 Windows 专用用例跳过。
  - 第一次跑时 `typecheck:service` 排在服务依赖安装之前而失败；
  - 改为它自己先确保依赖后通过。
- **key 与凭据扫描**：
  - `scan-keys` 扫描 369 个文件，命中 0；
  - 本机生成的 4 项凭据在 551 个待提交文件与 Docker 测试日志中命中 0；
  - API 用例另断言日志与审计里没有任何密码与令牌。
