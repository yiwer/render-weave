# 05: 代建工程师用一条命令把本地工作区与资源推送到客户的租户

**What to build:** 命令行推送命令，以及对应的服务端导入接口：先算差异，有冲突就整体拒绝，没有冲突就在一个事务里提交。

**Blocked by:** 04

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「代建导入」；用户故事 33、34、35、36；验收 A05；ADR-0017、M243。

- [x] 推送两类内容：
  - 本地工作区里的静态数据定义、编译产物、模板与样例数据集；
  - 资源版本仓库里的资源及其内容版本。
- [x] 推送前列出差异：新增、更新、冲突。可以只看差异、不提交。
- [x] 判定冲突：
  - 静态数据定义同名同版本、内容却不同（ADR-0008）；
  - 资源按 ID 和内容版本对比，种类不同。
  
  有冲突就整体拒绝，服务端保持原样。
- [x] 模板每推送一次记一个新修订，按名称指向当前修订，也可以把当前修订指回旧修订。
- [x] 文档按原始字节入库；推送后从服务端读回的字节与本地一致。
- [x] 推送凭代建工程师令牌鉴权。令牌只经环境变量传入，不出现在参数、日志和输出里；每次推送记审计。
- [x] 推送未初始化的目录或旧版资源目录时，问题说明与 M239 一致。
- [x] 决定记 M 编号；[代建指南](../../../docs/agent-guide.md)补上推送这一步。

**测试接缝：** 命令行推送命令，推送到内存后端的服务；结果经开放 API 读回核对。

## Answer

2026-10-19 完成。决定见 M264（推送的做法与冲突规则）与 M265（模板修订），说明见[出图服务](../../../docs/service.md#代建推送)，代建流程里的这一步见[代建指南](../../../docs/agent-guide.md)第 9 步。

**成果**

- **命令行**（`src/push.ts`，接进 `src/cli.ts`）：
  - `renderweave push --server --tenant --workspace --resources [--dry-run] [--token-env]`：读本地工作区与资源版本仓库，先请服务算差异，没有冲突时上传服务缺的内容，再请服务提交；
  - `renderweave template-revisions --server --tenant --template [--current <修订号>]`：列出模板的修订，或把当前修订指向某一修订；
  - 代建令牌只从环境变量读取，缺省 `RENDERWEAVE_AUTHORING_TOKEN`；命令行不接受令牌参数。
- **端点**（`service/src/api/authoring.ts`，全部只认令牌被指定的租户，在读请求体之前就判定）：
  - `POST …/push-plans` 算差异，`PUT …/contents/{哈希}` 上传内容，`POST …/pushes` 提交；
  - `GET …/workspace` 与 `GET …/contents/{哈希}` 读回，`POST …/template-current` 改当前修订；
  - 原来的 `GET /v1/authoring/tenants/{租户}` 也移到这里。
- **差异与冲突**（`service/src/push.ts`）：服务按自己的当前状态判定，提交时锁住租户的一行再重算；按原始字节的 SHA-256 比较。冲突是：定义或编译产物同名同版本字节不同、数据集同 ID 字节不同、资源种类不同或内容版本分叉。要写入的文档按内容重新归类，种类与键与声明不符就拒绝。
- **存储**：
  - 迁移 0003 加模板修订与当前修订两张表，开行级安全；修订对应用账号只能追加；
  - 推送进来的文档来源写成"种类:键"，模板那一行指向当前修订；
  - 两种后端都实现了内容存储、推送状态、推送提交与改当前修订。
- **引擎**：归类规则抽成 `classifyWorkspaceDocument`，本地读工作区与服务端核对共用，与 `parseJsonKeepingPrecision` 一起从公开入口导出。读工作区的行为与问题说明不变。
- **文档**：`docs/service.md` 加"代建推送"一节，端点、问题码与存储布局同步；代建指南加第 9 步；README 加推送一节；`GLOSSARY.md` 加推送、模板修订；`CODING_STANDARDS.md` 注明 `push` 是客户端，不算服务外壳。

**判断**

- **模板只在内容变了时记修订**：字节相同记为不变。票据写"每推送一次记一个新修订"，照字面会让无改动的推送刷出相同的修订（M265）。
- **数据集同 ID 字节不同算冲突**：票据只点名了定义与资源，但用户故事 34 要求不覆盖客户已有的东西，客户可以改数据集（票据 10）。要换样例就另起数据集 ID（M264）。
- **服务端资源比本地新时记为不变**：客户替换过的资源，本地落后时不覆盖，也不拒绝。
- **有冲突时命令行仍提交一次**：不上传内容，由服务拒绝并记审计 `push.reject`；"每次推送记审计"因此包括被拒的推送。

**验证**

- **推送用例**（`service/test/push-suite.ts`，8 项）：从 `src/cli.ts` 跑命令行，推送到本机端口上的服务，再经开放 API 读回。同一组用例跑两种后端：
  - 只看差异列出 4 份文档与 2 个资源的新增、跳过渲染请求，服务端不变；推送后 4 份文档与 2 个资源内容版本读回的字节与本地逐字节相同；再推一次全部不变，状态不变；
  - 模板改动记修订 2；`template-revisions` 列出两个修订，`--current 1` 后工作区里的模板回到修订 1 的字节，再看差异时本地算更新；不存在的修订与模板都拒绝，状态不变；
  - 定义同名同版本改了字节、同时改了模板：只看差异报 1 个冲突、1 个更新；推送整体拒绝，模板也没有记修订，服务端与之前逐项相等；数据集同 ID 改了字节同样拒绝；
  - 资源追加 v2 后推送，服务端有 v1、v2，v2 字节读回一致；另一个仓库里同 ID 的种类不同、v1 字节不同都是冲突，状态不变；只有 v1 的仓库记为不变，不覆盖 v2；
  - 资源目录不存在、或是旧版资源目录时，推送报的问题行与 `resources-list` 的逐字相同（M239），服务端不变；
  - 本地工作区模板重名时报 `input.duplicate`，不推送；
  - 接口层：上传内容与路径哈希不符、提交时内容没上传、种类或键或字节数与声明不符都拒绝；只上传没登记的内容读不到；清单里同键重复、内容版本不从 v1 起、资源 ID 不合规、未知种类都答 400；
  - 令牌：没设环境变量时退出码 2 并说出变量名；给 `--token` 参数是用法错误；缺省变量名可用；推送到没指定的租户答 `request.notFound`，伪造的令牌答 `auth.required`，连不上服务说"无法连接"；审计里有 1 次 `push.commit`、2 次 `push.plan`，都标为跨租户、记的是令牌标签；命令行输出、服务日志与审计里没有任何密钥的 16 字符片段。
- **权限矩阵与跨租户端点清单**：新加的 6 个端点进了两张表。权限矩阵 24 个端点逐一断言；跨租户清单 14 个端点，另一租户的四种身份访问 A 的租户，回答与访问随机租户逐字相同。
- **变异检查**：依次改坏 13 处：

  - 没登记的内容也能读、不按内容核对种类与键、资源分叉不算冲突、不查令牌指定的租户；
  - 资源目录不是版本仓库时照样推送、输出里带出令牌、数据集同 ID 当作不变、本地有严重问题照样推送、推送不记审计。
