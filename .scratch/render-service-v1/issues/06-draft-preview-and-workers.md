# 06: 经渲染 worker 进程同步出草稿预览，超时与内存超限的渲染被结束，worker 自动恢复

**What to build:** 任务队列、worker 的调度进程与渲染子进程、模板列表与只读查看接口、同步草稿预览接口，以及入队前的限制检查。

**Blocked by:** 05

**Status:** ready-for-agent

**Trace:** [阶段 4 PRD](../spec.md)「服务结构」「开放 API」；用户故事 2、3、11、38、45、46；验收 A06、A07；ADR-0017。

- [ ] 任务队列放在 PostgreSQL 里，worker 用 `SELECT … FOR UPDATE SKIP LOCKED` 领取任务。
- [ ] 每个 worker 容器有一个调度进程和一个渲染子进程，一次只做一项。子进程在任务之间复用；超时、崩溃或做满一定项数后换新。
- [ ] 模板列表与只读查看接口，返回名称、当前修订、适用尺寸范围、对外参数和所用的数据定义。
- [ ] 草稿预览接口同步返回图片、问题清单与布局摘要，不计额度，按租户限制并发与频率。代建工程师可以用被指定租户的身份预览。
- [ ] 执行隔离：
  - **单项超时**：调度进程结束子进程，本项失败，问题说明写明是超时；
  - **内存超限**：容器限制结束子进程，结果同上；
  - 两种情况下 worker 都自动恢复，后续任务照常完成。
- [ ] 入队前在接口进程里检查限制，不出图，超限直接拒绝、不占 worker：
  - 请求与数据集的字节数；
  - 单张最大像素：取套餐值，且不超过引擎上限；
  - 循环展开后的项数与元素数。
- [ ] 超时与内存上限可以配置；Docker 后端测试用极小的值，稳定触发上面两种情况。
- [ ] 决定记 M 编号。

**测试接缝：** 开放 API。内存后端用进程内 worker；超时、内存超限与恢复只在 Docker 后端测。
