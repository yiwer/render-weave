# 07: 经开放 API 异步批量正式交付，逐项提交出图记录，可查进度、可取消

**What to build:** 批量交付接口、批次快照、逐项任务、出图记录写入对象存储、批次汇总、取消与幂等键。

**Blocked by:** 02、06

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「开放 API」「出图记录」；用户故事 12、14、15、23、24；验收 A06、A08；ADR-0017、ADR-0019、M246。

- [x] 提交批量交付时，接口进程做票据 01 的"固定"，存好批次快照，按项入队，立即返回批次标识。单张正式图也按只有一项的批次交付。
- [x] 一个批次只由接受它的那个构建的 worker 处理。滚动发布时，旧 worker 做完已接受的批次再退出。
- [x] 每项正式交付成功时，先写对象，再在一个事务里提交记录行。事务提交之前，这一项对任何读者都不存在。
- [x] 同一租户内相同字节只存一份，跨批次也是。
- [x] 能查批次状态、逐项进度与结果。失败项带的问题清单与单次渲染一致（票据 02）。
- [x] 全部项结束后写批次汇总，语义同本地的 `batch.json`（M153）。
- [x] 取消：还没开始的项标为未执行，正在渲染的一项由调度进程结束。
- [x] 幂等：
  - 提交时带幂等键，重试返回同一批次，不重复交付；
  - worker 重领同一项时，记录行只提交一次。
- [x] API 密钥可以提交批次、查询结果。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API。结果经查询接口和票据 08 的导出核对。

## Answer

2026-10-19 完成。决定见 M268（批量正式交付）与 M269（批次项的调度：构建固定、排空、顺序与租约），说明见[出图服务](../../../docs/service.md#批量交付)与[渲染 worker](../../../docs/service.md#渲染-worker)。

**成果**

- **端点**：
  - `POST /v1/batches` 收与本地 `deliver` 相同的批量请求，只出正式图（写 `draft` 答 400）；单张也是一项的批次；
  - `GET /v1/batches/{批次}` 查状态、进度、汇总、逐项状态与问题清单；
  - `POST /v1/batches/{批次}/cancel` 取消；
  - 提交与取消记审计；API 密钥与客户成员都能用。
- **固定与入队**：接口进程用引擎的 `freezeBatch` 固定批次，外层非法整批拒绝（400，问题清单与本地相同）。快照存成本租户的内容，按项入队，答 202。
- **单项的限制**：像素、展开规模与已保存数据集的字节数逐项检查，超限的项不渲染、直接失败，问题码与预览相同；请求体超过 8 MiB 整批 413。
- **幂等**：`Idempotency-Key` 在租户内唯一；同键同请求返回同一批次，请求不同答 409 `batch.idempotencyConflict`。
- **交付与记录**：渲染子进程按快照交付一项，先写对象，再在一个事务里登记（"批次加项序号"唯一）。最后结束的一项在同一个事务里锁住批次行，发布 `batch.json`，字节与本地相同。对象按 SHA-256 存，跨批次去重。
- **取消**：排队的项立即标为未执行；正在渲染的一项由调度进程结束；已交付的保留；批次级问题 `delivery.cancelled`。
- **worker**（`service/src/worker/`、`service/src/delivery.ts`）：
  - 只领本构建的批次项，预览不限构建；
  - 收到 SIGTERM 时排空：不领预览，做完本构建排队的批次项再退出；Compose 停止宽限 30 分钟；
  - 预览优先，批次项按项序号轮转；
  - 租约（单项超时加 60 秒）过期由同构建重领；已登记的项沿用、不重渲染；写回以领取次数作凭据；领 3 次仍没做完记 `worker.crashed`；
  - 没渲染完的项写问题清单、标失败；健康检查多了取消的计数。
- **存储**：迁移 0005 给批次行加快照、构建、幂等键与汇总，批次项进 `render_tasks`，新的 `rw_claim_task` 按构建、租约与顺序领取；内存后端的批次改为按 SHA-256 存进本租户的内容，与 PostgreSQL 后端一样去重。
- **引擎**：`summarizeBatch` 的第一个参数放宽为只要构建标识、根模板与模式（`BatchSnapshot` 照样能传），服务端由批次行提供；不改已有行为。
- **文档**：`docs/service.md` 加"批量交付"一节，"渲染 worker"一节补顺序、构建固定、取消、租约与排空，配置、端点、问题码与测试同步；`GLOSSARY.md` 加"批次"；M268、M269。

**判断**

- **批量交付只出正式图**：草稿走预览（限频、不计额度），不让批次绕过预览的限制。切换条件：控制台需要整批草稿时，加带预览限制的批量草稿。
- **单项超限只让这一项失败**，不整批 413：与 M153 的"单项失败不影响其他项"一致；预览是单张，仍答 413。
- **构建固定按 `freezeBatch` 的构建标识**：旧构建的 worker 全都不在时，它接受的批次停在排队中，要再起旧构建的 worker，不由新构建代做（ADR-0013 的"记录只由确切构建产出与重放"）。
- **批次项按项序号轮转**：小批次不被先提交的大批次堵住；租户之间按份额分配留到容量基线或客户反馈之后。
- **没渲染完的项写问题清单**：导出时每个失败项都有 `problems.json`，与引擎失败项一样。代价是：过了租约才交回的旧 worker 若写问题清单，会先于新的一次登记；租约比单项超时长一分钟，只有调度进程本身卡住时才会这样。
- **数值都是暂定的**：请求体 8 MiB、租约 = 单项超时 + 60 秒、领取 3 次、取消查看间隔 200 ms、停止宽限 30 分钟，由容量基线（票据 15）再定。

**没做**：计费（票据 09 接到写回的事务里）、出图记录的查询、下载与导出（票据 08）、webhook（票据 11）、队列积压的指标与任务行的清理（票据 15）。批次里的单项超时没有在 Docker 后端单独测（见验证）。

**验证**

- **内存后端**（`service/test/batch.test.ts`，12 项，进程内 worker）：
  - 3 项的批次（2 项交付、1 项数据集不存在）：失败项的问题清单与引擎相同；`batch.json` 与 `record.json`、`input.json`、图片、问题清单、布局摘要都与引擎在本进程交付的逐字节相同；两条记录用引擎的 `replayRecord` 重放通过；`readBatchFrom` 读到已结束的批次；
  - 单张也是一项的批次，写 `draft` 答 400；外层非法、根模板不存在、超过 1,000 项、标识重复、请求体不是对象都整批拒绝，问题清单与本地 `freezeBatch` 相同；
  - 单项超出像素、数据集字节数、循环项与元素数各让那一项失败，其他项照常；请求体超限整批 413；
  - 幂等键：重试同一批次（结束前后都是），不同请求 409，别的租户用同一个键另建批次，空键 400；
  - 取消：排队中取消整批未执行、立即发布清单；渲染中取消后其余两项未执行；结束后再取消不改变什么；
  - 构建固定：别的构建的 worker 不领批次项，照样做预览；排空：做完本构建的 3 项，期间排队的预览答 503；
  - 租约：登记后"退出"的 worker 过了租约由同构建重领，沿用登记、不重渲染；过期写回不改结果；第二次领取正在做时第一次交回失败结果，以第二次为准；每次都没做完的项第 4 次领到时记 `worker.crashed`，写出问题清单；
  - 调度顺序：预览、A1、B1、A2、A3；审计 `batch.create`、`batch.cancel`；日志里没有密钥。
- **权限矩阵与跨租户端点清单**：新加 3 个端点，矩阵 31 个端点、清单 21 个端点逐项通过（另一租户的批次与随机 ID 答得完全一样）。
- **Docker 后端**：`node service/scripts/test-docker.mjs` 从空环境起服务，8 个文件、69 项通过，服务日志 317 行都是合格的 JSON。
