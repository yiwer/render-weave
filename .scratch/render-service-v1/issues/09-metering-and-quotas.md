# 09: 按月额度计量正式交付张数与代建 token，额度不够整批拒绝

**What to build:** 用量事件、当期计数、套餐设置、批次预占与逐项结算、对账、用量查询，以及推送时附带的 token 用量。

**Blocked by:** 07

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「计量与额度」；用户故事 18、24、30、37、39、41；验收 A09；ADR-0020、M242。

- [x] 平台管理员设置租户套餐：每月出图张数、单张最大像素、并发数。
- [x] 提交批次时预占额度：在一个事务里锁住当期计数行，检查"已用 + 预占 + 本批项数 ≤ 限额"。不够就整批拒绝，问题码 `quota.exceeded`，HTTP 429，说明里写剩余额度。
- [x] 结算：
  - 每项成功时，在提交记录行的同一个事务里写用量事件：已用加 1，预占减 1；
  - 失败和未执行的项退回预占；
  - 批次结束时退回剩下的预占。
- [x] 不重复计费：同一幂等键重试、worker 重领同一项，都只计一次。
- [x] 对账任务回收崩溃后遗留的预占。Docker 后端测试在批次进行中结束 worker 和接口进程来验证。
- [x] 草稿预览和重放不计额度。
- [x] 计费周期是按 UTC+8 切分的自然月，额度不结转。
- [x] token：推送命令可以附带轮次目录，读取各轮 `round.json` 里的输入、输出、缓存读、缓存写 token，记为该租户的用量事件，只记不拦。
- [x] 客户管理员和平台管理员能查已用、预占、剩余与明细。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API 与推送命令。

## Answer

2026-10-20 完成。决定见 M274（套餐、预占与逐项结算）与 M275（对账任务与代建 token 的记账），说明见[出图服务](../../../docs/service.md#计量与额度)。

**成果**

- **套餐**：每月出图张数、单张最大像素、并发数。平台管理员用 `PUT /v1/platform/tenants/{租户}/plan` 设置，建租户时也可以带 `plan`；不设时每月 0 张、1 亿像素、并发 2。单张最大像素取套餐值，且不超过服务上限，用于预览与批次项的入队前检查。预览与重放的并发数取套餐值，取代原来的全局缺省值 `previewConcurrency`。
- **预占**：`POST /v1/batches` 在建批次的事务里锁住当期计数行，"已用 + 预占 + 本批项数"超过限额就整批拒绝，答 429 `quota.exceeded`；说明写限额、已用、预占、剩余与本批项数，响应另带 `quota` 对象。幂等键查重也在这把锁里：重试返回已有批次，不再检查额度。
- **结算**：交付成功的一项与登记它的事务相同：已用加 1、预占减 1、记一条 `image` 用量事件。退回预占分三处：
  - 登记失败项时退回 1；
  - 没登记就结束的项，在写回或取消时退回；
  - 批次结束时与发布批次清单同一事务，退回剩余。

  退回只从批次的剩余预占里扣。用量事件有"租户、批次、项"唯一索引。
- **周期**：按 UTC+8 切分的自然月，不结转。批次的周期按接受它的时间定，结算记在这个周期。
- **对账**：接口进程启动时与之后每 60 秒（`RW_RECONCILE_MS`）调属主函数 `rw_reconcile_reservations`，退回两类批次的预占：
  - 已结束还有预占的；
  - 接受它的构建 30 秒内没有 worker 报到、闲置超过 `RW_RESERVATION_GRACE_MS`（缺省 10 分钟）的。

  每退回一个批次记一行日志。Compose 的 `api` 透传这两个变量。
- **代建 token**：`renderweave push --rounds <目录>` 读这一单的轮次目录，各轮 `round.json` 的四种 token 随清单交给服务，与推送同一事务记为用量事件，只记不拦；同一轮（`round.json` 的 SHA-256）只记一次。提交的回答与命令行输出有 `usage`：附了几轮、新记几轮与新记的 token 合计。
- **查询**：
  - 客户管理员：`GET /v1/usage`、`GET /v1/usage/events`；
  - 平台管理员：`GET /v1/platform/tenants/{租户}/usage`、`…/usage/events`，记跨租户审计。

  回答包括限额、已用、预占、剩余与四种 token 的合计，明细可按周期与种类筛选、按 ID 翻页。
- **存储**：迁移 0007 加三张表与对账函数：
  - `tenant_plans`、`usage_counters`、`usage_events`，三张都开行级安全，`usage_events` 只授 SELECT 与 INSERT；
  - `batches` 加 `period` 与 `reserved`；
  - `rw_reconcile_reservations`。

  后端接口：`TenantScope` 加 `plan`、`setPlan`、`usage`、`listUsageEvents`；`TenantTasks.createBatch` 可能答 `shortfall`；`ServiceBackend` 加 `reconcileReservations`；`PushWrites` 加 `rounds`。
- **文档**：
  - `docs/service.md` 加"计量与额度"一节，同步配置、进程、端点、错误、代建推送、预览、批量交付、重放、租户隔离与测试；
  - `GLOSSARY.md` 加"套餐""计费周期""用量事件""对账"；
  - M274、M275。

**判断**

- **没设套餐的租户每月 0 张**：开通客户必须设套餐（M242 套餐由管理员手工设置），免得新租户没有额度限制地出图。阶段 5 自助注册时改为试用套餐。
- **批次的用量记在接受它的周期**：额度检查是按那个月做的，跨月交付完的批次不挤占下个月的额度。
- **token 的周期按推送时间**：不按轮次的结束时间，已结账的月份不再变。
- **对账只退"没人再交付"的批次**：worker 单独崩溃时同构建的 worker 会重领，不算遗留。被退回的批次以后若又交付完，成功的项照样计已用，限额最多超出这一批的剩余项数。额度检查在接受时已经做过，代价可以接受。
- **并发数限的是预览与重放**：批次项按项序号轮转（M269），不按租户限并发；要限时在领取函数里按租户计数。
- **崩溃验证用真实进程**：tester 不能控制 Compose，所以在 tester 里用镜像编译好的服务另起接口进程与 worker 进程。服务代码的副本多一个标记文件，构建标识与 Compose 里的 worker 不同，批次只能由它交付，强杀后就没人接手。

**没做**：token 额度拦截（ADR-0020：阶段 5）；按像素加权；在线支付与账单；控制台里的用量页面（票据 14）。

**验证**

- **内存后端**（`service/test/metering.test.ts`，11 项，进程内 worker）：
  - 套餐：建租户不设时每月 0 张，一并设、单独设都能读回；7 种越界或多余的取值答 400，不存在的租户 404；客户管理员与平台管理员看到的用量相同，设套餐与看用量记跨租户审计；不合规的周期与种类不答 200；
  - 预占与 429：限额 5 张时 3 项的批次预占 3、剩余 2；再交 3 项答 429 `quota.exceeded`，说明写"剩余 2 张""本批 3 项"，`quota` 对象逐项正确，没有建批次（审计只有一条 `batch.create`）；交付完已用 2、预占 0；已用 2 再交 3 项正好用完，再多 1 项被拒；调高套餐后当期限额随之改变；
  - 幂等：同一个键重试不重复预占，交付完后额度用完再重试照样答 200 与同一批次，只计 2 张；同一个键同时提交两次、额度只够一批，一个答 202、一个答 200 同一批次；
  - 重领：第一个 worker 登记并结算了第一项后不交回，同构建的 worker 过了租约重领，这一项只计一次；
  - 退回：排队时取消当即退回全部预占；批次进行中，登记了问题清单的失败项与没写成成果的失败项各当即退回 1，取消时排队的项当即退回，正在渲染的一项做完后计已用；
  - 不计额度：两次草稿预览与一次重放后用量与事件不变；
  - 单张最大像素：套餐 1000 像素时预览答 413（说明写"超出单张上限 1000"），批次中这一项失败、不计已用；
  - 周期：2031-01-31 23:59:59（UTC+8）接受的批次跨过零点才交付完，仍记在 1 月；2 月从 0 开始、不结转，2 月照样交满 3 张；周期的起止是 UTC 的 16:00；
  - 对账：宽限内不退；构建还有 worker 在线时不退；没有 worker、闲置超过宽限时退回 3 项，只退一次；worker 回来交付完，成功的 2 项计已用，预占不成负数；
  - 明细：按 ID 倒序，`kind` 筛选与 `before` 翻页正确，平台管理员看到的相同；操作员、API 密钥与代建令牌 403；另一租户的管理员看不到。
