# 10: 经开放 API 管理数据集与图片、字体资源，替换资源前先看影响

**What to build:** 数据集的读写与校验接口，资源的上传、列出、替换检查与应用替换接口。

**Blocked by:** 05

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「开放 API」；用户故事 6、7、8、22、27；验收 A06；ADR-0018、M152、M241。

- [x] 数据集：
  - 能新建、读取、修改、复制、列出；
  - 按原始字节存；
  - 保存时按静态数据定义的编译产物校验，问题清单定位到字段，结果与引擎一致。
- [x] 提供只校验、不保存的接口，供表单实时提示。
- [x] 资源：
  - 操作员能上传新的图片和字体，得到资源 ID 和 v1；
  - 字体不做授权确认（M241）；
  - 资源种类创建后不能改。
- [x] 替换资源分两步：
  1. 只读检查，返回受影响的模板、数据集与字体配置；
  2. 管理员凭检查报告应用，按预期版本提交，过期的报告被拒绝（M152）。
- [x] 每个新端点都加进票据 04 的跨租户端点清单。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API。

## Answer

2026-10-19 完成。决定见 M270（数据集接口）与 M271（资源接口：上传、列出、读回、替换检查与应用替换），说明见[出图服务](../../../docs/service.md#数据集与资源)。

**成果**

- **数据集端点**：
  - `GET /v1/datasets` 列出（ID、名称、所选的静态数据定义、哈希与字节数），`GET /v1/datasets/{数据集}` 读回保存时的原始字节；
  - `POST /v1/datasets` 新建、`PUT /v1/datasets/{数据集}` 整份替换、`POST …/{数据集}/copies` 复制；
  - `POST /v1/dataset-checks` 只校验、不保存，供表单实时提示；
  - 新建、修改、复制记审计，只记数据集 ID。
- **按原始字节存与校验**：写数据集的端点不经全局 JSON 解析，请求体原文交给引擎；有严重问题答 400 与问题清单，什么也不存。超过 15 位有效数字的数值按原文报 `dataset.tooManyDigits`。
- **资源端点**：
  - `GET /v1/resources`、`GET …/{资源}` 列出全部内容版本，`GET …/{资源}/versions/{版本}/content` 读回原始字节（经引擎核对哈希，`application/octet-stream` 加 `nosniff`）；
  - `POST /v1/resources?kind=…&id=…` 上传新资源，从 v1 开始，不写 ID 由服务生成；同一 ID 已有答 409，ID 与种类创建后不变；字体不做授权确认；
  - `POST …/{资源}/replacement-checks` 替换检查：只读，返回资源的当前版本、候选内容的哈希、受影响的模板与数据集位置、字体配置与工作区指纹；
  - `POST …/{资源}/replacements` 凭报告应用：按预期版本追加内容版本，旧版本内容保留；资源已有新版本或工作区变了答 409 `resource.replacementStale`，报告与资源不符、候选内容不在服务端答 400 `resource.replacementInvalid`；
  - 检查与应用只给客户管理员；上传与替换记审计。
- **引擎**（两处预重构，行为不变）：
  - 新公开入口 `checkDataset(字节, 工作区)`：JSON 与精度、身份部分、编译产物与资源引用。按编译产物校验的那一段从预检中抽出成 `checkDatasetData`，渲染入口与它共用；
  - 新公开入口 `resourceImpact(已读出的文档, ID, 字体配置?)`：从本地 `inspectResourceWorkspace` 中抽出不读文件的部分，本地的指纹与报告不变。
- **存储**：`TenantStorage` 加两个操作。`saveDataset` 带"新建时不存在、修改时已存在"的条件；`guardedResources(guard)` 在资源提交的同一个事务、同一把锁里先核对工作区文档的登记。保存数据集与推送、资源提交、改模板的当前修订锁住同一行。两种后端都实现了，没有新迁移。
- **测试与清单**：权限矩阵加 11 个端点，跨租户端点清单加 11 个端点（A 的数据集 `ds-greeting` 与上传的资源 `a-logo`）；测试准备加 M402 样例（`seedM402`）。
- **文档**：`docs/service.md` 加"数据集与资源"一节，端点、问题码、存储布局与测试同步；`docs/resources-versioning.md` 加 `resourceImpact`，`docs/dsl/data-definition.md` 加 `checkDataset`；`GLOSSARY.md` 加"替换检查"；M270、M271。

**判断**

- **保存要求数据集合格**，有严重问题不存：数据集只用于出图，不合格的出不了正式图；表单的草稿状态留在客户端，由只校验的接口提示。提示级问题照常保存，回答里带上。
- **复制重新排版**：副本只改身份部分的 ID 与名称，写成缩进 2 格的 JSON；数值不超过 15 位有效数字，按双精度往返不变。原件先校验，推送进来的、有严重问题的数据集不复制。
- **替换检查只给管理员**：检查是替换的第一步，候选内容会存进租户；操作员与 API 密钥只能上传新资源（M247）。
- **工作区指纹在提交的同一个事务里核对**，不另占数据库连接：另占连接时，同一租户排队等锁的写请求占满连接池（10 个）就会死锁。
- **上传不嗅探格式**，与本地导入相同，能不能绘制由预览报告。切换条件：客户上传错文件成了常见支持问题时，在上传处加格式嗅探。
- **数据集的并发修改不加版本条件**，后写的覆盖先写的。切换条件：控制台出现多人同时编辑同一数据集时，`PUT` 加 `If-Match`。

**没做**：删除数据集与资源（v1.0 不删，M152）；回收替换检查存下、没应用的候选内容（与其他未登记对象一样，v1.0 不回收）；OpenAPI 描述与快照（票据 11）；控制台（票据 12、14）。
