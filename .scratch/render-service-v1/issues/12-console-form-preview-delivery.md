# 12: 客户在出图控制台用表单填数据、调参数、看预览，然后批量交付并下载

**What to build:** 出图控制台的第一条纵切：登录、模板列表与只读预览、参数面板、按数据定义生成的表单、草稿预览、批量交付与下载。

**Blocked by:** 08、10

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「出图控制台」；用户故事 1–8、11–15；验收 A11；M248。

- [x] 控制台只调用开放 API，不另开后端接口，由接口进程作为静态文件提供；界面只做中文。
- [x] 能登录、退出。
- [x] 模板：
  - 列表里每个模板带缩略预览、适用尺寸范围和对应的数据定义；
  - 在只读预览上用参数面板调对外参数，看草稿预览。
- [x] 表单：
  - 由编译产物生成，字段用显示名称；
  - 覆盖全部字段类型：文本、数值、日期、时刻、时间、布尔、图片、列表、数据定义引用；
  - 校验以服务端的问题清单为准，问题定位到字段；
  - 图片字段能从本租户的资源中选图，也能上传新图；
  - 数据集能保存、修改、复制。
- [x] 草稿预览把问题位置叠加在图上。
- [x] 批量交付：显示逐项进度与结果，能取消；失败项显示问题说明。
- [x] 能下载单张图片和整批压缩包。
- [x] 浏览器端到端测试覆盖"填表 → 预览 → 交付 → 下载"这条主路径（Docker 后端）。
- [x] 前端框架等选型决定记 M 编号。

**测试接缝：** 浏览器端到端测试，结果经开放 API 核对。

## Answer

2026-10-20 完成。决定见 M278（静态数据定义的只读端点）、M279（控制台的技术形态）、M280（出图参数与预览）、M281（浏览器端到端测试）与 M282（结构与视觉：原型方案一）。维护说明见[出图服务](../../../docs/service.md#出图控制台)的"出图控制台"一节，客户开发者看到的新端点见[开放 API](../../../docs/api.md)。

**先做了一轮原型**：

- 三种结构：以数据集为中心、以出图任务表格为中心、以模板画布为中心；
- 三种视觉：参考 calendly.com、together.ai 与 motherduck.com；
- 图与问题都由引擎当场渲染。

用户选定方案一，视觉用"清爽"。原型存档在分支 `prototype/console-v1`（db8aa41，不进 main），设计画布在 <https://claude.ai/artifact/9X9QBCHkxND13Hc1ioaW8t>（私有）。

**成果**

- **页面**（`service/console/`，React 加 Vite，界面只做中文）：
  - **登录与退出**：只有客户管理员与操作员能用，其他身份登录后提示改用成员账号；令牌只放在本标签页。
  - **数据集是首页**：列出数据集，可以勾几份同一数据定义的一起出图；本标签页提交过的出图任务列在底部。
  - **编辑一份数据集**：左边是按编译产物生成的表单，字段用显示名称；右边是草稿预览、对外参数与尺寸。
    - 九种字段类型都有输入方式；顶层简单字段排成网格，对象列表能放进单元格时排成表格（停靠站点一行一站），简单值的列表是一排小输入框，可选值固定的列表是一组勾选。
    - 边填边经 `POST /v1/dataset-checks` 校验，问题显示在对应的输入框或单元格下面。
    - 图片字段从本租户的资源中选，或上传新图；表格里是缩略按钮加弹出的选图面板。
    - 保存、修改、复制；有未保存的修改时不能出图。判断修改与键的先后无关，清空再填回原值不算修改。
  - **草稿预览**：问题定位到元素的，按布局摘要叠加在图上，与清单同号。预览与正式交付用同样的尺寸与分辨率（M280）。
  - **出图侧栏**：选模板、对外参数与尺寸。
    - 可以按一个整数对外参数的范围出多张，比如线路牌按本站序号 1–35 出 35 张，项 ID 写成"数据集/参数=值"；
    - 提交带幂等键；侧栏随即显示逐项进度，格子上是参数值；
    - 点一项看图、下载或看问题说明；进行中能取消；结束后下载整批压缩包。
  - **模板**：只读。列表有缩略预览、适用尺寸范围、数据定义与对外参数；调参看草稿预览，按模板新建数据集。引擎内置的数据定义只给子模板用，不给新建入口。
- **后端**：
  - `GET /v1/static-schemas` 与 `GET /v1/static-schemas/{name}/versions/{version}` 返回静态数据定义的原文与编译产物（M278）。这是开放 API 的端点，进 OpenAPI 描述、权限矩阵与跨租户端点清单；v1.0 还没对外发布，并入 1.0.0 并重写基线，变更记录里注明。控制台没有自己的后端接口。
  - 接口进程在 `/console/` 下提供构建好的静态文件，带内容安全策略与缓存头。这些路由标成不属于开放 API，不进路由表与描述（M279）。
- **构建**：镜像构建时对控制台做类型检查并构建；`npm run typecheck:service` 也检查控制台。tester 镜像装了 Alpine 的 Chromium。
- **文档**：`docs/service.md` 加"出图控制台"一节，并同步概览、本机启动、数据集端点与测试；`docs/api.md` 加静态数据定义的用法；`GLOSSARY.md` 加"出图控制台"；记下 M278–M282。

**判断**

- **接着中断的会话做**：本票据先由另一个会话开工，做到浏览器用例 6 项过了 5 项时额度用完中断，代码没有提交。本会话在它的工作树里接着做：保留它的接口客户端、表单模型、预览排队、静态数据定义端点、会议胸牌夹具与测试骨架，按方案一改写了页面结构、表单排版、出图流程与视觉。
- **预览用正式的分辨率**：原型时实测，带码线路牌按 60 DPI 出草稿报 `barcode.sizeInvalid`，按 120 DPI 没有问题。预览慢一点，换来不报假问题。
- **操作员看不到剩余张数**：用户故事 18 要操作员看到本月已用、预占与剩余，但 M247 只给客户管理员读用量。这里按 M247 只给管理员显示，冲突留给票据 14（用量页）定。
- **M402 夹具补了粗体字体**：测试夹具 `seedM402` 只放了中等字重，线路牌正式出图要的粗体没有放，正式交付每一项都失败。补上之后，用到这个夹具的用例都照常通过。
- **清空必填字段就省略这个键**：服务端报"必填字段缺失"，比交一个空字符串报"长度至少 1"更准确。
- **本机快速版跳过取消**：进程内 worker 渲染压力项时占住接口进程的事件循环，页面拿不到批次状态；Docker 里 worker 是独立进程，取消以 Docker 为准。

**没做**：

- Excel 导入（票据 13），出图记录、用量与管理页（票据 14）；
- 点图上的元素跳到对应字段（方案三的长处，草稿预览接口已返回布局摘要，以后加不需要新接口）；
- 列出批次的接口：出图任务从数据集页进入，本标签页提交过的列在数据集页底部；
