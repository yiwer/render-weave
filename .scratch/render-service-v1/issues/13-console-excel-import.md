# 13: 客户从 Excel 导入一批数据，逐行看到问题，确认后再交付

**What to build:** 服务端解析 Excel 的接口和控制台的导入界面：一行一个渲染项，支持简单列表和一层引用列表两种写法。

**Blocked by:** 12

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「出图控制台」；用户故事 9、10；验收 A11；M248。

- [x] Excel 在服务端解析，解析库只用 MIT 或 Apache 许可证的。
- [x] 支持的写法：
  - 一行一个渲染项；
  - 列对应顶层字段，表头写显示名称或字段名称都可以；
  - 简单类型的列表用分隔符写在一格里；
  - 一层数据定义引用的列表另起一张表，用关联列对应主表的行。
- [x] 导入结果先作为预览返回：数据集、批量请求，以及逐行逐列的问题清单。有问题的行不进入批次，客户确认后才提交。
- [x] 控制台能下载模板：按数据定义生成一份带表头的空白 Excel。
- [x] 准备两份 Excel 样例，测试中都能导入并交付成功：
  - 价签：字段是扁平的；
  - 线路牌：站点是引用列表。
- [x] 单个文件的大小和行数有上限，超出就拒绝。
- [x] 决定记 M 编号。

**测试接缝：** 开放 API 的导入接口；控制台的导入走一条浏览器端到端测试。

## Answer

2026-10-20 完成。决定见 M283（接口与流程）、M284（解析）、M285（写法与空白表）与 M286（上限）。维护说明见[出图服务](../../../docs/service.md#excel-导入)的"Excel 导入"一节，客户开发者的用法与问题码见[开放 API](../../../docs/api.md#excel-导入)。

**成果**

- **导入预览**：`POST /v1/excel-imports` 收模板名、`.xlsx` 的 base64、对外参数与出图参数，答：
  - 逐行的渲染项 ID、能不能提交、读出的数据集与问题清单；
  - 整份的问题，如不认识的列、没被引用的行；
  - 只含能提交的行的批量请求，数据集内联在各项里。
  预览不保存任何东西，客户确认后把批量请求原样提交到 `POST /v1/batches`。各行由引擎的 `checkDataset` 校验，问题与保存数据集时相同，另带单元格（工作表、行、列与表头）；导入自己发现的问题用 11 个 `import.*` 问题码。出图参数与对外参数由 `measureRender` 按第一行能提交的数据检查一次，不合规时回答里没有批量请求，免得预览说能提交、提交时整批被拒。
- **两种写法**：一行一个渲染项，表头写显示名称或字段名称，上方可以有标题行；简单类型的列表用换行、顿号、逗号或分号写在一格；引用与引用列表另起一张以字段显示名称命名的表，用关联值对应主表的行，主表的几行可以共用一个关联值。单元格按字段类型转换：日期与时刻认 Excel 的序号与常见文字，是否认 是/否，图片可以只写资源 ID，数值取 15 位有效数字。
- **空白表**：`GET /v1/static-schemas/{name}/versions/{version}/workbook` 按数据定义生成。文字类的列设成文本格式，保住货号的前导零；单值的可选值与是否给下拉选择，每列选中时提示怎么填。
- **解析**：只用 MIT 许可证的 yauzl 解压、yazl 打包，工作表与共享字符串由本仓库的 XML 扫描器读取，不接受 DTD。分三遍只解开关系、工作簿、共享字符串、主表与引用表，样式、图形与别的工作表不解开也不算进上限；部件按 BOM 认 UTF-8 或 UTF-16。
- **上限**：文件 5 MiB、解压后 32 MiB、非空单元格 50 万、主表 1,000 行、引用展开 5 万行，超出整份拒绝（413 `limit.workbookTooLarge`）；读不了的文件答 400 `import.workbookUnreadable`，旧版 .xls 与加密的工作簿提示另存。
- **控制台**：数据集页"从 Excel 导入…"打开侧栏：选模板、对外参数与尺寸，下载空白表，上传文件，逐行看能不能提交与问题所在的单元格，确认后提交，随后转到出图任务的进度页。
- **样例**：`fixtures/excel/` 下两份 `.xlsx` 与导入后应得到的数据，用 openpyxl 3.1.5 生成（`make-samples.py`）：
  - `price-tags.xlsx`：商品价签，字段扁平，6 行，另有一列"备注"不对应字段；
  - `route-signs.xlsx`：M402 线路牌，停靠站点在另一张表，2 行，第一行读出来与 M402 数据集逐字段相同。
  价签的数据定义与模板是新夹具 `fixtures/workspaces/price-tag/`。
- **文档**：`docs/service.md` 加"Excel 导入"一节，`docs/api.md` 加用法与问题码，`GLOSSARY.md` 加"Excel 导入"与"空白表"（不叫"Excel 模板"，免得与模板混淆），记下 M283–M286；OpenAPI 快照与 1.0.0 基线已更新，变更记录注明并入。

**判断**

- **按模板导入、JSON 加 base64**：模板决定数据定义；一个 JSON 请求带齐文件与出图参数，回答里的批量请求可以直接提交，开放 API 保持 JSON（M246）。代价是请求体大三分之一。
- **数据集内联、不另存**：表格就是客户的数据源，几百行价签存成数据集只会塞满列表；每张图的出图记录自带数据。
- **不用现成的表格库**：ExcelJS 停在 2023 年，SheetJS 新版不在 npm；自己读能在解开之前按 zip 里登记的大小拒绝超限文件、拒绝 DTD。读的写法覆盖共享字符串、内联字符串、富文本与注音、公式结果、命名空间前缀、省略坐标与 1904 日期系统，都有用例。
- **原因已说明时不重复引擎的问题**：关联值找不到、单元格是错误值时，不再列引擎对同一字段的"必填缺失"。
- **解压上限从 64 MiB 降到 32 MiB**：读的时候整份 XML 在内存里，字符串约是字节数的两倍；1,000 条线路各 50 站约 18 MB，32 MiB 够用。
- **审查之后补的防护**：代码审查报告 15 处，修了 14 处。最要紧的两处是放大：引用表按关联值分组原来是平方级的复制，主表的几行共用一大组关联值时展开也会成倍放大，现在分组是线性的，展开合计上限 5 万行。另外只解开用到的部件与工作表（样式、数据透视缓存不算进上限），出图参数先检查一次，表头上方允许标题行，认 UTF-16 部件，空白表只写 DOS 时间戳、哪个时区生成都同样的字节。
- **价签夹具自己做了一份**：仓库里没有价签的数据定义与模板（第三阶段评估时由 Agent 当场生成，不入库）。新夹具字段扁平，覆盖文本（含可选值与格式）、数值、是否、日期与简单列表，模板用派生变量在没有会员价时隐藏那一行。

**没做**：

- 导入在接口进程里同步解析、没有按租户限流：与提交批次时固定批次同类，留给容量基线（票据 15）实测后一起定；
- 映射配置：表格结构超出这两种写法时再加（M248）；
- 把导入的行另存为数据集；导入时按一个参数的范围出多张（表单出图有）；
- .xls 与 CSV；
- 用真实的 Excel 与 WPS 填写空白表再导入：本机没有 Excel 与 WPS，空白表只经 openpyxl 打开核对过，留给真人走查（票据 15）。

**验证**

- **导入接口**（`service/test/imports-suite.ts`，14 项，内存与 PostgreSQL 加 S3 两种后端都跑）：
  - 价签样例：6 行读出的数据与 `price-tags.json` 逐字段相同（货号的前导零、日期、TRUE/FALSE 与"是/否"、顿号逗号分号分开的卖点），"备注"列提示忽略；按预览提交后 6 项都交付。预览前后数据集列表不变。
  - 线路牌样例：第一行读出来与 M402 数据集逐字段相同（35 个站点、时刻序号换成 07:30、只写资源 ID 的补上 `res:`），第二行的 06:30:15 保留秒；提交后 2 项都交付。
  - 逐行逐列的问题：11 行里只有 1 行能提交，其余各自定位到列：类型不对、可选值之外、必填为空、渲染项 ID 重复、#N/A、卖点多一项、卖点太长（定位到 `features[2]` 与 K 列）、货号丢了前导零、"1e400"；空行跳过。
  - 引用列表：关联值找不到、站点表里的必填与可选值问题定位到站点表的单元格、没被引用的站点行提示、主表没有站点列时站点表照样读、引用表在说明表之后也认得主表、单个引用对应两行、缺关联值列的表没人引用时只提示。
  - 六种写法读出同样的胸牌数据（九种字段类型）：Excel 的共享字符串、内联字符串、命名空间前缀、省略坐标、1904 日期系统、UTF-16 部件；富文本不取注音，公式取结果并消掉 0.1×120 的尾差。
