# 14: 客户在控制台查询与导出出图记录、查看用量，管理员管理成员、密钥、资源与 webhook

**What to build:** 控制台的记录、用量与租户管理页面。

**Blocked by:** 11、12

**Status:** resolved

**Trace:** [阶段 4 PRD](../spec.md)「出图控制台」；用户故事 16–22、25；验收 A11；M247、M248。

- [x] 记录：能按时间、模板、批次查询出图记录，下载图片，导出记录。
- [x] 用量：显示本月已用、预占与剩余张数，以及用量明细。
- [x] 管理员页面：
  - 成员与角色；
  - API 密钥，只在创建时显示一次；
  - 审计日志；
  - webhook 的注册与投递记录。
- [x] 资源页面：能上传新资源；替换前显示影响检查的结果，确认后才应用。
- [x] 操作员看不到管理员页面，直接调用对应接口也被拒绝。
- [x] 浏览器端到端测试覆盖记录导出和一次资源替换。
- [x] 决定记 M 编号。

**测试接缝：** 浏览器端到端测试，结果经开放 API 核对。

## Answer

2026-10-21 完成。决定见 M300（用量的可见范围）与 M301（记录、资源、用量与管理页面）。维护说明见[出图服务](../../../docs/service.md#出图控制台)的"出图控制台"一节，客户开发者看到的变化见[开放 API](../../../docs/api.md)的鉴权与变更记录。

**成果**

- **页面**（`service/console/src/pages/`）：导航多了出图记录、资源、用量；客户管理员另有"管理"。
  - **出图记录**（`records.tsx`）：
    - 按登记日期、模板、批次查询 `GET /v1/records`，一页 50 条，"加载更多"接着翻；
    - 筛选写在 # 路由里，日期按浏览器的本地时间，起止都含当日；
    - 每行下载图片、导出这一项；按批次筛选时可以导出整批、下载整批图片、打开出图任务。
  - **用量**（`usage.tsx`）：
    - 一个计费周期的限额、已用、预占、剩余，套餐与代建 token 的合计，可以换周期；
    - 明细按种类筛选，只在客户管理员的页面上。
  - **资源**（`resources.tsx`）：
    - 列出图片与字体，两种角色都能上传新资源；
    - 替换只给客户管理员：选新内容 → 检查影响（逐处列出引用它的模板与数据集、服务的字体配置）→ 确认替换。报告只对它检查的那个文件有效，过期时服务端答 409，页面丢掉报告。
  - **管理**（`admin.tsx`）分四个标签：
    - 成员与角色：改角色、停用与启用，自己的不在这里改；
    - API 密钥：创建时显示一次，列表只有开头，可吊销；
    - webhook：注册时签名密钥显示一次，停用与启用，投递记录；
    - 审计日志。
    - 操作员打开管理页只看到说明，不请求管理端点。
  - 共用：翻页 `usePaged`（`hooks.ts`）与页脚 `PagedFooter`。图片的下载文件名与出图任务页共用 `imageFileName`。资源上传或替换之后，表单的选图列表重新读取。
- **后端**（M300）：
  - 新权限 `usage.summary` 给操作员（API 密钥、管理员随之都有），`GET /v1/usage` 改用它；
  - `GET /v1/usage/events` 仍是只给客户管理员的 `usage.read`；
  - 没有新端点。OpenAPI 快照与 1.0.0 基线已更新：`x-access` 变了，兼容检查算访问要求改变；按 M276 定稿前可以重写基线，变更记录已注明。
- **文档**：
  - `docs/service.md`：概览、权限表、计量查询、出图控制台、测试；
  - `docs/api.md`：鉴权与变更记录；
  - `docs/discovery/requirements.md`：M300、M301；
  - `CONTEXT.md`。

**判断**

- **操作员能看用量合计（M300）**：票据 12 把用户故事 18 与 M247 的冲突留到这里。
  - 提交批次额度不够时，429 本来就把限额、已用、预占与剩余告诉提交者，合计不是新泄露的信息。
  - 明细逐条带批次与代建轮次，供管理员核对费用（故事 21），仍只给管理员。
  - API 密钥按 M247 有操作员的全部权限，也能看合计。
  - 切换条件：客户要求合计也保密时，按租户配置收回。
- **日期按浏览器本地时间**：看记录的人按自己看到的时间找图。计费周期另在用量页按 UTC+8 写明。
- **没有"按筛选结果打包导出"**：开放 API 只有按项与按批次导出，一个批次就是一次交付的整体，不为控制台另开端点（M248）。
- **自己的角色与状态不在管理页改**：免得管理员把自己降级或停用后锁在门外。服务端"至少保留一个启用的管理员"的规则不变。
- **只显示一次的密钥**只放在那块面板的状态里：关掉、换标签或离开就没了，不写 sessionStorage 与 URL。

**没做**：

- 窄屏与移动端适配：用户说不用处理。原先为手机宽度加的表格横向滚动已撤掉。
- 按筛选结果打包导出；在记录页上重放（开放 API 有，控制台没放入口）。
- 新成员与重置密码仍由平台管理员办理（M247）。
- "加载更多"的翻页没有端到端覆盖：测试数据每类都不到 50 条。
- 真人走查（A11 的一部分，票据 15）。
- Agent 评估：opencode 周额度用完，没法跑。本票据没改 Agent 资料、MCP 工具合同与提示词，按 M232 的规则也不需要跑。

  - 计量：操作员与 API 密钥读到的合计与管理员的逐字段相同，`/v1/usage/events` 仍答 403。

  - **出图记录**：
    - 不筛选、按模板、按批次查到的与开放 API 相同；
