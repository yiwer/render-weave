# 模板设计评估集

## 问题

Agent 评估的门槛（M230）只有一个模板场景 `m402-template`：一张横版线路牌、一套线路牌约定。模板参考、模板任务提示词与领域约定改了之后，我们只知道 M402 还行不行，不知道价签、卡片、表格屏、票据这些版式会不会退步；`CONTEXT.md`「尚待实测」也写着资产标签等其他领域要先写约定包再测。用户在 2026-10-25 提供了一套专为模板评估做的素材（13 张样图、39 张图片与它们的画廊页），可以据此补上这块空白。

## 方案

一套与门槛并列的评估集，经同一条产品路径（`renderweave agent run` 的模板辅助设计）跑，用同一个评估命令换配置运行（M333）。

1. **12 个用例**：样图 01–13 去掉 04 会议胸牌（M222：Agent 参考的示例就是胸牌）。每例给 Agent 示例图、项目说明、领域约定、专家版数据定义与数据集、示例出图请求；Agent 只做模板。
2. **材料进版本库，资源逐例组装**（M334）：样图与用到的图片放在 `scripts/agent-eval/template-design/`；每个单元在自己的目录里组资源仓库，字体共用、图片只放本例的，共用的 `fixtures/resources` 不动。
3. **数据驱动评分**（M335）：每例 `stress.json` 写压测（改数据、参数、尺寸后草稿出图，记严重问题），`checks.json` 写版面检查（在布局摘要上判断文字、图片、码图、字号最大、区域与颜色，可先改数据再判断）。M402 场景的评分不变。
4. **领域约定与用例文档**（M336）：为 8 个新领域写约定包，只写行业惯例；价签约定补促销价签一条；线路牌约定不改。每例写用例文档，交代来源、考察点、数据定义取舍、压测与检查的理由、与样图的差异。
5. **通过线**：先暂定为压测全部、版面检查 85%，05 有专家模板作正例；首轮真实模型基线后逐项复核检查，定稿（票据 03，M337）。

## 用户故事

1. 作为维护者，我改了模板参考之后，能用一条命令看到 12 种版式各自的压测与版面结果，而不只是 M402。
2. 作为维护者，我能从报告的未过原因直接看出是哪一项检查、差在哪里（位置、字号、颜色）。
3. 作为维护者，我新增一个领域时，有现成的约定包写法与用例目录可以照抄。
4. 作为维护者，我跑评估集不会改变门槛场景的输入与结果。

## 验收

- A1：`run.ts --config scripts/agent-eval/template-design/config.json` 能跑、能 `--rescore`、能续跑，报告与门槛同格式。
- A2：12 个用例的工作区经引擎载入无问题；示例数据集、全部压测与检查的数据变体都通过数据集校验。
- A3：05 专家模板压测与版面全过，只有空画板的模板版面不达线。
- A4：门槛场景的配置、资源与评分不变；全量测试通过。
- A5：首轮真实模型基线跑完，每例的检查经过复核，通过线定稿（票据 03）。

## 不做

- 不把评估集并入门槛（切换条件见 M333）。
- 不为 Agent 提供写工具或新的 MCP 工具；不改 DSL。
- 不做数据定义提取与数据集提取的评估：本集只评模板；新领域的数据定义提取另行补测。
- 不检查像素级的样式（行底色、线条颜色）；颜色只检查文字片段，相似度只作参考。
