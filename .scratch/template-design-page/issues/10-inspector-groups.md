# 10: 检查器按元素类型分组，文字的内容与适配能直接看懂

**What to build:** 分组顺序按元素类型定，加内容与适配两个专属编辑器。

**Blocked by:** 09

**Status:** resolved

**Trace:** [PRD](../spec.md)；用户故事 8；验收 A07；方案第 7 节。

- [x] 分组顺序照方案第 7 节的表；没写的可选项留在组里显示缺省值，取代"其他 N 项"（M356）。
- [x] 内容：文字与插槽排成一行，打字是文字，`/` 插入字段，点插槽改展示格式，格式按字段类型校验；片段样式点开改。写明一个文字元素只排一行或一列（M339）。
- [x] 双击图上的文字就地打开内容编辑。
- [x] 适配：只给 DSL 合法的步骤组合，横排竖排分开；下限、放不下时的等级、缩字组及成员数；最后一行是这一处实例的结果（压缩比、字号、字距）。
- [x] 字体按字体族分组列字重，选的仍是资源引用（M115）。
- [x] 互斥与失效写明原因，不等报错。

**测试接缝：** 单元测试走 `properties.ts` 的入口；浏览器用例改竖排站名的适配步骤。

## Answer

完成于 2026-11-05，分支 `worktree-template-design-page`。

**成果**

- `template/properties.ts`：分组按方案第 7 节的表，每种元素只出现它有的几组，先后合同一条顺序；去掉"其他 N 项"，没写的项留在组里显示缺省值。字段带 `exclusive`（左右、上下二选一）与 `blocked`（竖排不能倾斜）。
- `design/content-editor.tsx`、`template/content.ts`：文字和插槽排成一行，打字是文字，`/` 或按钮插入字段，点插槽改字段、展示格式与片段样式。不用 contentEditable：每段文字是一个输入框，输入法组字时不写回。
- `design/fit-editor.tsx`：步骤只给 Schema 允许的组合，横排竖排分开；用不上的项不藏，写明要什么才生效；最后一行是这一处实例的结果（`fitResult`）。
- `template/fonts.ts`：字体按族分组列字重，选的仍是资源引用。
- 双击图上的文字就地打开同一个内容编辑器；点外面或 Esc 收起，选中不动。
- 短的枚举摊开成分段（书写方向、对齐、放不下时），和原型一致。

**验证**

- `service/test/template-properties.test.ts` 新增 22 个用例：分组先后、适配步骤、互斥、失效、片段增删、展示格式、字体；写回结果由 `checkDslDocument` 判断。`template-overlays.test.ts` 加 `fitResult`。
- 浏览器用例「模板设计（票据 10）」走 M402 竖排站名：双击就地改、分组、字重、竖排只有三种步骤、改步骤后压缩下限写明失效、`/` 插入字段、Esc 打出字面的 `/`、格式不合法不写回、片段样式、删除插槽。
- 全部「模板设计」浏览器用例 6 个通过。
- 观感：文字检查器、插槽弹层和原型第 7 节对过；画板的轨道编辑还是通用表单。

**偏差**

- **字体族靠资源 ID 拆：** 资源接口只回答 ID，没有字体族的元数据，所以按 `font-族-字重` 的约定拆，显示成 "hei Medium"，不是原型的"思源黑体 Medium"。要显示真名，得让资源接口带字体元数据（开放 API 加法），不在这张票里。
- **展示格式的校验拆了一个引擎模块：** `src/display-format-pattern.ts` 没有依赖，控制台和引擎共用，规则只有一份；引擎行为不变。
- 字面的 `/`：选字段时按 Esc。中文输入法里按 `/` 打出来的是顿号，所以另给了"插入字段"按钮。
