# 模板设计页重做 PRD（第一、二期）

2026-11-05。设计事实源是[模板设计页方案](../../docs/template-design-page.md)与[原型](../../docs/prototypes/template-design/README.md)，本文只写范围、用户故事、接缝与验收，不重复设计。方案里的第三期（接 P3 预览通道）、第四期（接 P2、P4 的 Agent 与评论）不在本期。

## Problem Statement

P1 的模板设计页（票据 08）只够做小改，用户走查后说这块要再修正（M383）：

- **一次只看一份输入。** 模板是"数据、参数、尺寸 → 图"的函数（ADR-0007），页面只有一个样例下拉框，改完看不出 2 站、50 站、长站名会怎样。
- **不说影响范围。** 改循环模板里的一个元素，图上 35 处一起变，页面不写明。
- **看不到值从哪来。** 作用域不继承，字号可能经两层调用传进来，页面只显示变量名。
- **派生变量改不了。** 语料里 70% 的派生变量是 `branch`，页面只把它们当建议项，没有编辑入口（`service/console/src/pages/template-design.tsx`）。
- **不能增删元素。** 客户做不了模板，只能改已有的；阶段 5 的目标是客户自助（M206、路线图）。
- **只能填数。** 54% 的元素在自由布局里（M392）。
- **布局摘要的信息没用上。** 压缩比、放不下都在预览回答里，页面没显示。

## Solution

第一期把页面重组成函数编辑器：舞台上是引擎出的真图，左边是跨模板的结构与变量，右边只显示选中的东西，底部的样例带换输入。第二期让结构能改：增删移动、手柄、从字段创建、循环与调用表单、分支编辑器、状态样式、从零新建。DSL 不变；保存语义不变（M346、M356、M383）。

### 完成标准

- **第一期**：客户管理员打开 M402，点第 12 站的站名，看到"定义在站点，图上 35 处"；从字号追到主模板的内部参数并改掉，图换了；切到 50 站样例，打开适配层，看到哪些站名被压缩、哪些放不下；点问题定位到元素；只看不改不留工作副本与审计。P1 的模板设计用例照过。
- **第二期**：不写 DSL，从空白模板做出 M402 的站点模板（循环、竖排站名、缩字组、状态样式、派生变量），用 M402 的数据出图 0 个严重问题；真人走查。

## User Stories

客户管理员：

1. 我想打开设计页就看到真图，这样改的就是最终会出的东西。
2. 我想点图上的元素就选中它，这样不用先在树里找。
3. 我想知道改这个元素会影响几处、属于哪个模板，这样不会误伤。
4. 我想在树里跨模板看到完整结构，这样不用在模板之间切页。
5. 我想看到当前数据下哪些元素不显示、为什么，这样不会以为它丢了。
6. 我想切换数据、对外参数和画板尺寸看结果，试值不写进模板。
7. 我想一眼看到每份样例有没有问题，这样知道哪份要细看。
8. 我想看到哪些文字被压缩、压到多少，这样知道版面的压力在哪。
9. 我想分清哪些内容来自数据、哪些是写死的。
10. 我想看到每个变量在当前样例里的值，悬停时图上标出谁在用。
11. 我想从一个绑定的值追到它真正的来源，跨作用域也一样。
12. 我想把一个写死的值提取成参数，这样以后能调。
13. 我想让绑定只列类型相符的变量，不能绑定的直接不给入口并说明原因。
14. 我想点问题就定位到元素、字段或检查项。
15. 我想看这次改了什么，并在图上和当前修订对比。
16. 我想看选中元素的 DSL，能复制下载。
17. 我想复制、删除、排序元素，包进容器，改名字。
18. 我想在图上拖动改位置、尺寸、顺序、间距与轨道，拖动只会写出合法的 DSL（M392）。
19. 我想把字段拖到模板上直接生成绑定好的元素。
20. 我想用表单配置循环与子模板调用，只列基准相符的模板，缺的参数标红。
21. 我想不写表达式就配条件分支，并看到当前命中哪一支。
22. 我想按取值配状态样式，并看到每个取值在图上有几处。
23. 我想从空白开始做一个模板。
24. 我想把一块元素提取成子模板，这样能复用。

操作员与代建工程师：

25. 操作员的模板预览页不受影响（画板 11，M356）。
26. 代建工程师的推送、拉取与冲突判定不受影响（M348）。

## Implementation Decisions

- **留**：`template/properties.ts`（Schema 生成字段）、`template/session.ts`（撤销、暂存、冲突）、`template/document.ts`、`useLivePreview`、`hitElement`、发布修订页。
- **换**：`pages/template-design.tsx` 拆成外壳、舞台、结构、变量、检查器、样例带；字段外观换成值格。
- **写回都是纯函数**：结构编辑与手柄各一个模块，给文档与操作、得到新文档，和 `properties.ts` 的 `writeProperty` 同样的做法，不碰页面与接口。
- **不引入依赖**：不动 `package-lock.json`（评估固定它的字节）。拖动、树、弹层都自己写（同 M380）。
- **开放 API 只做加法**（M246）：读当前修订内容、预览带求值、布局摘要的描述、新建空白工作副本。
- **DSL 不变**。写不进 DSL 的操作不提供，例如 `wrap` 不能配 `equal` 或 `mergeBy`。
- **保存语义不变**：自动暂存、"保存"记一笔、"发布修订"生效（M346、M356、M383）。例外只有一条：工作副本改成第一次改动时才开（票据 01）。
- **样例不落库**：试值存浏览器，压测样例用内联数据集。切换条件见方案第 8 节。

## Testing Decisions

### 接缝

1. **开放 API**：服务测试只经 HTTP，内存后端进 `npm test`，PostgreSQL 加 S3 后端在 `node service/scripts/test-docker.mjs`；OpenAPI 快照相对 1.0.0 只有加法。
2. **引擎公开入口**：`render` 的新选项，用 `docs/examples/m402-dsl/` 做输入，写法照 `test/element-locations.test.ts`。
3. **写回的纯函数**：单元测试只经"给文档与操作、得到新文档"，结果由引擎的 `checkDslDocument` 判断，写法照 `service/test/template-properties.test.ts`。
4. **浏览器用例**：`service/test/console-suite.ts`，设 `RW_BROWSER`。
5. **观感**：和 `docs/prototypes/template-design/screenshots/` 逐张对照。用例不查观感，验收分开说"行为已验证"与"观感已对照"。

改控制台后在 `service/` 下跑 `../node_modules/.bin/tsc --noEmit -p console`，`npm run typecheck` 查不出未使用的 import。
