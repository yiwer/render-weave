# 01: 宽高一格写完：数值加尺寸方式，打数就是固定

**What to build:** 把堆叠、网格与画板里的宽高，和循环的每项尺寸，换成"数值 + 尺寸方式"一格（方案「检查器」、原型 01）。

**Blocked by:** 无

**Status:** resolved

**Trace:** [PRD](../spec.md)；用户故事 2；验收 R01、R09；M396。

- [x] `place.width`、`place.height`（父布局是堆叠、网格时）与循环 `itemLayout` 的每项宽高换成一格：左边数值框显示这一处的实际尺寸（布局摘要），右边下拉选随内容、撑满、按比例撑满；没写时数值淡色。
- [x] 在数值框里打数就写 `{ fixed: n }`，选随内容、撑满写 `hug`、`fill`，选按比例撑满写 `{ fill: n }`；固定值绑定变量仍走值格（`{ fixed: { var } }`），绑定时显示灰底条。
- [x] 自由布局的左、右、上、下、宽、高与最小、最大不变；画板的适用尺寸不变。
- [x] 状态样式里改尺寸照旧写进覆盖（票据 17），手柄写的数不变（M392）。
- [x] 写回的纯函数有单元测试：三种父布局、每种写法，`checkDslDocument` 没有严重问题，撤销还原字节。
- [x] 第一、二期里改尺寸的浏览器用例改成新控件照过。

**测试接缝：** 写回纯函数（`service/console/src/template/`）；浏览器用例。

## Answer

完成于 2026-11-09，分支 `worktree-template-design-page`。

**成果**

- `service/console/src/template/size.ts`（纯函数）：`sizeModel` 从生成规则给的变体认出宽高字段（有"固定"和随内容、撑满这类常量才算，认不得的照旧画变体下拉），`itemSizeModel` 是循环的每项尺寸；`typedSize` 答打一个数写什么（按比例时改权重，别的写固定，清空去掉这一项，不合法答原因），`chosenSize` 答选一种方式写什么（换成固定取现在的固定值，没有就取这一处的实际尺寸）。
- `service/console/src/components/size-cell.tsx`：一格是数值框加尺寸方式下拉，拼成一个框；没写、随内容、撑满时数值框空着，淡色是这一处的实际尺寸（布局摘要，检查器经 `FieldContext.box` 带进来）；固定值能绑定变量与提取为参数，绑定时数值框换成灰底条，同值格。
- `template/properties.ts`：宽高没写时的缺省按父布局（网格撑满，堆叠与自由随内容），下拉第一项写"缺省（随内容）"。
- 字段渲染（`components/property-fields.tsx`）在设计页遇到宽高就画这一格；循环的每项尺寸（`design/loop-form.tsx`）也换成它，互斥的方式在下拉里禁用并写原因。

**验证**

- `service/test/template-size.test.ts` 9 项：自由、堆叠、网格三种父布局，打数、随内容、撑满、按比例、换回固定、清空都过 `checkDslDocument`，写回原值内容还原；循环每项尺寸同样；不合法的输入答原因。
- 浏览器用例「模板设计（第三轮 01）」：胸牌的矩形里打数是固定、随内容时淡色显示实际宽、按比例改权重、0 当场拦下不写回、固定值绑定与断开；堆叠里的文字写"缺省（随内容）"；一直撤销回到原样。第一、二期改了尺寸操作的三个用例（P1 的循环每项高、票据 15 的互斥、票据 20 的标识行与地标）跟着改，全部「模板设计」浏览器用例 16 个通过，template 单元用例 266 项通过，控制台严格类型检查没有报错。
- 观感：票据 20 用例里截了标识行与地标的检查器，宽、高、每项宽都是一格，和原型 01 的写法一致。

**偏差**

- 自由布局的宽高也换成了这一格：票据写"不变"是我看错了，自由布局的宽高和堆叠、网格用的是同一个 size 定义（随内容、撑满、固定、按比例），左右上下与最小最大没动。
- "撤销还原字节"：纯函数这层写回原值时 `place` 里键的先后会变，单元用例比的是内容相等；逐字节还原是编辑会话的撤销负责的（它存的是原文），浏览器用例撤销到底后比内容相等。
- 原型 01 里宽高并排一行、标签缩成 W、H；现在仍各占一行。要和检查器分组一起重排，记进票据 05。
