# 05: 检查器只显示写了的与常用的属性，别的从"+ 属性"加

**What to build:** 没写的可选项不再一律摆出来显示"缺省"，收进每个元素底部的"+ 属性"（方案「检查器」）。

**Blocked by:** 01、02、03、04

**Status:** resolved

**Trace:** [PRD](../spec.md)；用户故事 6；验收 R01、R09；M396。

- [x] 每种元素一份"常用属性"表（例：文字的内容、文字块、适配、位置与尺寸、显示；容器的排布、位置与尺寸、填充、显示），常用的与写了的总是显示，其余在"+ 属性"菜单里。
- [x] 从菜单加一项写它的初值（同现在"添加"按钮的 `initial`），加了就显示；去掉一项（行尾"去掉"）删掉这个键，回到菜单里。
- [x] 状态样式模式下：被覆盖的项总是显示，可覆盖的都能从"+ 属性"加（写进覆盖）。
- [x] 位置与尺寸里宽高并排成一行，标签缩成 W、H（原型 01；票据 01 的一格已经做好，这里只重排）。
- [x] "常用属性"表是纯数据，加属性时不用改页面；Schema 生成字段的规矩不变（`template/properties.ts`）。
- [x] 第一、二期的浏览器用例里找不到的字段改成先从"+ 属性"加，照过；画板与十二种元素各加一项、去掉一项的写回过 `checkDslDocument`。

**测试接缝：** 浏览器用例；写回纯函数。

## Answer

完成于 2026-11-10，分支 `worktree-template-design-page`。

**成果**

- `service/console/src/template/optional.ts`（纯函数，不碰页面）：`COMMON_PROPERTIES` 是画板与十二种元素各一份的"常用属性"表，只有键名；`splitPanel` 把 Schema 生成的字段分成"显示的"与"+ 属性里的"：必填的、常用的、写了的总是显示，其余可选项进菜单；写了的不常用项（样例里画板的填充、容器的圆角）显示着并且能去掉；表里没有的类型全部显示。`addedValue` 给初值：同"添加"按钮的 `initial`，开关加上就是打开，填充与背景从白色起，最小、最大宽高从这一处的实际尺寸起（最小往下取、最大往上取，加上时画面不变）。加属性只改这张表，Schema 生成字段的规矩没动（`template/properties.ts` 没改）。
- 检查器（`design/panels.tsx` 的 `PropertiesTab`）：每个元素底部一排"+ 属性"，点一项写它的初值，这一行出现在它原来的分组里，焦点落进它的编辑器；加上的项名称后面有 ✕（`components/property-fields.tsx` 的 `FieldRow`，`property-remove`），点了删掉这个键、回到菜单里。清空输入框时键没了、这一行先留着（人还要接着打字），换元素或撤销后才回菜单。要先有别的项才能写的（线条的随框缩放要先有视图框）在菜单里是灰的，提示写明先加哪一项；当前写法下不能用的（竖排文字的倾斜）不进菜单。
- 状态样式模式：被覆盖的项总是显示；能从"+ 属性"加的只有这个取值下可覆盖的，加上写进 `states.cases.<取值>`，自身属性不动；这一行有圆点与"重置为自身属性"，没有 ✕，重置后回到菜单里。
- 位置与尺寸里宽高并排成一行，名称缩成 W、H（`PlaceRows`），全名留在提示与读屏的名称里；票据 01 的一格没改，半行里按比例的"份"省掉，没写时下拉只写"缺省"（引擎怎么排在提示里）。

**验证**

- `service/test/template-optional.test.ts` 12 项：表里的键都是 Schema 生成的字段；显示的与菜单里的不重不漏；原型 01 里画板、容器、文字、图片、循环的菜单；画板与十二种元素菜单里每一项加上都过 `checkDslDocument`（没有严重问题）、加了就显示并且能去掉、去掉回到原样；几种初值；清空的项先留着；竖排文字的倾斜不在菜单里；状态样式模式下被覆盖的显示、加的写进覆盖、重置回到原样。
- 浏览器用例「模板设计（第三轮 05）」：全元素牌的文字上常用项没写也显示、八项在菜单里；宽高在一行、名称是 W 和 H、读屏名称还是"宽""高"、数值框不窄于 40px；加旋转写 0、出现在位置与尺寸、焦点在这一行，改值、清空（行留着）、再改、去掉回菜单；描边加上是带必填子项的初值、"去掉"只有一个；加了内边距再撤销不留空行；容器加裁剪与最大宽（初值大于 0）再去掉回到原样；循环加反序、只取一段；线条先加视图框才能加随框缩放；画板加一项再去掉；撤销到底内容回到原样。站点的站名选"本站"后加旋转写进覆盖、自身没有、有圆点没有 ✕，换回自身属性不显示，重置后回菜单。
- 第三轮 04 的用例里倾斜改成先从"+ 属性"加；第三轮 01 的用例里堆叠文字的宽改成看"缺省"与提示。第一、二期的用例没有找不到字段的，原样通过。全部控制台浏览器用例 47 个通过（3 个平时不跑），template 单元用例 322 项通过，三处类型检查没有报错。Docker 后端的用例这张票没跑。
- 观感：本地开发服务上截了十六种状态（站名、画板、文字、容器、循环、线条、堆叠里的文字、窄窗），和原型 01 对照：宽高一行带 W、H，底部一排虚线框的"+ 属性"，两处一致；检查器内容宽 314px，窄窗下没有横向滚动。

**偏差**

- "去掉"是名称后面的 ✕，不在行尾：放行尾会把编辑器挤窄、绑定按钮和别的行对不齐。占整行的项（描边）的 ✕ 在标题行右端，原来底下的"去掉描边"链接在这种情况下不再出现。
- 菜单里的名称是 Schema 的名称去掉单位（"裁剪超出部分""填充色"），没有照原型缩成"裁剪""填充"；原型里循环菜单的"合并相邻"仍在循环那张表单里，不在"+ 属性"。
- 原型的菜单只列了几项，这里列的是 Schema 里全部没写的可选项（站名多出内边距、自身对齐、最小最大宽高）。
- 状态样式模式下没有"去掉"，用原有的"重置为自身属性"。
- 宽高并排后没写时下拉只写"缺省"，全称"缺省（随内容）"在提示里：半行放不下全称，浏览器对下拉的文字不按内边距截断，会盖住箭头。不并排的宽高（循环每项、有一边用不了时）照旧写全称。
- "撤销还原字节"同票据 01–04：纯函数比内容相等，逐字节还原是编辑会话的撤销负责的。
