# 模板设计页第三轮 PRD：参照成熟设计软件优化页面与流程

2026-11-09。设计事实源是[第三轮方案](../../docs/template-design-refine.md)与[原型](../../docs/prototypes/template-design-v3/README.md)，本文只写范围、用户故事、接缝与验收，不重复设计。决定见 M395、M396。第一、二期的规格在 [.scratch/template-design-page/](../template-design-page/spec.md)。

## Problem Statement

第二期做完之后，模板设计页已经能不写 DSL 从空白做出 M402 的站点模板（票据 20），但做的过程太长：按走查路径数，要 120 下操作。卡点集中在几处（方案「走查路径逐步数」）：

- **来回切页**：加元素在左面板的"添加"页，改参数在"变量"页，每加一个元素都要切过去再切回来。
- **一个属性两个控件**：宽高是"尺寸方式下拉 + 输入框"，外边距、内边距要先选"分别设置"才出四个框，排布是一个下拉加三行。
- **检查器太长**：没写的可选项一律显示"缺省"，文字的十几项散在三组里，适配展开成六行。
- **重复劳动**：调用方已经传了 `index`、`currentIndex`、`stopNameSize`，被调模板里还要一个个建，每个改类型、改显示名称；"地标不为空才显示"要先建派生变量再绑；新循环、新容器是固定尺寸，在堆叠里要一个个改成随内容。

用户走查后要求参照成熟的二维设计软件（Claude Design、Figma 之类）优化整体页面与操作流程（M395），看过方案后确认方向（M396）。

## Solution

骨架不动（舞台是引擎的真图，左边跨模板的结构，右边只显示选中的东西，底部换输入），改三件事：

1. **少切页**：插入搬到舞台底部的工具栏；左面板合成"图层 / 数据"两页，字段在"数据"页里拖到图上建元素、拖到元素上就连上。Agent 是左面板的第三页，P2 接入时出现。
2. **检查器收紧**：尺寸一格写完（打数就是固定），四边一格，排布用方向图标加九宫格，文字的常用属性一块，适配一行摘要，没写的可选项收进"+ 属性"。
3. **重复劳动交给页面**：一键建调用方传的参数，一个弹层建参数与派生变量，按字段是否为空显示一步建，新元素按父布局给尺寸，运算数一个下拉；加选中条、快捷操作（Ctrl+/），样例带默认收成一行。

DSL、保存语义、开放 API 都不变，只动控制台。

## User Stories

客户管理员：

1. 我想不切页就能加元素：底部工具栏点一下就加到选中的位置。
2. 我想在一格里看到并改宽高与尺寸方式，打一个数就是固定。
3. 我想一格写完内边距、外边距的四边，要分开时再点开。
4. 我想用方向图标和九宫格配排布，一眼看出是横排还是纵排、往哪边对齐。
5. 我想文字的字体、字号、颜色、书写方向与对齐挤在一块，适配一眼看到结论。
6. 我想只看到写了的和常用的属性，别的需要时从"+ 属性"加。
7. 我想把字段拖到已有元素上就连上数据，也能从元素上选"连接数据"。
8. 我想调用方已经传进来的参数，在被调模板里一键建好，类型、显示名称与缺省值照调用方。
9. 我想一个弹层就建好参数（名称、显示名称、类型、谁来给、缺省值）或派生变量，显示名称不用先删再打。
10. 我想"某字段不为空才显示"一步做完，不用先自己建派生变量。
11. 我想新元素的尺寸按它所在的布局来：堆叠里随内容，不用一个个改；新建的容器直接让我起名。
12. 我想当场新建被调模板时尺寸已经按图上的实际大小填好，建好就进入它。
13. 我想条件里的运算数在一个下拉里选变量或直接打值。
14. 我想选中元素后，在它旁边就点到常用的结构操作。
15. 我想搜一个词就找到动作或属性并直接执行。
16. 我想舞台更大，样例带需要时再展开。
17. 我想 Agent 在左面板里，带着选中的元素说话，改动是能撤销的提案（P2 接入）。

操作员与代建工程师：

18. 操作员的模板预览页不受影响；代建工程师的推送、拉取与冲突判定不受影响。

## Implementation Decisions

- **只动控制台**：`service/console/src/` 下的设计页、检查器、左面板、舞台与样例带。开放 API 不加不改，OpenAPI 快照不变。
- **写回仍是纯函数**：新控件（尺寸一格、四边一格、排布、一键建参数、按字段是否为空显示、新元素尺寸）各自落在 `service/console/src/template/` 的纯函数里，给文档与操作、得到新文档，结果由 `checkDslDocument` 判断；页面只调用它们。
- **字段仍由 Schema 生成**（`template/properties.ts`）：新控件是同一份字段的另一种外观，加属性自动多一项的规矩不变。"+ 属性"只决定显示哪些，不改字段表。
- **一个动作一处实现**：选中条、右键菜单、快捷操作、检查器里的同一个动作调用同一个函数，写回逐字节相同。
- **插入的位置规则不变**（票据 14 的 `insertionPoint`）：选中容器就放进去，选中别的就放在它后面。
- **不引入依赖**，不动 `package-lock.json`。
- **Agent 页接入前不显示**（票据 08 的规矩）；本轮只留位置。
- **评论工具**是第四期，本轮工具栏上不显示。

## Testing Decisions

### 接缝

1. **写回的纯函数**：单元测试只经"给文档与操作、得到新文档"，结果由 `checkDslDocument` 判断，撤销还原字节；写法照 `service/test/template-properties.test.ts`、`template-handles.test.ts`。
2. **浏览器用例**：`service/test/console-suite.ts`，设 `RW_BROWSER`。第一、二期的用例改成新控件后的等价操作，行为断言不放宽。
3. **观感**：和 `docs/prototypes/template-design-v3/screenshots/` 逐张对照。用例不查观感，验收分开说"行为已验证"与"观感已对照"。
4. **严格类型检查**：改控制台后在 `service/` 下跑 `../node_modules/.bin/tsc --noEmit -p console`。

## Out of Scope

- Agent 页的内容与接入（P2）；评论（第四期）。
- 方案第一轮里的第三期：一键压测、多样例一起看、实时旋钮（M352）。
- 任意摆放、多选与对齐分布（M392）；矢量路径的图形编辑。
- 面板停靠；模板列表页、发布修订页、操作员预览页的改版。
- 开放 API 的任何改动。

## Further Notes

- **领取顺序**：01–04、06、10、11、12、15 没有前置阻塞，但 01–05 都改检查器的同一组文件（`components/property-fields.tsx`、`design/panels.tsx`、`template/properties.ts`），建议一张合入再开下一张；06、07 都改左面板。
- **与并行工作的关系**：主检出常有评估在跑，每张票在独立 worktree 里做，合入前确认没有评估在跑（`docs/dev-setup.md`「已知的坑」）。Docker 后端测试会清同一检出的环境（M386），隔离跑时设 `COMPOSE_PROJECT_NAME` 与端口。
- **原型只作讨论**：`docs/prototypes/template-design-v3/index.html` 的控件点了不写回，数值是演示。
