# 数据定义发布为不可变的静态数据定义，数据集依赖不可变版本

取代 ADR-0005。数据定义仍可修改，但发布后形成不可变的静态数据定义；数据集必须选定一个静态数据定义，并按其编译产物 JSON Schema 校验。字段以字段名称为身份，数据集中的键与模板绑定都使用字段名称，显示名称可随时修改。

静态数据定义以数据定义名称加自动递增的版本号标识，其中的数据定义引用指向确切版本。模板的基准同样是静态数据定义的确切版本，渲染时数据集选定的版本必须与模板基准完全一致。模板本身不设版本、可以直接修改，包括把基准升级到同一数据定义的新版本：升级前列出失效的绑定，由人或 agent 修复后才能保存，因为字段以名称为身份，系统无法区分"改名"与"删除后新增"。改用另一个数据定义则复制模板。

ADR-0005 曾选择不发布不可变版本，让数据定义随改随用，靠修改前列出受影响模板来承担安全性。但字段以名称为身份后，修改字段名称会让已有数据集的键全部失效，而数据集无法像模板绑定那样由系统顺手更新。依赖不可变版本可以根本上避免这一点：已有数据集始终对应它当初选定的版本，后续对数据定义的任何修改只体现在新版本中。代价是重新引入版本概念：引用指向确切版本，被引用的数据定义更新后，引用方也要发布新版本才能用上；模板没有版本而匹配要求完全一致，模板升级后，选定旧版本的数据集与仍引用旧版本的调用方模板将无法再与它匹配。为此，模板升级前列出这些数据集与调用方模板，由用户选择一并迁移到新版本，或先复制一份模板留给旧版本；数据集迁移生成新数据集，原数据集保持不变，与依赖不可变版本的出发点一致。

依据：2026-10-08 建模草稿讨论 M18 二次修订（业务实体模型 G1）与 M36–M41，见[需求探索记录](../discovery/requirements.md)。
