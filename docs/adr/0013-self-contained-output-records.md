# 正式交付保存自足的出图记录，用确切构建重放

第二阶段的正式交付保存不可变、带格式版本且能整体复制的出图记录：包含模板及调用依赖、数据集、静态数据定义与编译产物、请求与渲染选项、资源内容版本及实际字节、渲染器构建标识和结果摘要。重放只使用记录内容，验证完整性及构建兼容性后重新渲染，不访问当前工作区；先把只有一个渲染项的正式交付做完整，再复用到批量出图。

只存引用或资源版本号会让历史依赖当前仓库的保留策略，只存图片又不能解释或重新验证生成过程；因此接受保存字体和图片的磁盘成本，换取脱离原工作区的复现能力。同一卷可用不可变文件的硬链接去重，但每份记录保有自己的文件入口，复制后仍自足，删除其他记录不影响它；不支持时独立复制，不能依赖外部符号链接。模板仍然没有领域版本，记录保存的是当时内容，不改变 ADR-0008。

当前没有分发历史渲染器的能力，故记录只接受确切兼容构建重放，不尝试由新引擎“尽量还原”。构建标识应覆盖实际引擎与依赖，不能仅用包版本或 Git 提交号；记录不携带可执行程序。代价是重放仍需取得相应构建，长期运行环境保存另行规划。

依据：已有 M10、M59、M61，本轮规划 M150–M155、实施 M172–M179 与[第二阶段 PRD](../../.scratch/local-production-output/spec.md)。票据 06–07 已实现单项记录、完整模板/静态定义/素材依赖、独立资源副本、最后发布完成清单及自足重放；构建标识覆盖实际引擎、包元数据、锁文件和生产依赖字节。去重仍由后续票据实施，见[出图记录说明](../output-records.md)。
