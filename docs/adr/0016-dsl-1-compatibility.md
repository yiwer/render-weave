# DSL 1.0 冻结现行写法，1.x 只做加法，继续拒绝未知键

DSL 1.0 就是数据定义（`renderweave-schema/1`）、模板（`renderweave-template/1`）、数据集、渲染请求与批次请求的现行写法。这次冻结不改名、不改语义，只写下成文契约：

- 人读参考放在 `docs/dsl/`，Agent 参考放在 `agent/reference/`；
- 结构契约是 `schemas/` 中的 JSON Schema 2020-12；
- 一致性测试保证 Schema 拒绝的文档引擎一定拒绝，引擎多出的拒绝只限于参考中列明的语义检查。

1.x 内只做加法：新增可选键、元素类型或枚举值。旧文档的解析结果与出图结果保持不变。删除、改名或改变已有写法的语义时，标识升到 `/2`，并附迁移说明与迁移检查。

解析器继续拒绝未知键，而不是忽略它们（M90 S7）：

- **代价**：用了 1.x 新增写法的文档，在较早的引擎上会被拒绝，而不是降级渲染。
- **理由**：出图是交付物，静默忽略一个拼错或不认识的键，比报错危险得多；拒绝也让"这份文档需要哪个引擎"在出图前就暴露出来。
- 同理，任何可选键都不能写成 `null`（M223）：`null` 不等于"没写"。

没有选择"宽进严出"，也就是忽略未知键、只校验已知部分：那样 Schema、引擎与编辑器对同一份文档会有三种理解，这正是 DSL 1.0 要消除的。也没有选择在冻结时顺手整理写法，例如统一命名或合并相似的键：现有工作区、出图记录与 Agent 资料都依赖现行写法，整理的收益抵不过迁移成本，留待确有需要的 `/2`。

依据：M219、M223，第三阶段 [PRD](../../.scratch/agent-template-authoring/spec.md) 与[票据 01](../../.scratch/agent-template-authoring/issues/01-dsl-schema-and-dataset.md)。
