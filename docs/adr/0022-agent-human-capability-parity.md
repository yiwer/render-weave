# Agent 与人类共享代建写入能力，发布以版本、审计与回退控制风险

2026-10-21 用户确认：人能做的，Agent 同样能做。数据定义既可以从示例图提取，也可以从数据集提取；静态数据定义允许 Agent 直接发布。人类页面仍保留查看、手操与微调。

这取代 M53 的“Agent 不能保存、发布、删除或正式出图”，以及 M205 的“Agent 写入只经人工批准的提案”。ADR-0015 的只读 MCP 边界随之修订。

## 决定

- **同一能力面**：保存工作副本、校验、预览、发布静态数据定义、保存模板修订、应用资源替换，只有一套代建 API。网页会话与 Agent 服务令牌都调用它，不设“Agent 专用发布通道”，也不要求 Agent 把成果包装成提案。
- **按角色授权**：权限仍按 M247 的矩阵。Agent 令牌沿用代建令牌（代建工程师），默认可以推送、预览，并写入发布静态数据定义与模板修订；资源替换等客户管理员操作要显式授权。角色之外不再按“人/Agent”分叉。
- **写入工具**：Agent 的 MCP 合同增加与代建端点一一对应的写工具。只有服务签发的 Agent 令牌能拿到写工具；开发者使用的只读 MCP 会话仍只有读工具。工具合同升版并复跑 Agent 评估。
- **审计**：每次写入记录主体（人或 Agent、令牌或会话）、租户、操作、前后内容哈希、差异摘要与时间；Agent 另记轮次与理由（如有）。
- **可回退**：静态数据定义发布仍不可变，回退是发布旧内容的新版本；模板修订可以指回旧修订；资源替换沿用影响报告与预期版本核对。Agent 直发不改变历史。
- **策略**：默认直发；租户可以按范围配置“发布前需人工批准”，但这是策略，不是架构上的硬门槛。额度、限流与并发限制对人类和 Agent 同样适用。

## 为什么

- 两套写入路径会让网页与 Agent 的行为逐渐分叉，校验、审计与冲突处理都要维护两份。统一到一套 API 后，页面、API 与 Agent 看到的是同一份状态与同一个发布结果。
- 风险控制点从“谁在操作”改为“能否回退、留下了什么记录”。静态数据定义不可变、模板有修订、资源替换有影响报告与预期版本核对，这些机制已经存在；补齐主体审计与可选审批策略后，Agent 直发的破坏面可控。
- 人类页面仍是一等公民，不能因为 Agent 能直发就退化成只读展示。Schema 设计页同时支持手动表单、示例图提取与数据集提取；模板页保留查看、结构化属性、参数旋钮、评论定位与手动微调；发布页保留差异、影响、历史与回退。

## 代价与边界

- Agent 的破坏面从“只能提案”扩大到“能写生产资源”。缓解靠角色授权、审计、不可变版本与回退，不靠事后解释。写工具只能发给 Agent 身份，不能出现在普通只读 MCP 会话里。
- 受阻成果仍按 ADR-0021（`0021-blocked-agent-outcomes.md`）处理：实际渲染有严重问题的模板候选不得批准或应用；本文的直发只适用于通过校验与渲染检查的成果。本文只改代建资源的写入与发布，批量正式交付的边界不变。
- v1.0 的服务端仍按 ADR-0017 不托管 Agent；本地 Agent 经带令牌的代建 API 或写工具写入。阶段 5.1 若把工作台放到服务端，按 ADR-0017 的切换条件补 ADR-0015 的四项，不改变本文的权限与审计模型。
- MCP 合同与 Agent 评估要跟着改；工具说明要讲清楚“默认直发”与“租户可要求审批”的区别。
- 需要新增或调整审计字段、角色分配与工具合同；发布端点、模板修订端点与资源替换端点都要接受 Agent 主体。

依据：2026-10-21 用户确认；M53、M205（被本文取代）、M247、M278（被本文修订）；ADR-0008（不可变静态数据定义）、ADR-0014（资源清单提交）、ADR-0015（被本文修订）、ADR-0017（服务端不托管 Agent）、ADR-0021（受阻成果的审核边界）。
