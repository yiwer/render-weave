# 代建检查与提交绑定同一份内容，资源变化必须重新检查

2026-10-23，依据用户要求制定整体优化 PRD 所作的架构决定，尚待实施。对应 [PRD 的 D02、D03、D09](../../.scratch/agent-harness-hardening/spec.md) 与 M310；补充 ADR-0014、ADR-0021，不改变 ADR-0022 的默认直发与可选审批策略。

## 问题与证据

[研究复现](../research/2026-10-23-agent-dsl-harness-review.md)证明：审核通过之后，在同一路径下追加图片资源版本，审核页仍可显示旧预览、保留旧批准，而应用使用新资源。只有工作区文档哈希或资源目录位置，不能说明审核与提交的内容相同。应用前再渲染能发现严重问题，却不能证明新图仍是人核准的图。

现有资源版本仓库已经有固定版本的读取能力，正式出图记录也保留可重放内容。缺口在于代建检查、预览缓存、审核结论和应用边界尚未共同使用一份完整身份。

## 决定

1. 每次检查保存内容身份，包含候选集合、依赖文档、出图请求、可信参考与内容事实、实际使用的资源版本及字节、引擎构建与判据版本。所有报告、预览缓存与核准结论指向该身份。模型配置另属于实验身份，不混进已有候选的内容身份。
2. 本轮读取固定资源，优先复用资源版本仓库。旧资源清单目录通过宿主私有副本和字节哈希获得同样保证，不修改原目录、不强制先迁移。图片、字体、后备字体与 SVG 所用字体都在追踪范围，损坏或缺失不得静默替换成当前版本。
3. 应用前比较实际依赖资源：版本仓库核对版本与字节身份，旧目录核对清单映射、种类及相关字节哈希。相关内容变化使旧检查依据失效，并返回差异与重新检查入口；当前本地审核流程必须重新预览、核准。无关资源变化不阻断，工作区覆盖选项不能绕过资源核对。
4. 最后一次版本核对与候选提交处于同一个短时并发控制边界。通过产品入口参与同一工作区和资源仓库写入的操作共享锁定约束或等价事务，并使用稳定锁顺序。公开渲染、审核与应用读取时协调同一边界，取得完整一致的输入副本后再耗时计算；不得读取未完成提交的混合内容。模型调用和耗时渲染在写锁外完成；锁内核对所检查的输入仍相同，变化则整体拒绝。
5. 本地多文件提交保存提交意图、旧/新内容身份与可恢复记录，不能把逐文件替换称为天然原子事务。中断恢复须得出完整旧状态或完整新状态；重复提交同一成功标识返回已有结果。恢复遇到新的外部修改时停止，不用旧备份覆盖它。提供完整状态前，相关产品操作应识别未完成提交并先恢复或明确阻断。
6. 固定范围是本次检查和提交依据，不是永久固定模板的资源引用。提交后合法资源替换继续按原影响检查与版本规则作用于未来出图。正式出图仍按既有出图记录保留实际内容。
7. 阶段 5 默认直发同样须在内容变化后重新检查；只有租户策略要求人工批准时才重新批准。本期不新增服务端写接口，也不改变人和 Agent 共享能力面的决定。

## 取舍与替代方案

- 选择内容身份和资源版本，拒绝仅靠路径、修改时间或“应用前无严重问题”判断一致。哈希与固定副本增加本地读取、存储和生命周期管理，但能给出可复查的核准对象。
- 选择最后提交边界的短时并发控制，拒绝从开始生成一直锁到应用。前者允许长任务期间其他工作继续，代价是提交时可能因冲突重查。
- 选择相关资源冲突集合，拒绝任意资源更新都废弃审核。需要准确追踪字体回退等间接依赖，换来更少的无关返工。
- 选择复用现有仓库及本地恢复机制，暂不引入新的数据库或长事务框架。后续托管复用服务事务，不能直接把本地文件恢复当成多人生产数据库。

## 保证边界与验收

### 本地实施的恢复互斥（2026-10-23，M318）

共同目录边界增加 OS 持有的外层互斥：Windows 用按真实目录哈希命名的 named pipe，Linux 用同规则的 abstract Unix socket，均由 Node 22 原生 `net` 提供。只用于本机进程争用，不传业务数据。宿主或恢复者强退后，OS 自动释放拥有权。磁盘层保留随机令牌、进程/宿主、启动时间与持续更新的租约；在 OS 独占下，租约过期且确认旧进程死亡后将旧锁目录整体移走，再清理。正常释放也先整体移走，清理失败不遗留主路径中的空锁。

选择这个组合，是因为单靠目录 `mkdir` 加 PID/租约无法安全完成多恢复者的回收：逐个删拥有者文件后自身强退会留下空锁，直接 rename 可能误移动另一恢复者刚获得的新锁。OS 互斥消除了该回收竞争，代价是本地保证限定 Windows/Linux 同宿主。旧版空锁、未知拥有者、其他宿主、仍存活或无法证明死亡的进程均保守阻断；不支持混跑绕过新边界的旧产品版本。停掉旧维护进程、备份并核查目录之后，由操作者处理未知旧锁。

提交意图 `renderweave-apply-intent/1` 保存完整旧/新字节与哈希、原工作区 JSON 基线、批准/轮次/成果守卫、目标目录及包含 `applied.json` 的最终结果。写业务文件前先发布参与目录指针。恢复先取得所有参与目录的共同约束，再检查每份内容只能是记录的旧状态或新状态，未涉及的工作区文件与批准依据也须保持原样；第三种内容一律列冲突并保留。已经准备的合法提交前滚为完整新状态；尚未发布意图的强退保留旧状态。完成凭据原子发布，幂等重试返回同一 `commitId` 与原结果。成功凭据同时绑定当前轮次与审核，不能从另一轮复制后冒充本轮成功。

这不是逐文件天然原子事务，也不是服务端事务或跨宿主锁。公开读取在完成恢复前只返回等待/需要恢复，取得完整副本后释放约束再进行渲染。候选检查点和 Agent 执行恢复仍属于 ADR-0024。

保证覆盖遵守上述约束的产品写入入口。任意手工磁盘写入或恶意宿主不受同一事务约束，但后续读取仍必须核查字节并拒绝损坏。断电后的介质持久性依赖操作系统和存储，本期验收覆盖宿主强退、可控提交中断与恢复，不宣称跨任意存储的分布式事务。

按 PRD A04–A06，从公开资源替换、审核和应用入口验证相关/无关资源变化、字体间接依赖、并发替换、提交中断、幂等重试、旧目录及损坏。验收同时包含合法对照，不能靠拒绝全部应用满足一致性要求。
