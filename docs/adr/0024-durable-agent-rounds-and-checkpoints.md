# 本地 Agent 轮次由宿主持久记录，通过完整检查点开新轮次接续

2026-10-23，依据用户要求制定整体优化 PRD 所作的架构决定，尚待实施。对应 [PRD 的 D08–D11](../../.scratch/agent-harness-hardening/spec.md) 与 M311、M312；扩展 ADR-0021 的受阻成果与恢复草稿，保留 ADR-0015 的执行器复用选择。

## 问题与证据

已有恢复能力依赖执行器返回后由宿主收尾；轮次主记录在末尾写入，接续又依赖该记录。宿主被强制结束时，可能已有可用候选却没有完整轮次记录。研究中的这一点属于[代码证据](../research/2026-10-23-agent-dsl-harness-review.md)，新增强退验收尚待实施。

供应商会话不是业务工作记录，不能承担候选、可信参考、审核状态和应用结果的唯一事实源。不同候选的质量也不适合压成一个未经校准的分数。

## 决定

1. 宿主在启动执行器前提交持久轮次记录和固定输入，运行中原子更新状态并追加关键事件。区分准备、执行、收尾、完成、停止和失败；完成要求成果检查及记录提交完成。执行状态、技术质量、内容/视觉结论与审核状态分开，停止不代表没有成果，完成也不代表业务通过。
2. 一个轮次只有一个有效执行拥有者。接管陈旧拥有者前确认原执行器不能继续写入，不能仅因超时便并发接管。恢复操作必须辨认记录版本与中断状态，不能伪造历史完成、批准或发布成功。
3. 宿主保存完整候选集合的不可变字节和哈希，包含被调模板、检查身份与结果。完整候选集合的 `check_outcome` 每次完成检查后，宿主发布本次检查实际消费字节的检查点，并给出可观察的保存完成状态；检查执行完成不等于业务合格。先保存字节，再检查保存副本，最后原子发布记录。半写、清单不全、读取中变化及未经显式集合检查的零散写入不覆盖上一份完整检查点。MCP 检查与比较继续只读，宿主负责保存。
4. 接续沿用既有入口，从旧轮次的完整检查点开一个新轮次，显式引用来源、检查依据和新反馈。首版不恢复供应商内部会话，不把多次启动伪装成原执行连续运行。历史完整轮次继续可读；身份不全时只保留可证事实并要求重新检查。
5. 宿主统一处理取消、超时、明确硬额度和执行器失败，停止该轮新请求与相关执行器，经过有界本地保存后留下结果或可恢复状态。耗时终检与渲染同样处于可终止的边界，不依赖会被同步运算阻塞的定时器。先支持可执行的时间与轮数上限；不以结束后才返回的 token 统计冒充实时硬费用上限。停滞只计算仍有核准必修问题的完整修复机会，正常确认、终检和分页不计。具体保护值见 PRD，便于后续凭实测调整。
6. 分开保留最后完整候选与有证据更好的候选。只在同一检查依据下，以技术约束和修改范围为前提，确认关键指标无退步且至少一项核准指标改善才更新后者；互有得失或证据不足则不可排序。不静默替换 Agent 正式提交，退步时向审核人展示差异。
7. 宿主恢复草稿仍标明 `hostRecovery`，只可查看和接续，不能直接批准或应用。应用中断的提交意图、幂等性与恢复边界遵守 [ADR-0023](0023-authoring-check-and-commit-identity.md)，不由执行状态推断应用成功。

## 取舍与替代方案

- 选择宿主业务记录和新轮次接续，暂不采用供应商会话恢复作为保证。会损失部分不可导出的推理上下文，也可能增加重读成本，但候选和依据能跨执行器、跨会话验证。
- 选择本地记录与原子发布的检查点，暂不引入通用工作流框架或数据库服务。增加记录迁移、检查点清理和崩溃恢复分支；换来对当前本地代建规模适用、可从 CLI 故障验证的状态。
- 选择保守的可比关系，拒绝“最后一次就是最好”或用未校准总分自动选胜。不能总是给出唯一最好版本，但能避免未知信息和维度权衡被掩盖。
- 选择有界停止与保存，拒绝等待无限收尾。远端已发出的请求可能继续执行或计费，本地取消不承诺上游即时退款；已知成本与未知用量分别记录。

## 切换条件与验收

### 已实施的整轮监督边界（M319，2026-10-23）

执行器、模型代理、受管 MCP 和同步终检保留在同一业务宿主中；外置轻量监督进程只处理截止时间、取消信号、所属进程树和最多 30 秒的本地保存宽限。选择可终止进程边界，避免同步渲染阻塞普通定时器；代价是每轮额外进程启动及 Windows/Linux 生命周期协调。不替换执行器工具循环，也不把比较、选择或检查点发布移到监督器。

Windows 使用仍存活业务宿主的 PID 定向 `taskkill /T /F`，Linux 使用独立进程组；正常完成也回收本轮残留后代。停止先终止运行子树，再由独立保存进程发布 `stop/1` 原因及已知用量，复用完整检查点，不重新渲染。保存宽限耗尽返回明确 `incomplete`，不伪造完成记录。异常外部强退使 Windows 根进程已消失时，不能证明所有后代已结束，保留现有 `pendingRecovery/interrupted` 语义；不声称进程崩溃、脱离受管树或远端调用都已清理。

墙钟默认 60 分钟，输入准备完成后、执行器启动前起算；40/80 默认轮数不变。硬 token/费用设置因当前适配器无法执行而在启动前拒绝。消息 ID 去重用量只是已知快照，不能当实时硬限额。停止后有完整检查点才能从新轮次接续，零散恢复草稿仅供诊断。合同、旧格式读取及故障验收见[整轮预算](../agent-budgets.md)。

阶段 5 若需要多人协调、服务端托管、跨机器调度或租约接管，应复用服务持久存储与事务，并按 ADR-0017、ADR-0022 补齐隔离和审计，不扩展本地文件锁来冒充分布式调度。

### 已实施的保守停滞边界（M324，2026-10-23）

完整检查保存、完整反馈交付、成功候选写入和下一次完整复测共同组成机会；不以工具调用次数或文件哈希变化代替。比较直接使用完整检查的技术硬约束、核准业务缺项和视觉逐项测量，不依赖较好候选选择，不引入总分。基准改变、新增未知、半写和反馈不完整时不能确认连续无进展。

选择“阈值证据形成后，完整反馈之后再次成功写入已列候选才停止”，避免把最后一次自检当成新循环。分页、纯诊断、正常确认不触发；执行器正式 result 封住新的异步停止决定。代价是最后检查后无后续事件的挂起要等墙钟预算，而不是猜测其意图。默认两次，配置固定到轮次和实验身份；停止由既有监督器与有界保存执行，详细证据与旧记录兼容见[停滞控制](../agent-stagnation.md)。

按 PRD A07–A11，从 CLI 强退、取消、短预算、并发恢复及连续修改验证外部结果：只存在一个有效拥有者，保留最后完整集合，不发布半写检查点，不误停正常进展，不改写正式提交。使用现有假执行器验证确定性故障，再用真实模型验收接续与反馈效用。
