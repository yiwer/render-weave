# 共同候选实拷贝保存，各验收计划独立绑定输入与运行请求

2026-10-23，M327，[可靠执行与可信验收 PRD](../../.scratch/agent-harness-hardening/spec.md) D06/D16、票 20。

## 问题

实验身份已经逐字节固定构建、资料、评分器和输入，但原工作目录仍会继续开发和构建。仅记录 Git 提交或路径不能保证后续模型活动使用相同字节。反过来，把资料策略校准的输入直接放进唯一共同身份，又会阻止原四场景、可信反馈及留出案例使用各自独立的核准事实。

## 决定

1. `renderweave-candidate/1` 保存共同源码、实际 dist、Agent 资料、Schema、评估代码、锁文件及实际安装依赖的独立文件副本。包括 WASM 与执行 TypeScript 所需的本机依赖，不通过 node_modules 联接读取工作目录。忽略可再生的命令链接和工具缓存；保留实际文件模式。共同默认策略、合同版本、Node 版本/平台/二进制摘要进入身份。
2. 每个验收计划另存 `renderweave-candidate-binding/1`：引用共同候选，固定该计划的完整实验身份、原始评分配置、资源原字节、执行器版本/文件摘要及确切单元。输入路径仍按现有评估入口读取，摘要不符则拒绝。提供方未公开可固定修订时仍为 `providerRevision: null`。
3. 评估 CLI 显式接收绑定，在首次及每轮模型派发前核对包、当前执行内容和计划身份；报告与实验清单记录绑定。旧实验不能事后补造绑定，续跑不能删除或替换绑定，打印的续跑命令保留绑定。旧报告重新评分仍另存，不补造候选来源。
4. 包和绑定只写新目录，清单最后发布。来源变化、损坏或链接不能被宣称为完整冻结。修改代码、资料或策略得到新候选；用旧绑定对比新绑定时列差异，并保守要求重跑受该绑定覆盖的全部单元。不同候选的观测不拼成一次通过。
5. 人工审核链使用独立的 `renderweave-stage-request/1` 与 `renderweave-candidate-stage/1`，固定核准材料摘要、原样公开参数、实际工作区/资源和上游已应用轮次。每次人工应用后再绑定下一阶段；不把独立数据集阶段变成自动采纳的转录场景。宿主预检成功后仅调用一次既有公开 CLI，沿原监督器取消/保存，原始轮次不改写，另存一次消费记录及输出字节凭据。核准清单只由宿主持有，模型仍只接当前阶段的公开输入。

## 取舍

选择实际副本与派发前重核，代价是额外磁盘占用和哈希检查时间，换来工作目录变化不会改写既有候选。共同包与逐计划输入分离，代价是多份绑定与资源证据，换来不同计划共享同一构建而保留独立结论。

这是本机可验证的候选，不是通用可迁移运行时。操作系统、Node 和原生执行器身份照实登记；跨平台离线验证保存各自环境及共同源文件/资料、图片和摘要证据，不把平台二进制假定为相同。原生 Claude 不嵌入包，实际文件和版本在每个计划的派发前核对。

候选冻结不等于真实模型门槛通过，不改变阶段 5 默认直接发布与可选审批决定，也不证明租户写入、托管隔离或客户自助已验收。操作及证据边界见[候选冻结](../agent-candidate-freeze.md)。
