# ADR-0028 草案：Excel 数据转换由现有 Claude Agent 编写脚本并隔离执行

## 背景

M363 要求把 `quick_print` 的 Excel 制作表能力接入 RenderWeave，用 CodingAgent 取代单次 LLM 提取；用户指定沿用模板识别的 Claude + OpenCode Go。

当前 Claude Code 数据集提取只开放 Read、Write、Edit、Glob 与领域工具（`src/agent/tasks.ts:34`），没有运行转换脚本的能力。ADR-0025 的本地文件边界不是操作系统沙箱；ADR-0027 也明确把开放式代码执行留给独立沙箱与新 ADR。

本草案给出接入方向；后续已用本机 Docker 验证窄原型（M365），并在价签 staticSchema 上完成一次真实模型反馈重提测试（M366）；完整业务闭环与托管隔离复核仍待完成，不表示代码执行已获生产验收。

## 建议决定

1. **沿用现有 Agent**：本地闭环使用已有 Claude Code 执行器，经现有宿主代理访问 OpenCode Go；沿用当前模型配置、额度、轮次记录和检查点，不另实现模型循环。
2. **提供隔离执行工具**：受控读取器从原文件生成带原始坐标、类型、格式和合并范围的完整单元格视图；Claude Code 编写 Python 3 转换脚本，工具把固定视图、脚本和参数交给独立的执行环境。首期转换以标准库处理结构化视图，不由每份脚本自行安装 Excel 解析依赖。生成代码不在宿主进程里 `eval`，不通过放开宿主 Bash 来执行。窄原型已验证固定镜像、stdin 传入且无宿主挂载的 Docker 路径；生产读取依赖和隔离边界仍须另行落实。
3. **最小权限**：原始文件只读，输出只写本轮产物；执行环境不带模型 key、服务凭据、宿主目录或容器控制套接字；默认无网络。依赖预装并固定版本，限制 CPU、内存、进程数、时间与输出量，停止轮次时一并停止执行。
4. **职责分开**：脚本负责转换，宿主负责固定输入、检查文件边界、校验候选、验证来源及应用。脚本无法修改可信基准、审核记录、最终检查和生产数据。
5. **可重放**：保留原件、脚本、依赖/运行环境标识、输出及其哈希，记录退出状态和诊断。同输入和固定脚本可不调模型重跑；变更原件或目标数据定义后重新核对，不能沿用旧批准。

## 与现有决定的关系

- 本地 Claude Code 路径是 ADR-0027 仍保留的现有路径，本次按用户指定组合使用。
- 本草案补充 ADR-0027 的“加代码执行”切换条件；不更换全产品默认执行器。
- 若该任务托管后仍用 Claude Code，则与 ADR-0027 的“产品循环由 Tool Runner 驱动”冲突，须在服务化实施时显式修订；不能以复用模型渠道为由暗中切换执行器。
- ADR-0025 的宿主持有凭据、低可信内容不授予权限仍适用。工作簿中的文字是待处理资料，不能扩大脚本或 Agent 权限。

## 取舍

优点是模型理解表的结构，程序负责大量重复的数据处理；同一脚本可复跑，错误可返回给 Agent 修正。代价是新增执行隔离、依赖管理、产物检查与停止机制，不能继续把“只开放文件工具”当作完整边界。

只增加固定 Excel 读取工具也能改善观察能力，但不足以覆盖任意多层表头、跨列列表和客户特有转换；先验证一个窄的脚本执行工具。若真实样本证明声明式映射足够，优先收敛成固定转换工具，不扩大通用权限。

## 定稿前的验证

- 用实际制作表验证读取、脚本修复、来源核对和引擎出图的完整闭环。
- 验证越界路径、链接逃逸、环境读取、网络访问、无限循环与大量输出被隔离；配对正常转换能够完成。
- 验证取消、崩溃与恢复不会遗留执行进程或重复应用成果。
- 确定运行环境、Excel 依赖及 `.xls` 的处置；未实测前不写成已支持。
