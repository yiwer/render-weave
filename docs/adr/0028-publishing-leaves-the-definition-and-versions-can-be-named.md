# 发布不影响数据定义，静态数据定义的版本可以自定义

修订 ADR-0008 里"自动递增的版本号"的说法，以及 M346 的"发布后删除草案"。其余不变：静态数据定义不可变，数据集与模板绑定确切版本。

**发布只是从数据定义产出一份静态数据定义。** 草案留着，能接着改，能再发下一版，也能删除，这些都不影响已发布的版本。草案记的基于版本换成刚发布的这一版，下次发布与它比较。同一份内容可以用不同版本发布多次。

**版本由发布的人定。** 缺省是下一个编号，可以改成字符串，写法照旧 RenderWeave 的 `versionTag`：`^[a-z0-9][a-z0-9._-]{0,63}$`，同一个数据定义下唯一。`2` 与 `v2` 这样的字符串就是编号 2，所以一个写法只对应一个版本，页面上不会出现两个长得一样的版本。引用（模板的基准、数据集的 `staticSchema`、字段的 `ref`）写 `{ "name", "version" }`，`version` 是整数或字符串。

**整数继续有效，这是和旧项目唯一的不同。** 旧项目必须手填、没有编号。全改成字符串要动 DSL 文档、85 个样例与测试文件、开放 API 的类型、Agent 的工具合同与评估，换来的只是不再有缺省编号。用户定了保留。代价是"最新版本"不能靠比较版本得出，要看发布的先后，所以工作区文档多带一个登记时间。**切换条件**：缺省编号成了负担（比如用户总在改成别的写法），再去掉它，并按上面的范围全改。

**Agent 先不用自定义版本。** 工具合同的版本仍是整数，发布由系统分配。要让 Agent 选自定义版本，再升合同、重跑评估。

旧项目的依据：`outside_context/legacy-renderweave/specs/renderweave-v1.md:54`（发布不锁住 Draft）、`:69`（`versionTag` 的规则）、`:250-255`（发布命令）。决定记在 M384。
