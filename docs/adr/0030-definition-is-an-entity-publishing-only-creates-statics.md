# 数据定义是独立的实体，发布只产出静态数据定义

取代 ADR-0028 里草案的部分（"草案留着""基于的版本换成这一版"）。ADR-0028 里版本的部分不变：缺省是下一个编号，可以写自定义的字符串。

用户走查时指出：Schema 独立于 StaticSchema，Schema 的主键是 key，StaticSchema 不可变、主键是 key+version；发布就是创建一个不可变的 StaticSchema，对原有的 Schema 毫无影响，Schema 仍然可以继续发布或修改。参照的是 `E:\GenCode\RenderWeave`：`GLOSSARY.md:8-9`（Schema 本身就是草稿，不设 SchemaDraft 实体）、`docs/adr/0002-static-publications-are-immutable.md`、`src/schema-repository.js:5-9`（`schemas` 与 `static_schemas` 两张表，后者由触发器禁止改删）、`src/publication.js:65`（发布只插入 Static）。

ADR-0028 只做到"发布不删草案"。那时数据定义没有自己的实体：列表是静态版本与草案的并集，推送来的名称没有草案，要先"复制为草案"才能改；发布还要改草案记的基于版本。用户在页面上看不出区别，因为他打开的线路牌根本没有可编辑的内容。

**数据定义是一张表，主键是（租户, 名称）。** 每个名称只有这一份，本身就是可编辑的定义，没有"草案"这个东西。它不进工作区，渲染、数据集与模板只看静态版本。

**发布只写静态版本。** 数据定义的内容、哈希、保存人、保存时间逐项不变，所以不记基于的版本；和哪一版比较读取时现算，取这个名称最新发布的版本。同一份内容可以发布多次。

**推送第一次带来一个名称时建数据定义，内容是最新版本去掉版本号；之后再也不碰它。** 旧项目没有推送，这是这里要补的规则：推送和发布同理，都只产出静态版本，不改已有的数据定义。

**删除数据定义不影响静态版本，模板与数据集照旧用。** 有过静态版本的名称不能再新建。旧项目用 UUID 做身份，自然不会复用；这里名称就是主键，新建同名的会把旧版本认成自己的，所以靠"这个名称有没有静态版本"判断，不必另存墓碑。推送的新版本也不会让它复活。静态版本上标"来源已删除"。

**名称沿用现在的写法，不换 UUID，也不迁移引用。** 模板、数据集与字段的 `ref` 都按名称引用，换身份要动 DSL 文档和全部样例，换来的只是复用名称这一件事。切换条件：真的要改名。

**回到旧内容没有单独的操作，把内容存回数据定义再发布。** 去掉 ADR-0028 的"用这一版覆盖草案"：数据定义没有修订历史，覆盖之后恢复不了。复制静态版本要换名称，是一个新的数据定义，从头发布。切换条件：要做修订历史时，再加恢复。

**接口换路径，不留旧路径。** `/draft` 系列只有控制台与测试在用（1.2.0 加的，P1 还没交付给客户），留着等于留两套概念。问题码 `draft.stale`、`draft.versionTaken` 不改：模板工作副本也用前者，改码换不来什么。

**存量由部署步骤补。** 迁移改表结构，内容在对象存储里，SQL 读不到，迁移留一个标记，`setup` 逐个租户补，全部补完才删标记。接口进程等 `setup` 结束才启动，这期间没有别的写入。

这次不做：旧项目的成组发布与依赖固定、数据定义的修订历史、删除前按引用阻止。决定记在 M389。
