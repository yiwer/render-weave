# Agent 完整检查点与接续

受管 `agent run` 的 `check_outcome` 由宿主先固定候选集合，再调用同一成果检查器检查保存副本。返回 `checkpoint: { status: "saved", id, contentIdentity }` 后，该集合才成为可恢复检查点。`readReview` 与 `agent review` 的状态页提供同一检查点身份、文件哈希及检查结果。完整但业务不合格的集合可以保存；缺少依赖、JSON 半写、清单不完整或固定期间文件改变会返回 `notSaved` 和原因，上一检查点保持不变。

主模板与候选清单中所有文件按原始字节保存；本轮工作区依据整体保存，覆盖必要被调模板、数据定义与数据集。核准上下文、参考图及本轮固定资源身份也参与核对。调用闭包单独核对，其他语义错误不能遮住缺依赖。工作副本后续编辑、只完成一份模板、单文件可解析和未执行整组检查都不会自动更新检查点。

## 保存合同

| 记录 | 合同 |
|---|---|
| `checkpoints/<id>/record.json` | `renderweave-checkpoint/1`；来源 `hostRecovery`、保存时间、启动记录哈希、完整文件哈希、同一检查器的完整结果和内容身份 |
| `checkpoints/<id>/agent/` | 本次检查消费的 `outcome.json` 与候选原始字节 |
| `checkpoints/<id>/snapshot/` | 本次固定的工作区依据，包含被调模板及定义、数据集 |
| `basis.json`、`reference-image` | 固定的核准上下文及可选参考图；资源字节仍在轮次的固定资源副本，读取核对实际使用的哈希 |
| `checkpoint.json` | `renderweave-checkpoint-ref/1`；最后完整检查点 ID 与记录哈希。它是唯一发布点 |
| `checkpoint-recovery.json` | 当前恢复拥有者与目标新轮次；短锁内核对并发布，正常结束后释放 |

宿主先写 `.pending-<id>` 目录，检查完成后把完整目录改名，最后原子更新指针。发布途中强退只会保留上一完整指针或新完整指针；未发布目录和临时文件不能恢复。每次读取验证记录、候选、清单、依据及实际使用资源的哈希；损坏会给出诊断，不借用残留文件。终检同样保存完整检查点，正式成果从终检消费的固定副本复制。保证针对进程强退与本地原子替换，不声明断电或网络共享文件系统事务。

MCP 合同升至 **0.13.0**。独立 `renderweave mcp` 仍只有只读检查，没有宿主时不返回保存状态。受管 MCP 由宿主启动，执行器配置仅包含 stdio 转发地址；检查桥的随机令牌只进入受管 MCP 进程环境，不进入执行器环境、工作目录、配置文件或工具输出。检查桥只接受本轮固定候选的空检查请求，不接受外来判据、路径或检查结果。

## 从中断轮次开始新轮次

```powershell
node dist/bin.js agent review out/round-1 --no-open
node dist/bin.js agent run --from out/round-1 --feedback feedback.md --out out/round-2 --key-env OPEN_CODE_API_KEY
```

`--from` 沿用原任务及参考资料，把检查点候选按原字节放到新轮次 `agent/candidates/`，把原记录放到 `agent/previous/`。新 `inputs.previous.checkpoint` 记录 ID、内容身份与 `hostRecovery`；新反馈、提示词、工作区依据及资源重新固定，新轮次重新检查。检查点恢复保留被检查的工作区依据，记录的发布目标仍是原工作区，后续应用仍执行工作区变化检查。原轮次状态、正式交回、批准及应用事实均不被补写。轮次链读取已有执行状态，不伪造质量结论；PID 后续复用仍按执行状态的保守规则判断可写性。

只有宿主和旧执行器都已明确失去写入能力、启动身份与检查点能核对时才允许恢复。仍存活、跨机/未知拥有者、无完整检查点或内容损坏均拒绝。针对同一源轮次的恢复拥有权在现有短锁内处理，至多一个有效写入者；旧恢复尝试已完整结束或其宿主/执行器都明确退出后可重试，时间经过多久都不是抢占依据。

检查点仅可查看或接续，不能直接批准、应用。新轮次真实交回后再进入现有人工审核。旧版完整轮次继续走原 `--from` 入口；缺失历史身份和资源版本时保留已知事实，在新轮次重新固定，不能补造旧版本。旧报告和原始记录不迁移、不改写。

验证见 `test/agent-checkpoint.test.ts`：实际 CLI、假执行器和真实 MCP，覆盖保存信号、两模板集合、业务受阻、半写/缺依赖、读取变化、保存/终检强退、发布中断、字节接续、恢复竞争与直接批准/应用拒绝。预算、较好候选选择、停滞与真实模型效果属于后续票据。
