# 按需资料真实配对：预登记准备

当前尚未派发真实模型。政策见 [policy.json](policy.json)，状态 awaiting-candidate；须先合入票12/15/16/17最终实现，固定构建、资料、预算和配对输入，再将登记状态置为 frozen 并记录时间、提交与完整内容身份。登记完成后才启动模型。

只使用票14预登记的独立合成校准案例：中文/英文四类任务，共8例，full/on-demand各重复2次，总32次。与用户留出图片、裁切或退化版本无关；这些合成案例继续属于校准，不证明泛化。

主指标是全部尝试的输入、缓存读、缓存写token合计，最低有用下降20%。每次尝试必须完成记录，四类提供方计量（输入、输出、缓存读、缓存写）已知且usageSource=result；消息小计、未知和历史缺失不能伪装成零成本。thinking包含在输出中，不再次相加；明细未知照实列出。人工审核/修正/返工分钟若未实测均未知，所以不能仅据token减少声称订单总成本改善。

净收益另设两条守卫：候选全部尝试的输出token合计不得高于full；候选实际墙钟不得高于full。墙钟使用已完成评估分段区间的并集 `timing.actualWallMs`，不把ABBA块之间另一策略的运行或人工等待算给本策略；同时报告尝试耗时合计与完整性。任一项未知或升高均保留full。这是保守工程决策线，尚未经业务校准，派发后不得看结果改线。

候选全部16次原始成果须通过目标修正、非目标保留、未知范围保留、末次工具检查与终检一致及规定后续页取得；任何配对质量维度退步、关键错误或越界均拒绝改默认。两组同模型、effort缺省、40/80轮数、60分钟整轮预算、同输入/判据及串行调度。顺序为full第1次→on-demand第1次→on-demand第2次→full第2次，各块同例顺序；提供方未知修订保持不可固定，不声称消除时间影响。

32次完整前不作默认决定。硬额度立即停止后续派发，不自动等待或切换模型绕过；计划缺失明确未完成。完整负结果可以保留full并关闭票18。原评估报告的机制/未核准来源计数不改写，实际原生CLI、上游模型信息与独立尝试原件另建来源登记。任何调整默认都在票20候选冻结之前完成，不以本试验代替后续固定候选的模型门槛。

离线比较入口（不调用模型）：

```powershell
node --import tsx scripts/agent-eval/context-trial-report.ts --policy <已冻结policy.json> --pair <pair.json> --full <full最终分段报告.json> --on-demand <on-demand最终分段报告.json> --out <新比较报告.json>
```

入口核对两组冻结身份和预登记单元，按全部尝试原始数值汇总，缺失单元退出3，身份不匹配拒绝产生结果，已有比较报告不覆盖。完整数字通过时仅返回 `requires-source-verification`，不会自动核准真实来源或修改默认；未知、回退消息、范围违例、输出/墙钟升高均不能触发采用。真实采用仍需来源登记和本票的明确决定，原始失败与负结果保留。

原件归档仅用于本次试验：输入清单的格式为 `renderweave-context-trial-archive-inputs/1`，`roots` 每项含唯一 `label` 和源目录 `path`，须覆盖校准准备、两组全部轮次/失败/重试/流日志、报告与冻结资料；不能只选最后成功的轮次。运行 `node --import tsx scripts/agent-eval/archive-context-trial.ts --pack <输入清单.json> --out <新归档目录>` 后，每个文件以SHA-256去重保存，清单保留原相对路径与原根绝对路径，清单自身摘要另存。

清理工作树前，用同一脚本 `--restore <归档目录> --out <新恢复目录>` 恢复全部原件并逐文件核对SHA，再从公开 `readReview` 抽查代表轮次。恢复不重写记录中的绝对路径；归档保证字节可恢复，不保证移动到任意位置后可直接接续执行。来源登记把CLI初始化模型与实际响应消息中的模型分别列出；提供方未返回的修订保持未知，不能把初始化字段冒称提供方版本证明。
