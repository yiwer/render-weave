# Excel Agent：通用渲染项与交付接续

2026-11-03。从已审核应用的数据集，按明确计划生成标准批次请求、固定依赖并交付图片。实现分支 `feature/excel-agent-p06`，基线 `a05b5db`；验收状态和命令结果以[票据 04](../../.scratch/excel-agent-extraction/issues/04-prepare-and-deliver-output.md)为准，操作见[出图接续说明](../excel-agent-output.md)。

## 实现判断

增加 `prepareAgentOutput` / `deliverAgentOutput` 和对应正式 CLI；前者生成可检查的计划产物，后者复用 `freezeBatch` / `runFrozenBatch` / 出图记录与重放。计划可按数据集选择不同模板、尺寸和对外参数，也可把任意明确列表路径的位置传给模板参数，不包含线路或站点字段。

全部应用候选必须有出图安排或跳过理由。源数据与定义在准备时必须符合已审核应用的内容；准备后使用固定文档及资源版本字节，交付前再独立核对计划范围、候选、定义、源审核依据和引擎身份。文件完整性通过不等于允许替换已审核数据。

这是对现有批次 API 的衔接，不新增图片渲染器、业务语义评分器或发布审批。P04/P05 的 Claude Code + OpenCode Go 原始提取证据继续使用；本轮没有新增模型调用。

## 受控夹具端到端结果

验收脚本先把归档提取结果导入独立工作空间，与模型不可见的既有真值逐字段比对，再自动审核应用这些**仓库夹具**。自动核准不代表用户或客户业务核准，也没有修改上一轮保留的待审成果。

| 场景 | 准备与实际结果 |
|---|---|
| 六份商品价签数据集 | 明确跳过 1 份；剩余 5 份普通价签，另给其中 1 份出大号 JPEG；2 个批次，6/6 正式交付 |
| `catalog@1` 嵌套目录 | 按 `/batches/0/items` 展开，明确跳过原始位置 2；实际参数 `1、2、4、5、6`，5/5 正式交付 |
| 问题清单 | 两个场景均为 0 严重问题、0 提示 |
| 独立重放 | 两个场景各取首项重放，图片字节与正式成果完全一致 |
| 重复业务值 | 测试将两个商品改为相同品名，经受控审核后仍分别出图；货号与参数保持位置对应 |
| 取消与失败 | 测试确认跨组取消保留未执行数量，布局失败不能被准备成功掩盖，草稿只记预览 |

## 证据与复跑

`docs/agent-eval/excel-output-p06/` 保存测试报告、端到端汇总、CLI 输入输出、固定清单、示例图片和源码/构建身份。完整运行目录在工作树 `out/excel-p06/accept-01/`，包含工作空间、审核轮次、版本资源、准备目录、全部图片和自足出图记录；含字体的完整目录未加入版本库。文档证据子集不能当作可独立交付的准备包。

在该工作树根目录运行，输出目录的父目录须存在，每次换新目录：

```powershell
npm run build
New-Item -ItemType Directory -Force out/excel-p06 | Out-Null
node scripts/accept-excel-output.mjs --out out/excel-p06/accept-02
```

脚本只使用已归档的模型提取结果，复跑不消耗模型额度。首轮模板夹具漏写横排适配的 `compressGlyphs` 步骤，被现有规则拒绝；补齐夹具后通过，未放宽引擎规则。

## 边界

一次列表展开选择明确 JSON Pointer，不支持通配符、多层自动分组、跨表 join 或脚本表达式。计划最多 1000 个展开位置；客户表、大表性能和人工工时仍属 P07。正式 `agent run` 的工作簿输入、统一检查点及生产隔离还未收口；代码保留在独立分支。

审核页面交互走查仍受环境阻塞：Computer Use 原生管道不存在，浏览器宿主也不可用。未宣称这部分已验证；可执行的 CLI/API 与图片成果已经验证。
