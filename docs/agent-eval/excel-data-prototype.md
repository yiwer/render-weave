# Excel 数据处理机制原型

2026-11-03，M365。P01–P03 的窄原型支持继续做 Claude 编排：固定单元格视图、隔离运行转换脚本、独立核对来源与完整候选这条路径可行。它尚未证明真实制作表的业务语义正确，也未接入产品。

后续 P04 已按工作空间 staticSchema 泛化并进行一次真实模型测试，见[接续报告](excel-agent-p04.md)（M366）；下文保留 P01–P03 当时的观察与边界。

验收状态、命令与提交记录以[票据 01](../../.scratch/excel-agent-extraction/issues/01-validate-data-processing-prototype.md)为准。代码和机器证据单独保留在分支 `prototype/excel-agent-p01-p03`，目录 `scripts/prototypes/excel-agent/`；主线仅保存设计和结论，不把验证脚本直接作为产品实现。

## 已取得的证据

| 问题 | 实测观察 | 对实现的影响 |
|---|---|---|
| 表格信息是否可追溯 | 两方向的不同合并列组、原始数值与格式化时间、空格、前导零、圈号和隐藏数据均能保留；区域可以分页 | 先建立结构化视图，再让模型按需查看；不能只传压缩文本 |
| 大量转录能否交给脚本 | 固定脚本输出两份有序数据集；与人工列出的期望逐字段相同，同输入重跑输出字节相同 | 模型理解结构，脚本负责全部记录的转换 |
| 是否独立发现缺陷 | 注入漏站、漏班时、去重、错序、遗漏第二份候选、伪造及重复来源、未分类区域均被拒绝 | 脚本自己的成功声明不能作为通过依据 |
| 能否复用引擎 | 经公开入口 `publishStaticSchema`、`checkDataset` 校验两份候选；第二份候选非法时间也被拒绝 | 不重写定义校验，不只检查第一份 |
| 隔离限制是否实际生效 | 普通转换成功；容器内非 root、根文件系统只读、无宿主测试秘密、无 Docker socket、无外部网络；内存、进程数、超时、输出上限及取消均有故障探测 | 生成脚本不在宿主运行，不通过放开宿主 Bash 执行 |
| 是否能宣布业务成功 | 机械通过报告仍保留 `semantic: needsReview` 与 `applicable: false` | 业务含义需独立真值或人工审核，不能从执行成功推出 |

隔离采用固定 Python 3.13 slim 镜像摘要、stdin 输入、无宿主挂载、有界临时目录和 JSON 输出。镜像摘要、运行设置、环境、源码哈希及每项探测结果在该分支的 `evidence/results.json`；`evidence/report.html` 可离线打开查看。普通转换原始执行记录、独立检查和引擎报告也一并保存。

容器配置参考 [Docker run](https://docs.docker.com/engine/containers/run/)、[资源约束](https://docs.docker.com/engine/containers/resource_constraints/)与 [none 网络](https://docs.docker.com/engine/network/drivers/none/)，判断以本次实际探测为依据，不把配置文档当作运行结果。

## 不能扩大解释的结论

1. **没有调用模型。** 截断脚本失败后换回正确脚本的修复演示由验收程序控制；这证明反馈可用，不证明 Claude 能自主修复。用户指定的 Claude Code + OpenCode Go 保持不变，下一阶段才接入。
2. **样本是人工构造。** 只覆盖两方向、合并表头和有限字段；没有多层任意嵌套表头、单位推断、历史配置继承或完整 `quick_print` 替代验收。
3. **读取器是受限 OOXML 验证实现。** 只接 `.xlsx`、有限数字格式；公式不执行，缓存最新性未知。未支持格式和附加内容显式报告；`.xls`、宏和图片内容不支持。采用标准库是为缩小验证依赖，不是生产 Excel 解析库的最终决定。
4. **映射语义仍需审核。** copy/collect 从已声明位置重建值；错误映射若内部一致，机械检查不能识别其业务含义。被归为说明的区域及映射规则本身必须可审。
5. **隔离有部署边界。** 本次在本机 Docker Linux 引擎验证所列行为，没有完成共享宿主威胁模型、宿主崩溃回收或多租户并发验证。容器不能仅凭这组探测宣布适合生产执行任意代码。
6. **未接应用或出图。** 原型只生成候选与证据，不写业务数据、不触发正式批次；人工修正、检查点恢复和整套候选应用留到 P05，逐站出图留到 P06。

机械报告与引擎报告刻意分开：`check-good.json` 中 `engineSchema` 为 `notChecked`，引擎结果以 `engine.json` 为准。产品集成时应聚合两者，且语义待审仍不可应用。

## 后续实施判断

先做 P04：在现有 Claude Code 任务编排上接工作簿查看、隔离执行和独立反馈，使用 OpenCode Go；用固定夹具检验模型能否读出两个不同列组、保留完整站名及重复值，并修复至少一个注入缺陷。记录所有尝试、错误、用量和耗时。之后以真实制作表和独立人工真值校准，才考虑 P05 的审核与应用。

本次不改变 ADR-0027 的产品执行器决定；[ADR-0028](../adr/0028-excel-agent-script-execution.md)继续为草案。流程合同仍见[数据处理流程设计](../excel-agent-workflow.md)，验证脚本不直接升级为稳定产品接口。
