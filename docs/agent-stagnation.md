# Agent 有证据的停滞停止

`agent run --stagnation-threshold 2` 缺省允许连续两次完整修复复测无核准进展。阈值必须是安全正整数，非法值在启动前拒绝；公开 API 为 `stagnationThreshold`。实际值显示在启动提示，保存于 `round-start.json.runtime` 和 `round.json.runtime`，评估入口同名参数写入 `identity.budgets.stagnation`。改变阈值必须新建实验，不能向原身份续跑。

## 完整修复机会

一次机会依次要求：

1. 宿主已保存完整候选的 `check_outcome`，且非空核准必修问题已完整交付执行器。
2. 执行器结构化事件证明 `Write`/`Edit` 成功写入了前后完整集合中的候选文件。
3. 下一次显式集合检查完成并保存，反馈也已完整交付；基准、工作区、资源、任务、请求与判据相同。

完整反馈可以是未截断的检查结果，或同一 `reportId/contentIdentity/total/groupBy` 从 offset 0 连续读到 `nextOffset: null` 的全部 `outcome_feedback` 页，含超长项全部 JSON 分片。页本身不产生新检查、修复机会或停止。缺页、跳页、报告过期、边读边写、写入与检查重叠、`notSaved`、半写和身份不足使周期失效；未列入成果集合的杂项写入不算候选修复。

达到阈值只形成停止证据。收到这些完整反馈后，又成功写入最后完整集合中列出的候选，且没有未完成的并发写入，才证明开始下一次修复活动并停止。本轮正式 `result` 一旦到达，不再发起新的停滞决定；此前已作出的停止仍保留。最后自检、重复诊断后直接交回可以正常结束；无后续事件的等待由墙钟预算保护。仅 `Read`、备注自评、分页和反复检查均不能触发这个下一周期边界。

## 问题和进展

核准必修范围来自完整检查中的严重技术问题、可信内容基准缺项、核准视觉区域的异常及越过容差的字号/尺寸/位置偏差。待确认和未知不是必修结论；模型备注不能扩大或缩小该集合。没有可信业务基准时，完整候选的引擎硬约束仍可核查；没有可核查问题时只依赖时间和轮数。

只比较同一依据下的原始逐项证据，复用候选比较器的核准测量，不依赖较好候选选择、总分或模型自评。任一必修问题消除，或任一核准维度有可证明改善，都会清除连续无进展周期；字号偏差尚在但实际缩小也算进展。新增未知或依据改变使证据不足，不据此停止。候选哈希改变本身不算改善，正确候选的空问题集合不计数。

## 停止结果与兼容

复用[整轮预算](agent-budgets.md)的监督、所属进程树终止和最多 30 秒本地保存路径。`run.stopped.reason: "stagnation"` 及 `stop.json` 保存：

| 字段 | 证据 |
|---|---|
| `threshold`、`basis` | 生效阈值，以及任务/工作区/资源/请求/参考/政策/判据身份 |
| `cycles[]` | 前后已发布检查点 ID、内容身份、必修问题、完成写入的调用 ID 与候选路径 |
| `cycles[].feedback` | 前后检查调用 ID、报告 ID、全部续页的调用 ID/offset/nextOffset |
| `continuedBy` | 证明继续修复的成功写入调用、路径及此前完整检查点 |

检查点保留不可变候选、输入及实际检查结果；日志保留结构化调用上下文。停止后只可查看恢复草稿、用 `--from --feedback` 新开轮次，不能生成批准或应用成功。新轮次不继承旧停滞计数；旧轮次、检查与停止原因不改写。已知用量沿用停止保存，未知不补零。

合同升至 **0.17.0**；工具权限不变，`round/1`、`round-start/1`、`execution/1` 与 `stop/1` 使用加法字段。旧轮次缺少阈值/周期证据时继续按既有事实读取，不从历史重复调用倒推停滞；旧实验的 null 阈值可重新评分，不能默认为新阈值后继续派发。确定性验收经公开 Agent CLI/API 与真实 MCP、渲染，使用完整假执行器，不代表真实模型质量收益。
