# Agent 运行方式验证（M190）

结论：Claude Code 加 Qwen token plan（qwen3.8-max）可以作为业务 Agent 的运行方式，M190 的三个验证点均通过。

- **看图**：qwen3.8-max 经 Anthropic 兼容端点能读示例图，也能读 MCP 工具返回的预览图。
- **工具闭环**：Agent 调用进程内渲染工具，读回预览图，再与示例图对照。
- **候选质量**：从 M402 示例图产出的数据定义与数据集，结构正确、转录准确，三次运行都一次通过校验。偏差集中在 5 条领域约定上，模型从图上推不出来。专家改 6 处左右即可，不属于"大量返工"，路线图的切换条件没有触发。

验证日期 2026-10-14，Windows 11，Claude Code 2.1.296。模板生成不在 M190 范围内，没有测，见文末「未覆盖」。

## 环境与隔离

- **端点**：`https://token-plan.maas.qianwenaiapi.com/apps/anthropic`。key 经 `ANTHROPIC_AUTH_TOKEN` 以 Bearer 方式发送；主模型、子 Agent 模型都是 qwen3.8-max（用户指定，具备视觉）。
- **key**：只从环境变量 `QWEN_TOKEN_PLAN_API_KEY` 读取，不打印、不写文件。在全部输出目录、配置目录与脚本中逐字搜索 key，0 个文件命中。
- **子进程环境**：从空白开始，只放系统必需变量与 Qwen 配置，配置目录（`CLAUDE_CONFIG_DIR`）独立。宿主会话的 `ANTHROPIC_BASE_URL`、`CLAUDE_CODE_*` 等变量与登录凭据都不继承。
- **权限**：以 `--restricted` 运行，没有任何执行代码的工具，文件工具限于工作目录。`--strict-mcp-config` 只连本验证的 MCP 服务；初始化消息确认可用工具只有指定的几项。
- **MCP 服务**（`scripts/m190/mcp-server.mjs`）：进程内调用引擎，只读。提供草稿预览 `render_draft`（返回 PNG 图片内容块）、`check_definitions`、`check_dataset`、`list_resources`。
- **费用显示**：Claude Code 不认识 qwen 模型名（stderr 报 `unrecognized_model`），它算出的 costUSD 没有依据。token plan 的实际额度消耗未知。

## 验证点 1：看图

直接调兼容端点，用原图（3496 × 780 PNG）转录 M402 示例图，与专家数据集（`docs/examples/m402-dsl/dataset-m402.json`）逐位对照：

| 模型 | 读图 | 耗时 | 站名（35） | 地标圈号 | 道路（35） | 班次（15） | 顶栏（6） |
|---|---|---|---|---|---|---|---|
| qwen3.8-max | 能 | 82–139 s | 35 | 读出 9 个，位置与数字全对 | 33 | 15 | 6 |
| qwen3.8-flash | 能 | 25 s | 35 | 不读 | 35 | 15 | 6 |
| qwen3.7-plus | 能 | 29–35 s | 35 | 0–8，不稳定 | 32–33 | 15 | 6 |
| auto | 能 | 21 s | 35 | 10，其中 1 个是误读的蓝色"1"圆标 | 34 | 15 | 6 |
| qwen3.6-flash | 能 | 47 s | 漏 1 站，之后错位 | — | — | 15 | 6 |
| qwen3.7-max | 不能 | — | 400 `Unexpected item type in content` | | | | |
| glm-5.3、deepseek-v4-pro | 不能 | — | 回答"没有看到图片" | | | | |

- 站名按去掉带圈数字后比对。带圈数字是地标图片（M77），模型常把它并进站名。
- 设计稿上草埔地铁站、布龙立交上方的蓝色"1"圆标确实存在，M97 决定按早期错误设计忽略。所以专家数据集里没有它，不是模型看错。
- 8 路并发时，qwen3.8-flash、qwen3.6-flash、deepseek-v4-pro 在约 5 s 连接失败，逐个重试都返回 200。验证脚本因此逐个请求。

## 验证点 2：工具闭环

Agent 先用 Read 看示例图，再调用 `render_draft` 读回预览图。工作区副本埋了两个只在预览图上出现的标记：第 23 站改名为"七星瓢虫站"，票价改为 7。请求的本站序号是 23。

| 运行 | 读示例图 | 调用渲染 | 预览图本站 | 预览图票价 | 轮数 | 用时 |
|---|---|---|---|---|---|---|
| 1 | M402、2 元、东门 | 413 ms 出图 | 七星瓢虫站 | 7 元 | 4 | 72 s |
| 2（`run.mjs`） | 通过 | 通过 | 七星瓢虫站 | 7 元 | — | 238 s |

- 两个标记都答对，说明 MCP 工具结果中的图片内容块经兼容端点传给了 qwen3.8-max，模型也读懂了，这是已验证的。
- 运行 1 还答对了下一站"大世纪花园"，列出的差异也都真实存在，包括蓝色"1"圆标。

## 验证点 3：数据定义与数据集候选

**任务**：Agent 只拿到示例图和一份 DSL 参考（`scripts/m190/dsl-reference.md`）。参考里只有语法和一个商品价签的例子，不含任何 M402 内容。Agent 用 Write 写候选，用 MCP 工具校验。运行结束后，由引擎独立重新校验，再与专家版对照。

### 三次运行

| 项 | 运行 1 | 运行 2 | 运行 3（`run.mjs`） |
|---|---|---|---|
| 用时 / 轮数 / 输出 tokens | 619 s / 10 / 28.6k | 662 s / 10 / 31.4k | 636 s / 11 / 27.4k |
| 校验 | 一次通过；引擎重新校验 0 问题 | 同左 | 同左 |
| 结构 | 站点定义加主定义，主定义用 list<ref> 引用 | 同左 | 同左 |
| 站名（去圈号） | 35/35 | 35/35 | 35/35 |
| 道路 | 35/35 | 34/35 | 31/35，23–29 站分段边界偏一位 |
| 班次 | 15/15 | 15/15 | 15 个全对，另多编 2 个 |
| 地标圈号 | 并进站名 | 并进站名 | 建成"换乘线路号"`list<number>`，数字全对，语义错 |
| 标识 | 单张图片字段；地铁、医院正确，另转录了蓝色圆标 | 同左，蓝色圆标有一个错位一站 | 同左，蓝色圆标映射到 `landmark-1` |
| 线路号文本 | 缺，只有图片 | 缺 | 有，文本加图片，与专家版一致 |
| 运营说明与班车类型 | 分开 | 合成一段文本，"运营"写成"营运" | 合成一段文本 |

### 与专家版对照

专家版共 15 个字段（线路牌 v1 有 11 个，停靠站点 v1 有 4 个），三次都对上的有 8 个：线路号图、运营方、首班、末班、班次列表、站点列表、站名、所在道路。

三次都出现的偏差有 5 条，都是领域约定，从图上推不出来：

| 约定 | 专家版 | Agent 的写法 | 依据 |
|---|---|---|---|
| 站名下的 ①②③ 是地标图片 | `landmark` 图片字段 | 并进站名，或建成数字列表 | M77 |
| 站名上方的标识 | 文本枚举列表，模板按取值选图 | 单张图片字段，一站放不下两个标识 | M97 |
| 票价 | 票制文本加数值票价（展示格式 `0.##`） | 一段文本"一票制2元" | M402 草稿 |
| 终点站 | 模板派生变量，取站点列表末项 | 另设 `destination` 字段，数据重复 | M24 |
| 本站序号 | 模板参数，由渲染请求给出，同一数据集可出每一站的牌 | 放进数据集 | M30、M62 |

- 蓝色"1"圆标三次都被转录。这是业务决定（M97），只看图无法知道。
- Agent 自己列出的"需业务确认"清单覆盖了圈号、图标、线路号形态与本站语义，所以专家复核时有现成的切入点。
- **返工量（推断）**：每份候选约 6 处字段级修改，再加上 9 个站名去掉圈号、补 9 个地标引用。比从零写少得多。

## 延迟与用量

- **做数据定义一轮约 10.5 分钟**，大部分时间在模型的长思考上。工具调用都在 7–40 ms 内完成。
- **闭环单轮 72–238 s，波动大**。
- **交互式场景（M208 的评论与旋钮）不能用 qwen3.8-max 逐轮响应**（推断）。qwen3.8-flash 读图 25 s 且转录全对，可以作为交互轮的候选，阶段 3 需要实测它的工具调用。

## 对路线图的影响

- **代建路线继续**：数据定义这一层只需少量返工，切换条件（"专家仍需大量返工"）没有触发。
- **提升质量的关键是领域知识，而不是换模型**：上面 5 条约定应作为领域提示交给 Agent，例如术语表与常用写法。改进后用 `--steps design` 复测，看偏差是否消失。
- **Claude Code 的 Read 会缩小大图**（推断）：运行 3 编出的两个班次，可能与示例图被缩小后小字难辨有关；直接调 API 用原图时，班次 15/15。阶段 3 的工具应提供局部放大或裁剪。
- **ADR-0009（CloudKiln）的执行方式需要改写**：本地方式已验证；云上按会话隔离的运行方式还没测。

## 复现

```bash
npm run build
node scripts/m190/run.mjs out/m190/run1
```

- `--steps vision,loop,design` 可以只跑其中几步，`--vision-models` 指定看图的模型。
- 报告写在 `<输出目录>/report.json`。各步骤的流式日志、MCP 调用日志与候选文件都在同一目录下。
- Claude Code 可执行文件默认取 PATH 上的 `claude`，也可以用 `CLAUDE_BIN` 指定。
- 运行 1、2 用的是同样的提示和工具，是在开发这个脚本时手动跑的。
