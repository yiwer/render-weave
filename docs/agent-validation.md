# Agent 运行方式验证（M190）

结论：Claude Code 加 Qwen token plan（qwen3.8-max）可以作为业务 Agent 的运行方式，M190 的三个验证点均通过。

- **看图**：qwen3.8-max 经 Anthropic 兼容端点能读示例图，也能读 MCP 工具返回的预览图。
- **工具闭环**：Agent 调用进程内渲染工具，读回预览图，再与示例图对照。
- **候选质量**：从 M402 示例图产出的数据定义与数据集，结构正确、转录准确，三次运行都一次通过校验。偏差集中在 5 条领域约定上，模型从图上推不出来。专家改 6 处左右即可，不属于"大量返工"，路线图的切换条件没有触发。
- **领域约定复测**：把这 5 条约定写成领域约定文档交给 Agent 后，两次复测全部做对，专家返工降到 1–2 处。
- **模板生成**（阶段 3 首测，1 次）：Agent 拿到干净的模板 DSL 参考与专家版数据定义，23 分钟写出 5 个模板，出图 0 问题，版面接近专家模板。压测暴露 3 处适用范围设置问题，专家改 3 处即可。用户验收另发现 2 处版面问题：带圈数字排成了站点列之外的一行；道路名没有同间隔分布。
- **通用化**（M216）：交给 Agent 的资料改为三层——通用做法指南、领域约定包、项目说明，提示词本身不含具体业务。
  - 带"通用指南 + 线路牌约定"时，模板两次都通过全部 10 个压测场景和用户指出的 2 处版面检查，数据定义 15 个专家字段全部对上。
  - 只给通用指南时，拆分类规则大多做对；需要领域知识的地方（带圈数字是地标），Agent 列为待确认，没有乱猜。
  - 换用 366 设计稿时，线路牌约定照样适用；约定没覆盖的分段票价，由通用规则拆成了三个字段。
- **局部放大工具**（M217）：加了 `view_image` 后，366 的 59 站两次都转全，地标 15/15、设施图标 18/18，没有多标。剩下的错误是长站名在列首或列尾掉一个字。代价是用时翻倍。

验证日期 2026-10-14，Windows 11，Claude Code 2.1.296。模板生成不属于 M190，作为阶段 3 的首测一并记录在此。

## 环境与隔离

- **端点**：`https://token-plan.maas.qianwenaiapi.com/apps/anthropic`。key 经 `ANTHROPIC_AUTH_TOKEN` 以 Bearer 方式发送；主模型、子 Agent 模型都是 qwen3.8-max（用户指定，具备视觉）。
- **key**：只从环境变量 `QWEN_TOKEN_PLAN_API_KEY` 读取，不打印、不写文件。在全部输出目录、配置目录与脚本中逐字搜索 key，0 个文件命中。
- **子进程环境**：从空白开始，只放系统必需变量与 Qwen 配置，配置目录（`CLAUDE_CONFIG_DIR`）独立。宿主会话的 `ANTHROPIC_BASE_URL`、`CLAUDE_CODE_*` 等变量与登录凭据都不继承。
- **权限**：以 `--restricted` 运行，没有任何执行代码的工具，文件工具限于工作目录。`--strict-mcp-config` 只连本验证的 MCP 服务；初始化消息确认可用工具只有指定的几项。
- **MCP 服务**：验证时用的是一次性的 `scripts/m190/mcp-server.mjs`，进程内调用引擎，只读。它提供草稿预览 `render_draft`（返回 PNG 图片内容块）、`check_definitions`、`check_dataset`、`list_resources`，M217 起另有 `view_image`。第三阶段票据 03 起由正式的 `renderweave mcp` 取代（[说明](mcp.md)，M225），脚本已删除；loop 步骤用新服务复测通过，见下文「改用正式服务后的复测」。
- **费用显示**：Claude Code 不认识 qwen 模型名（stderr 报 `unrecognized_model`），它算出的 costUSD 没有依据。token plan 的实际额度消耗未知。

## 用户验收（模板首测）

用户验收首测模板，认为其余都不错，指出 2 处版面问题：

1. **带圈数字被排在了站点列之外，自成一行**。设计稿里地标是竖排站名的最后一格：没有地标的站名占满整列，最后一个字与别列的地标在同一底线上（M27、M77）。首测模板中，无地标站名的底边比地标底边高 12 mm。
2. **道路名用了两端分布，首尾字贴边**。设计稿是同间隔分布：两侧留白与字间距相同（M131）。这条约定当年也是用户纠正后才定下来的。

两处都加进了模板评估的自动检查，并用专家模板校准过：

- 地标底线：比较第 1 站（无地标）站名底边与第 4 站地标底边的差值，在 2 mm 以内为通过。专家模板差 0 mm，首测模板差 −12 mm。
- 道路名对齐：静态检查绑定 `road` 的文字元素是否为 `spaceEvenly`。专家模板通过，首测模板为 `distribute`。

## 通用化：三层资料（M216）

用户要求提示词通用，不能只对这一款线路牌有效，也要兼顾其他场景。旧的约定文档把三种性质的内容混在一起，现在拆开：

| 层 | 文件 | 内容 | 何时给 |
|---|---|---|---|
| 通用做法 | `scripts/m190/guide.md`（票据 04 起为 `agent/guide.md`） | 任何"示例图 → 数据定义 → 模板"都适用的 16 条规则（第 16 条转录规则见 M217），从这次观察到的失败中提炼，不含具体业务。规则涵盖：<br>· 出图选择是参数且有"不选"值；可推出的信息不存；组合值拆开；编号另存文本<br>· 类别图标用枚举；像文字的符号先查资源；含义不明不建字段<br>· 适用尺寸按目标范围；重复元素字号一致；分布方式按示例图留白判断<br>· 可选元素放在所属排布流里；交付前预览验证极端情况 | 每次都给（`--no-guide` 用于对照） |
| 领域约定 | `scripts/m190/domain-route-sign.md`（票据 04 起为 `agent/domains/route-sign.md`） | 线路牌领域的 12 条约定：带圈数字是地标、设施类别、票制与票价、本站 0 不标、地标是站名流的最后一格、道路名同间隔分布等。不含任何具体项目 | `--domain route-sign` |
| 项目说明 | `scripts/m190/scenarios/<场景>/brief-<步骤>.md` | 本次设计稿的尺寸、目标范围、命名、示例图对应的请求、客户说明（如 M402 的蓝色圆标忽略） | 按 `--scenario` 自动给 |

- 模板参考补上了内联数据集写法，Agent 可以用它试验极端数据。

### 结论

- **三层资料可以推广**：通用指南管拆分方法与验证习惯，领域约定管行业知识，项目说明管这一单的事实。同一领域的新设计稿，只需写一份项目说明。
- **换一个领域**（如价签、资产标签），要先写该领域的约定包；没有约定包时，通用指南会把领域知识缺口列为待确认，而不是乱猜。
- **以后沉淀经验时分清归属**：
  - 能用一句与行业无关的话说清的，写进通用指南；
  - 只在某个行业成立的，写进领域约定；
  - 只关于这一单的，写进项目说明。

- **做数据定义一轮约 7–12 分钟，做模板约 21–31 分钟**，大部分时间在模型的长思考上。要求验证极端情况后，模板的轮数与预览次数大约翻倍。工具调用在 7 ms–1.1 s 内完成。
- **闭环单轮 72–238 s，波动大**。
- **交互式场景（M208 的评论与旋钮）不能用 qwen3.8-max 逐轮响应**（推断）。qwen3.8-flash 读图 25 s 且转录全对，可以作为交互轮的候选，阶段 3 需要实测它的工具调用。

## 对路线图的影响

- **代建路线继续**：数据定义与模板都只需少量返工，切换条件（"M402 级别仍需专家大量返工"）没有触发。
- **提升质量的关键是分层的领域知识，而不是换模型**：带"通用指南 + 领域约定"后，数据定义与模板都基本不用返工（见「通用化」）。
- **Claude Code 的 Read 会缩小大图**：直接调 API 用原图时班次 15/15，经 Read 时曾编出班次、漏站。加了局部放大工具后，366 两次都转全了 59 站，已验证。放大工具应纳入阶段 3 的正式 MCP 工具。
- **ADR-0015 取代 ADR-0009（CloudKiln）**：本地方式已验证；云上每轮独立容器、经网络连接 MCP 服务还没测。

## 复现

产品命令（票据 04、05）：

```bash
npm run build
renderweave agent run --task 数据定义提取 --sample docs/examples/materials/m402-route-sign.jpg \
  --brief scripts/m190/scenarios/m402/brief-definition.md --domain route-sign --resources fixtures/resources --out out/agent-t05-m402
renderweave agent review out/agent-t05-m402
renderweave agent apply out/agent-t05-m402 --workspace <工作区>
```

验证脚本：

```bash
npm run build
node scripts/m190/run.mjs out/m190/run1
```

- `--steps vision,loop,design` 可以只跑其中几步（缺省就是这三步），`--vision-models` 指定看图的模型。
- 资料分层：通用指南缺省就给，`--no-guide` 去掉；`--domain route-sign` 加线路牌约定；`--scenario m402|366` 选项目说明与示例图。366 只能跑 design。
- 模板生成：`--steps template`，可加 `--max-turns`。评估包含压测、地标底线与道路名对齐检查。
- 只评估、不调用模型：`node scripts/m190/run.mjs --evaluate <候选目录> [--scenario 366]` 评估数据定义候选；`node scripts/m190/run.mjs --evaluate-template <工作区> [输出目录] [--template-name 名称]` 评估模板。
- 报告写在 `<输出目录>/report.json`。各步骤的流式日志、MCP 调用日志与候选文件都在同一目录下。
- Claude Code 可执行文件默认取 PATH 上的 `claude`，也可以用 `CLAUDE_BIN` 指定。
- 运行 1、2 用的是同样的提示和工具，是在开发这个脚本时手动跑的。
