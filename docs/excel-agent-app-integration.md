# 按静态数据定义导入数据集：应用接入方案

2026-11-03，M374。基于合并后的 `main`：远端 `7b4a782`、本地 Excel 分支 `baede19`，合并提交分别为 `b136693`、`417ca6e`。本文是代码审读后的实施方案，下面的新页面、任务接口和存储合同尚未实现。

## 判断

将能力放进**数据集模块的“智能导入”**。用户先选静态数据定义的确切版本，上传工作簿并说明提取范围，Agent 生成候选；用户核对来源、批注和待确认项，确认后保存为普通数据集。模板是保存之后的可选接续，也可以从已有模板带入它所用的定义。

这项能力已经具备本地闭环，缺的是服务化接缝与页面。现有“从 Excel 导入”不能直接改名复用：它要求模板、按标准表头解析、把数据内联到出图批次，**不会保存数据集**。两种入口应分别叫“智能导入数据集”和“标准表格批量出图”，保留现有接口语义。

## 用户流程

1. **选定义**：数据集页点“智能导入”，选名称及版本；从静态数据定义详情进入时预填；从模板进入时锁定模板的 `base`。没有定义时去数据定义模块创建并发布，不让本轮偷偷改定义。
2. **给资料**：上传 `.xlsx`，填提取意图、对象划分和范围。表格可以跨页、有多层表头、合并单元格和批注。首版不要求用户先下载标准表重填，不扩展到未验证的格式。
3. **看执行**：页面展示读取、映射、转换、独立检查及修正重试的阶段；可取消。关闭页面不取消任务，再打开能继续查看；页面不持有模型 key。
4. **核对候选**：左侧工作表原文、坐标与批注，右侧按定义生成的数据集表单；字段可跳回来源。单独展示未映射内容、排除理由、推断及检查失败。VML 的零基行列与批注所在单元格分别展示；没有显示框也不能丢掉批注原文。人工改值必须有原因。
5. **确认保存**：明确展示将保存多少份、各份名称和定义版本；完整集合通过检查后一次保存。首版只创建新数据集，重名明确返回冲突，不默默覆盖或跳过；用户调整身份后重核。取消或失败的任务不写正式数据集。
6. **接续使用**：跳回数据集列表，能直接编辑；存在兼容模板时可预览或出图，没有模板时仍能完成导入。以后从这份数据集进入模板制作；模板需新增显示字段时，先发布对应静态数据定义，再让这些字段经过可重放的数据审核。

数据关系为 `静态数据定义 → 候选数据集 → 确认保存的数据集 → 兼容模板 → 渲染项 / 交付`。115 路只是一个样本，页面、接口和任务里不出现固定的上下行、站序或线路字段。

## 服务边界与拟定合同

### 任务与运行时

纳入 P2 的统一 Agent 任务，任务类型沿用 `dataset-extraction`，素材类型为工作簿。拟定任务输入只有租户可访问的素材 ID、`staticSchema: {name, version}`、用户说明和可选的上一轮 ID；服务端记录原件哈希、定义及引用闭包哈希、工具/执行环境身份。客户端不能提交服务器路径、任意 URL、Python 可执行文件或待执行脚本。

任务状态建议为 `queued → running → needsReview → applied`，另有 `failed`、`cancelled`；运行阶段另记读取/转换/检查，不把“独立检查通过”当作“已保存”。轮次重试形成新轮次，保留历史与来源匹配的人工修正；旧确认绑定的内容改变即失效。

P2 统一提供创建、查询、取消、事件流、审核保存和应用接口，本任务通过附件与候选类型扩展，不再建立第二套导入队列。接口名称与 OpenAPI 升版在 P2 合同票据中统一确定。事件有序号并支持断线续读；worker 租约失效后，旧 worker 不能发布成果或应用；所有读取与应用都按租户重新鉴权。

**运行时分两层**：现有本地实测继续使用用户指定的 Claude Code + OpenCode Go。应用内循环遵守 ADR-0027 的 Tool Runner 决定，将受控读取、转换沙箱和独立检查做成同一任务的工具；模型仍可使用 Claude。原型脚本 `scripts/prototypes/excel-agent/agent-run.ts` 不是可直接塞进 HTTP 处理函数的生产服务。Tool Runner 的工作簿工具及评估尚未完成，不能宣称两种执行器效果相同。托管渠道沿用 ADR-0027/P4 的待定项，不以本地 OpenCode Go 成功代替多租户渠道验收。

生成的转换代码只进独立沙箱；API 与 Agent 宿主执行固定检查程序。取消同时停止模型循环及转换任务，CPU、内存、进程、时间、输出量与网络约束按 ADR-0028 收口。沙箱不持有模型 key、租户存储凭据或生产写权限。

### 审核与一次保存

保留现有 Excel 证据格式、来源检查及完整集合规则。服务适配器把固定素材和文档装配成本轮受控输入，将结果登记到租户内存储；HTTP 层不返回本机目录。尽量提取本地与服务共用的检查接缝，不把 Fastify、PostgreSQL 或对象存储依赖引入引擎 `src/`。

拟新增存储行为 `commitDatasetImport`（合同名待实施确定）：

- 输入绑定租户、任务、审核修订、候选集合哈希、确切定义及其依赖身份、幂等键；应用前复核权限、来源、完整集合及引擎检查。
- 原件、候选和证据可先按哈希存对象；只在一个事务里登记全部数据集、导入来源关系、应用结果与审计。数据库登记成功才可被读者看到。
- 任一 ID 冲突或校验失败，整组不登记。应用请求相同且已成功时返回原数据集 ID 集合；同一幂等键带不同内容时拒绝。
- 首版只创建。以后支持更新时必须加目标内容哈希的并发条件和整组差异预览，不能直接复用无版本条件的 `PUT /v1/datasets/:id`。
- 原始工作簿和来源不塞进每份数据集的业务字段；用租户内导入记录指向数据集和证据。后续手工编辑保留“当时导入内容”与当前内容的区别，不能把旧来源标成当前值已经验证。

这是用户主动导入时的“确认保存”，不增加管理员发布审批。租户的数据定义/模板发布策略保持原范围；未来自主 Agent 的写入仍遵守 ADR-0022 的授权约定。

### 与模板制作和交付连接

数据集保存后沿用现有模板 `base` 匹配及数据集编辑器。新模板沿用模板工作副本、预览和修订发布；不把参考图生成的模板绑死到 Excel 导入任务。多尺寸、多列表位置的通用出图计划已有本地实现，服务化交付仍需把计划转成现有服务批次；首版导入不自动出图，也不把导入数量计成图片用量。

模型用量应记录成功、失败和取消的实际轮次，按轮次身份去重；未提供的实际扣费与人工业务审核工时继续显示未知，不能记为 0。

## 实施顺序与验收

| 顺序 | 范围 | 完成标准 |
|---|---|---|
| 1 | 数据集按静态数据定义新建，模板变可选 | 无模板的非公交定义能创建、编辑、保存；旧模板入口与标准表批量出图回归通过 |
| 2 | P2 工作簿任务与隔离工具适配 | 固定同一原件和定义可完成提取；取消/重启不遗留执行、不串租户；全部批注和 VML 锚点仍能独立核对 |
| 3 | 审核应用服务接缝与整组提交 | 修改须写原因；来源变更使旧确认失效；最后一份冲突时前面也不入库；重复提交只产生一组数据集和一次应用记录 |
| 4 | 智能导入页面与模板接续 | 非公交样本及同一 115 原件端到端通过；刷新恢复任务，能查批注、修正、确认保存，再选兼容模板出图 |

先做第 1 项，它不依赖模型或 P0 门槛；第 2–4 项并入 P2，遵守既有开工门槛。无需先重做全部模板制作界面。详细票据见[应用接入索引](../.scratch/dataset-import-app/README.md)。

本次只完成代码合并、回归与接入设计，没有把智能导入按钮或后台任务标成已上线。
