# 字体与缺字替代

引擎只使用资源仓库里的显式字体，不读取系统字体。`npm run fetch-fonts` 按 `scripts/fonts.json` 下载固定版本的思源黑体并核对 SHA-256；样例资源仓库已登记 Regular（400）、Medium（500）、Bold（700）、Heavy（900）四个字重。

模板照常引用原字体，不需要引用后备字体。引擎在求值完成后、布局开始前按 Unicode 码点检查字形 ID；只有 ID 为 0 的字才替代，空格等无墨迹但有字形的字符保持原样。替代后的实际字体同时参与测量与绘制，保留原片段的字号、颜色和倾斜。横排、竖排、变量插槽、循环容器与子模板调用均适用，隐藏分支不检查。

## 引擎配置

`render(workspace, request, options?)` 的 `options.fallbackFonts` 是后备字体的**资源 ID** 列表（不带 `res:`），由接入引擎的程序配置，不属于模板 DSL 或渲染请求。命令行使用默认列表：

```ts
await render(workspace, request, {
  fallbackFonts: ['font-hei-regular', 'font-hei-medium', 'font-hei-bold', 'font-hei-heavy'],
});
```

自建资源仓库可用自己的 ID 登记思源黑体，并在这里列出。省略配置采用上面的默认值；空列表禁用替代。后备字体仅在遇到缺字时读取，每次渲染独立缓存；未安装、种类错误或无法读取的后备资源不参与选择，没有可用后备字体时仍缺字，按严重问题处理。

原字体与候选字体的字重取文件 `OS/2.usWeightClass`，不能读取有效值时按 400。选取字重距离最小的可用后备字体，距离相同取较轻者；同字重有多个资源时按配置顺序。选定字体仍缺字时不串换其他字重。原字体资源已在后备配置中时直接检查并报告缺字，不重复尝试该字体。

## 结果

- 成功替代：`text.glyphFallback`，等级 `hint`，允许正式出图。
- 仍缺字：`text.glyphMissing`，等级 `severe`，正式出图无图片；草稿可查看当前字体的缺字符号与问题边框，见[草稿预览与正式出图](render-modes.md)。
- 需要字形塑形或从右往左排版的文字（阿拉伯文、希伯来文、印度系文字、泰文等）：`text.unshapedScript`，等级 `severe`。引擎逐字从左往右排，这类文字出来与原文不一致；东阿拉伯数字不算（M288）。
- 每个文本元素分别合并成功替代与仍缺字的问题，字符去重、按首次出现顺序列出，并附 Unicode 码点。问题以元素路径定位，循环实例含序号；缩字组两轮布局不会重复报告。
- 文本布局摘要在有替代时增加 `fontFallback: true`；`fragments` 按实际字体拆分，`font` 是实际资源引用，替代片段另有 `sourceFont` 记录原字体。未替代文本不增加这两个属性，原有片段边界保留。模板和数据集内容不被改写。

测试夹具的来源、许可证与再生成命令见 [缺字字体夹具](../fixtures/resources/font-subsets/README.md)。
