# 草稿预览与正式出图

渲染请求的 `mode` 取 `draft`（草稿预览）或 `final`（正式出图）。两种模式使用同一套真实内容检查，不同之处在是否出图，以及是否增加草稿占位与问题边框。批量交付的草稿批次逐项沿用本页规则，成果与正式交付的区分见[批量草稿](output-records.md#草稿批次)。

| 情况 | 正式出图 | 草稿预览 |
|---|---|---|
| 没有问题 | 图片、布局摘要 | 相同图片与布局摘要 |
| 只有提示 | 图片、布局摘要 | 图片、布局摘要，并标记可定位的问题元素 |
| 有严重问题，但可展开 | 无图片，保留问题清单与真实内容布局摘要 | 图片、问题清单、包含占位的布局摘要 |
| 无法展开 | 只有问题清单 | 相同问题清单，无图片与布局摘要 |

## 检查顺序

先解析工作区与请求，然后独立执行模板静态检查、数据集校验、版本一致性检查和对外参数检查，汇总之后再判断是否能展开。模板静态检查使用模板自己的基准版本；数据集校验使用数据集选定的版本。某项输入不可用时，仍执行其他有输入的检查。例如版本不一致时，也能同时得到未知插槽、缺失字段与参数问题。

模板或数据集无法解析、目标不存在、编译产物缺失或无法使用、版本不一致、调用成环、循环或子模板的数据基准不符等，都会阻止展开。保留具体问题，并附加 `render.expansionBlocked` 汇总码。请求在最初解析时即不合法则直接返回 `request.invalid` / `request.outputTooLarge`，无需后续检查。

可展开时依次求值、加载资源、检查缺字、排版，再决定是否绘制。正式出图即使发现严重问题，也完成可执行的布局检查，返回布局摘要。命令行在草稿成功出图时返回 0，未出图时返回 1；同一输出目录里上一次留下的图片会被清除。

## 占位

因已有问题而显示为空的变量插槽，在草稿中显示 `〔显示名称〕`，如 `〔站名〕`。显示名称来自编译产物中的字段标题或参数、派生变量声明；未知变量没有显示名称时用引用名。占位片段在布局摘要中带 `placeholder: true`。正式出图始终使用真实值，不显示占位。

正常缺失的可选字段、未取到项、合法的空默认值保持空白。来源追踪覆盖单引用、循环实例、基本类型循环项、子模板参数，以及取项或条件分支产生的引用；其他列表项的问题不会让当前项的正常缺值变成占位。因问题缺值的图片不画内容，在已知元素框处画问题边框。

真实内容先完成一次检查与排版；只有草稿含占位时，才单独用占位文字重排。占位自身造成的溢出或缺字不进入公共问题清单，因此同一输入的两种模式得到完全相同的问题清单。草稿布局摘要描述实际显示的占位布局，可能与正式的真实内容布局不同。

## 问题边框

草稿给已定位的问题元素画红色边框，配白色衬边；不改写元素本身的描边。边框最后叠加，跟随元素及其祖先的旋转，不受业务内容的透明度、裁剪与叠放遮挡。零宽或零高的缺值元素至少有 2 mm 的定位标记，隐藏元素不画边框。

问题清单中的元素路径直接定位；被调模板的静态问题映射到相应实例，绑定来源已知的缺值定位到实际插槽或图片。没有元素位置的字段、参数或检查项问题只保留在清单里，不给画板随意画框。
