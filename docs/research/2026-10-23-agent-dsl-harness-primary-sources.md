# Agent 设计模板 DSL 的 harness：一手资料研究

研究日期：2026-10-23。本文是架构评估的外部依据与建议，不是已采纳决定，也不声明本轮完成了真实模型验证。仓库代码检查、测试和综合评分由同日主报告记录。

**判断：RenderWeave 应继续采用“受限 Agent 生成工作副本 + 确定性引擎检查 + 带来源的视觉反馈 + 明确的应用边界”。优先投入评估覆盖、可恢复状态与可信测量，再以对照实验决定独立视觉评审、约束解码和多 Agent 的投入。** 这一判断同时得到生产实践 S1–S8 与学术研究 S9–S16 的支持；具体收益仍须在本项目的中文、英文任务中测量。

## 范围与证据口径

本研究先读了 `CONTEXT.md`、`GLOSSARY.md` 与 [上一份视觉反馈研究](2026-10-22-template-visual-fidelity-harness.md)，再独立检索并打开下面列出的官方文章、论文和协议资料。这里的 harness 指围绕模型的任务组织、资料装配、工具、验证、执行限制、状态留存和恢复机制，不把模型本身或提示词等同于整个系统。

仓库背景以文档声明为限：当前有任务轮次、工作副本、审核与应用（`CONTEXT.md:67`）；有四场景真实模型评估和 `invalid` / `incomplete` 状态（`CONTEXT.md:68`）；有受阻草稿、固定参考、局部测量及来源留存（`CONTEXT.md:87`–`90`）。这些是需要核对代码与实测的现有能力，不能重新写成“尚未建设”。文档同时明确遮挡、对比度、复杂变换等仍未知（`CONTEXT.md:88`），OCR 尚未接入（`CONTEXT.md:91`）。

证据分级：**A** 为正式论文或协议；**B** 为作者预印本、官方工程报告；它们都属于一手来源，但厂商内部经验不等于独立复现，论文实验也不等于本仓库的效果。每条“仓库启发”均为本研究的工程推断。

日期按打开后的正文、论文提交历史或正式出版页记录，不采用搜索引擎的“几个月前”。检索日期以前可见的版本才纳入。研究不以“最新”代替相关性。

## 官方工程与生产实践

### S1. 跨轮次的可靠性依赖外部状态，而不只依赖上下文压缩

- **来源与日期，B**：[Anthropic，Effective harnesses for long-running agents](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)，2025-11-26。
- **来源主张**：其长任务实验把初始化与后续执行分开，使用功能清单、进度记录和版本历史交接；仅给高层目标并反复压缩上下文，仍出现一次做太多、留下半成品和过早宣告完成。
- **适用边界**：这是长时间软件构建经验，并非模板设计的随机对照试验。功能清单也不能由执行者任意改成已通过。
- **仓库启发**：利用已有 `round.json`、`draft.json`、候选哈希和轮次链，补齐可恢复的“剩余问题、已修问题、最佳候选、停止原因”。结构化状态由宿主确认；Agent 的总结是说明，不是质量事实。

### S2. 资料应按需展开，并衡量信息效用

- **来源与日期，B**：[Anthropic，Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)，2025-09-29。
- **来源主张**：上下文管理需要持续选择高信息量内容；轻量标识与运行时检索可以渐进载入资料，也可将必要内容预装与按需检索结合。按需查找会增加运行时间，需要有效的工具与导航。
- **适用边界**：文章给出工程原则，并未证明任意短提示词一定更好，也未要求所有任务引入向量检索。
- **仓库启发**：已有三层资料、Schema 指针、区域分页是正确方向。进一步记录每轮装入的资料量、工具结果截断、实际读取章节与首次检查问题；按任务能力选取参考，保持索引可见。工具输出超限应保留总数与续取入口，不能静默丢掉严重问题。

### S3. 评估对象是模型与 harness 的整体，结果与轨迹各有职责

- **来源与日期，B**：[Anthropic，Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)，2026-01-09。
- **来源主张**：区分任务、重复试验、评分器、执行轨迹与最终环境状态；组合代码、模型和人类评分器；能力探索与防回归测试应分开。过度规定工具调用顺序会错罚有效解法。
- **适用边界**：官方路线建议中的样本规模只是起步经验，不是统计充分性证明；模型评分器需要人工校准。
- **仓库启发**：以实际渲染、信息覆盖、模板规则和修改范围作为主要结果；用轨迹定位成本、失误和恢复行为。工具调用是否发生不能替代结果是否正确。将四场景继续作为防回归门槛，另建涵盖中英文、不同版式与失败类型的能力集。

### S4. 独立评审值得试验，但多 Agent 复杂度必须随模型能力重新审视

- **来源与日期，B**：[Anthropic，Harness design for long-running application development](https://www.anthropic.com/research/harness-design-long-running-apps)，2026-03-24。
- **来源主张**：作者将 planner、generator、evaluator 分工，用明确标准改善设计评审；独立 evaluator 仍会偏宽松，需要校准。模型更新后，作者逐项移除机制，取消原有 sprint 分解，并将部分任务的评审移到末尾；任务已落在模型稳定能力内时，评审可能成为额外成本。
- **适用边界**：少量长任务实践不证明“三 Agent”是普适最优；原创性标准也不适合原样套到“忠实还原客户示例图”的任务。
- **仓库启发**：先保留单个生成 Agent 加确定性工具，增加一次独立、看证据的样式/状态审核实验。评审不能看作者自评分，输出区域、问题与证据。只有在保留集上提高缺陷发现或交付率，才提升调用频率；不默认每轮常驻 planner 与 evaluator。

### S5. 让知识和约束可发现、可执行，减少手册堆积

- **来源与日期，B**：[OpenAI，Harness engineering: leveraging Codex in an agent-first world](https://openai.com/index/harness-engineering/)，2026-02-11。
- **来源主张**：其内部项目把简短入口用作知识地图，详细知识和执行计划进入版本化仓库；通过检查工具保持文档链接、结构与约束有效，并让 UI、日志、指标成为 Agent 可读反馈。
- **适用边界**：是一个团队的内部建设报告；吞吐量或估计提速不能外推到 RenderWeave，也不能据此取消业务审核。
- **仓库启发**：当前 `CONTEXT.md`、术语表、ADR、三层资料的方向一致。下一笔收益是自动检查“工具合同、DSL 参考、样例与实际能力是否一致”，以及压缩入口中的历史叙述。把已反复犯错的规则落成校验器或可定位测量，不继续追加长段提醒。

### S6. 确定性工作流与 Agent 循环可以混合

- **来源与日期，B**：[Stripe，Minions — Part 2](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2)，2026-02-19。
- **来源主张**：Minions 的 blueprint 把 Agent 节点和确定性节点放在同一状态机中；固定校验由代码保证执行，Agent 负责实现与处理未知问题。运行使用隔离的开发环境，CI 重试有上限，最后交回人工审核。
- **适用边界**：Stripe 拥有长期建设的开发环境与测试基础；其 CI 次数上限不是设计任务应照搬的常数。
- **仓库启发**：将“冻结输入 → 生成/修改 → 引擎检查 → 比较 → 交回”视为宿主保证的路径，Agent 决定怎样修正。已具备的最终检查继续保留；补充无进展检测、最佳候选和可解释终止，避免无限重试。预算由任务难度和实测收益确定。

### S7. 限权工具、执行环境和模型防御是不同层

- **来源与日期，B**：[Anthropic，How we contain Claude across products](https://www.anthropic.com/research/how-we-contain-claude)，2026-05-25。
- **来源主张**：进程/虚拟机、文件系统和网络出口约束用于限定实际影响范围；提示词与分类器改变的是行为概率。可信连接器也可以读取被污染的数据，因此连接器审核不等于内容可信。
- **适用边界**：隔离效果取决于实际边界、凭证暴露和出口规则；文章不支持“只读工具已经消除所有风险”的结论。
- **仓库启发**：分别评估本地内部代建与未来客户自助。逐项验证执行器及子进程可达的路径、环境变量、网络、进程资源与跨租户数据；参考、素材、资源名、数据内容都不能提升为宿主指令。阶段 5 的写能力应通过作用域明确的能力和审计实现，而不靠模型承诺。

### S8. MCP 的工具注解是提示，不是强制权限

- **来源与日期，B**：[MCP 维护者，Tool Annotations as Risk Vocabulary](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/)，2026-03-16；对照 [官方 Tools 规格](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)，固定修订 2025-11-25，A。
- **来源主张**：`readOnlyHint`、`destructiveHint` 等注解描述工具行为，却不保证实现真的遵守；来自不可信服务的注解不能作为安全事实。风险还取决于工具组合和所处理的数据。
- **适用边界**：规范字段与服务端权限模型各有职责；无需为了采用 MCP 自动增加人类确认次数。
- **仓库启发**：现有只读合同必须由实际文件/资源访问控制与测试支持。后续写工具用服务端身份、对象作用域、预期修订和幂等规则做检查；“只读”名称或注解不能替代实现证明。

## 学术研究

### S9. 工具的交互设计本身是性能变量

- **来源与日期，A**：[SWE-agent 正式发表页](https://proceedings.neurips.cc/paper_files/paper/2024/hash/5a7c947568c1b1328ccc5230172e1e7c-Abstract-Conference.html)，NeurIPS 2024；[作者论文](https://arxiv.org/abs/2405.15793v3)首版 2024-05-06，本文采用 2024-11-11 v3。
- **来源主张**：研究专为 Agent 设计的文件导航、编辑、反馈与测试接口，展示接口选择会影响任务行为和成功率。
- **适用边界**：软件修复任务的成绩不能代表视觉模板生成；“工具更多”不等于接口更好。
- **仓库启发**：保留领域工具的清晰语义：一次调用尽量给出可行动的元素路径、源模板与实例位置、差值、下一步查询入口。评价工具合同升级时，同时量工具调用数、首次错误率和修复效率；不要仅比较描述文案是否更完整。

### S10. 多次成功与多次尝试中成功一次是不同能力

- **来源与日期，A**：[τ-bench 作者论文](https://arxiv.org/abs/2406.12045v1)，2024-06-17；[ICLR 2025 正式论文](https://proceedings.iclr.cc/paper_files/paper/2025/file/1b126cc38b8638e07bef37e7b2bb72bf-Paper-Conference.pdf)。
- **来源主张**：通过最终数据库状态判断任务是否完成，并提出 `pass^k` 测量同任务多次试验都成功的可靠性；任务涉及领域规则与用户交互。
- **适用边界**：用户由模型模拟，领域是服务事务；原始模型排名已过时，本项目只借用评估思想。
- **仓库启发**：现有连续两次达线是可靠性意识的良好起点。进一步报告单次成功、重复稳定性、端到端交付成功和恢复成功，并把额度/基础设施无效轮次从模型失败中拆开。四个固定场景的两次通过不代表跨客户、跨版式的总体可靠率。

### S11. 图像到代码需要细粒度评价，合法代码并不足够

- **来源与日期，A**：[Design2Code 正式发表页](https://aclanthology.org/2025.naacl-long.199/)，NAACL 2025，2025-04；[作者论文](https://arxiv.org/abs/2403.03163)。
- **来源主张**：在 484 个真实网页上评价截图到代码，并以自动指标和人工评价配合；细分分析显示元素遗漏与布局是主要薄弱点。
- **适用边界**：网页与线路牌的密集中文、毫米单位、循环模板不同，论文成绩或指标阈值不能直接迁移。
- **仓库启发**：将 DSL 结构合法、引擎可出图、内容正确、视觉还原、换数据后仍正确分开。已有固定参考与局部测量应继续发展；把空骨架、缺小字、错误绑定与整张参考图贴背景等反例纳入评分器校准。

### S12. 区域分解可以减轻遗漏，但组合关系仍需全图检查

- **来源与日期，A**：[DCGen 作者论文 v3](https://arxiv.org/abs/2406.16386v3)，首版 2024-06-24，采用 2025-04-25 v3，标明 FSE 2025 接收；正式 DOI 为 [10.1145/3729364](https://doi.org/10.1145/3729364)。
- **来源主张**：将截图拆成较小区域，逐区生成再组装，针对元素遗漏、失真和错位开展实验。正式论文还报告整体错位仍有局限。
- **适用边界**：该方案主要解决网页生成；区域切分会损失跨区约束，不能证明任意局部修补都让全图更好。正式 DOI 本次打开返回 403，方法及版本以可访问的作者 v3 核实。
- **仓库启发**：已有 `compare_reference` 与局部放大可作为区域任务入口。区域需稳定编号并关联元素路径；修复局部后重测整张画板，特别是对齐、循环间距、缩字组和相邻区域。先修关键缺失与结构，再修细节。

### S13. 新建与修改必须分开评测，编辑要同时看改善与保留

- **来源与日期，B**：[CANVAS 论文 v2](https://arxiv.org/html/2511.20737v2)，首版 2025-11-25，采用 2025-11-27 v2；[提交记录](https://arxiv.org/abs/2511.20737)。
- **来源主张**：598 个工具式 UI 设计任务分为复制与修改；评价结合图像相似性、语义与组件属性，研究几何、布局和文字错误。
- **适用边界**：对象是设计软件的移动 UI，不是 RenderWeave 的数据驱动模板；平均相似度不能替代关键内容门禁。
- **仓库启发**：新模板重点看覆盖与布局；辅助修改必须同时核对目标区的改进、非目标区的保留、模板规则和代表数据。现有修改范围反馈可升级为“哪些要求满足、哪些回退、哪些未知”，而非只统计改了多少元素。

### S14. 约束解码能约束结构，不能代替语义与渲染验证

- **来源与日期，A**：[XGrammar-2: Dynamic and Efficient Structured Generation Engine for Agentic LLMs](https://arxiv.org/abs/2601.04426v4)，首版 2026-01-07，采用 2026-08-05 v4，作者标明 ACM CAIS 2026；[正式 DOI](https://doi.org/10.1145/3786335.3813124)。
- **来源主张**：通过动态结构切换、跨语法缓存、即时编译等机制，降低动态结构生成的运行开销。
- **适用边界**：这是推理服务与解码器层方案；闭源模型或兼容代理是否提供相关能力需实查。结构符合语法不保证引用存在、循环作用域正确、文本可见或版式满意。
- **仓库启发**：先统计失败中有多少来自 JSON/Schema 结构，再决定投入。优先使用现有服务确实支持的结构输出能力；保留完整 JSON Schema、引擎语义检查与渲染。没有证据表明语法错误是主瓶颈时，不为它自建模型服务。

### S15. 注入评估要同时测安全与正常任务效用

- **来源与日期，A**：[AgentDojo 作者论文 v3](https://arxiv.org/abs/2406.13352v3)，首版 2024-06-19，采用 2024-11-24 v3；NeurIPS 2024 Datasets and Benchmarks。
- **来源主张**：以不可信工具返回内容为攻击面，提供可扩展任务与攻击环境；基准同时包含正常任务和安全测试，并允许新增攻击与防御。
- **适用边界**：原始任务包括邮件、银行和出行，不覆盖本项目的所有图像/资源输入；静态攻击列表通过不证明永久安全。
- **仓库启发**：建立贴合业务的样例：图片中嵌指令、资源名称含指令、素材要求改核准参考、数据字段要求读取宿主秘密、旧轮次诱导绕过应用检查。分别测任务是否继续完成、是否越权、是否污染质量判断；不能只计算拦截率。

### S16. 控制流和数据来源应显式分开，但来源证明不等于内容证明

- **来源与日期，B**：[CaMeL: Defeating Prompt Injections by Design v2](https://arxiv.org/html/2503.18813v2)，首版 2025-03-24，采用 2025-06-24 v2；[作者代码](https://github.com/google-research/camel-prompt-injection)。
- **来源主张**：从可信请求确定控制/数据流，通过能力与工具调用策略限制不可信数据影响执行和外传。论文明确不覆盖所有内容层攻击，例如在不改变受保护数据流时输出错误摘要。
- **适用边界**：安全保证依赖其威胁模型、解释器和策略，不能泛称“提示注入已解决”；引入完整双模型运行时也有实现与效用成本。
- **仓库启发**：沿用固定参考、实际材料哈希和不可由 Agent 自改的通过规则。将“文件来自哪里”“值是否符合可信事实”“模型如何解释它”分开。按本项目需要落实这些边界，现阶段不必照搬完整 CaMeL 运行时。

建议单列四类结果，避免一个总分掩盖问题：

1. **技术可交付性**：结构、引用、作用域、资源、完整请求实际渲染、正式出图。
2. **内容和模板规则**：可信字段与文字、循环完整性、条件显示、状态样式、换数据后不失效。
3. **视觉质量**：区域覆盖、几何、文字、色彩、可见性、层次；保留未知。
4. **运行质量**：重复稳定性、中断恢复、错误归因、预算、延迟、人工审核时间和越权率。

这四类是评估设计建议，不改变现有 DSL 或评分合同。其中“换数据检查”应覆盖边界数据与变换关系，例如站点增减后循环项数随之变化、长文字触发约定的适配、状态变化只影响相应元素；它用于检验模板规则，不能仅用同一张图片的重现代替。
