# 产品路线图

结论：RenderWeave 做成面向对外客户的出图 SaaS。

- 做模板以 Agent 为主入口，网页负责看、改与出图。
- 第一个收费版本（v1.0）只把出图做成多租户服务；模板由我们团队用 Agent 工作台代客户制作，客户自助做模板在 v1.x 逐步开放。
- 阶段 3 的 Agent 可行性验证已做完能力验收：代建模式可行（[第三阶段验收](stage3-acceptance.md)）。收尾只差一位内部成员按指南走一遍并计时，之后进入阶段 4。

决定见需求记录 M204–M208。本文是规划，不是"当前能力"；当前可执行的能力以 `CONTEXT.md`「已实现能力」和两期阶段验收为准。

## 已确认的产品事实（M204）

| 问题 | 答案 | 影响 |
|---|---|---|
| 用户是谁 | 内部团队和对外客户都有，以对外 SaaS 为主 | 第一版就要多租户隔离、鉴权、配额；客户不会写 DSL |
| 新模板频率 | 每月几个 | 做模板是客户上手阶段的事，日常价值在出图；为低频动作造重型编辑器不划算 |
| 部署 | 云服务器 | Agent 运行时必须按会话隔离；渲染要在独立 worker 中执行，带超时与配额 |

## 产品形态（M205）

三种角色，三条路径：

1. **设计（模板作者）**：
   - 上传示例图，Agent 给出数据定义、示例数据集与模板草案。
   - 示例图与引擎预览对照，在预览上点选元素提出修改。
   - Agent 以提案形式修改：结构化差异、前后对比图与校验结果，人批准后才写入。
2. **出图（操作员）**：
   - 由数据定义的编译产物自动生成表单，或从 Excel 导入。
   - 逐项草稿预览、批量交付，查询出图记录并重放。
3. **集成（开发者）**：HTTP API、webhook、命令行；MCP 供开发者自己的 Agent 使用。

不做的事：

- **自由拖拽的画布编辑器**：至少 v2 之前不做。DSL 是约束式的，例如"站点多了先收窄列间留白，不够再全组统一缩字"，拖拽难以表达这类规则。网页上的可视化是检查器加结构化属性面板。
- **把 Claude Code 原样作为产品入口**：业务用户需要领域界面而不是通用编码 Agent 的终端，安全上也要求只读工具加人工批准（ADR-0001、ADR-0003），并且不能以 Claude Code 的名义对外。Claude Code 或 Agent SDK 只作为运行时，以及开发者经 MCP 的入口。

Agent 运行时：

- 每个会话一个独立容器，只提供只读的领域工具（MCP），写入只经提案。
- 工具是固定合同，模型可以替换（Claude 或 Qwen），不绑定 Claude Code 程序。

交互与视觉方向（M208）：

- **交互参考 Claude Design**：左边对话、右边画布；在画布元素上留评论来定位修改；助手按需生成调节旋钮，旋钮对应模板参数，拖动后由引擎实时渲染；保留版本历史，可导出，也能直接进入批量出图。它合并了"对话提案"和"点选检查器"两条路线，结构化属性面板保留为辅助。
- **视觉**：暖色中性风格，米白底、陶土色强调、衬线标题。保持 RenderWeave 自有品牌，不使用 Anthropic 的标识与字体。
- **实测**：原型里在 50 DPI 下实时渲染一次约 120–300 ms，旋钮实时预览可行。正式出图的 120 DPI 预计更慢，服务化时要用缓存、低分辨率预览加最终高清渲染。

切换条件：如果阶段 3 证明 Agent 做不出可用的模板（M402 级别仍需专家大量返工），重心改为"结构化属性面板加组件库"，Agent 降为局部修改助手。阶段 3 的结果没有触发这一条：两张没见过的示例图都由 Agent 做到可交付，返工靠文字反馈完成，没有人手改 DSL。

## 第一版：代建模式（M206）

v1.0 只把出图做成多租户服务，内容包括：

- 多租户与鉴权；数据库加对象存储。
- 带超时与配额的渲染 worker 池。
- 由数据定义生成的数据集表单与 Excel 导入。
- 批量交付与出图记录；开放 API 与 webhook；模板只读预览与参数面板。

模板由内部团队用 Agent 工作台代建。

- **理由**：模板频率低，代建能把风险最大的"外部用户自助编辑"推迟；每次代建都积累经验，包括哪些提示有效、哪些组件可复用、Agent 卡在哪里。
- **开放自助的条件**：代建排期跟不上（例如等待超过一周），或客户频繁要求自己做小改。
- **开放顺序**：先开放点选元素做小改（字号、颜色、绑定），再开放示例图向导与组件库。

## 现在就要定下来的难逆转事项

这些都要在阶段 4 开工前写成 ADR：

- **租户模型与存储抽象**：引擎已经通过 `ResourceRepository` 取资源；工作区文档和出图记录仍直接读写本地文件，需要同样抽象出来。
- **出图记录放进对象存储后的格式**：保留现在"记录自足、可重放"的性质，这是对外的合规卖点。同批硬链接去重改为按内容哈希寻址，跨批次也能去重。
- **字体授权**：客户上传的字体要用于服务端渲染并存入出图记录，需要定授权策略，至少在上传时由客户确认授权范围。
- **模型提供方抽象**：MCP 工具合同固定，模型可替换；如果主要客户在国内，Qwen 很可能是主力。第三阶段的评估门槛已在 qwen3.8-max、Claude Haiku 5.5 与 Gemini 4 Argon 上通过，换模型时用同一套评估判断（[Agent 评估](agent-eval.md)）。

## 值得做的产品想法

- **模板改动影响检查**：参照资源替换前的影响检查，改模板前用一组样本数据重新渲染并给出差异图，让非专家敢改模板。出图记录与重放已经具备。
- **组件库**：站点徽标、道路段、发车时间这类子模板沉淀为组件，Agent 优先组合组件而不是从零写 DSL。
- **示例图当作 Agent 的测试**：每轮迭代自动比较预览与示例图的结构差异（OCR 文字、区块位置）。

## 概念原型

界面形态的一次性原型保存在分支 `prototype/saas-workbench`（不进 main），图片与数据都由引擎真实生成：

- A：Agent 代建工作台。
- B：检查器结构化编辑。
- C：数据出图控制台。
- D：对话加画布，Claude Design 式，这是选定方向（M208）。D 的调节旋钮由引擎实时渲染。

运行方式见分支上的 `prototype/saas-workbench/README.md`。按 M205、M206、M208：

- **v1.0**：D 作为内部团队的代建工作台，C 作为客户的出图界面。
- **v1.x**：把 D 开放给客户，先开放评论与旋钮，再开放示例图向导。
- **A、B**：保留作为参考。

原型用于讨论界面形态，不作为实现基础。
