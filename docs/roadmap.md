# 产品路线图

结论：RenderWeave 做成面向对外客户的出图 SaaS。

- 做模板以 Agent 为主入口，网页负责看、改与出图。
- 第一个收费版本（v1.0）只把出图做成多租户服务；模板由我们团队用 Agent 工作台代客户制作，客户自助做模板在 v1.x 逐步开放。
- 阶段 3 的 Agent 可行性验证已验收通过：代建模式可行，真人照指南从示例图走到正式出图约 30 分钟（[第三阶段验收](stage3-acceptance.md)）。验收后补了 DSL 的纵向循环（M236）。

决定见需求记录 M204–M208。本文是规划，不是"当前能力"；当前可执行的能力以 `CONTEXT.md`「已实现能力」和两期阶段验收为准。

## 已确认的产品事实（M204）

| 问题 | 答案 | 影响 |
|---|---|---|
| 用户是谁 | 内部团队和对外客户都有，以对外 SaaS 为主 | 第一版就要多租户隔离、鉴权、配额；客户不会写 DSL |
| 新模板频率 | 每月几个 | 做模板是客户上手阶段的事，日常价值在出图；为低频动作造重型编辑器不划算 |
| 部署 | 云服务器，地点不限（M240）；开发时在本机 Docker 上模拟，对象存储用 S3 协议 | Agent 运行时必须按会话隔离；渲染要在独立 worker 中执行，带超时与配额 |

## 产品形态（M205）

三种角色，三条路径：

1. **设计（模板作者）**：
   - 上传示例图或原始数据集，Agent 给出数据定义、示例数据集与模板草案。
   - 示例图与引擎预览对照，在预览上点选元素提出修改。
   - Agent 与人类共用一套写入能力，可以直接保存草案、发布静态数据定义与模板修订；结构化差异、前后对比图与校验结果照常给出。租户可以要求发布前人工批准，但默认直发；人类始终可以在页面上查看、手操与微调（ADR-0022）。
2. **出图（操作员）**：
   - 由数据定义的编译产物自动生成表单，或从 Excel 导入。
   - 逐项草稿预览、批量交付，查询出图记录并重放。
3. **集成（开发者）**：HTTP API、webhook、命令行；MCP 供开发者自己的 Agent 使用。

不做的事：

- **自由拖拽的画布编辑器**：至少 v2 之前不做。DSL 是约束式的，例如"站点多了先收窄列间留白，不够再全组统一缩字"，拖拽难以表达这类规则。网页上的可视化是检查器加结构化属性面板。
- **把 Claude Code 原样作为产品入口**：业务用户需要领域界面而不是通用编码 Agent 的终端，安全上也要求只读工具加人工批准（ADR-0001、ADR-0003），并且不能以 Claude Code 的名义对外。Claude Code 只在本机代建的过渡期作为缺省执行器，以及作为开发者经 MCP 接入的入口。

Agent 运行时（M340，ADR-0027）：

- **循环**：由 RenderWeave 在服务端进程内用 Anthropic Client SDK 的 Tool Runner 驱动，不依赖 Claude Code、Agent SDK 或 Managed Agents。
- **工具**：全部由 RenderWeave 定义，读工具与写工具按身份授权，写工具只发给 Agent 身份（ADR-0022）。没有命令行与通用代码执行，所以不按轮次起容器；托管给客户前，对这一点做威胁建模复核。
- **模型**：工具是固定合同，模型可以替换（M232）。
- **展示**：桌面端与网页订阅事件流，展示轮次的执行过程（模型消息、思考摘要、工具调用、业务事件），不运行循环，也不持有模型 key。

交互与视觉方向（M208）：

- **交互参考 Claude Design**：左边对话、右边画布；在画布元素上留评论来定位修改；助手按需生成调节旋钮，旋钮对应模板参数，拖动后由引擎实时渲染；保留版本历史，可导出，也能直接进入批量出图。它合并了"对话提案"和"点选检查器"两条路线，结构化属性面板保留为辅助。
- **视觉**：暖色中性风格，米白底、陶土色强调、衬线标题。保持 RenderWeave 自有品牌，不使用 Anthropic 的标识与字体。
- **实测**：原型里在 50 DPI 下实时渲染一次约 120–300 ms，旋钮实时预览可行。正式出图的 120 DPI 预计更慢，服务化时要用缓存、低分辨率预览加最终高清渲染。

切换条件：如果阶段 3 证明 Agent 做不出可用的模板（M402 级别仍需专家大量返工），重心改为"结构化属性面板加组件库"，Agent 降为局部修改助手。阶段 3 的结果没有触发这一条：两张没见过的示例图都由 Agent 做到可交付，返工靠文字反馈完成，没有人手改 DSL。

## 第一版：代建模式（M206）

v1.0 只把出图做成多租户服务，内容包括：

- 多租户与鉴权；数据库加对象存储。
- 带超时与配额的渲染 worker 池。
- 由数据定义生成的数据集表单与 Excel 导入。
- 批量交付与出图记录；开放 API 与 webhook；模板只读预览与参数面板。

模板由内部团队用 Agent 工作台代建。

- **理由**：模板频率低，代建能把风险最大的"外部用户自助编辑"推迟；每次代建都积累经验，包括哪些提示有效、哪些组件可复用、Agent 卡在哪里。
- **开放自助的条件**：代建排期跟不上（例如等待超过一周），或客户频繁要求自己做小改。
- **开放顺序**：先开放点选元素做小改（字号、颜色、绑定），再开放示例图向导与组件库。

## 阶段 5 的分段（2026-10-27）

结论：阶段 5 分六段做。先做不依赖 Agent 门槛的代建接口与人类页面（P1），再把 Agent 搬到服务端并接上同一套写入（P2）。交互预览（P3）与 P2 并行，对客户开放 Agent（P4）放在两者之后，桌面薄壳（P5）只等 P1 的控制台新框架。

依据是[桌面工作台原型](prototypes/desktop-workbench/README.md)（画布第 36 版的 21 张画板）与仓库现状的逐页对照。出图这条线（画板 13–19）已在阶段 4 做完；缺的集中在代建写入、服务端 Agent、交互预览与桌面壳四块，逐项出处见 [P1 PRD](../.scratch/authoring-api-and-pages/spec.md) 的「当前证据」。

| 段 | 做什么 | 落地的原型画板 | 做完的标准 | 依赖 |
|---|---|---|---|---|
| P0 收门槛与生产化（进行中） | Tool Runner 在一次评估里跑满 M230 四个场景后改为本机缺省（ADR-0027）；原 38、公交留出与真人走查照旧；收费前的生产化：备份与恢复、登录限频、OTel、整批导出取舍（[平台化研究](research/2026-10-26-platform-architecture.md)第 6 节 4.x） | — | 四个场景连续两次达线；云上从空环境跑通阶段 4 的全流程 | — |
| P1 代建接口与人类页面（5.0） | 数据定义草案读写、校验、版本差异与发布；模板工作副本、属性面板与发布修订；审计补内容哈希与差异；租户审批策略；推送识别网页上的改动；平台管理页；控制台换成原型的新框架，画板 13–18 迁入 | 06 07 08 10 12 19 20，13–18 换框 | 客户管理员与代建工程师走同一套代建接口，发布、回退、审批与审计可查；真人走查 | 无 |

为什么这样排：

- **P1 先于 P2**：人类页面与代建接口不依赖 Tool Runner 门槛，现在就能开工。ADR-0022 要求人和 Agent 走同一能力面，Agent 的写工具建在 P1 的接口上，不另开写入通道。这与平台化研究第 6 节"5.0a 服务端 Agent 内核在前、5.0b 人类页面在后"的顺序相反，研究写于 Tool Runner 门槛尚未开跑时。
- **P3 与 P2 并行**：预览通道只动渲染路径，不碰 Agent。
- **P5 只等新框架**：桌面端是同一份页面加一层壳，壳层的工作与 P3、P4 互不阻塞。

与 M299 的对应：P1–P3 是 5.0（代建内核与人类页面、Agent 身份与写入工具），P4 是 5.1（Agent 工作台对客户开放）；5.2 的数据集接入兼容页仍按真实需求再做。原型里不进任何一段的小项（撤销批次取消、改数据后单独重交一项、轮换 webhook 签名密钥）按真实需求再排。

## 现在就要定下来的难逆转事项

这些都要在阶段 4 开工前写成 ADR。2026-10-19 已写成 ADR-0017–0020：

- **租户模型与存储抽象**（[ADR-0018](adr/0018-tenants-and-storage-abstraction.md)）：引擎已经通过 `ResourceRepository` 取资源；工作区文档和出图记录仍直接读写本地文件，需要同样抽象出来。
- **出图记录放进对象存储后的格式**（[ADR-0019](adr/0019-output-records-in-object-storage.md)）：保留现在"记录自足、可重放"的性质，这是对外的合规卖点。同批硬链接去重改为按内容哈希寻址，跨批次也能去重。
- **字体授权**：已定（M241），放宽、不做限制，不另写 ADR。
- **服务形态与执行隔离**（[ADR-0017](adr/0017-service-shape-and-render-isolation.md)）：进程模型、任务队列，渲染 worker 怎样做到强制超时与内存上限。同步的 WASM 绘制在进程内打断不了（[第二阶段验收](stage2-acceptance.md#接入服务前必须补的验证)），所以隔离单位至少是进程。
- **计量与额度**（M242，[ADR-0020](adr/0020-metering-and-monthly-quotas.md)）：按月额度计出图张数与 token 数；哪些出图计数、批量交付怎样预占与结算、超额时怎样拒绝。
- **模型提供方抽象**（并入 [ADR-0017](adr/0017-service-shape-and-render-isolation.md)：出图不调用模型，v1.0 服务端不托管 Agent）：MCP 工具合同固定，模型可替换。Agent 与人类的写入能力对等见 [ADR-0022](adr/0022-agent-human-capability-parity.md)。第三阶段后改用 OpenCode Go 上的 Claude Haiku 5.5，质量要求高时用 Gemini 4 Argon（M232）；服务器地点不限（M240）。第三阶段的评估门槛已在 qwen3.8-max、Claude Haiku 5.5 与 Gemini 4 Argon 上通过，换模型时用同一套评估判断（[Agent 评估](agent-eval.md)）。

## 值得做的产品想法

- **模板改动影响检查**：参照资源替换前的影响检查，改模板前用一组样本数据重新渲染并给出差异图，让非专家敢改模板。出图记录与重放已经具备。
- **组件库**：站点徽标、道路段、发车时间这类子模板沉淀为组件，Agent 优先组合组件而不是从零写 DSL。
- **示例图当作 Agent 的测试**：每轮迭代自动比较预览与示例图的结构差异（OCR 文字、区块位置）。

## 概念原型

界面形态的一次性原型保存在分支 `prototype/saas-workbench`（不进 main），图片与数据都由引擎真实生成：

- A：Agent 代建工作台。
- B：检查器结构化编辑。
- C：数据出图控制台。
- D：对话加画布，Claude Design 式，这是选定方向（M208）。D 的调节旋钮由引擎实时渲染。

运行方式见分支上的 `prototype/saas-workbench/README.md`。按 M205、M206、M208：

- **v1.0**：C 作为客户的出图界面。D 作为代建工作台原定在 v1.0，按 ADR-0017 推迟到托管 Agent 时再做；在那之前，代建用命令行流程。
- **v1.x**：先开放人类可操作的数据定义/模板编辑页与发布页，再开放 D 的 Agent 工作台（评论、旋钮、示例图向导、数据集提取）；Agent 与人类同能力写入，见 [ADR-0022](adr/0022-agent-human-capability-parity.md)。
- **A、B**：保留作为参考。

阶段 5 的界面方向另有一份桌面工作台原型：claude.ai 上的设计画布，21 张画板加一张用户故事地图。2026-10-28 起画板源文件、素材与逐张截图导出在 [docs/prototypes/desktop-workbench/](prototypes/desktop-workbench/README.md)；分支 `prototype/desktop-workbench` 保留第 24–36 版的存档历史。它把 D 的方向推到全部模块：左栏常驻 Agent 对话，右侧是模块内容，模块在标题栏右上角下拉切换，桌面端特点由 M341 的薄壳承担。分段见上文「阶段 5 的分段」。

原型用于讨论界面形态，不作为实现基础。
