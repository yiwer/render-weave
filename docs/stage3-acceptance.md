## 端到端代建（A11）

两张示例图都走完了"完成标准"的流程：

> 数据定义提取 → 审核、发布 → 数据集提取 → 审核、应用 → 模板辅助设计 → 审核、应用 → 正式出图 → 一轮模板修改

全程只用 `renderweave` 命令与审核页，没有手工复制或改写工作区文件。模型是 OpenCode Go 上的 Claude Haiku 5.5，命令与[代建指南](agent-guide.md)一致。

### 操作方式与偏差

- **操作者**：Claude 代内部成员执行。审核决定基于看过的示例图、预览与正式出图，但用时只是机器操作的时间。
- **审核途径**：审核操作经审核页自己的接口 `/api/review` 提交，与页面上的点击等价（同一个 `changeReview`）。原因是这次桌面应用的内置浏览器截不了图。审核页的浏览器走查在票据 05–07 做过，截图存档在 `docs/images/agent-review/`。
- **三条乱码的审核意见**：`pricetag-def-b`、`pricetag-dataset`、`366-def` 三轮最初用 Git Bash 的 curl 提交，命令行按本机代码页发出中文，审核意见存成了乱码。审核决定与改值不受影响；这三轮已应用，意见改不了。
  - 已修复：审核服务现在严格按 UTF-8 解码，不是 UTF-8 的请求体返回 400，并补了用例（`test/agent-review.test.ts`）。
  - 之后的审核都用 Node 按 UTF-8 提交，意见正常。
- **示例图**：价签示例图是第三方素材（昵图网，带水印与素材编号），只复制到 `out/agent-t09/` 使用，不进版本库（M222）。

### 价签：领域约定包的作用

先只给通用指南跑一次（A），再加上新写的价签约定包 [agent/domains/price-tag.md](../agent/domains/price-tag.md) 复跑（B）。项目说明相同，都是 [brief-definition.md](../scripts/agent-eval/scenarios/price-tag/brief-definition.md)。

| | A：只有通用指南 | B：加价签约定 |
|---|---|---|
| 用时、轮数 | 69 秒、16 轮 | 65 秒、21 轮 |
| 字段 | 11 个 | 10 个 |
| 待确认项 | 7 个 | 2 个 |
| 待确认项内容 | 店标是否建字段、货号是否必填、计价单位要不要枚举、物价员的类型与长度、零售价上限、会员价是否可选、监制单位是字段还是固定文字 | 品名最长 40 字、规格最长 30 字（都是业务上限，图上看不出） |
| 水印 | 排除，并在说明中写明 | 排除 |

- **A 符合预期**：没有约定包时，Agent 把领域知识的缺口列成了待确认项，没有自作主张；水印与素材编号没有被当作价签内容。
- **A 的 7 个缺口在 B 里都按约定定了**：店标、物价员、监督电话作为门店信息随数据集给出；零售价必填、会员价可选，价格存数值、不设业务上限；计价单位用文本；监制单位是模板里的固定文字。B 剩下的 2 个是这一单的长度上限，只有业务方能回答。
- **约定包的归属**：只写价签行业成立的事，例如价格的存法、门店信息的归属、常见字段。这一单的尺寸、品名长度写在项目说明里（M216）。

  - 第 1 次的模板单元被额度窗口打断，删掉后单独重跑，再合回同一份报告 [2026-10-16-gemini-4-argon](agent-eval/reports/2026-10-16-gemini-4-argon.json)。

- **缺省模型不变**：换成 Haiku 5.5 会把素材的去向从千问改为 OpenCode 与 Anthropic（M212），这要先确认客户资料能否外发。切换条件：确认可以外发，且当时的评估门槛通过。
