# 模板设计质量方案：证据与独立复核

结论：现有 harness 已经能检查 DSL、执行渲染并恢复成果，最大的质量缺口是缺少可复核的视觉目标、对应关系与修改后的覆盖记录。优先补同尺度样式核查与质量评估；扩大泛用工具或新增多 Agent 编排的收益，当前没有项目内对照证据。

本文为[架构评审主方案](template-design-harness-review.md)的证据附件，不是新批准的决定或实施验收。研究日期为 2026-10-22，代码基线为 `0ab57b9d7b7d861f2060abf4f6821f4247f50c35`。事实、推断和建议分别标明；源码行号均以此基线为准。

## 1. 范围与证据强度

前提是静态数据定义（StaticSchema）、符合它的示例数据集及示例图均已提供。模板设计读取三者，识别呈现关系；不默认重新提取数据、反推数据定义或修改已发布的静态数据定义。

这个边界既符合当前 `template-design` 的 `requires: 'dataset'`，也符合 M298“已绑定静态数据定义的数据集用于模板测试”的决定。现有输入还需要项目说明和完整渲染请求，以明确物理尺寸、适用尺寸范围与模板参数。[src/agent/tasks.ts:40](../src/agent/tasks.ts#L40)、[src/agent/run.ts:475](../src/agent/run.ts#L475)、[requirements.md:667](discovery/requirements.md#L667)

| 证据类型 | 本次做了什么 | 可以支持什么 |
|---|---|---|
| 当前源码 | 读取任务注册、资料装配、MCP 工具、成果评估、评估评分函数 | 当前合同和实现边界 |
| 受版本管理的实验报告 | 复核 `docs/agent-arabic-retest.md` 与相关票据 | 历史试跑结论及其限制 |
| 本机历史文件 | 只读原工作区的字号对照 JSON 和工具调用汇总 | 核对报告中的数值、调用次数 |
| 官方公开文章 | 重新打开 Anthropic 三篇一手来源 | 公开产品能力和实验结论；不能证明产品内部实现 |

本次没有运行付费模型，没有重跑引擎或历史诊断脚本，没有改变业务 Agent 资料。后文“已验证”区分源码核对、本次文件复核和历史实测，不能把它们合并成“新方案已经有效”。

## 2. 当前能力与真正缺口

### 2.1 已有的底座应保留

| 已核对事实 | 实现依据 | 对方案的约束 |
|---|---|---|
| 模板任务有 4 个文件工具、9 个 RenderWeave MCP 工具 | [src/agent/tasks.ts:40](../src/agent/tasks.ts#L40) | 不缺基本读写、检查和预览能力 |
| 每轮复制项目说明、通用做法、领域约定、DSL 参考、成果格式、请求 | [src/agent/run.ts:252](../src/agent/run.ts#L252) | 按阶段选材可在现有装配层演进 |
| 上一轮候选、审核和反馈可接续；修改任务识别基底变化 | [src/agent/run.ts:272](../src/agent/run.ts#L272) | 不应另建一套不兼容的历史状态 |
| `inspect_layout` 返回元素路径、位置、尺寸及文字字号、压缩比、溢出 | [src/mcp/tools.ts:303](../src/mcp/tools.ts#L303)、[src/mcp/tools.ts:677](../src/mcp/tools.ts#L677) | 样式核查优先复用现有布局摘要 |
| `check_outcome` 已按完整请求实际渲染，内容统一为 `needsReview` | [src/agent/outcome.ts:280](../src/agent/outcome.ts#L280) | 技术合格不能被解释为视觉合格 |
| MCP 当前合同为 0.8.0；预览与看图有像素上限 | [src/mcp/tools.ts:33](../src/mcp/tools.ts#L33) | 对比时必须传递裁切和缩放信息 |

当前任务已要求先骨架、再分区、每段检查和预览，并要求用布局摘要核对文字尺寸。因此问题不能概括为“没有迭代流程”或“没有要求看图”。[agent/tasks/template-design.md:14](../agent/tasks/template-design.md#L14)

### 2.2 质量判据尚未闭合

**源码事实**：任务从读取资料和示例图直接进入写模板，没有要求交回独立的版面分析与参考对应清单；最终差异可以只写在 `notes` 中。[agent/tasks/template-design.md:13](../agent/tasks/template-design.md#L13)

**源码事实**：当前模板评估的硬门槛是 10 个压测场景和两项 M402 版面检查；相似度只作参考。相似度把两图缩到 437 × 98 后算逐像素差异。[docs/agent-eval.md:77](agent-eval.md#L77)、[docs/agent-eval.md:108](agent-eval.md#L108)、[scripts/agent-eval/score.ts:279](../scripts/agent-eval/score.ts#L279)

**推断**：上述检查擅长检出已知结构与溢出问题，对字号层级、局部信息遗漏、低对比和留白失衡的覆盖不足；降低分辨率后的整图平均值也容易弱化局部缺陷。不能用现有指标证明一般模板已达到设计要求。

**建议**：质量分成信息与绑定、视觉还原、实际尺寸下的可读性、数据适应性、修改稳定性五项。前三项补明确参考与核查结果，后两项继承现有压测及修改范围检查。不要把它们压成一个未经校准的总分。

### 2.3 固定输入与上下文组织

**源码事实**：模板任务要求先读 `docs/` 全部资料；通用指南同时含“建可选字段”“按业务设必填”等提取阶段指令。[agent/tasks/template-design.md:4](../agent/tasks/template-design.md#L4)、[agent/guide.md:11](../agent/guide.md#L11)

**推断**：固定静态数据定义的模板任务存在接收到越界指令的可能，尚无对照实验证明这导致了哪次错误。需要澄清适用阶段，不能把潜在风险写成实测因果。

**建议**：模板阶段只做字段到呈现角色的映射；图上要求无法由既有数据表达时报告缺口。新建定义或迁移必须是独立范围。项目事实、行业经验、通用流程继续保持三层归属，阶段索引不能打乱优先级。

**源码事实**：业务资料以 `agent/tasks/`、`domains/`、`reference/` 装配，当前任务注册没有业务 `SKILL.md` 加载步骤。把内容改名成 skill 并不会自动形成阶段控制或质量门槛。[agent/README.md:25](../agent/README.md#L25)、[src/agent/tasks.ts:40](../src/agent/tasks.ts#L40)

## 3. 阿拉伯文案例能证明什么

该案例是合同 0.7.0、旧源码下的历史基线；本次代码已含合同 0.8.0 的成果与中断处理。案例说明缺陷来源，不代表当前实现仍保留每一个旧问题。[docs/agent-arabic-retest.md:9](agent-arabic-retest.md#L9)、[src/mcp/tools.ts:34](../src/mcp/tools.ts#L34)

| 历史实测或本次只读复核 | 合理结论 | 不应推出的结论 |
|---|---|---|
| 中断候选普通站名为 5.5 mm，初写时就是此值 | 尺寸选择偏小，不是自动适配从大字号缩小 | 模型正常完成后必然仍保留小字 |
| 同候选改为 11 mm 后，所检查站名压缩比仍为 1、无溢出 | 至少该对照能容纳更大的字 | 11 mm 是正确最终字号，或适合所有状态 |
| DPI 50 改 100，物理字号和文字宽高不变 | 提高 DPI 不能修复本例的物理字号偏小 | 所有视觉差异都与渲染分辨率无关 |
| 19 次 `view_image`、7 次 `render_draft`、7 次 `check_templates`，0 次 `inspect_layout` | 具备工具和提示词不等于完成校准 | 多调用一次布局工具就必然修好 |
| 模板轮因硬额度中断，未交回 outcome | 是未完成轮次，候选可恢复，完成度未知 | 完整模板设计任务的一次最终质量失败 |
| 独立补做 11 场景、37 布局断言通过，仍有文字能力问题 | 候选在这些场景中有可用结构；技术检查不等于视觉成功 | 全输入空间正确，或阿拉伯文已支持 |

字号与 DPI 的数值依据为 [docs/agent-arabic-retest.md:105](agent-arabic-retest.md#L105)；中断、独立检查和视觉判断的边界见该报告 [第 85 行](agent-arabic-retest.md#L85)与 [第 95 行](agent-arabic-retest.md#L95)。本次读取历史 `font-size-results.json`，三组数值与报告一致；工具次数由历史 `audit.json` 的 `r3-template.toolNames` 核对。

“预览缩放导致模型误换算”仍是推断：日志有不同缩放比例，没有明确错误换算过程。引擎缺少阿拉伯文塑形是另一个已知能力边界，不能和字号错误混成同一原因。[docs/agent-arabic-retest.md:119](agent-arabic-retest.md#L119)、[agent/guide.md:32](../agent/guide.md#L32)

该案例原本还涉及提取错误；当前任务已经给定静态数据定义和数据集，不能把重做必填判断、补数据或 OCR 转录算进模板设计的改进收益。

### 历史材料的可迁移性

本次只读的原工作区为 `F:\GenCode\render-weave`。`out/arabic-board-retest-2026-10-20/diagnostics/font-size-results.json` 和 `audit.json` 在该机器上存在，但 `out/` 不进版本库，新 worktree 没有这些文件。

## 4. 一手外部经验与迁移边界

本节三篇官方来源均在 2026-10-22 重新读取。只讨论公开内容，不将产品营销描述与另一篇研究实验拼成“Claude Design 的内部架构”。

### Claude Design：让反馈直接指向对象

**公开事实**：官方介绍提供设计系统复用、元素评论、直接编辑，以及间距、颜色和布局调整控件。[Introducing Claude Design](https://www.anthropic.com/news/claude-design-anthropic-labs)

**迁移建议**：保存“元素路径＋修改意图＋作用范围＋已确认值”，让下一轮与局部回归检查共同使用。这契合本项目的结构化属性和参数旋钮，不要求自由拖拽编辑器。

**未知**：官方没有公开其完整上下文文件、内部 MCP 清单、skills 列表、视觉评分器或多 Agent 编排；不能据产品功能断言其实现。

### Harness 实验：独立评审要校准，复杂度要做删减实验

**公开事实**：该实验分离生成与评估，评估根据实际界面提出反馈；作者记录了评分需人工校准、后续迭代未必优于中间版本，并随模型能力变化删减编排。[Harness design for long-running application development](https://www.anthropic.com/research/harness-design-long-running-apps)

**迁移建议**：以已知好坏模板校准独立视觉评审，保留最佳候选；固定模型、预算和输入，分别测“只加设计基准”“加确定性检查”“再加独立评审”的增益。评审先报告有位置的缺陷，不用自评分替代验收。

**边界**：研究对象是网页和应用构建，其 Playwright 交互检查不能原样等价为打印模板的物理尺寸检查，也不能证明 RenderWeave 必须引入三个 Agent。

### Context engineering：按需检索和代表性范例

**公开事实**：官方建议上下文提供足够且高信号的信息、工具边界清晰、例子具有代表性；允许用轻量引用按需取回详细资料。[Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)

**迁移建议**：将完整 DSL 保留为参考，默认提供当前阶段相关索引；增加“图＋DSL＋设计理由”的成对范例，另保留不进入提示词的评估样例。

**边界**：按需读取不必然更快或更省 token；新增检索调用也有成本，需在同口径实跑中核对缺陷数、总成本和人工返工时间。

## 6. Review 时必须守住的高影响风险

| 风险 | 对策建议 | 验证方式 |
|---|---|---|
| 模型把自己的初始估计写成验收真值 | 设计基准逐项记来源、估计/核准状态和允许偏差；高影响歧义单独暴露 | 用故意错误的基准检查是否会自证正确 |
| 原图与示例数据不同导致“像素不一致”误报 | 先映射呈现角色，区分固定视觉与内容随数据变化；不强求逐字相同 | 同版式换标题、列表数量，仍能识别真正的字号和对齐错误 |
| 缩放、裁切、旋转或拍摄透视使坐标失真 | 明确原图有效区域、坐标换算和可信范围；不能校准时只做相对判断 | DPI 不变性、裁切偏移和非正视示例反例 |
| 验证过的旧图被用于批准新候选 | 记录候选调用树、数据、请求、资源内容版本、渲染构建和基准哈希 | 任一相关依赖改变后使核查失效 |
| “已调用检查”被当成“已覆盖” | 返回独立样式、状态、重复实例及未覆盖列表 | 漏掉终点/已过状态时明确未完成 |
| 独立评审放大自信或越来越偏离参考 | 校准盲评；保留最佳候选；明确本项目目标是还原和适应性 | 缺陷召回、误报、人工修正时间与总成本一起比较 |
| 为实现对比而绕过严重问题 | 能力受阻单独归因，保留受阻草稿；不关掉 `text.unshapedScript` | 草稿可看且正式交付继续拒绝 |
| 多套规格和业务状态相互漂移 | 设计基准是可追溯附件；复用轮次、成果、元素路径和模板修订 | 修改后核对说明、测量和实际候选一致 |

上述对策属于建议，尚未承诺所有字段、文件名或工具名。先在票据 34 的最小闭环上证明必要性，再固定合同，避免把一次分析变成新的复杂 DSL。

## 7. 可执行的验证顺序

1. 先复用票据 34：固定已有静态数据定义与数据集，人工核准少量参考区域，能发现历史 5.5 mm 偏差，并验证旧核查在候选变化后失效。[票据 34:13](../.scratch/agent-template-authoring/issues/34-verify-element-styles.md#L13)
