# 模板 P1 真实评估与交接对照口径

2026-10-22，沿用 template-design 分支。运行代码固定为 9b4a832（引擎代码与 c780e52 相同，后续仅记录证据）。在真实交接运行之前登记下列口径，不根据结果改阈值或挑样本。

## 凭据复核

用户要求核对指定密钥。只在内存比较，输出布尔结果：Windows Process 作用域的 OPEN_CODE_API_KEY 存在但不匹配；User 作用域存在且与用户指定值匹配；Machine 作用域不存在。前一轮把进程变量存在误当作值正确，因而不能用其 429 断言用户指定密钥额度耗尽。

每次发起真实评估的 PowerShell 子进程先从 User 作用域读取到本进程 OPEN_CODE_API_KEY，再由 --key-env OPEN_CODE_API_KEY 传入 Agent。不更改用户级变量，不把密钥或其摘要写入报告。读取链路为 src/cli.ts 的 process.env[keyEnv] → runAgentTask options.key → 隔离 Claude Code 的 ANTHROPIC_AUTH_TOKEN。切换后已观察到真实 assistant usage 与多轮工具调用。

新的评估使用 template-design-p1-key-verified / out/p1-live-key-verified，旧 429 报告原样保留并补充作用域说明，不混入新批次。

## 固定对照

- 模型：主、小模型均 claude-haiku-5-5；Claude Code 2.1.296；MCP 0.9.0；缺省推理力度；串行执行，避免模型作业互相影响耗时。
- 门槛：原四场景各两次，原评分不变；只给新建模板附加既定 M402 design-checks.json。保留质量失败，不追加试跑来替换。
- 上下文与像素比较：历史 P0 改前、P0 修订后，与 P1 无阈值的新建模板各两次。StaticSchema、示例数据集、示例图、请求、资源按保存记录核对一致性。历史运行时间只是观测，不宣称隔离性能基准。
- 交接组：在当前版两个无阈值模板轮次完成后，分别以其输入发起一次受控运行。统一阈值 **60,000 输入 tokens**。依据是 P0 修订组首次候选落盘前平均约 44,223、峰值约 120,897；选择首次候选附近但低于既有峰值的阈值，检验交接能否削减后续历史积累。此值是实验参数，不是注意力质量的通用界限。
- 每组只有阈值停止后才接续一次，接续轮不再设阈值。若第一轮已自然结束，记为没有触发交接；若接续峰值再超过 60,000，如实报告。阈值由响应后的 usage 触发，并不阻止已经发送的超限请求。
- 不追加人工设计反馈；只读取系统生成的 handoff-feedback.md。不修改候选、核查计划、评分标准或模型。遇到明确额度错误停止；运行时无法正常启动等无效尝试另记。

## 度量与证据

- 像素：用同一最终核查器重放所有完整候选，2048 × 457 采样、7 × 7 均匀窗口 SSIM、RGB 相似度和最差区域；不与旧 437 × 98 RGB 分数混用。失败或缺候选时标为不可测，不能记 0。
- 峰值：input_tokens + cache_read_input_tokens + cache_creation_input_tokens，按 message ID 合并；交接组取停止轮与接续轮的最大单请求值。未知值不记 0。
- 耗时：沿用 round.run.wallMs；交接组将两轮执行耗时相加。另记请求数、输出 tokens 和是否发生自动压缩。评分脚本耗时不并入 Agent 执行耗时。
- 质量：每个最终成果继续跑原 10 项模板压测、2 项版面断言，以及新增 8 组合核查。相似度只作诊断，不替代质量门槛。
- 结果逐样本列出，再汇总平均及变化；两次样本不推断稳定成功率或因果效果。将真实与离线证据分开标注。

所有新轮次与原始日志保留在 out/，版本库保存不含凭据的摘要、评分、图片、协议和验收说明。
