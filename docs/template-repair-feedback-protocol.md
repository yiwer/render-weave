# Haiku 元素反馈修复实验：事前协议

2026-10-22。基线 9baa40c；用户要求真实模型成对比较。实验脚本冻结提交及文件哈希另存 manifest，不改生产 harness、MCP、DSL 或默认资料。

## 假设与范围

最多两条带角色、路径和差值的元素证据，能比自行看图诊断更可靠地修复已保存模板。两臂均可看图、读模板、使用相同 13 个工具；“只看图”指没有宿主附加元素差异，并非禁用代码与布局工具。同一参考图、坏例、StaticSchema、数据集、请求和通用要求。

参考是仓库维护的 M402 模板在 740×165 mm / 50 DPI / currentIndex=5 的正式出图。已知参考结构仅供宿主评分和反馈，不给 Agent 正确 DSL。新坏例是新的部件/参数组合，不属于新业务领域留出集；评判器沿用前次校准规则，本批不得依据模型结果改评分。

## 固定集合和预算

- A：隐藏站点标识行、隐藏下一站地标；两个目标为 badges 与 next-landmark 的内容恢复。
- B：道路字号 6.5→4.5 mm，运营方字号 8→5 mm；两个目标为对应角色字号恢复。
- C：站点面板上留白 4→10 mm，下一站区左留白 8→20 mm；两个目标为 stations 与 next-stop 位置恢复。离线准备首跑的 28 mm 会在 currentIndex=10 产生内容溢出，故在任何模型调用前改为 20 mm，避免额外引入技术错误；失败准备目录保留。
- 3 坏例 × 2 臂（image / evidence）× 2 重复，共 12 单元。每单元固定两轮，每轮 `maxTurns=20`，不因第一轮已修复而省掉第二轮。这个预算限制模型回合，不限制文件编辑次数。
- 串行执行；第 1 次重复 A/C 先 image、B 先 evidence，第 2 次相反。两轮都结束再切换臂，不额外人工指导。不在模型计时期间跑离线渲染/测试。
- Windows User OPEN_CODE_API_KEY 显式注入进程，主/小模型均 claude-haiku-5-5，推理力度不覆盖；个人 skills 禁用。明确额度错误记 quota 并停止后续派发；普通 429 或服务故障记 invalid 并停止本批，不能冒充额度耗尽。无自动质量重试，未运行项保留。

## 反馈和验收

evidence 每轮最多两项、最多 1200 字符，按内容、字号、位置优先，再按偏差选取；每角色最多一项。只给实际值、参考值/差值和当前布局路径，不给应改哪条 DSL 的答案。第二轮重新测当前候选。image 得到相同通用复核要求，不给隐含通过/失败提示。

固定检查：每角色内容完整/顺序/陌生文本，字号平均绝对对数偏差 ≤ ln(1.1)，归一化中心平均偏差 ≤ 0.005；线路号匹配。几何/字号比较项不足时不得视为通过。另测首站改名和 currentIndex=10 的内容绑定，以及三个输入的严重渲染问题。阈值仅用于此次受控恢复，不是生产视觉验收线。

主指标：每臂 12 个初始目标检查的恢复比例（6 单元×2目标），以及 6 单元中“技术交回有效、目标全修复且无新增失败”的比例。目标恢复直接据测量，技术交回单列，不因其他技术检查失败而抹去已观测的目标修复。新增缺陷按**最初通过、最终失败的固定检查项数**计，不冒充独立视觉根因数。无可用成果时修复计失败，新增项记未知。内容匹配仍不证明最终遮挡/墨迹可见。

成本：两轮 wallMs 相加；峰值取两轮单请求有效输入最大值；结束方式、实际回合、请求数、skills 和 servedModel 另记。无完整 usage 的值记未知。SSIM 只作附件；不作为修复通过条件。样本少且同一业务模板，不能据此报告稳定成功率或独立因果效应。
