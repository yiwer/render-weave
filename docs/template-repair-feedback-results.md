## 实际比较的内容

同一维护模板的三组退化：图标缺项、字号缩小、位置偏移。每组两臂、各重复两次，每单元固定两轮，并向 Claude Code 传相同 `--max-turns 20`。预算是执行器参数；`round.run.turns`、请求数和有效输入单列，不把不同统计字段混成同一种回合。

image 臂可自行看图、读候选及调用现有工具；evidence 臂额外获得每轮新生成的最多两条元素差异。参考结构只由宿主用于测量，模型没有正确 DSL。通过现有 `--from` 接续，首轮要求及历史反馈仍可被读取，因此“最多两条”指每次新增反馈，不表示历史上下文总共只有两条。

主指标按目标检查实际恢复计数；有效技术交回、目标全修且无新增失败另外统计。新增失败只统计初始通过项，未测到的结果保留未知；第一轮修好但第二轮无成果不当成已证实回退。

## 已观察到的修复轨迹

字号坏例最能区分两臂。image 第一次把运营方恢复为 8 mm，却把道路留在 4.5 mm（参考 6.5 mm）；第二次两轮后仍分别为 5 和 4.5 mm。两份结果的全图 SSIM 分别为 0.982856 和 0.971747，技术交回也都合格，但仍有目标未修好。已有可信期望值时，明确测量可以补上纯图片对照遗漏的局部问题。

位置坏例第一次的两条反馈都指向同一个站点面板：标识和站名共用上留白。第一轮修好该面板，下一站区仍偏移；重新测量后，第二轮的两条反馈都落到下一站区，并完成修复。这支持继续试验按区域或共同祖先分组再选反馈，但本批没有执行这种去重策略，不能声称它已经提高效率。

第二次位置实验重复了相同轨迹。反馈截断确实会影响注意范围：每角色一项并不能保证覆盖不同区域。初始两条证据及第二轮更新都可在交互页展开。

最长的反馈组轮次是 A1 第二轮：新增差异清单已为空，仍读取 4 个 DSL 章节、调用 6 次布局检查，共 48 次工具调用，峰值 83,715 tokens；最终像素与第一轮相同。两条反馈的长度限制不能独立约束后续工具往返或保证更低的最坏峰值。

## 正式接入判断

| 项目 | 判断 | 具体边界 |
|---|---|---|
| 已核准字号的实际值、期望值、路径 | **优先接入现有按需核查入口** | 两次 B 均复现收益。复用 `styles` 的已核准毫米范围及候选指纹，先给少量差异，详情按需展开；不把参考模板的 6.5/8 mm 或本实验阈值变成项目默认值。 |
| 内容和绑定检查 | **保留为独立约束** | 缺项 A 两臂都修好，尚未证明附加反馈提高该类修复率；技术合格也不能替代视觉检查。 |
| 按区域/共同祖先去重，再取最多两条 | **下一轮实验优先项** | C 两次都被同一区域占满反馈额度。共同祖先只是分组线索，不能直接当作错误根因；仍保留总数和未覆盖信息。 |
| 已无待修项时停止、无进展时交回 | **下一轮与去重策略分别对照** | 验证相同最终质量是否减少开销及回退。当前 22.89 分钟只是固定两轮实验中的冗余候选时间。 |
| 全图 SSIM、FLIP 总分作最终门禁 | **不采用** | B 的 SSIM 0.972–0.983 仍漏字号；保留局部图像证据辅助核对。 |
| 全部角色清单或完整 DSL 自动注入核心 | **不扩大默认注入** | 此次反馈包最多 449 字符已足以修复字号；大峰值来自后续行为。保留渐进读取、候选绑定和个人技能隔离。 |

入口可复用[现有核查计划与 designCase/designTarget](template-design-checks.md)。本批通过 requirement/feedback 文件提供诊断，验证了信息本身的价值；改为可选 MCP 拉取后，Agent 是否主动调用仍需产品路径复测。接入前保持 `proposed` 与 `approved` 的区别，旧候选反馈不可作为当前验收证据。

## 解释边界

这是同一业务模板的受控恢复实验，参考期望已知；不代表任意 PNG 自动标注质量，也没有人类盲评。字段、字号和位置证据不证明最终遮挡、裁切或墨迹可见。新增失败项可能共用一个视觉根因。

位置坏例中，两条最大差异可能分别指向同一个站点面板下的图标和文字，挤掉另一块区域。实验保留事前选择规则，不为得到更好结果手工挑选反馈；是否需要按共同原因合并，将依据实际修复轨迹判断。

模型串行计时；评分在轮次结束后运行。密钥从 Windows User 的 OPEN_CODE_API_KEY 显式注入，主/小模型均 claude-haiku-5-5，无个人技能注入。服务故障、硬额度与未运行项分列，不用缺失值冒充零成本。

## 复现

```powershell
npm run build
npx tsx scripts/agent-eval/repair-experiment.ts --prepare out/repair-feedback-live
node scripts/agent-eval/repair-live.mjs --root out/repair-feedback-live
node scripts/agent-eval/repair-report.mjs --root out/repair-feedback-live --out docs/agent-eval/figures/template-repair-feedback
```

准备和真实执行均要求新目录；已运行的轮次不会静默覆盖或重复调用。进程使用用户级密钥及可执行的 claude.exe 路径，按[开发环境](dev-setup.md)设置，不在文件或命令参数写密钥值。
