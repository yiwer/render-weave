## 固定版本反例

用 `git archive 64d7baec6b795c2c5875b3ed754ef425438662be` 固定源码；从归档的 `src/index.ts` 调用公开 render 和 verifyElementStyles。字体与素材来自本机显式资源库，记录资源和全部 src 指纹，执行前后确认不变。所有布局来自真实出图；这是判据探针，不是模型对照。

| 探针 | 固定版本实测 | 含义 |
|---|---|---|
| 明确核准 8 mm / 实际 8 mm | 通过 | 基本显式字号可用 |
| 明确核准 8 mm / 实际 4 mm | 不通过，检出字号过小 | 已知字号差异能被发现 |
| 同一 8 mm 模板从 50 改 100 DPI | 仍通过 | 这条明确毫米字号路径未受 DPI 改变影响 |
| 参考路径完全不匹配 | 通过，匹配 0 | 未覆盖被当成通过 |
| 父字号 8 mm、实际片段含 5 mm | 通过，无异常 | 只检查父字号会漏掉小字片段 |
| 50×20 mm 标注框含留白，未核准字号 | 误推预期 19 mm，将实际 8 mm 判小 | 标注框尺寸不能直接推成字体字号 |
| 参考框向左移 100 px | 通过，无位置异常 | 当前这一接口没有位置比较，不能当位置已核验 |
| 空画板 | 通过，匹配 0，statesCovered 含 normal | 状态和覆盖必须来自实际证据 |

首次针对活动检出的结果因代码并发变化弃用。归档探针首次缺少未入库字体未出图，也弃用；最终报告为 `out/style-baseline-probe-final/report.json`。review 发现并修复 100 DPI 探针错误绑定 50 DPI 请求的问题后，8 个探针全部重放；实际请求与指纹随每行保存。

这些问题只归属于固定提交 `64d7bae`，不声称另一位 agent 的当前未提交实现仍有同样问题。建议将缺项、片段、框语义、状态覆盖作为后续合并的回归案例。
