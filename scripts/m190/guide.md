# 出图模板的通用做法

本指南适用于任何"示例图 → 数据定义 → 模板"的任务，例如标牌、价签、证卡、资产标签、海报。

- **优先级**：项目说明（brief.md）> 领域约定（domain-*.md，如有）> 本指南。
- **都没写到的**：按示例图判断，并列入待确认。

## 拆分：数据、模板与出图参数

1. **数据定义只收随业务对象变化的信息**，也就是同一类图之间内容不同的部分。固定装饰、颜色、版式和标签文字（如"票价："）都留给模板。
2. **能由其他数据推出的信息不存**，由模板派生。例如列表的首项、末项，某项的后一项，项数，某项是否在某个位置之前。
3. **"出哪一张"是出图参数，不进数据集**。同一份数据要出多张不同的图时，例如高亮哪一项、用哪种版式、出哪一面，这个选择由出图请求给出。参数要有"不选"的取值（例如 0 表示不高亮），模板要正确处理它。
4. **组合值拆开记录**：金额拆成类型文本加数值；时间段拆成起点加终点；带单位的量拆成数值加单位，单位通常固定写在模板里。
5. **编号和名称另存文本**：即使牌面上用艺术字图片呈现，也要有文本字段；图片作为可选的呈现资源另设字段。
6. **图标与小标记分两种处理**：
   - 表示类别的（设施、等级、类型），用文本枚举列表记录，模板按取值选图。
   - 表示具体内容的图片（照片、地标、标志），用图片字段引用资源。
   - 看起来像文字的符号（带圈数字、字母徽标）可能是图片：先查资源仓库，有对应资源就按图片处理。
7. **约束按业务上限设**，不按示例图的值设。列表项数、文本长度都要能服务同类的其他对象。
8. **含义不明的元素不建字段**：示例图里含义不明、或疑似设计错误的元素，不要凭猜测建字段，列入待确认。项目说明中客户的说明优先于示例图。

## 模板

9. **适用尺寸按项目说明的目标范围设**，不按示例图的尺寸设。被调模板的适用范围也要覆盖极端情况：项数最少时，一个合并段可能占满整行；项数最多时，每项最窄。
10. **同一角色的重复元素字号一致**，例如列表中每一项的名称。放不下时依次收紧空白、压缩字形、全组统一缩字（缩字组），不单独缩某一项。
11. **文字分布按示例图判断**：
    - 两侧留白与字间距相同，用 spaceEvenly；
    - 首尾字贴边，用 distribute；
    - 整体居中，用 center。
12. **可选元素放在它所属的排布流里**：没有值时隐藏、不占位，同一流里的其他内容自然延伸。例如列内的可选标记应是该列的最后一格，不要单独排成一行。
13. **状态用状态样式切换**：已过、当前、未到，或选中、未选这类状态，用状态样式按派生变量切换，不要复制元素。
14. **交付前用预览逐项验证**，全部没有严重问题再交付：
    - 示例图对应的请求；
    - 参数的"不选"值；
    - 首项与末项；
    - 列表最少与最多项；
    - 最长文本；
    - 目标尺寸的最小值与最大值。

    出图请求可以用内联数据集试验其他数据。
